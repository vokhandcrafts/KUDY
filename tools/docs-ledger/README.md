# Рэестр фактаў дакументацыі (docs ledger)

`npm run ledger:check` — машынная праверка бязгубнасці дакументацыі (G18.05):
кожны факт, які існаваў у `docs/` на момант базавай лініі, мусіць дагэтуль
існаваць — у файле-ўласніку, па спасылцы ці (для чыстай гісторыі) пад pinned
SHA ў `dropped.json`. Праверка не судзіць змест — толькі знікненне.

## Класы фактаў

| Тып | Прыклад | Адкуль бярэцца |
|---|---|---|
| `id` | `G01.03`, `R07`, `P02`, `D05`, `TR-3`, `AR-1` | прыёмкі ID па ўсіх `docs/**/*.md` |
| `code` | `story_id`, `npm test`, `--config` | інлайн-спаны ў зваротных апострафах (без fenced-блокаў; спан мусіць утрымліваць літару ці лічбу) |
| `section` | `09 §6.2`, `§2` | цытаванні раздзелаў праз `§` |
| `link` | `docs/architecture/09_technical_architecture.md` | адносныя target-ы markdown-спасылак (без `https:`, `mailto:`, чыстых якараў; фрагмент адкідваецца) |
| `heading` | `6. Слаі дадатку` | загалоўкі ATX-радкоў (#…######) толькі норматыўных файлаў |

**Норматыўныя файлы** — уласнікі фактаў з мапы валодання ў `docs/readme.md`:
нумараныя дакументы (`docs/NN_*.md`, `docs/architecture/NN_*.md`), прынятыя
ADR (`docs/architecture/decisions/`) і кантракт run-model
(`docs/run-model/README.md`). Загалоўкі іх тытчуцца пафайлава: уласны тэкст не
перапісваецца, таму зніклы ці з'ехаўшы ў іншы файл загаловак — змена для рэв'ю,
не «перанос».

## Што лічыцца «прысутным»

- `id`, `code`, `section` — ліпад цалкам сустракаецца дзе-заўгодна ў `docs/`:
  перанос факта ў файл-ўласнік праходзіць, знікненне — не.
- `link` — спасылка дзе-сінуць засталася, альбо файл-мэта дагэтуль існуе на дыску.
- `heading` — той жа загаловак у тым жа файле.

`docs/human-actions.md` — па-за сканам наўмысна: гэта часовы журнал дзеянняў
для чалавека, запісы з яго прыбраюцца па пацверджанні, і абнаўленне рэестра
фактаў гарала б на кожным такім пацверджанні.

## Базавая лінія і спіс страт

`npm run ledger:baseline` адзін раз фіксуе `tools/docs-ledger/baseline.json`
па стану бягучага коміта. Паўторны запуск перавызначае, што лічыцца фактам, таму
патрабуе `--force` і робіцца толькі ўсвядома, у рэв'ю.

Зніклы факт трапляе не ў новую базавую лінію, а ў `tools/docs-ledger/dropped.json`:

```json
{ "entries": [
  { "kind": "code", "value": "acquired_at",
    "reason": "чаму факт больш не дакументуецца",
    "sha": "повны SHA коміта з арыгіналам" }
] }
```

Кожны запіс мусіць мець `reason` і хаця б адно з `replacement` (спасылку на
новае месца факта) або `sha`. Страты без гэтага — не запісы, а прогалы;
`ledger:check` красіцца з назвай пункта. У PR змен класа «гісторыя» спіс
`dropped.json` чытае чалавек — яго зацвярджэнне фіксуецца ў
`docs/human-actions.md`.

## Падключэнне і гварда

Тэст `tools/docs-ledger/ledger.test.mjs` ідзе ў glob `npm test` — ганяе
рэальныя CLI (`ledger-baseline.mjs`, `ledger-check.mjs`) на пясочніцах
(выдаленне пункта фарбуе праверку, перанос праходзіць), рэпазітарную праверку
на бягучым HEAD і wiring: скрыпты `ledger:*`, запіс glob-а ў `npm test` і
гварда ў `tools/ci/check-required-checks.mjs` самі чырванеюць пры адкате
(implementation-rules §1). Такім чынам `required-checks.yml`, які ганяць
`npm test`, прымушае рэестр на кожным PR.

Тэст на зварот:

```
node --test tools/docs-ledger/ledger.test.mjs
```
