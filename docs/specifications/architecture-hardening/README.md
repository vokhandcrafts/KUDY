## Што лічыцца доказам

- Шэсць збоевых сцэнароў першаснага аўдыту ўзноўленыя прадукцыйнымі функцыямі. [Дадатковы скрыпт аналітыкі](../../audits/2026-10-02-events-rate-proof.mjs.txt) выклікае сапраўдны апрацоўшчык і SQL-порт з асінхронным драйверам: лічыльнік `1` дае `429 event_rate_limited`, запіс не адбываецца. Запуск з кораня PowerShell: `Get-Content -Raw docs/audits/2026-10-02-events-rate-proof.mjs.txt | node --experimental-strip-types --input-type=module`. Гэта гістарычны доказ збою, не тэст выпраўлення; ён не выклікае сетку ці сапраўдную базу сервера.
- Адсутнасць лімітаў чакання, верхняй мяжы тэрміну спасылак і запуску `arch:check` у GitHub правераная па кодзе. Гэта не доказ збою разгорнутага сервера.
- Гонкі фонавага GPS і адначасовых загрузак патрабуюць кіраванага ўзнаўлення. Для іх спачатку патрэбны тэст парадку аперацый; без збою нельга рабіць спекулятыўнае выпраўленне.
- Прыладавыя GPS, гук, сапраўдныя плацяжы, разгорнуты Supabase і налады абароны галіны не правераныя. Замена платформавых API ў тэстах даказвае толькі выклікі і парадак аперацый.

## Парадак

Спачатку апублікаваць дакументы ў асноўнай галіне. Пасля — сервер, гук, згода, бяспечны транспарт і запіс прагрэсу; затым жыццёвы цыкл рэсурсаў і праверкі. Падключэнне дадатку чакае адпаведных выпраўленняў. Жывая прыёмка выкарыстоўвае існую #296; выдаленне даных — існую #288. Залежнасці і канфлікты файлаў вызначаныя ў індэксе G20.

Кожнае выпраўленне мае паводзінны тэст, які падае пры адкаце змены. Выканаўца прытрымліваецца [правілаў рэалізацыі](../../agent-rules/implementation-rules.md), [рэвью](../../agent-rules/code-review.md), [доказаў](../../agent-rules/showboat.md) і [працэсу задач](../../agent-rules/issue-workflow.md).

[Скрыпт межаў](../../audits/2026-10-02-review-boundaries-proof.mjs.txt) запускаецца з кораня: `Get-Content -Raw docs/audits/2026-10-02-review-boundaries-proof.mjs.txt | node --experimental-strip-types --input-type=module`. Ён не выклікае сетку; частка сцвярджэнняў фіксуе дэфект, частка — ужо правільную паводзіну. Рэвью не становіцца доказам збою без праверкі.

## Межы рашэння

Не перапісваем ядро, не дадаём базавыя класы, не выносім калектар у асобны рэпазіторый. Памер файлаў і доля каментароў самі па сабе не абгрунтоўваюць перабудову. Пры рэальнай правцы файла захоўваем каментары пра прычыну рашэння і прыбіраем звязаную састарэлую гісторыю паводле існых правілаў; асобная масавая чыстка не патрэбная.

Генерацыя тыпаў датычыць толькі фармату даных, які належыць схемам. Унутраныя мадэлі і падтрымка старога каталога захоўваюцца. Рэестр дакументаў працягвае ахоўваць факты; яго нельга выключаць дзеля паскарэння тэстаў. Прапаноўваць асобны запуск праверак можна толькі з захаваннем абавязковага кантролю.
