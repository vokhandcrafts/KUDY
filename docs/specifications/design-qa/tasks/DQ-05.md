# DQ-05 — Write the design-QA agent rules

## Epic

Epic: #908

## Goal

Any harness can run the design-QA review on request and before closing a task with interface changes, and its findings separate rule violations from opinions (spec §6, §12).

## Sources

Spec: `docs/specifications/design-qa/2026-10-30-design-qa-system.md` (sections cited per criterion). Canon: `docs/design/visual-language.md`; decision register: `docs/design/brand/decisions.md` (only rows marked accepted are rules). Record the git commit the sources were read at.

## Acceptance criteria

1. [ ] `docs/agent-rules/design-qa.md` (English) defines: inputs; the accepted sources of truth and that drafts/proposals are never rules; the classes RULE / DIFF / OPINION / NOT-VERIFIED with the RULE citation-and-measurement requirement; the refuting second pass that drops a finding on doubt; the OPINION cap of 3; the report template.
2. [ ] `docs/design-qa/exceptions.md` lists the known canon exceptions (light cartography in dark theme DT-4, light splash DT-6, disabled = muted only in light theme, `hitSlop`).
3. [ ] `AGENTS.md` and `CLAUDE.md` point to the rules: run on request and mandatorily before closing a task that changes the interface. The agent is not run in CI and needs no API key.
4. [ ] The 48 dp target is an OPINION until the owner adds it to the canon (spec §12).

## Out of scope

Running the benchmark (DQ-07); image checks (DQ-11).

## Dependencies

Blocked-by: #909

## Proof

A dry run on one merged UI PR recorded in `docs/agent-tasks/results/DQ-05.md`, showing the report format and at least one dropped candidate from the second pass, or a statement that none arose.
