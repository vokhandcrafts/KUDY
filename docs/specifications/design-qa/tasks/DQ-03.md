# DQ-03 — Build the visual:check capture, compare and report tool

## Epic

Epic: #908

## Goal

One command captures the specimen and screen matrix on the emulator, compares each shot with its approved baseline and writes a report the owner can read in five minutes (spec §6.4, §8.1).

## Sources

Spec: `docs/specifications/design-qa/2026-10-30-design-qa-system.md` (sections cited per criterion). Canon: `docs/design/visual-language.md`; decision register: `docs/design/brand/decisions.md` (only rows marked accepted are rules). Record the git commit the sources were read at.

## Acceptance criteria

1. [ ] `npm run visual:check -- --surface <names>` captures through the existing driver, compares with pixelmatch (exact pinned dev dependency) using the DQ-01 threshold, and writes `manifest.json` (device, API, theme, font scale, locale, fixture, commit) and `report.md` with a verdict line, a DIFF table linking baseline/current/diff images, and a NOT-VERIFIED list.
2. [ ] Baselines live under `docs/design-qa/baselines/`; they are written only with `--update` (or `--update --from <dir>` for CI-produced captures). A test proves a run without the flag never writes a baseline.
3. [ ] Unit tests on synthetic PNG pairs: identical → pass; a changed block → DIFF with a diff image; size mismatch → explicit failure, not a pass.
4. [ ] A fast `npm test` check fails when a story has no baseline for the V1 matrix.
5. [ ] Missing adb, emulator or APK → the command exits non-zero with the reason; it never reports a pass.

## Out of scope

CI wiring (DQ-10); accessibility checks (DQ-06); approving baselines (DQ-04).

## Dependencies

Blocked-by: #910, #911

## Proof

The unit tests above fail when the comparison or the `--update` guard is reverted; Showboat demo with a seeded +2 px padding change producing a DIFF.
