# DQ-01 — Measure emulator screenshot noise and pick the reference AVD

## Epic

Epic: #908

## Goal

Know how much two captures of an unchanged screen differ, so the comparison threshold and the reference emulator come from measurement, not a guess (spec §8.1, §10).

## Sources

Spec: `docs/specifications/design-qa/2026-10-30-design-qa-system.md` (sections cited per criterion). Canon: `docs/design/visual-language.md`; decision register: `docs/design/brand/decisions.md` (only rows marked accepted are rules). Record the git commit the sources were read at.

## Acceptance criteria

1. [ ] Capture Explore (fixture catalog, phase B) and one static screen 5 times each on the local emulator and 5 times on the CI emulator profile from `.github/workflows/android-e2e.yml` (API 36, swiftshader), with window/transition/animator scales at 0 and a fixed status bar (demo mode or a cropped inset).
2. [ ] Report per pair: differing pixels (count and %), the bounding boxes of differences, and whether local and CI captures match within the proposed threshold.
3. [ ] Recommend a pixelmatch threshold and a max differing-pixel ratio, and name the reference environment. If local and CI differ beyond the threshold, the reference is CI and baselines are produced by a manual workflow run (spec §8.1).
4. [ ] Use the existing driver (`tools/e2e-android/driver.mjs`); restore every device setting changed by the run, also on failure.

## Out of scope

Building `visual:check` itself (DQ-03); any baseline commit.

`docs/agent-tasks/results/DQ-01.md` with the raw numbers, the commands and the device/AVD identifiers; captures kept in the CI artifact or the evidence folder, not as baselines.
