## Acceptance

1. [ ] Generators: clean walk, standing at every stop, fast walk, mid-route start; each is seeded and its trace file is reproducible byte for byte.
2. [ ] Scenario fixtures with explicit expectations: replay of a heard stop, mid-route start, reverse order, GPS gap, focus loss during guide audio, locked stop unlocked mid-walk by `AccessReady`. Each expectation names what must fire and what must not.
3. [ ] No auto-finish in any trace: without an explicit End the final state is `Active` or `Paused`.
4. [ ] Expectations are per trace, not "all stops": a partial walk passes when it matches its own expectation.
5. [ ] The suite runs in `npm test` and therefore in `required-checks`; changing one expectation makes CI fail with the trace name and the first differing report line.
6. [ ] The field-trace slot exists (format documented in the simulator README) and is empty; the results file lists recording a real walk as a `not-run` step for G11.02.

## Out of scope

Recording real walks; calibration of radius/dwell (G11.02); any engine rule change.
