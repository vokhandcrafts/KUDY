# G05.02.c — Android location adapter (expo-location, background)

**Status:** not-started. **Model class:** strong. **Dependencies:** [G05.02.b](G05.02.b.md) complete; [G06.09.b](../app/G06.09.b.md) complete (the app and the composition root the adapter plugs into). Parent task: G05.02.

## Scope

The device implementation of the location OS port from G05.02.b: foreground and background updates through `expo-location` (and `expo-task-manager` if the background API requires it), geofence regions, the Android foreground-service notification and permission requests at Start. The adapter only maps OS calls and callbacks to the port; every decision stays in G05.02.b.

Read: [09 §9, §9.1](../../architecture/09_technical_architecture.md) (background permission at route start, foreground service on Android, failure modes the watchdog cannot save), [ADR G00.01](../../architecture/decisions/G00.01-platform-evidence.md) §5, [ADR G00.04](../../architecture/decisions/G00.04-stack-baseline.md) §1 and §6 (pins, permissions), [device matrix G00.01.b](../../../spikes/G00.01-location-audio/evidence/G00.01.b-device-matrix.md), the spike `spikes/G00.01-location-audio/` as prior art (do not copy it wholesale; its constants are not defaults).

**Device decision (2026-09-23, founder):** no device and no Android SDK in this wave. Host proof: pure mapping tests, `tsc`, `expo-doctor`, `expo prebuild --platform android --no-install`. Every device cell stays `not-run`; the results status for the device part is `blocked-external`, and row G05.02 does not close until the matrix cells below pass.

## Allowed outputs

- `services/location/expo/` — the adapter, its pure mapping functions and their tests
- `services/location/` — only the split of the permission request into foreground/background in the port and its tests
- `app.json` (plugin options, notification text), `package.json` + `package-lock.json` (`expo-task-manager` only if required, exact pin via `npx expo install`)
- ADR G00.04 §6 (any new pin), `docs/demos/<YYYY-MM-DD>-g0502c-android-location.md`, `docs/agent-tasks/results/G05.02.c.md`

## Acceptance

1. [ ] The adapter implements the G05.02.b port exactly; the pure mapping from OS location objects and permission responses to `FixInput` / status values is tested on synthetic inputs, including missing accuracy and out-of-range values (rejected by the mapping, not passed on).
2. [ ] The port has separate foreground and background permission requests. With the fake port, `setMode('city-surface')` requests foreground only and `setMode('active-guide')` (the Start path) requests background, with the explanation string from the app config; no other mode requests background.
3. [ ] The Android foreground-service notification is declared, its text is in the app config, and `expo prebuild --platform android --no-install` produces a manifest with the service and the five location permissions (output recorded).
4. [ ] `npm run typecheck`, `npm test`, `npm run arch:check`, `npx expo-doctor` are green; the adapter is reachable only through the composition root of G06.09.b.
5. [ ] The results file lists, as `not-run` with the command or steps to run each later, the Android cells of the G00.01.b matrix that this adapter serves: foreground + dwell, locked screen, background, permission denial/revocation, GPS gap, recent-apps removal, force-stop, reboot, battery saver.
