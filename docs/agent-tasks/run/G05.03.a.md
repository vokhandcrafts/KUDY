# G05.03.a — Audio service: the single player and tagged callbacks

**Status:** not-started. **Model class:** strong. **Dependencies:** [G05.01.c](G05.01.c.md) (#199) complete — the reducer's `playing` variants and `play_token` shape are the contract this service echoes. Parent task: G05.03 ([16 row G05.03](../../16_delivery_backlog.md)).

## Scope

`services/audio` as a plain class over an injected player port: one physical player, commands that carry `play_token`, callbacks that return it unchanged, focus events, computed playback state. The service issues no tokens and interprets none (the controller owns them). The `expo-audio` adapter is [G05.03.b](G05.03.b.md).

Read: [ADR G01.02](../../architecture/decisions/G01.02-audio-ownership.md) §3.1–§3.8; [09 §6.1](../../architecture/09_technical_architecture.md) (player boundary paragraph, invariants 2, 5, 6), §6.3 (`audio` row); [19 §2.3, §3.4](../../architecture/19_class_and_module_map.md); [11](../../11_run_interaction.md) §3.2, §5.4 and criteria C18–C20, C38–C45.

**Canon note:** 19 §3.4 predates G01.02 and tags callbacks by `(sessionId, playId)` only. ADR G01.02 §3.2 and 09 §6.1 (`play_token = {kind, ref, seq}`) are the source; record the difference in the results file, do not edit 19.

## Acceptance

1. [ ] One player: a second `play` stops the first by command before starting (the fake port never has two active sources); rapid play/stop sequences end in the state of the last command.
2. [ ] Every callback (finished, failed → `story_play_failed(token, reason)`, paused, resumed) carries the exact token of the command that started the play; after dispose and re-creation, a callback of the old instance is not forwarded.
3. [ ] An interruption is reported as `FocusLoss` / `FocusRegain`, never as finished — for guide and moment plays alike; a test simulates a call during each kind.
4. [ ] Playback state (idle / playing / paused, position) is computed from the port on read, not stored in a second copy; position is in milliseconds, never a 0..1 ratio, and NaN / negative durations from the port become a failure, not a number.
5. [ ] Dispose followed by play re-creates the player (no reset of a disposed instance).
6. [ ] The service imports nothing from `core/engine` and never decides about `heard`, queue or automation.

## Out of scope

The `expo-audio` adapter, background mode, lock-screen controls and loudness normalisation ([G05.03.b](G05.03.b.md)); wiring callbacks into `step()` (G05.04, G05.05); Moment UI (G07.02).

## Proof

Tag each callback with the *current* token instead of the token of the source that produced it → the test where a late finish of play A arrives after play B has started fails (A's finish would be credited to B). Showboat: required (runtime behaviour, audio interruptions).
