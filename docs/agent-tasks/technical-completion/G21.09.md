# G21.09 — Use one UI locale registry and complete typed message catalogues

## Epic

Epic: #532

## Goal

Adding a UI language uses one registry and typed complete message sets, preserving existing be/en/uk behavior.

## Scope

Pure contracts/ui-locales.ts and contracts/ui-message-types.ts; native/controller/web selector and picker adapters consuming G21.24 canonical records; preserve runtime exports for G21.25 generation.

## Acceptance criteria

1. [ ] Define the eight requested UI codes and native names once: be/Беларуская, en/English, uk/Українська, de/Deutsch, es/Español, fr/Français, cs/Čeština, sv/Svenska. Keep UI locale types distinct from published content availability.
2. [ ] Move reusable native message interfaces to the shared pure contract zone; derive the key/parameter contract from the G21.24 canonical records and preserve existing selector exports and dynamic-message behavior without adding an i18n runtime dependency. Do not introduce another manually maintained source/context catalogue.
3. [ ] Inventory all message domains: chrome, preview, run, place, nearby, offers, hints, errors, permissions, purchase/restore, feedback and accessibility. Include guideHintStrings, which currently falls back to be for uk.
4. [ ] The selector/picker exposes only registered complete catalogues; a planned code with no complete catalogue is not advertised. Unknown inputs keep the approved error/fallback semantics.
5. [ ] Functional tests cover key/placeholder completeness and existing rendering; registry/key deletion is detected through the standard runner and the layer check remains clean.
6. [ ] Keep current be/en/uk rendering unchanged during migration; expose interfaces that G21.25 can generate without changing callers. Authoring lives in canonical source/translation data, not manual native/web copies.

## Out of scope

Production guide writing/narration, unrelated refactors, new runtime translation services, automatic worker launch and unauthorized workflow changes.

## Dependencies

Blocked-by: #533, #556, #557

## Proof

Locale registry and rendered-message tests (planned), npm test/typecheck/arch:check; existing be/en/uk output retained.
