# G21.24 — Define one canonical source record for every UI message

## Epic

Epic: #532

## Goal

Each UI message has one authoritative key/source/context record, separate from locale translations and generated runtime files.

## Scope

contracts/ui-messages/source.json and its schema; message inventory/migration map covering native and web domains.

## Acceptance criteria

1. [ ] Inventory actual messages rather than assuming a file/key count; map all existing native/controller/web strings and dynamic phrases to stable canonical IDs. Identical wording with different meaning/context is not merged blindly.
2. [ ] Use Belarusian as the existing base source. Each record defines id, source text/message pattern, screen/action context, parameters with types, applicable length/accessibility constraints and format; record the established safe plural/template format used.
3. [ ] A source text, context, placeholder contract or relevant constraint change changes its deterministic sourceHash. Define exact fingerprint inputs and canonical serialization; hashing excludes the hash/review fields themselves.
4. [ ] Keep per-locale translations and review metadata separately; base text is authored once. Preserve existing exports through the migration and retain current user-visible be/en/uk output.
5. [ ] Schema tests reject duplicate IDs, missing context, unknown fields, invalid message/parameter syntax and executable payloads; a changed source/context/parameter yields a different fingerprint.

## Out of scope

Production guide writing/narration, unrelated refactoring, runtime translation, premature source adoption/MCP installation and automatic worker launch.
