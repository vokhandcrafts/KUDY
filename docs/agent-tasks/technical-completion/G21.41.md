# G21.41 — Compare Chinese translation and exportable narration candidates

## Epic

Epic: #532

## Goal

Identify evidence-backed translation and speech-synthesis options for offline authoring of Chinese guides, with separate quality, access, cost and output-rights assessments.

## Scope

Allowed outputs: `docs/reports/chinese/translation-and-voice.md`, evidence JSON, synthetic input/authorized output samples and an isolated optional `spikes/G21.41-chinese-authoring/` evaluation probe. Read the tool registry and actual content/audio format and validation contracts. No production provider integration or narration publication.

## Acceptance criteria

1. [ ] Discover primary Chinese-language provider/project documentation and compare translation and TTS as separate roles. Seek at least two Chinese-provider candidates and one available baseline per role; unavailable candidates/roles carry actual access evidence rather than invented capability scores. Record product/model/version, script/spoken variant, region and API/local-model/export channels.
2. [ ] Use the common ten UI senses, two short synthetic tourism passages and Polish names/diacritics, dates, durations, quantities and pause cases. Label the proposed spoken/register variant. Check meaning/negation/payment promises for translation and pronunciation/naturalness/tempo/pause control for speech independently; record reviewer availability and uncertainty.
3. [ ] Distinguish direct executions from official demonstrations/documentation and blocked evaluations. For permitted runs record input, reproducible parameters, output checksum/format, duration, latency and dated price/unit evidence. Validate sample export against actual KUDY audio requirements, including whether conversion is needed; vendor demos alone do not prove export compatibility or pronunciation quality.
4. [ ] Record stock-voice commercial use, downloadable-file storage/redistribution rights, attribution, data retention/training policy, account/region/payment/API-key requirements, quotas and offline/local feasibility. Use only public/synthetic inputs and approved endpoints; no private guide, secret, account registration, paid run or permission expansion is authorized by this brief.
5. [ ] Read the shared registry before proposing tools and recommend use/defer/reject/owner-decision-required with measured reasons. Preserve unavailable access as an acceptable research result; request no token and install no compulsory MCP. Provide concrete prerequisites and cost caps for any later pilot to G21.42, without treating a provider language list as a quality benchmark.

## Out of scope

Runtime LLM/TTS, production guide recording, bulk text uploads, paid subscriptions, voice cloning, token storage, provider adoption and new accounts.
