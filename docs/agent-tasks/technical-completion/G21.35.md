# G21.35 — Normalize Windows export paths in the document-language gate

## Epic

Epic: #532

## Goal

Correct English exports pass on Windows and Linux, while missing or wrong document languages still fail the build.

## Scope

web/lib/content/exported-language.ts, its behavioral tests and the existing rendered-output scan integration; preserve locale layouts and public-content checks.

## Acceptance criteria

1. [ ] Reproduce the pinned failure before changing code: expectedDocumentLocale("en/app.html") returns en, but expectedDocumentLocale(String.raw`en\app.html`) returns be. The Windows build reports six wrong-document-language violations for correctly rendered English pages; the two exported-language tests fail.
2. [ ] Normalize filesystem separators at the appropriate existing boundary before interpreting the URL locale; search for and reuse an established path helper. Preserve default/shared-404 semantics, registered-locale allowlist, flat and nested export layouts and unsupported-prefix behavior; do not infer language from arbitrary substrings.
3. [ ] Behavioral cases exercise slash and backslash paths for en/app.html, en/index.html, nested guides/stops, root/default pages and shared 404.html. A valid English tree passes; missing lang and en pages declaring be fail with the offending path and expected/actual values. These cases fail when the fix is reverted.
4. [ ] Run the existing exported-language suite, standard Node runner and a real web build/export scan on Windows. Record equivalent focused proof on Linux, or identify a real Linux proof prerequisite rather than claiming an unrun platform. Do not suppress the language scan, leak scan or required checks.
5. [ ] Recheck generated document language and browser navigation for the currently shipped locales; retain the previous #534 user-visible fix. Keep the dated retest historical and write fresh results in docs/agent-tasks/results/G21.35.md.

## Out of scope

Production narration/content, full walk/device-service composition (#491), unrelated features/refactoring, disabling checks, global settings/cache deletion and automatic worker launch.

## Dependencies

Blocked-by: #590, #534

## Proof

node --test --experimental-strip-types web/lib/content/exported-language.test.ts; npm --prefix web run build; controlled-revert separator test.

## Pinned reproduction

```js
import { expectedDocumentLocale } from "./web/lib/content/exported-language.ts";
console.log(expectedDocumentLocale("en/app.html")); // en
console.log(expectedDocumentLocale(String.raw`en\app.html`)); // be; expected en
```

Run with Node's experimental strip-types flag. The issue contains the reproduction; no unavailable local report link is needed to understand it.
