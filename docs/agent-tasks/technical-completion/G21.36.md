# G21.36 — Restore a reproducible Windows Android debug build after cache failures

## Epic

Epic: #532

## Goal

A fresh debug APK builds and launches on Windows without relying on the cached APK, corrupt compiler output or unbounded host resources.

## Scope

Windows Android build/test procedure, scoped build helper configuration if needed, docs/development_setup.md and docs/agent-tasks/results/G21.36.md; no feature, dependency upgrade or broad cache deletion.

## Acceptance criteria

1. [ ] Use the published retest evidence to reproduce or isolate the final :expo-dev-launcher-gradle-plugin:compileKotlin failure: "Failed to clean up output files for task". Record exact SDK/JDK/Gradle/Node versions, commands, resolved build/cache paths and ownership. Earlier host failures include a missing Kotlin classpath snapshot and "The type initializer for System.Net.ServicePointManager threw an exception"; determine which are causal instead of treating memory pressure as a proven cause of every failure.
2. [ ] Identify the locking process, stale-cache state or concurrent build ownership and implement the smallest safe recovery. Bound Gradle/Metro workers and waits where needed; keep native module dependencies and app runtime unchanged. Stop only verified task-owned processes; never terminate other executors or silently weaken build checks.
3. [ ] Any generated-output cleanup validates resolved absolute targets, including junction targets, inside the explicit task-owned Android build/cache root; preserve source, credentials, unrelated caches and recoverable data. Do not run global cache deletion or modify global security settings. Keep diagnostics and cleanup failure visible.
4. [ ] Document a parameterized procedure in docs/development_setup.md that works from the published checkout, using the existing Expo prebuild/Gradle workflow. A successor must not require unpublished scratch files or the original tester's drive layout. Preserve package/lock/config changes caused by tooling for review; do not discard them silently.
5. [ ] Build a fresh debug APK with recorded SHA-256, size, commands and exit 0; install it in the real Android emulator, load the matching source version and run the published native navigation/locale/large-font/background scenarios. Repeat the build to prove the cleanup failure does not return. Record physical-device/iOS/full-walk limits; a cached APK or browser viewport is not fresh native-build proof.
6. [ ] If the available executor has no usable Windows SDK/JDK or native runtime, report blocked-external with the missing prerequisite under issue-workflow.md; do not close this issue with mocks or source-only checks.

## Out of scope

Production narration/content, full walk/device-service composition (#491), unrelated features/refactoring, disabling checks, global settings/cache deletion and automatic worker launch.

Two successful Windows debug builds with logged commands and APK identity, followed by real-emulator navigation/locale/large-font/background results.
