# G21.26 — Reject missing, stale and unreviewed locale messages in the standard checks

## Epic

Epic: #532

## Goal

A source change cannot pass the normal repository/CI checks while any shipped locale is missing, outdated or lacks required review evidence.

## Scope

tools/i18n/check-messages.mjs and behavioral suites wired through the current standard Node test discovery; required-runner proof.

## Acceptance criteria

1. [ ] Validate every shipped locale from the shared registry, not a fixed be/en/uk loop: missing/extra/empty keys, incompatible placeholders/plural forms and mismatched reviewedSourceHash fail with locale/key/reason.
2. [ ] Changing source text/context/parameters while keeping old translation metadata fails. Blindly replacing source hashes without the required review record fails; a valid unchanged translation needs an explicit renewed review and reason, not an automatic blanket bypass.
3. [ ] Reject missing/stale review evidence and required terminology provenance; generator --check also fails if edited data is not reflected in generated output.
4. [ ] Run the actual repository check through the standard test/required CI path, with controlled missing-key, changed-source, missing-evidence and removed-wiring cases. No optional-only green gate and no workflow edit without the repository-required authorization.
5. [ ] A fully reviewed same-commit update across all shipped languages passes. This check proves mechanical completeness/freshness, not semantic translation quality; that remains the recorded review responsibility.

## Out of scope

Production guide writing/narration, unrelated refactoring, runtime translation, premature source adoption/MCP installation and automatic worker launch.
