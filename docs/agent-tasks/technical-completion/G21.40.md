# G21.40 — Prove Chinese glyphs and layouts with app references and a visual probe

## Epic

Epic: #532

## Goal

Show how simplified/traditional Han text can remain readable in KUDY on native and web surfaces, with measured font/fallback behavior and reference observations from Chinese applications.

## Scope

Allowed outputs: `docs/reports/chinese/frontend.md`, evidence JSON/screenshots and an isolated `spikes/G21.40-han-layout/` visual probe. Read actual native font loading/tokens, web style/rendering entrypoints and the language identity contract. Do not change shared production components, approved tokens, locale registries or font dependencies before G21.42.

## Acceptance criteria

1. [ ] Observe at least three named Chinese applications across map/navigation, tourism/cultural audio and a download/access UI. Record platform, version/date, source URL and whether the interface was actually inspected or only official screenshots/docs were available. A missing category has explicit negative evidence and a nearest available reference. Extract behavior observations without copying code, assets or unverified licensed material.
2. [ ] Inspect existing font glyph coverage and at least two feasible font/fallback strategies for both writing candidates, including license, per-weight behavior, regional glyph form, package/subset size and offline loading. Do not infer coverage from a family name or use a Japanese glyph fallback as proof of correct Chinese regional forms.
3. [ ] Build a small synthetic probe for language selection, guide/place card, primary action, unavailable/error state, narrative text, timer and audio identity label. Test Han plus Latin/diacritics/digits, long names, punctuation, line breaks without spaces, narrow 320 CSS-pixel web/equivalent logical native widths and 200% text scaling where supported. No clipped essential action, missing-glyph box or inaccessible unreadable state counts as a pass. Use escape-encoded machine fixtures if required by existing commit guards, render real glyphs and never disable the guards.
4. [ ] Exercise initial font loading, failed/missing font and offline rendering. Capture native Android/iOS and web evidence where runnable, with device/browser/version and observed differences. If a platform is unavailable, mark it not verified and name the remaining device check; a DOM test or font cmap scan is not device proof.
5. [ ] Provide a font/layout recommendation, measured limitations and exact follow-up scope for G21.42. Keep simplified/traditional and regional variants labeled as candidates; the probe does not activate a locale or claim full catalogue coverage. Store generated artifacts according to project rules; apply the Showboat decision rule.

## Out of scope

Product redesign, copying another app, shipping a font/catalogue, expanding locale enums, production guides, external font uploads and permanent installation of new tools.
