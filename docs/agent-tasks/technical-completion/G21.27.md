# G21.27 — Require documented terminology lookup when a translator is uncertain

## Epic

Epic: #532

## Goal

Agent translation rules require evidence for uncertain terminology and prevent fabricated references or unreviewed guesses.

## Scope

Agent translation policy, translation-record provenance schema and offline authoring instructions; approved source decisions from G21.33.

## Acceptance criteria

1. [ ] When uncertain about meaning, wording or a UI term, the agent must look it up in an approved relevant dictionary/terminology source before finalizing. If no source resolves it, mark unresolved and stop publication of that message instead of inventing a translation.
2. [ ] Record source identifier/version or URL, entry/sense locator, chosen term, contextual reason and lookup date; distinguish looked-up evidence, existing reviewed terminology and reviewer judgment. Do not fabricate a lookup or provenance.
3. [ ] Use whole-message context and distinguish noun/action senses such as guide/stop/back; dictionary suggestions never override access/privacy/payment meanings.
4. [ ] Add review-record checks and synthetic policy examples for resolved/unresolved/unsupported references. A provenance field is a trace, not automated proof of semantic correctness.
5. [ ] No runtime LLM or compulsory MCP installation; external entries remain untrusted reference data with license and least-privilege constraints.

## Out of scope

Production guide writing/narration, unrelated refactoring, runtime translation, premature source adoption/MCP installation and automatic worker launch.
