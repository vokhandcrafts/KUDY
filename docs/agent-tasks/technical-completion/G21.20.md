# G21.20 — Approve separate text and audio identity for one guide

## Epic

Epic: #532

## Goal

A reviewed architecture defines mixed-language guide identity, recovery and access without treating a foreign-locale grant as authorization.

## Scope

Language identity ADR, core engine locale/grant constraints, bundle readiness, session snapshots/migrations, feedback attribution; design documentation only.

## Acceptance criteria

1. [ ] Inventory the current single-locale contract: core/engine/reducer.ts builds audio paths from s.locale and rejects grant locales differing from the session. Explain why changing only a dictionary cannot enable fr text/en audio.
2. [ ] Write and obtain explicit approval for a design with separately pinned text and optional audio locale/version. Keep existing single-language sessions readable and preserve progress across restart; choose additive/recoverable persistence changes with a rollback plan.
3. [ ] Define readiness and authorization for each actual text/audio layer, route/version/story mapping and paid tier; a grant for en cannot authorize fr bytes. Missing configuration, unavailable media, malformed cross-language mapping and unauthorized layers deny playback/start safely.
4. [ ] Define feedback experience attribution and analytics minimization without silently changing feedback target semantics or exposing secrets/coordinates.
5. [ ] Specify acceptance cases for fr text/en audio, text-only, same-language, restart, refund/expired grant, unavailable voice and UI switch. No runtime code or migration before written-design approval.

## Out of scope

Production guide writing/narration, unrelated refactors, new runtime translation services, automatic worker launch and unauthorized workflow changes.

## Dependencies

Blocked-by: #533, #550

## Proof

Approved language-identity ADR with concrete field/owner/migration/access mapping and test cases; G21.21 reads this version.
