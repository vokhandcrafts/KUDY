# G20.32 — Offline catalog and free-guide preview persistence

Issue: [#794](https://github.com/vokhandcrafts/KUDY/issues/794). Branch: `chatgpt/794`.

## Scope and storage

The live catalog service uses the existing derived zone-A SQLite `catalog_cache` table through `catalogSnapshotOver`. Only validated, projected list cards and public free-base preview fields (including public stop labels) are serialized. The snapshot is keyed by view kind, route ID and requested display-locale order. The service does not persist raw catalog/index/route documents, media URLs, paid text, credentials, or signed grants. `services/db/db.ts` already owns `rebuildDerived` and preserves zone-B session/history.

Production `controllers/deviceServices.ts` injects the zone-A port over the shared app SQLite driver for a real remote catalog. Demo sources stay bundled and do not use the remote snapshot port. `controllers/createServices.ts` hands the port to the existing service; no UI or download/run policy was reimplemented.

## Acceptance evidence by criterion

1. **Persistence without signed URLs:** `services/catalog/snapshot.ts` accepts only allowlisted public projection fields and supports safe corruption handling. `services/catalog/catalogService.ts` writes a complete validated list and a non-degraded public free-base preview. `services/catalog/snapshot.test.ts` checks SQLite rows and excludes raw story identifiers and HTTPS URLs. **Status: implemented, command not yet verified.**
2. **Offline restart:** the new test closes a file-backed SQLite database, reopens it, creates new real `createServices` controllers with an offline loader and compares list/preview facts. Preview download/Start button is derived again from the existing inventory port (the no-inventory case remains disabled with `preview#storage-unknown`). **Status: implemented, test execution pending.**
3. **Corruption and refresh:** invalid catalog JSON, index hash mismatch and missing route document cannot replace the last valid cached projection. Missing/corrupt SQLite snapshot reports a named non-crashing state; a complete later online fetch rewrites it. **Status: implemented, test execution pending.**
4. **Zone-A purge and demo compatibility:** the test inserts and checkpoints a real durable session, purges derived cache, then asserts the heard/auto-fired arrays survived. It also exercises `createServices` without a snapshot port for the bundled-demo seam. **Status: implemented, test execution pending.**
