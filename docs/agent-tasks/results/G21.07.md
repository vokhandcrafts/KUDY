## Што зменена

Два тэставыя файлы; прадукцыйны код не закрануты.

- `web/lib/content/entry-boundary.test.ts` — дзве пробы магчымасцей хоста
  (узор `tools/corpus/import.test.mjs`, дададзены G20.17/#488): `symlinkProblem`
  (mkdtemp + `symlinkSync` на файл) і `controlNameProblem` (mkdtemp +
  `mkdirSync` імя з кантрольным сімвалам). Пры няўдачы — именаваная прычына з
  `error.code`; пры ўдачы — `null` і тэсты абавязковыя. Скіп-опцыя
  `{ skip: …Problem ?? undefined }` на роўна сямі symlink-тэстах і двух
  кантроль-іменных тэстах; дзве пераносныя назвы-тэсты («bad name», «bad
  locale») без умоў. Фікстура тэсту «a symlinked bundle entry is ignored»
  дапоўнена да паўнавартаснага чужога дрэва (`outside-route/v1/route.json`
  замест голага `route.json`): без гэтага рэверт ахову не выводзіў тэст з
  зелянявы (крытэрый 3).
- `tools/collector/cli.test.mjs` — проба `readonlyDirProblem`: mkdtemp,
  `chmodSync(dir, 0o555)`, спроба запісу; запіс удаўся → хост не выконвае
  біты дазволаў каталога → именаваны скіп тэсту «a rejected run converts to
  the exit-2 diagnostic path (the main().catch guard)». Забаронены запіс
  (норма) → тэст выконваецца без зменаў.

Забароны не аслаблены: ніводна deny-сцвярджэнне не заменена на поспех, ніводны
скіп не спрычынены catch-усякоўным блокам (пробы лоўяць роўна сваю аперацыю),
catch-усякоў файлсістэмных вынятак няма, CI-аховы не мяняліся (`.github/` не
чакана — няма аўтарызацыі; жорсткая мяжа issue-workflow §7).

## Крытэрыі

1. **Рэпрадукцыя дзесяці ззояў.** Выканана на гэтым Linux-хосце на
   нязмененым кодзе (main `0c24e0b`, тэсты з каміта адхілены `git stash`)
   праз LD_PRELOAD-шым `.scratch/g2107-repro/winfs-shim.so` (не каміціцца,
   тэчка git-ігнараваная; крыніца ніжэй): ён мадэлюе тры абмежаванні Windows
   на мяжы libc — `symlink`/`symlinkat` → `EPERM`, `mkdir`/`mkdirat` з
   кантрольным сімвалам у апошнім кампаненце → `EINVAL`, `chmod` дырэкторыі →
   поспех без абмежавання. Вывад паўторна правераны:
   - entry-boundary: **9 fail (усе сем symlink з EPERM ва ўсталёўцы + два
     кантроль-імены з EINVAL), 2 pass** (пераносныя «bad name»/«bad locale») —
     1-у-1 спіс рэтэсту;
   - cli (`--test-name-pattern "a rejected run converts"`): **1 fail,
     `actual: 0, expected: 2`** — INSERT прайшоў, бо chmod не абмежаваў
     каталог.
2. **Пробы ўзоры #488; няўздольны хост скіпае іменавана.** Вывад шым-прагону
   выпраўленага кода (ніжэй): 9 скіпаў entry-boundary з прычынамі
   «symlinks cannot be created on this host (EPERM)…» і «filenames with
   control characters cannot be created on this host (EINVAL)…», 1 скіп cli
   з прычынай «directory mode bits are not enforced on this host…». Спробы
   магчымасці — нічога не прапускаюць на здольным хосце (на Linux усе тры
   пробы даюць `null`) і не мяняюць deny-паводзіны.
3. **Здольны Linux: без скіпаў + падзенне пры рэверце ахову.** Наўтыўны прагон
   (без шыма): entry-boundary **11/11 pass, skipped 0**; cli **13/13 pass,
   skipped 0**. Рэверт-эксперыменты (адзінкавыя часовых патчы прадукцыйных
   файлаў, пасля кожнага `git checkout --`):
   - `requireIdentifier` не кідае → **4 fail** (дзве назвы-тэсты + дзве
     кантроль-імены);
   - кантэйнмэнт каталога зняты (`containedFilePath` без кідка, пакрокавыя
     containment-працягі выдалены, `containedDirNames` ідзе праз сімвальныя
     спасылкі, re-pin індэкса discovery зняты) → **5 fail** (усе каталогавыя
     symlink-тэсты, у тым ліку «evil-route» уваходзіць у каталог праз
     узмоцненую фікстуру);
   - `listFiles` у leak-guard ідзе праз спасылкі (`statSync` замест адмовы ад
     следвання + re-pin) → **2 fail** (абедзве leak-guard-тэсты);
   - `.catch` зняты з `main()` у `tools/collector/collector.mjs` → **1 fail**,
     працэс гіне на неапрацаваным адмове (exit 1 без прэфікса), што і
     фіксуе каментар тэсту.
4. **Windows: пераноснае падмноства + именаваныя скіпы.** Свежага прагону
   дзвюх мадыфікаваных сют на рэальным Windows у гэтай сесіі няма: даданне іх
   у job `windows-portable` — змена `.github/workflows/required-checks.yml`,
   забароненая без асобнай аўтарызацыі. Факты для Windows: (а) рэтэст
   2026-10-03 прагнаў абодва сюты на рэальным Windows — пераносныя тэсты
   праходзілі там (у пераліку збояў з дзвюх сют толькі дзесяць вышэй); (б)
   шым-прагон паказвае іменаваныя скіпы і пераносную зеляняву, якія атрымаў
   бы няздольны хост (вывад ніжэй). Прычына скіпаў называе абмежаванне і шлях
   яго зняцця (Windows: elevated shell або Developer Mode); catch-усякоў няма,
   CI-аховы не аслаблены.

## Крыніца шыма (`.scratch/g2107-repro/winfs-shim.c`, не каміціцца)

LD_PRELOAD-модуль: `symlink`/`symlinkat` → `EPERM`; `mkdir`/`mkdirat` з
кантрольным сімвалам (< 0x20) у апошнім кампаненце шляху → `EINVAL`; `chmod`/
`fchmod`/`fchmodat` дырэкторыі → 0 без змены рэжыму. Астатняе — праз
`dlsym(RTLD_NEXT)`. Кампіляцыя: `clang -shared -fPIC -O2 -o winfs-shim.so
winfs-shim.c`. Праверка адпрацоўкі перад прагонам: без шыма symlink і
кантроль-імена ствараюцца, chmod дае EACCES на запіс; з шымам — EPERM /
EINVAL / запіс удаецца.
