## Што зменена

- `supabase/functions/deno.json` — канфіг асяроддзя праверкі:
  `nodeModulesDir: "auto"` (Deno сам ставіць pinned npm-залежнасці з lock),
  `lock: true`; нічога не выключана з праверкі, strict-рэжым па змоўчанні
  не паслаблены.
- `supabase/functions/.deno-version` — адзіны ўладальнік версіі рантайма
  (`2.9.7`, апошні стабільны на 2026-10-02). Яго чытаюць і check-скрыпт, і
  workflow (`deno-version-file`), таму CI і лакальная праверка не разыходзяцца.
- `supabase/functions/deno.lock` — замарожаны граф залежнасцей (адзіная
  вонкавая залежнасць прадукцыйнага графу — `npm:postgres@3.4.9` з
  integrity-сумай); праверка бяграе з `--frozen-lockfile` — састарэлы або
  адсутны lock дае адмову.
- `tools/ci/deno-typecheck.mjs` + `npm run server:typecheck` — enumerate
  `supabase/functions/*/index.ts` (ноль энтрыпоінтаў = fail-closed), пошук
  рантайма (`KUDY_DENO` або PATH), сравненне версіі з пінам, `deno check
  --frozen-lockfile` па энтрыпоінтах; рэжым `--file` для фікстуры. Fail-closed
  на кожным адсутным уваходзе; сакрэтаў не патрабуе.
- `supabase/functions/_fixtures/deno-async-mismatch.ts` — комітованая
  фікстура A26-01 (гл. крытэр 3).
- `tools/ci/deno-typecheck.test.mjs` (новы glob `tools/ci/*.test.mjs` у
  `npm test`) — паводзінны тэст: fail-closed брамы і жывыя прагоны.
- `tools/ci/check-required-checks.mjs` — рэверт-гвард: страта скрыпта,
  workflow-job або SHA-піна setup-deno робіць гвард чырвоным.
- `.github/workflows/required-checks.yml` — producing job `server-typecheck`
  (аўтарызавана праз #493); `denoland/setup-deno` замацаваны правераным
  поўным SHA `22d081ff2d3a40755e97629de92e3bcbfa7cf2ed` (v2.0.5, рантайм
  node24; SHA рэшаны праз GitHub API, не «згаданы»); старыя тэгі
  checkout/setup-node — зона G20.27.

## Тыповыя фіксы ў прадукцыйным кодзе (першае ўключэнне чэкера)

Root `tsconfig` выключае `supabase/`, таму гэты граф ніхто калі не правяраў
тыпамі; першы прагон даў 8 памылак. Усе выпраўленыя ў гэтай задачы — без
выключэнняў файлаў і без кастаў вакол async-містчыкаў:

- `device-wire.ts` — `DeviceSqlClient.unsafe` аб'яўляе рэальны дамейн
  параметраў (`(string | number | boolean | null)[]` замест недасяжнага
  `readonly unknown[]`): сапраўдны `postgres.Sql` цяпер структурна задавальняе
  інтэрфейс (дакументаваная заява стала праўдзівай), рэтра-фейкі тэстаў
  сумяшчальныя.
- `events-core.ts` — `EventSqlRunner.query` прымае толькі прымітыўныя
  параметры (pinned выказванні будуюць іх на месцы); `params` уставак
  тыпізаваны як `string[]` (усе пуш-ы — радкі); `EventTableFieldSpec.const`
  — `string | number` (як у JSON Schema: радковыя і цэлалікавыя палі).
- `rc-webhook-core.ts` — `typeof type === 'string'` перад `Set.has`
  (невядомы тып і раней даваў false, паводзіны не змяніліся).
- `events/index.ts` — адаптар копіюе прымітыўны спіс у новы зменлівы масіў
  для драйвера (без каста); JSON-імпарт кананічнай табліцы — `as unknown as
  EventTableSpec` з каментаром-спасылкай на `contracts/events/event-contract.test.mjs`
  (машынная праверка формы ў стандартным наборы; гэта мяжа-рэстэйтмент, не
  async-каст).
- `grant/index.ts` — `requestDeps` прымае `ResolvedConfig` (ён і ёсць
  фактычны тып; `revenueCatSecret/Base` існуюць толькі на ім); `headers` у
  `serialize` анатаваны `Record<string, string>` (union з `?: undefined`
  не праходзіў індэкс-сігнатуру).

## Па крытэрах

1. **Энтрыпоінты пералічаныя, чэк пакрывае іх імпарт-граф; без выключэнняў
   і кастаў вакол async.** Энумэрацыя — `*/index.ts` пад
   `supabase/functions/`: `device`, `events`, `grant`, `rc-webhook` (4);
   ноль знойдзеных = fail-closed. Тэст «the fixture is not part of the
   production enumeration» фіксуе дакладны спіс, фікстуры (`_fixtures/`,
   `_shared/`) не энумэруюцца. 8 знойдзеных памылак выпраўленыя (раздзел
   вышэй), паўторны прагон зялёны.
2. **Піннаваны рантайм/залежнасці, без сакрэтаў; адсутнасць уваходаў
   fail-closed.** Версія — `.deno-version` (2.9.7), параўноўваецца з
   `deno --version`; drift → выхад 1. Залежнасці — `deno.lock` +
   `--frozen-lockfile` (адсутны lock → адмова; праверана жывым прагонам з
   пераназваным lock). Сакрэтаў няма: чэк чыстае тыпы, не злучаецца з базай.
   Жывыя дэма-блокі гл. showboat-дэму.
3. **Фікстура A26-01 дае ненулявы выхад; чыстыя энтрыпоінты праходзяць.**
   Фікстура `supabase/functions/_fixtures/deno-async-mismatch.ts` чытае
   `db.unsafe(...)` як гатовы радок (той самы клас
   `[key: async-sql-result-not-awaited]`); чэк адказвае `exit 1` з адной
   іменаванай дыягностыкай TS7053 «can't be used to index type
   'PromiseLike<ArrayLike<unknown>>'». Чысты прагон — `exit 0`. Абодва —
   камітованыя тэсты + блокі дэмы.
4. **Producing job у абавязковым workflow; бачнасць branch protection —
   запісаная як неразвязаная; абарона не мянялася.** Job `server-typecheck`
   дададзены ў `required-checks.yml` (аўтарызацыя #493); ён вяртае
   зелёны/чырвоны статус коміту. Рэверт-гварды: страта скрыпта → гвард
   `FAIL — package.json has no server:typecheck script`; страта job-а →
   `FAIL — required-checks.yml does not run server:typecheck` (+ пра SHA-пін);
   абодва эксперыменты выкананыя ў сесіі адпраўкі, аднова — зялёная.
   Бачнасць у branch protection з гэтай сесіі не правяраецца (няма
   admin/read:project scopes) — **не лічыцца аўтаматычна пройдзенай**; дадаць
   `server-typecheck` у required statuses — крок аператара
   (`docs/human-actions.md`).

## Межы і не праверанае

- Жывы Supabase-runtime (`Deno.serve` на дэплоі) — not-run да дэплою
  (прэцэдэнт G08.01/G08.02); тыпавая праверка не замяняе прыёмку на
  рантайме.
- На CI job `tests` (npm test) без Deno скіпае два runtime-тэсты з бачнай
  прычынай; рэальны чэк на CI бяжыць у асобным job `server-typecheck`, дзе
  Deno ўстаноўлены піннавана.
- Змена версіі Deno: абнавіць `supabase/functions/.deno-version` і пры
  неабходнасці `deno install --entrypoint …` для `deno.lock`; усе іншыя
  спажыўцы піна (скрыпт, workflow, гвард) чытаюць той самы файл.
- Showboat-дэма:
  [2026-10-02-g2013-deno-typecheck.md](../../demos/2026-10-02-g2013-deno-typecheck.md);
  `uvx showboat==0.6.1 verify` — выхадны код 0.
