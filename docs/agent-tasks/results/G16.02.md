## Contract decisions (single mapping points)

- Target key: `formatTargetKey`/`parseTargetKey` — canonical sorted-key JSON of `{id, kind, locale, version}` (the PK must be byte-stable across restarts). The wire object (`kind` + `route_id|place_id` + `version|content_version` + `locale`) maps at the sync's `toWireTarget`; the server's canonical key columns are `feedback-core.ts` `FeedbackTargetKey`.
- Draft JSON (`feedback_local.draft`): `{op:'put', score, reasonCodes, disclosureVersion}` | `{op:'delete'}` — camelCase, this module's own serialization; the snake_case wire body is built only in `feedbackSync`.
- Outbox payload: the desired value without the disclosure (the `disclosure_version` column is its single carrier).
- Retry bookkeeping lives in the outbox row (`attempts`, `next_attempt_at`); reconfirmation re-arms the SAME mutation id and restarts its seven-day window by moving `created_at` — the idempotent replay is what answers the unknown server outcome.
- The retry schedule is the `21` §5.4 ladder verbatim — «backoff 2, 4, 8… секунд, мяжа 5 хвілін, з jitter» — as `nextDelayS`: the ladder jittered by a factor derived from the mutation id (stable per mutation, so evidence stays byte-reproducible; different across targets, which staggers herds) and hard-capped at 300 s. A server-sent Retry-After is honored as given (clamped to the cap) — the server asked for that exact wait.
- Structural validation only client-side (score 1..5, ≤3 unique reason strings, locale/version patterns copied verbatim from `feedback-core.ts`); the registry allowlist and the closed reason-code lists stay the server's authority.

## Acceptance walk (issue card, line by line)

1. **Restart never creates duplicate counts or changes target version/locale** — `queue-durability` restart test (close/reopen, same mutation delivered once, target key asserted unchanged) + `queue-sync` crash-recovery test (same mutation id retried, one record).
2. **Late ACK cannot erase a newer draft** — repository edit-while-flight tests + sync late-duplicate test: the newer desired value flows as the follow-up against the acknowledged revision; a duplicated response of the consumed mutation is dropped (`applied:false`, state untouched).
3. **Delete during an uncertain send is resolved then deleted, not falsely marked complete** — `delete-acknowledges-send` branch keeps the in-flight PUT, stores `{op:'delete'}` as the next desired value, and only after its ACK queues the CAS-delete tombstone (`queue-repository` + `queue-sync` delete tests).
4. **401 does not auto-register a device and replay historical feedback** — the sync is inert without an identity (`skippedNoIdentity`), a 401 stops the mutation as `action_required`, the secret box counters prove zero `saveSecret` calls, and further flushes dispatch nothing.
5. **Cache rebuild preserves drafts/outbox; device deletion cancels them without removing downloaded content** — `rebuildDerived ×2` leaves the draft, the acknowledged value and the queue intact (rows, not only tables — the table-level guard already lives in `db.test.ts`); `clearDeviceAccountState` empties both feedback tables while bundle assets and the session row stay.

Task-file steps 1–5 map onto the same suites (step 1 = the crash/ACK-window tests; step 2 = the transactional write + discovery separation; step 3 = one-in-flight index + waiting edits; step 4 = outcome mapping incl. Retry-After/backoff/7-day; step 5 = device-delete + late-response guards + cache-purge proof).
