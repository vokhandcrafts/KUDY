# G20.35 — Аднаўленне кананічнай затрымкі і ахова паўзы

Дата: 2026-10-29. Задача: [#815](https://github.com/vokhandcrafts/KUDY/issues/815).

## AC1 — кананічная канфігурацыя

У `controllers/deviceServices.ts` вытворчая кампазіцыя перадае ў Run `defaultPipelineConfig` з `core/pipeline/pipeline.ts` замест асобнага `{ dwellMs: 0 }`. Лікавае значэнне не дублюецца; фільтры дакладнасці, хуткасці і згладжвання не змяняліся.

## AC2 — кантроль часу і радыуса

`controllers/deviceServices.integration.test.ts` стварае сапраўдныя `createDeviceServicePorts`, `createServices`, Run controller і pipeline; падмененыя толькі межы АС (геалакацыя, аўдыё) і гадзіннік. Правяраецца адсутнасць запуску на першай кропцы і да парога, адзінае спрацоўванне на парозе, выхад за радыус і паўторнае назапашванне часу пасля вяртання. Адкат `pipelineConfig` да нуля павінен парушыць праверку перад парогам.

## AC3 — актыўны кантроль паўзы

Актыўная прагулка атрымлівае паслядоўнасць фіксаў, пры якой павінна запусціцца гісторыя. Тая самая паслядоўнасць пасля `pauseSession()` не павінна запускаць гісторыю; дадаткова правяраецца зняцце GPS-падпіскі. Гэта тэсты праз вытворчыя кантролеры, не асобная імітацыя функцыі `dwell`.

## AC4 — Android і стан праверак

- **Android / эмулятар: NOT RUN.** Уладар запатрабаваў не запускаць эмулятар; фізічная прылада праз даступныя інструменты не падключаная. Прыладавае пацверджанне паводзін застаецца адкрытым.
- **Node integration / npm test / typecheck / arch:check / jscpd / engine:regressions: NOT RUN.** Лакальны `KUDY Local MCP` двойчы вярнуў `UNAVAILABLE: MCP SSE probe returned 429 from openai.org`. GitHub App дазволіў чытаць і каміціць код, але не запускае лакальныя каманды.
- **Revert experiment: NOT RUN** праз тое самае абмежаванне.
- **Showboat: NOT CREATED / NOT VERIFIED.** Гэты выпраўлены runtime-баг патрабуе Showboat паводле `docs/agent-rules/showboat.md`, але `uvx` і `showboat verify` недаступныя без лакальнага выканання.
- **Самаправерка:** звераны код з задачай #815, кананічнай `defaultPipelineConfig` і шляхам `LocationService → RunOrchestrator → acceptFix → step`; гэта не замяняе фактычны прагон.

## 2026-10-30 — заўвагі рэв’ю PR #903

- Аддзялілі файлавую сістэму кожнай кантраляванай прагулкі ад агульнага fixture G20.20. Гэта ліквідуе ўзаемнае забруджванне загрузак у тэстах.
- Абнавілі G21.21: геалакацыя і вытворчы Run карыстаюцца адным кантраляваным гадзіннікам, а паслядоўнасць фіксаў ахоплівае кананічныя шэсць секунд.
- У `RunOrchestrator` скідваецца стан pipeline пасля паспяховай Pause і Resume, таму ранейшы dwell і час перапынку не дадаюцца да першага фіксу адноўленай прагулкі.
- Кампазіцыйны тэст правярае частковы dwell, адлучэнне GPS, вяртанне і новыя шэсць секунд да запуску. Асобны тэст reducer перадае `DwellCompleted` у Paused непасрэдна праз `step()`, маючы актыўны станоўчы кантроль. Выдаленне аховы фазы павінна змяніць `autoFired` і зламаць тэст.

**Стан праверак пасля праўкі:** лакальны запуск Node, typecheck, поўнага `npm test`, `arch:check`, `jscpd`, адкатаў і Showboat **не праведзены**. Лакальны MCP адхіліў запуск `node --test` з паведамленнем `Project tree is too large to verify sensitive-path masks safely`. На момант запісу GitHub API не вярнуў workflow runs/statuses для апошняга SHA; гэта не лічыцца паспяховым CI. Перад merge патрэбныя фактычныя зялёныя абавязковыя праверкі і незалежнае станоўчае рэв’ю. Android-эмулятар не запускаўся паводле ўмовы ўладара.
