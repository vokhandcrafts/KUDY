## What was decided

- **Форма кораня.** `createServices(ports)` вяртае `Services`, дзе член існуе толькі калі дадзены яго порт: сення гэта `contentRepo` (сев `PackageStore` з G04.03). Так `Services` люструе рэальнае, што корань можа канструяваць, і не абяцае сэрвісаў без партоў. `db` наўмысна не ўваходзіць: яго API — функцыі над `driver` (G04.01), яўны ўладальнік сесійнага радка — `useRunController` (G05.05) — і прыладны драйвер (TR-10); член з'явіцца з уласнай задачай, у кораня няма мёртвых абгортак.
- **Порты як параметры, не адзінката.** App-шлях: `app/_layout.tsx` → `createServices(devicePorts)` адзін раз (`useMemo []`) → `ServicesContext` + экспартаваны `useServices()`. Фэйкаў у app-білдзе няма: пакуль адаптары не прыйшлі (G05.02.c/G05.03.b/TR-10), порт-набор пусты і `Services` пусты — гэта сумленны стан, задакументаваны каментарам у `_layout`.
- **Ad-hoc тыпы без прыдуманых імёнаў.** Межа `services/` ↔ кантролер апісаная праз `NonNullable<Services['contentRepo']>` і сапраўдныя кантрактныя тыпы `EvaluateInput`/`Readiness` з `services/contentRepo/types.ts` — ніякага пераказу канону `19` §3.5 уласнымі інтэрфейсамі (правіла 2).
- **Хэлпер стора.** Адзіны імпарт zustand у кантролерах — `createControllerStore` (vanilla) + `useController` (React): фабрыка ганіцца ў node без React, хук дае экранны шлях; `useSampleController` паказвае пару. Контролер пішацца аднойчы і працуе і ў app, і ў тэсце (мэта issue).
- **tsconfig — адно свядомае адхіленне.** Root `tsconfig.json` атрымаў `"allowImportingTsExtensions": true`. Прычына: `controllers/` бярэ яўныя `.ts`-спецыфікатары (іх патрабуе `node --test --experimental-strip-types`), а root tsc працягвае правяраць `controllers/` праз імпарт з `app/_layout.tsx` — без сцяга гэта TS5097. Прэцэдэнты: `services/` (G04.03) па той жа прычыне; root tsc заўжды `--noEmit`, таму сцяг законны. Гард — `controllers/wiring.test.ts`, адкат правераны.
- **`tsPreCompilationDeps` наўмысна НЕ ўключаны.** З ім type-only імпарты ўваходзяць у граф, але скан дае 2 новыя no-cycles запісы (`web/lib/i18n/be.ts`/`en.ts` → `index.ts`) — а брыф забараняе новыя baseline-запісы. Правіла `controllers-services-type-only` пакідае дазвол `dependencyTypesNot: ['type-only']`: сёння value-імпарты ловяцца, type-only не трапляюць у граф; калі сэмантыка зменіцца — правіла застанецца карэктным. Задакументавана ў `tools/arch/README.md`.
- **Правілы названы па ідыёме рэпазітара** (`app-no-core` сіметрычна да `app-no-services`; `controllers-services-type-only` кажа сам за сябе), кананічныя крыніцы — у каментарах канфіг і ў табліцы README.

## Acceptance criteria — паводле карты issue

1. ✅ Кампазіцыйны корань — адзіны модуль, што канструюе сэрвісы: па-за коранем (`controllers/createServices.ts`) і тэстаў усе імпарты `services/` — type-only. Правіла `controllers-services-type-only` (allowed/forbidden з `dependencyTypesNot: ['type-only']`); наўмысны value-імпарт з кантролера — exit 1 з назвай правілы (сэндбокс-тэст + дэма); `app/` увогуле не дакранаецца `services/` (`app-no-services`, G06.09.a).
2. ✅ Порты — яўныя параметры: той самы `createServices` збірае app з device-партоў (`app/_layout.tsx`) і Node-тэст з фэйкаў; тэст ганіць кантролер-узор канцом: порт → сапраўдны `evaluatePackage` над сінтэтычным пакетам → стан сторы (`ready`, `tierAvailable ['base']`), без React і React Native.
3. ✅ Кожнае правіла Allowed outputs мае фікстуру-парушэнне, якую `arch:check` адхіляе з назвай: `app-no-services`, `app-no-core`, `controllers-services-type-only`, `services-zone-closed` (services → controllers), `core-zone-closed` (core → controllers); станоўчы сэндбокс (type-only імпарт + корань + controllers → core) праходзіць. Усё — у дэме.
4. ✅ Экраны — заглушки G06.09.a без зменаў (толькі `_layout.tsx` пашыраны); ніводны экран не імпартуе `services/` і `core/` — мацуецца правіламі `app-no-services`/`app-no-core` на рэальным дрэве (`arch:check` OK).
5. ✅ `npm run typecheck`, `npm test`, `npm run arch:check`, `npx expo-doctor` — зялёныя (свежыя лічбы ў Checks); пін стора дакладны (`zustand` `5.0.15`) і запісаны ў ADR G00.04 §6.
