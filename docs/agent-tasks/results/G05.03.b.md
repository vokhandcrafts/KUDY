The device implementation of the G05.03.a player port on expo-audio, delivered as
`services/audio/expo/` (the brief's only code output): `status-mapping.ts` (pure
mapping from expo-audio `AudioStatus` + the adapter's command ledger to the port's

## Acceptance criteria — walked from the card

1. ✅ **The adapter implements the G05.03.a port exactly; status mapping tested on
   synthetic statuses, including an interruption (→ focus loss, never finished), an
   error status (→ failure with reason) and NaN / zero durations.** The adapter
   implements every member of `AudioPlayerPort` one-to-one and echoes the play
   command's source key on source-scoped events (the tagged-callback idiom, G05.03.a
   `types.ts`). The mapping suites (`status-mapping.test.ts`, 8 tests) drive the
   mapper with fully-populated synthetic `AudioStatus` objects: an uncommanded
   playing→paused transition maps to `{type: 'focus-loss'}` (asserted never
   `finished`), the output returning maps to `focus-regain`, and the launch still
   finishes naturally after the interruption; a source that reported loaded and then
   unloaded maps to `failed` with the reason quoting the player's `playbackState`;
   a NaN duration passes through the snapshot conversion verbatim and the service
   guard (G05.03.a `snapshotProblem`, driven through `AudioService` +

## Canon notes — decisions recorded (no shared doc edited)

- **expo-audio 1.1.1 has no error field — checked, not assumed.** `AudioStatus`
  (node_modules/expo-audio/build/Audio.types.d.ts) carries no error surface, and on
  Android the player is ExoPlayer whose error state is `STATE_IDLE` — the same
  state a fresh player starts in (android/src/main/java/expo/modules/audio/
  AudioPlayer.kt, `playbackStateToString`; `didJustFinish` is mapped from
  `STATE_ENDED` on every tick). The mapper therefore discriminates a failure by a
  was-loaded flag (loaded → unloaded = failure with the `playbackState` in the
  reason) and settles the launch after finished/failed so repeated ENDED ticks
  cannot re-fire the event. Real error-path behaviour on a device stays with the
  «Call / other audio» and file-repeat cells above.
- **No focus events are synthesized for a settled launch.** After finished/failed
  the physical player reports no more transitions (ended or dead), and focus facts
  belong to a live launch; the mapper maps settled ticks to nothing. The service
  still forwards focus events verbatim whenever the adapter emits them.
- **The lock-screen walk stops at the boundary** instead of wrapping: no canon line
  fixes wrap-vs-stop (`09` §6.3 says only «locked прапускаецца без змены
  прагрэсу»), and stop is the conservative reading — a repeated next at the end
  selects nothing rather than jumping to the head.
- **The composition root is not edited.** The brief's allowed outputs exclude
  `controllers/` and `app/`; the adapter plugs in through the port parameter of
  `createServices` (the composition root's own contract from G06.09.b), and the
  `Services.audio` member arrives with the task that wires the controller sink
  (G05.05), as the G06.09.b results prescribe. Note for that task: `app/` cannot
  import the adapter directly (`app-no-services`), while `app/_layout.tsx` comments
  that «the app build passes device ports» — the wiring task must resolve this
  consciously (e.g. a root-side factory in `controllers/`, or a documented
  exception in the arch config), not silently.
- **LUFS loudness normalisation (−16 LUFS, `09` §6.3) is out of scope** per the
  brief — it applies to the recordings, not the player; no backlog row owns it yet.
  **Follow-up for the backlog owner:** add a row owning recording-level loudness
  normalisation to −16 LUFS.
