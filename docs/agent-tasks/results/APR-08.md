# APR-08 — дасье Data safety, location і foreground services

Дата праверкі: **2026-10-22**. Задача: [#811](https://github.com/vokhandcrafts/KUDY/issues/811). Эпік: [#299](https://github.com/vokhandcrafts/KUDY/issues/299). База: main на момант стварэння галіны codex/811. Тып: агляд зыходнікаў і дакументальны чарнавік, **не Play Console submission**.

## Мяжа доказу

Ніжэй «К» = пацверджана ў названым code/config; «М» = захаваны вынік release-маніфеста APR-02 (2026-10-18), але не новы production AAB; «Н» = патрабуе знешняй праверкі ў runtime, SDK/Play Console або карыстальнікам. Ніводнага перахопу трафіку production-зборкі, праверкі SDK sandbox, чытання production БД, Play Console screenshot або новага Android відэа падчас APR-08 **не было**. Не лічыць адсутнасць выклікаў у пошуку доказам, што native SDK нічога не адпраўляе.

Паведамленні ў часе праверкі: #804 (APR-06) і #805 (APR-07) закрытыя; рашэнне APR-07 у [ADR](../../architecture/decisions/APR-07-device-data-deletion.md) ёсць; пэўны зацверджаны APR-06 ADR/здымак disclosure ў апублікаваных файлах не знойдзены. Пры ўнясенні формы абавязкова праверыць сапраўдны Android UX. Google Play патрабуе ўліку ўсіх варыянтаў актыўных зборак, а не толькі гэтага здымка source.

## 4. Location + Foreground Service declarations

**Background location — адна галоўная функцыя (чарнавік на англійскай):**

> KUDY plays location-triggered audio-guide stories during a user-started city walk. When the screen is locked or the app is not visible, background location enables the next story to start near its stop without repeatedly unlocking the phone. The user starts the walk and can pause or end it; this stops the location subscription. Exact GPS fixes are used for trigger decisions locally and are not fields of the KUDY event log. Online map tile requests to OpenFreeMap may reveal the viewed map area.

Перад фактычнай падачай праверыць UX: source adapter requestPermission('background') зараз выкарыстоўвае OS requestBackgroundPermissionsAsync, а параметр explanation не паказвае; тэкст app.json не замяняе prominent **in-app** disclosure. Google патрабуе disclosure да runtime prompt, згадванне background location і адзін скразны сцэнар у відэа. Планавае відэа (пажадана каля 30 секунд): Start → поўны in-app disclosure і дзеянне карыстальніка → OS permission → Run → згарнуць/заблакаваць экран → synthetic route fix і бачны вынік autoplay → вярнуцца → Pause/End, FGS notification спынілася. Няма гэтага запісу ў гэтым PR.

**FGS location** (draft): User-started walk maintains a location foreground service while in progress to trigger a nearby story with the screen off. If delayed/interrupted, automatic triggering may pause; visible manual playback remains the fallback. Start/Resume activates the subscription after grants, Pause/End releases it. Android notification configured in app.json. Трэба паказаць сапраўдны notification/start-stop/screen-off behavior у native video, а не толькі код.

**FGS mediaPlayback** (draft, НЕ сцвярджаць, што запускаецца): Playback of narrated guide audio may require continued operation with the screen locked. The release manifest declares the unexported AudioControlsService and FOREGROUND_SERVICE_MEDIA_PLAYBACK, but current adapter activation of lock-screen/mediaPlayback service has not been verified. У полі «using this service» нельга апірацца толькі на manifest; пасля runtime даследавання альбо выканаць FGS-specific video, альбо ўдакладніць непатрэбную дэкларацыю з уладальнікам Android.

**FGS microphone**: не ўжываецца ў правераным release manifest APR-02, AudioRecordingService выключаны. Не падаваць асобную microphone FGS як актыўную толькі з-за Expo залежнасці.

Кожны выкарыстаны FGS type у Play мае асобныя функцыю, уплыў затрымкі/спынення і відэа. Вынікі прынятыя ў праекце APR-06 патрэбна звесці з рэальным release UX перад публікацыяй; закрыццё issue #804 само па сабе не стварае Android відэадоказ.

## 5. Перадача ў #299 і чалавечыя доказы

1. Атрымайце **production AAB** і яго merged release AndroidManifest, package/SDK inventory з версіямі і SHA (APR-01 / #806); не падмяняць дэма release APK.
2. На Android release з Google Play Services запішыце два безасабовыя трафік-логи: карту з follow і без яго (OpenFreeMap); запыты backend/RC/Play з выдаленымі токенамі, ідэнтыфікатарамі, IP і каардынатамі. Звярніцеся да privacy/Data safety guidance RevenueCat, OpenFreeMap, Expo і Google; аддзяліце тэхнічны факт ад палітыкі правайдара.
3. Праверце runtime disclosure з #804 і native screen-recording на permission prompt, start/pause/end, notification, screen-off/lock-screen аўдыё і fallback; папраўце flow у асобнай задачы, калі адлюстраванне не адпавядае рашэнню.
4. Пасля #835/#836 праверце кнопку My KUDY, status пасля 204/403/offline/restart, feedback і queues, адрозніце provider-side delete ад KUDY delete. Пераправерце ўсе 9 privacy моў.
5. Для [#849](https://github.com/vokhandcrafts/KUDY/issues/849) пацвердзіце production scheduled retention, час апошняга паспяховага прагону і alerts, без сырых даных.
6. У Play Console (уладальнік #299) звярце ўсе Data safety rows, user-data/encryption/deletion fields, background location і кожны FGS type; зніміце скрыншоты ўведзеных **фактычных** значэнняў, статус адпраўкі і Google review result.
