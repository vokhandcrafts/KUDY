- What: new `dispatch` subcommand and `tools/collector/dispatcher.mjs` — a

  `--port` override) rendering the «Агляд» page: campaigns with record counts

## Proven (criteria of issue #369)

1. **Loopback-only server, port default + override, busy-port diagnostic** —
   `startDispatcher` binds `127.0.0.1` (test asserts `dispatcher.address ===
   '127.0.0.1'`), `DEFAULT_PORT = 8767` pinned by test, `--port` validated
   (1–65535; `abc`/`0`/`65536` → exit 2 with `invalid --port`). A busy port
   rejects with `port N is already in use — choose another with --port`;
   the CLI's existing `main` catch turns it into the exit-2 diagnostic —
   no stack trace.
2. **Read-only server** — structural: `new DatabaseSync(dbPath, { readOnly:
   true })`, no write statements on the request path. Guard test
   «no request writes to the database or the snapshots tree»: sha256 of the
   DB file and the snapshots tree listing are byte-identical after fetching
   `/`, a media file, a traversal attempt and an unknown path; an absent
   snapshots dir stays absent (openStore's mkdirSync would create it —
   reverting to the writable open turns the test red).
3. **«Агляд» page** — test «overview page shows per-campaign counts and
   journal diagnostics» fetches the real server (fixture DB: two campaigns,
   records in every status, a media row, a failed seed step with
   `HTTP 503`, a failed youtube step with the yt-dlp diagnostic) and asserts
   the Belarusian counts row, photo/failed columns, and the diagnostics
   column; a populated page does not show the empty banner.
4. **Empty states, not 500** — missing DB file and missing snapshots dir:
   the page renders «Яшчэ нічога не сабрана — запусціце run --campaign …» and
   «Журнал пусты.» with status 200; the server creates nothing on disk.
   A store file that exists but cannot be queried (a zero-byte file, a foreign
   schema) answers a named `dispatcher: …` 500 diagnostic within a bounded
   time — the body is computed before the response head is written, so the
   hang regression found in review (writeHead before render) turns the
   bounded-timeout test red.
   An existing but unusable DB file stays fatal for the CLI (exit 2,
   README's «непрыдатны --db» convention).
5. **No URL escape from the data dir** — the `/media/…` route resolves
   through `resolveStaticFile` (root + platform-separator containment).
   Raw-path tests: literal dot-segments are normalized by the URL parser
   (404), encoded slashes survive it and reach the guard, which answers
   «шлях выйшаў за межы тэчкі даных»; corrupt percent-encoding (`/media/%zz`)
   is a 404, never a thrown URIError; mutation check — replacing the guard
   with a bare `join` turns the suite red, restoring it green.
6. **node:test boots the server and fetches the page; red on revert** —
   `tools/collector/dispatcher.test.mjs` (9 tests, covered by the existing
   `tools/collector/*.test.mjs` npm-test glob) reaches the production
   entrypoint `startDispatcher` over real HTTP; every assertion is on
   rendered content or server behavior, so removing the feature (or any
   single guard: containment, read-only open, loopback bind, default port,
   body-before-head order) turns a named test red.
