## Shared invariants honored

No runtime LLM, weather engine, public ratings, user-profile inference or rating-based ranking (the module reads none of them); no new GPS/player owner (zero imports, no platform access); no paid-content disclosure (index offers carry previews only; the selector returns ids/reasons, never content); a collection is data here — it cannot start a Run or create an entitlement (the selector has no side effects); unknown locale/time/season is never silently accepted as a match (fail-closed gates, labeled differences).

## Interpretation decisions (documented for review)

- `reasons` on both exact and alternatives: `editorial` always (index membership is the author's pick, `20` §1); `theme_match`/`within_time`/`season_recommended` mirror each passed explicit gate. Differences carry the full explanation for alternatives.
- `differences` emission order is fixed (§4 union order) so the label list is deterministic.
- Corrupt offer fields (non-object `ref`, missing `availability`, non-integer `editorial_order`, corrupt duration, non-array `themes`/`season_recommendations`) degrade fail-closed with diagnostics-in-data (exclusion or a labeled difference), never a throw (implementation-rules 14). Corrupt *criteria* fail closed the same way (review round 1): a malformed `max_minutes` cannot prove any offer within time and a non-array `theme_ids` cannot prove a theme match — each offer stays a labeled alternative (`duration_unknown` / `theme_mismatch`) and nothing becomes exact, so the core never widens a malformed or a valid query. Rule 1 of `21` §4 keeps criteria validation at the controller boundary; both behaviors are pinned by isolating revert-guards.
