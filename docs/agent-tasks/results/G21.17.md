# G21.17 result — Filter guides by UI text language and keep chrome independent

Date: 2026-10-04 (claim [2026-10-04T15:05Z](https://github.com/vokhandcrafts/KUDY/issues/551#issuecomment-5980381792)). Branch: `zcode/551` from main `a46d39d`.

## What was done

The content-selection boundaries now show only guides whose published text covers the selected UI language, and the run chrome stays pinned to the active session:

- **The one selection rule** — `offerShownInTextLocale(textLocales, uiLocale)` in `components/guide-card.tsx` (the zone the screens import): the projection filter of the city catalog view (ready and offline lists) with the two honest empty states — the new `textLocaleEmpty` explanation when other languages have guides, NAV3's `notPublished` when nothing is published at all. The Nearby list filters the same way (`app/map.tsx`), with the same empty distinction. The discovery selector applies the same gate over the criteria (`localeOk` in `core/discovery/selectDiscovery.ts` — the core cannot import the components zone, so the two spellings name each other).
- **The switchable query language** — `DiscoveryControllerState.criteriaLocale` is state (was a construction-time snapshot `localePreference[0]`, i.e. always `be`), with the `setCriteriaLocale` action: the UI-registry code moves the query, re-selects over the loaded index and recomputes the controls; an unknown code is rejected at the boundary (the `setTimeLimit` idiom). The analytics `content_locale` payload reads the switched value.
- **Live wiring** — `createServices` subscribes to the UI-locale store: a switch re-projects the catalog cards (the catalog service's display options resolve per call — selected language first, composition fallback after) and re-selects discovery. The preview's display preference and the moment teasers' locales are evaluated per open; a fresh walk picks the selected UI language's layer when the downloaded package carries it (the composition preference after), never beyond it.
- **No-substitution deep links (AC4)** — `app/route/[id].tsx` renders the new localized `previewTextUnavailable` state when the resolved preview's published text does not cover the selected UI language; the be/en content is never substituted and the mixed-language playback stays G21.21's.
- **Chrome independence (AC3)** — the run words already ride the session's pinned locale (`runMapStrings(ready?.locale ?? locale)`, issue #524); now proven by `ui_switch_keeps_content_pin`, and the My KUDY history rows label their content language (`SessionLocaleLine` — the registry's native name, an unknown stored code renders as-is).
- **Canonical words** — two new records in `contracts/ui-messages/source.json` (`native.chrome.textLocaleEmpty`, `native.chrome.previewTextUnavailable`, anchored to their catalog leaves, en/uk translations reviewed against the pinned source hashes) flowing through the G21.25 generator into all ten outputs.
- **Existing expectations updated to the new canon** — the Nearby suites' review/proximity orders and the hint-card arrange no longer expect the en-only `e1-place` in the be UI (it filters out — the point of the task), and the #523 authored-content switch test rides the uk-text b1 guide.

## Acceptance criteria walk

1. **fr UI + be/en-only guide text → absent from catalogues, discovery and nearby; a valid empty catalogue shows a localized explanation, never a service failure.** The catalog view test (`empty_locale_catalogue`) and the Nearby integration test (a uk-stripped valid catalogue under the uk UI → the language explanation, no cards, no error state); discovery: the fr criteria answer is empty over the be/en/uk fixture (`selected_text_locale_filter`, controller suite + demo block).
2. **fr text with en audio → fr title/text and explicit audio availability.** The availability facts line (`textAudioLine`) renders text and audio as separate facts on every card (pre-existing G21.16 fields); the guides-screen integration test proves the switch re-projects titles into the selected language (uk → «Історії сукнарів…»), so an offer is read in its published language. Explicit audio-language selection is G21.21's and is not pre-empted: nothing here selects audio implicitly.
3. **Run chrome from the UI catalogue; a switch never changes the active session; a differently localized session stays resumable and labelled.** `ui_switch_keeps_content_pin` (run render suite): a mid-walk switch keeps the pinned-locale words, the map and the back label; the history rows carry the language label (registry native name; unknown codes render as-is).
4. **Direct links without selected-language text → localized unavailable, no silent be/en substitution.** The preview gate test: a uk-stripped guide under the uk UI renders `preview-text-unavailable` with the localized word, the be title is gone from the tree, and switching back restores the preview in place. Mixed playback remains denied by the engine's grant-locale comparison (untouched).
5. **All eight UI locales, empty and malformed catalogues, mid-session switch; Start full-readiness and paid denial preserved.** The pure filter test walks all eight registry codes; the empty states are the two named ones (language explanation / notPublished); malformed catalogues keep their named degraded states (the degraded-banner suites pass unchanged); the full-readiness and paid-denial suites pass untouched. The device leg of the proof is not verified in this session (no physical device ran; the controller/Jest proof is complete).
