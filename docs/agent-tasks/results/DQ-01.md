## Рэкамендацыі (спец §8.1, §10)

1. **Парог pixelmatch: 0.1** (стандартнае знячэнне). Вымераны шум кантэнту = 0
   на ўсіх парогах да 0.2, таму парог бярэ запас на будучыя змены растэрызатара
   і не рызыкуе прапусціць рэальную змену.
2. **Максімальная доля розных пікселяў: 0.05%** ад параўноўванай вобласці
   (~1250 px на экране). Запас ×4 супраць найгоршага назіранага статусбарнага
   значэння (0.0129%) і на дзесяткі разоў меней за любое рэальнае змяненне UI
   (зрух карткі на 2 px ≈ дзясяткі тысяч пікселяў).
3. **Эталонны асяроддзе: CI-профіль** — pixel_5, API 36, google_apis x86_64,
   swiftshader_indirect (флагі з `android-e2e.yml`). Лакальны pixel_6 (`kudy-test`)
   узорам не служыць: розныя ўзоры па канструкцыі → паводле правіла §8.1 узоры
   здымае ручны запуск workflow (PNG з артэфакта). Лакальная рэпліка `kudy-ci`
   (створаная дакладнай камандай workflow) дае байт-аднолькавыя ўласныя серыі і
   можа быць кандыдатам на лакальны здымак узораў, але эквівалентнасць
   «лакальны host ↔ CI runner» у гэтай задачы не вымераная — да асобнай праверкі
   эталонам лічыць CI.
