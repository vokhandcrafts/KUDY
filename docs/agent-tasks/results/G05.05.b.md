# G05.05.b — Pause, Resume, End and restart recovery

Issue #217 · branch `zcode/217` · 2026-09-25 · executor: Zcode session (GLM-5.3-Flash).

The rest of the session lifecycle now lives in `useRunController`. The
Pause/Resume/End transactions of ADR G01.03 §3.3 run in the orchestrator's
`onCommitted` hook — after the engine committed, before the effects fire — as
**one** store transaction each (Pause: UPDATE `state='paused'` + the sets
checkpoint that retires the queue; Resume: the plain UPDATE; End: UPDATE
`finished` + `finished_at` + the final checkpoint), so a failing write aborts
the pending effects and the rollback leaves the row in its previous state.
After End the controller drops the row reference: the finished row is history,
and no later callback, fix or `AccessReady` writes it. The wakelock port and
the restart recovery (`recover()`) complete the lifecycle per 09 §9, 11 §6 and
09 §9.1.

## What was decided

- **The durable write rides the commit point.** The lifecycle transitions are
  detected in `onCommitted` from the before/after phases; each performs its
  single store transaction with the transition's durable delta, before the
  engine's effects (StopAudio/ClearGeofences) are applied — ADR §3.3's «эфекты
  толькі пасля commit». A failing store write propagates and aborts the
  effects (the G05.05.a decision 2 pattern).
- **`sessionId` is dropped on End.** A finished row never receives another
  checkpoint (ADR §3.1: history is never overwritten); a repeated End finds no
  transition (the reducer ignores `End` in `Ended`) and writes nothing.
- **Wakelock = the session axis of 11 §6.** Acquired after the Start commit
  and on Resume, released on Pause and End; the screen-foreground rule stays
  with the composition root.
- **Resume lifts the automation suspension.** The issue criterion 2's
  parenthetical «`autoplay_suspended = true`» restates ADR G01.03 §3.3's
  Resume row. The canon sources agree on the opposite outcome and were
  accepted later: 09 §6.1 invariant 7 lists `Resume` сесіі among the lifting
  actions, 11 §5.2 lists «Працягнуць» пасля паўзы сесіі, the frozen run-model
  sets `s.suspended = false` in its `Resume` case, and the accepted engine
  reducer + its tests pin the same. Per implementation-rules 6 the code
  follows the canon and the test asserts the canon outcome; ADR §3.3's row is
  pre-G01.02-sync wording whose 09/11/15/14/16/18 synchronization is G01.03.c's
  assigned scope (ADR §5) — it was not edited here. Nothing sounds as a
  mechanical effect of the Resume dispatch itself: the tap is the explicit
  human action, and the next trigger simply runs the general conditions again.
- **Restart recovery is a state, not an action.** `recover()` reads the live
  row through the `RunRecovery` port and injects the restored state via
  `orchestrator.restore()` — no event, no effect, no audio. The restored
  fields: `version`/`locale`/`heard`/`auto_fired`/`play_seq` verbatim from the
  row; `playing`/`queued` null and `autoplay_suspended` true per ADR §3.2;
  `last_fix` null (transient — the first trigger after a restart needs a fresh
  fix). A restored **active** row re-arms the location window (09 §9.1); a
  restored **paused** row holds no subscription (11 §4.2) — its window
  re-arms through the explicit Resume.
- **The pinned version is guarded at the controller boundary.** The recovery
  payload carries the package identity it was read from; when it does not
  match the row's `route_id`+`version`, nothing of that payload enters the
  session (AC5, ADR §3.4) — the newer catalog's stops and layers are refused
  whole. Recorded layers whose files do not verify today become the recovery
  report (`unavailableTiers`, ADR §3.7's «чэсна недаступны» state), never a
  content swap. The composition root binds the port to the row's stored
  package; the tests exercise the real `evaluatePackage` path (rule 15).

## Acceptance criteria, walked from the card

1. **Pause** — `criterion 1: Pause persists the row paused…`: the row reads
   `state='paused'` with the retired queue (`auto_fired ['stop-1','stop-2']`)
   from the same transaction; the guide launch stopped by command
   (`audioPort: play …, stop`), a playing Moment keeps sounding (the paired
   moment test asserts no stop command); the location service holds no
   subscription and pushes no regions; the wakelock port was released.
2. **Resume** — `criterion 2: Resume re-arms the row, GPS and the window…`:
   the row reads `active`; the GPS mode re-armed (one subscription); the
   window set re-armed and ranks only after a fresh fix; no audio command left
   the dispatch; the canon flag outcome is asserted with the source note
   above. The «continue» tap is the explicit action; the subsequent trigger
   plays under the general conditions.
3. **End** — `criterion 3: End mid-audio…`, `End from Paused and after one
   story…`, `the next Start after End…`: the row is `finished` with
   `finished_at` from the injected clock and the final checkpoint (queue
   retired); guide audio stopped, a moment kept sounding; wakelock released;
   subscriptions zero; a repeat End writes nothing; the next Start minted a
   new `session_id` and row with fresh sets; `resumeSession` after End is a
   no-op, the ended row stays finished.
4. **Restart recovery** — `criterion 4: a process restart restores the live
   row…`, `a paused row restores…`, `no live row or an owned session…`: the
   restored state carries the durable fields verbatim, `playing`/`queued`
   empty, nothing sounds; «continue the saved walk» is the exposed state
   (phase + `recovery` view), never a controller action; the transient queue
   died with the process while the durable sets survived; the location arms
   only for the active restore; `recover()` never clobbers a session the
   controller already owns.
5. **Pinned version** — `criterion 5: a newer catalog package never enters…`,
   `the pinned package files are still required…`: a version-2 payload over a
   version-1 row restores `version='1'` with empty tiers, the foreign stop's
   geometry unreachable, and `unavailableTiers: ['base']` reported; a damaged
   pinned package (the real unreadable-media stub through the real
   `evaluatePackage`) restores the session as state with the layer honestly
   unavailable and nothing played.
6. **After End** — `criterion 6: a callback, a fix and an AccessReady after
   End…`: a late moment callback, a wandering fix and a real
   `emitAccessReady` leave not a single durable byte moved; the row stays
   history, the downloads stay disk-only (ADR §3.5 scope (b)).

## Review cycle

The pr-reviewer pass on the first push returned ✅ with 2 Medium + 1 Low, all
fixed in this push and each guarded by a failing-on-revert check:

- `recover-race-after-await` — the ownership check in `recover()` is repeated
  after the `await` (a Start that commits during the package read keeps the
  controller; concurrent `recover()` calls deduplicate). Guard: `criterion 4:
  concurrent recover() calls deduplicate after the read` — with the re-check
  removed it observes two restores (two wakelock acquires) and fails.
- `wakelock-not-reacquired-on-restore` — a restored Active walk takes the
  wakelock back in the restore branch (11 §6); the paused restore still holds
  none until the explicit Resume. Guards: the wakelock-call assertions in the
  two restore tests.
- `unused-port-method` — the dead `live()` read was removed from the
  `RunSessionStore` port; the row read belongs to the `RunRecovery` port.
