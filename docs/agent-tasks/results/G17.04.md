# G17.04 — Wiki collector (MediaWiki API)

Issue #159 · branch `zcode/159` · 2026-09-25 · executor: Zcode session (GLM-5.3-Flash).

The collector gained the wiki stage (docs/24_web_collection.md «Калектары →
Энцыклапедыі і вікі»): a campaign's optional `wiki` block carries the MediaWiki
`api.php` endpoint, article and category lists and the category-expansion depth.
Every article and category becomes a `run_log` step (`wiki-article` /
`wiki-category` with its work order in `detail`). The article step fetches the
parse response (`prop=text|revisions`, formatversion 2), wraps the HTML fragment
in a document carrying the API's normalized title and drives it through the
existing snapshot pipeline — snapshot.html, text.md, `links` rows, URL and
content-hash dedup — as a `raw_records` row with `source_type=wiki`,
`rights=licensed` and an `attribution` object in `metadata.json` (site,
revision_id, contributors_url, license `CC BY-SA`). The category step lists the
members (`cmlimit=max`, `cmtype=page|subcat`), enqueues articles and
subcategories and records its expansion decisions as notes in `detail`.

New file `tools/collector/wiki.mjs` (the MediaWiki contract: request URLs,
response parsers with corrupt-input diagnostics, the topic filter, the rights
and license constants, the attribution builder); `runloop.mjs` gains the two
wiki handlers, the `loadApi` transport boundary (the default performs the real
http(s) fetch — the framework's first live network path, tests inject recorded
fixtures) and wiki-step enqueuing; `runCampaign` is now async (the transport
awaits); `snapshot.mjs` parameterizes `processFetchedPage` (sourceType, rights,
attribution, metadataOverrides, enqueueImages) instead of growing a second
pipeline; `campaign.mjs` gains the validated `wiki` block; `collector.mjs`
awaits the run and converts a rejected run into the exit-2 diagnostic path;
`testkit.mjs` gains the wiki YAML override. The suite is wired by the existing
`tools/collector/*.test.mjs` glob — no runner edit needed.

## Acceptance criteria — walked from the card

1. ✅ **Fixture API responses → `raw_records` with `source_type=wiki` and
   complete attribution metadata (each field asserted).** The AC1 test runs a
   fixture parse response through `runCampaign` and asserts the record's
   source_type and normalized-title URL, then asserts every `attribution`
   field in `metadata.json` separately (site, revision_id, contributors_url,
   license), plus the revision timestamp/user mapped into
   `published_at`/`author` and `language: null` (the parse response carries no
   content language — absent metadata stays null, the G17.01.b convention).
   Relative `/wiki/` anchors resolve against the article URL into the `links`
   table.
2. ✅ **Category expansion respects the topic filter and depth; the negative
   tests name the filter.** The topic filter is the campaign's `topics`: a
   subcategory is expanded only when one topic appears in its title
   (case-insensitive substring, `Category:` prefix ignored); listed (root)
   categories bypass the filter — the operator chose them explicitly. An
   out-of-topic subcategory is not expanded at all: nothing fetched, the
   category step completes with the note «'Category:Sport w Gdańsku' not
   expanded: no campaign topic matches (topics: architektura)». The depth
   budget counts expansion levels (1 — listed categories only, 2 — plus their
   in-topic subcategories): a child beyond it is not enqueued, the note names
   the limit («depth limit 1 reached»). Tests: «AC2: category expansion
   fetches member articles and in-topic subcategories», «AC2 negative: an
   out-of-topic subcategory …», «AC2 negative: the depth limit …».
3. ✅ **`rights` is `licensed` automatically for wiki sources.** The mapping is
   the `WIKI_RIGHTS` constant in `wiki.mjs` (spec «Правы»: «Вікіпедыя і
   MediaWiki-сайты — licensed (CC BY-SA)»); the test asserts the literal
   `'licensed'`, not the constant, so reverting the mapping fails it.
4. ✅ **A missing-title fixture yields a logged diagnostic and the run
   completes.** The MediaWiki error envelope (`missingtitle`) fails exactly
   its own step with «wiki api error for 'NotExist': missingtitle — …»; the
   valid article is recorded, the run finishes. Corrupt payloads (bad JSON,
   missing `parse.text` / `revisions`, missing `categorymembers`, member
   without ns/title) fail their own steps with named diagnostics — one test
   covers six corrupt shapes. Suites are wired into `npm test` via the
   collector glob; jscpd clean.

## Canon notes — decisions recorded (no shared doc edited)

- **The wiki transport is live by default.** Unlike the file://-only page and
  image loaders, `loadApi`'s default performs the real http(s) fetch: G17.04
  is the fetching task (the issue's goal), live runs are manual, and no later
  task supplies the fetcher the way G17.02 does for seeds. Tests and the demo
  inject recorded fixtures; no test touches the network. The README's «Сетка
  тут не чапаецца» statement was updated with this carve-out.
- **`async runCampaign`.** The real transport awaits, so the run loop awaits
  handlers and `runCampaign` is async; the CLI awaits it and maps a rejection
  to the exit-2 diagnostic path. The sync store/snapshot/media machinery is
  unchanged.
- **Expansion is category-driven, not link-driven.** The spec's «пераход па
  вікі-спасылках» is realized through MediaWiki's native topic structure
  (categories), matching the issue's acceptance criteria; article links are
  still extracted into `links` but do not enqueue steps.
- **Topic filter = campaign `topics`.** The campaign's theme tags double as
  the wiki expansion filter — no separate `wiki.topics` key; an empty topics
  list matches nothing (no blind expansion beyond listed categories).
- **One batch per category step.** `cmlimit=max` is requested; a `continue`
  token in the response completes the step with a visible note instead of
  silently truncating. Real pagination is left to a later task.
- **Non-content category members are skipped, not fatal.** `cmtype=page|subcat`
  still lists non-content pages (templates, stub banners) as type «page»; a
  member with a namespace outside 0/14 completes the category step with a
  skip note («namespace N is not article content») while its articles still
  collect — a legitimate API answer must not fail the whole category (added
  after review round 1). A member without ns/title or a null revid remains corrupt input
  and fails the step with a diagnostic (round-2 review).
- **Attribution lives in the snapshot's `metadata.json`**, not in new
  `raw_records` columns: the RawRecord passport is spec-verbatim (the schema
  test pins it), and the spec's raw copy already names «метаданыя
  старонкі» as part of the snapshot. The wiki record keeps the passport shape.
- **No image steps for wiki** — photos are out of scope per the issue, so the
  wiki path passes `enqueueImages: false` and `media/` stays the empty
  G17.01.b folder; the HTML keeps its `<img>` markup in snapshot.html.
- **Title normalization dedups.** The record URL derives from the API's
  normalized `parse.title`, so two spellings of one title listed directly and
  via a category collapse into one record (UNIQUE(campaign_id, url)) while
  remaining two steps.
