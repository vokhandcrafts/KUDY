# G05.01.c — Audio ownership in the reducer

Issue #199 · branch `zcode/199` · 2026-09-24 · executor: Zcode session (GLM-5.3-Flash).

The third production-reducer slice completes the G01.02 owner rules in
`core/engine/`: `reducer.ts` grows the tagged-callback machinery (`tokenOf`,
`tokenMatches`, `stopAudio`, `momentLaunchOf`), the `PlayMoment` /
`MomentFinished` / `AudioFailed` / `UserPausedAudio` / `UserStoppedAudio` /
`FocusLoss` / `FocusRegain` / `ResumeAudio` / `GuideResume` transitions, and
the guide-only audio stop on session `Pause`/`End`; `state.ts` adds the
live-pause flag `paused` to both `Playing` variants and the marker nuance in
`stopStatus` (a paused launch is not «playing»); `events.ts` adds the
`Start.playingNow` injection; `commands.ts` carries the token on
`PlayStory`/`StopAudio`/`ResumeAudio` and makes `PlayMoment.path` optional.
The new acceptance suite is `core/engine/ownership.test.ts` (21 tests).
Semantics mirror the frozen documentation model `docs/run-model/run-model.mjs`
(G01.02.b row of its README); the model files were not edited.

## Acceptance criteria — walked from the card

1. ✅ **`playing` has guide | moment variants and the token is `{kind, ref,
   seq}`; a non-matching callback is ignored entirely — one test per callback
   kind.** The guide token IS the accepted `(session_id, play_id)` pair and
   rides the `PlayStory` command; the moment token is echoed from the
   controller's mint (asserted with a distinctive seq — the engine never
   re-counts). Rejection tests per kind: finished-guide (a late
   `AudioFinished` of a launch replaced by a moment), finished-moment
   (stale `MomentFinished` token frees nothing), error (stale `AudioFailed`
   neither frees nor suspends), resume (`ResumeAudio` with an unminted token
   is a refusal, not a resume), focus (physical events carry no token and are
   never gated — asserted working).
2. ✅ **An explicit `PlayMoment` stops the guide by command (not as finished),
   clears the queue and suspends automation until `GuideResume`;
   `MomentFinished` never mutates `heard`.** The P02 test asserts the exact
   command pair `StopAudio` + `PlayMoment`, the interrupted story absent from
   `heard`, the queued stop retired to `auto_fired` (§3.6.2) and the flag set;
   the proof test asserts `MomentFinished` frees the player while `heard`
   stays empty, the suspension stays held and no queue starts (§3.6.3);
   `GuideResume` is the single way back and sounds nothing by itself — the
   next trigger runs the general conditions while the retired stop stays
   retired.
3. ✅ **`FocusLoss` is never `AudioFinished`; the 10-minute threshold closes
   the play; a manual pause has no threshold.** `FocusLoss` on any owner is a
   live pause (`paused: true`, `focus_lost_at` armed, no `heard` credit, the
   stop marker follows the audible state); `FocusRegain` exactly at
   `focusRegainWindowMs` keeps the launch live (the comparison is `>`), past
   it the launch is closed and a `ResumeAudio` of the closed token is refused
   — the later listen is a fresh launch with a new token; a manual pause
   resumed an hour later still continues the same token.
4. ✅ **`autoplay_suspended` is set and cleared only by the invariant-7 events;
   `ResumeAudio` on a moment does not clear it.** The flow test walks
   PlayMoment (sets) → MomentFinished (does not clear) → paused moment
   resumed by tap (launch continues, flag stays) → `GuideResume` (clears) →
   `AudioFailed` (sets again, never credits `heard`).
5. ✅ **Session Pause and End stop only guide audio; Start while a moment plays
   injects `playingNow` and waits for the player to be free.** Pause with a
   guide launch emits `StopAudio`; Pause with a moment launch emits only
   `ClearGeofences` and leaves the launch untouched (not even paused);
   `End` during a moment keeps it sounding and its `MomentFinished` still
   frees the player after `End` while a late guide callback mutates nothing;
   `Start.playingNow` injects the moment variant with `playSeq: 0`, the
   autotrigger queues while the player is busy, and four malformed
   `playingNow` payloads are refused with `RangeError` (plus three malformed
   `PlayMoment` events refused without mutation).

## Canon notes — decisions recorded (no shared doc edited)

- **`PlayStory`/`StopAudio`/`ResumeAudio` commands carry `token`** — ADR
  G01.02 §3.2 («PlayStory(…) з тым жа токенам у камандзе; спыненне — StopAudio
  дзеянне над бягучым токенам»); 09 §6.1 already lists `ResumeAudio(play_token)`.
  The G05.01.a union had bare commands because nothing played yet.
- **`PlayMoment.path` is optional** — the engine cannot derive the tier of a
  place-based teaser story, and the frozen model's `PlayMoment` command emits
  no path; the controller resolves the teaser path before handing the command
  to `services/audio`.
- **Moment tokens are echoed, never minted** — the controller owns the
  process-wide moment counter (ADR §3.2); the engine validates the shape
  (`isMomentLaunch`) and the `ref === momentId` binding, refusing malformed
  launches entirely.
- **Player events reach the reducer after `End`** — the physical player
  outlives the session (ADR §3.4/§3.8): a moment launch keeps sounding, so its
  tagged callbacks still work while every session-lifecycle event stays
  ignored; the frozen model applies the same player-event filter in `Ended`.
- **`PlayMoment` is reachable from Active and Paused** (the model has no state
  guard on it); in Idle the moment playback lives in the controller's single
  player — the engine has no mirror there (ADR §3.8), and after `End` a new
  `PlayMoment` is not a live player callback.
- **`FocusRegain` consumes `config.focusRegainWindowMs`** — the last
  unconsumed `EngineConfig` number (09 invariant 5); the boundary comparison
  is strictly `>` (exactly 10 minutes stays live).
