# G02.04 — Публікацыя і адкат каталога

**Issue:** [#56](https://github.com/vokhandcrafts/KUDY/issues/56) · **Галінка:** `zcode/56` · **Статус:** `complete` (серверны/каталожны код; прыладавая прыёмка не закранаецца — TR-2б адкладзены, [рашэнне ў #123](https://github.com/vokhandcrafts/KUDY/issues/123#issuecomment-5753625602))

## Што зроблена

Новы інструмент `tools/publish-catalog/publish-catalog.mjs` — рэальная публікацыя каталога з адкатам (interim-вывад у `web/lib/content` пакінуты для фікстурнай стадыі G10.01.b; парытэт замацаваны тэстам). Адзін запуск = адзін рэліз з `release/release-manifest.json`, які зрабіў `build-bundle` (G02.03).

Публікацыя працуе па парадку: **поўная праверка пакета → lay файлаў → захаванне release-файлаў → атамарны pointer swap апошнім крокам**. Прыватны пласт верыфікуецца, але ў публічнае дрэва не кладзецца (09 §5: extended да праграмы ідзе праз гранты, не праз catalog origin).

## Крытэрыі issue — парадок па пунктах

1. **Спачатку правяраецца поўны пакет, пасля абнаўляецца каталог** — да любога змянення target: кожны артефакт маніфеста супраць bytes+sha256 (`manifest-mismatch`, `manifest-missing-artifact`), кожны запіс `lock.json` супраць файла (`lock-mismatch`, AC1-тэсты), registry-блок маніфеста супраць файла экспарту. Тэст «tampered staging file aborts the publish before the target changes» фіксуе пусты target пасля адмовы.
2. **Версіі нязменныя** — розныя байты па шляху готовай версіі (у каталогзе) ці яе lock/індэкса → `version-immutable`, публікацыя адмяняецца, каталог байт-ідэнтычны да і пасля (AC2). Байт-ідэнтычны republish — ідэмпатэнтны (`copied: 0`).
3. **Адкат паказвае папярэднюю гатовую версію** — перад pointer swap цяперашні `catalog.json` захоўваецца як `catalog.previous.json`; `--rollback` атамарна мяняе іх у абодва бакі (AC3: v1→v2→rollback→v1→rollback→v2). Без папярэдняга — `no-previous`.
4. **Абрыў не публікуе палову пакета** — файлы кладуцца да пойнтэра, пойнтэр пішацца temp+rename у той самай тэчцы; збой да rename пакідае стары каталог жывым, сірэцкія файлы перазапісвае наступны запуск (AC4: імітаваны crash-стан → каталог v1 нечыты, потым v2 публікуецца паверх сірот).
5. **Індэкс і registry гатовыя да pointer update** — `discovery_index` (schema/revision/path/bytes/sha256) бярэцца з верыфікаванага маніфеста; `releases/<route_id>/<version>/{release-manifest,feedback-target-registry}.json` захоўваюцца разам (21 §5.2), sha registry супадае з маніфестам (AC5). Шматрэлізнае накопленне: routes зліваюцца па route_id, пойнтэр — найноўшы апублікаваны індэкс.
6. **Legacy/unknown-schema/rollback правераныя** — legacy v0 (босы масіў): v1 envelope пішацца нанава, v0 файл захоўваецца даслоўна для адкату і ім жа аднаўляецца (AC6); unknown major (`catalog_schema_version: 2`) адхіляе і публікацыю, і адкат (`catalog-unknown-major` — неінтэрпрэтаваны каталог не перазапісваецца); schema-няспраўны v1 target → `catalog-invalid`. Выніковы каталог перад запісам прапускаецца праз той самы `readCatalogDoc` з `contracts/reader.mjs`, якім чытае вэб/праграма — адна інтэрпрэтацыя.

## Парытэт з interim-вывадам

`deriveInterimCatalog` (G10.01.b) і публікатар маюць супадаць на адных уваходных: AC-тэст «parity» параўноўвае routes і discovery_index дэп-роўна. Адзінае значнае адрозненне крыніц: публікатар бярэ факты з верыфікаванага маніфеста, interim — з хады па дрэве; пласты ў абодвух вызначаюцца па route-кантракце (`access_tier: extended` у route.json), бо ў public дрэве extended не існуе.

## Self-review (аўтарская, не рэвью-вердыкт)

- Кантракты скапіяваныя з кананічных крыніц з анкер-каментаром: pattern `route.version` і `discovery_index.path` — з `catalog.schema.json`; інтэрпрэтацыя каталога — `contracts/reader.mjs`; lock-форма — 09 §4 праз build-bundle.
- Патэнцыйнае абмежаванне, запісанае сумленна: envelope мае адзін `discovery_index` — шматмаршрутны таргет аднаго горада атрымлівае пойнтэр найноўшага рэлізу; поўнацэнны city-index з усімі гідамі — пытанне аўтарскага працэсу (паза радком G02.04).

- Чужыя файлы не кранутыя апрача: `package.json` (глоб сюты — rule 7), `tools/build-bundle/test-wiring.test.mjs` (гвард павінен ведаць новую тэчку), два каментары ў `web/lib/content/{site,bundle}.ts` (сынхранізацыя ісціннасці, rule 8).
