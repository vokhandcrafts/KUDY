## Крытэрый 1 — інвентар і ўладальніцтва тэстаў

✅ Выканана.

Стан да змены: `npm test` пералічваў зоны ўручную (substring-літаралы);
гвард `tools/build-bundle/test-wiring.test.mjs` правяраў толькі
прысутнасць літаралаў у скрыпце — файл, дададзены ў пералічаную тэчку,
належаў «літаралу», а восем спайкавых сюітаў (`spikes/G00.0*/…`,
`test/*.test.mjs` — прамыя шляхі без зоны) былі па-за стандартнай
камандай. Дакладная дзірка пацверджаная перарасшырэннем глабаў да змены:
183 закамічиваны тэставых файлаў (`git ls-files -- '*.test.mjs' '*.test.ts'
'*.test.tsx' | wc -l` на базе 930215e), 8 уналежаных (усе — `spikes/G00.*`).

Стан пасля:

- `package.json` → `npm test`: зоны-глабы замест ручнога пераліку —
  `"test/*.test.mjs"`, `"contracts/**/*.test.mjs"`,
  `"spikes/**/*.test.mjs"` (уключае ўсе восем спайкавых файлаў;
  лакальны прагон іх да ўключэння — 53/53 pass; `live-remote.test.mjs`
  самаскіпаецца з бачнай прычынай mock mode, правіла 7).
- `tools/ci/test-discovery.mjs` — адзіны ўладальнік пытання
  ўладальніцтва: перарасшырае рэальныя глабы `node --test` і
  `testMatch` з `jest.config.js` (не пераказвае іх — implementation-rules 2),
  інвентарызуе `git ls-files` па `*.test.*`, вяртае ўналежаныя.
  Exclusions-seam (`EXCLUSIONS`) пусты: пасля ўключэння спайкаў
  выключаных файлаў няма; мёртвы або няпоўны запіс exclusion — дыягностыка.
- `tools/ci/test-discovery.test.mjs` — гвард: на рэальнай рэпе ўналежаных
  няма (`✔ … pass 6 / fail 0`); дэльты «зняў глаб → названыя файлы» і
  «зняў testMatch → app/components уналежаныя»; карупц-канфіг адказвае
  дыягностыкамі, не крэшам (implementation-rules 14); .tsx пад node і
  падвойная прыналежнасць іменаваныя.

Новы прыняты тэставы шлях па-за глабамі = чырвоная названая праверка
«unowned committed test files: …».

Rule 8 (pointer): substring-гвард `tools/build-bundle/test-wiring.test.mjs`
выдалены; яго функцыя (file-level wiring) перанесеная ў discovery-гвард са
superset-пакрыццём. Гістарычныя згадкі: `results/G05.06.a.md` (пунатар
ніжэй), `docs/agent-rules/lessons-learned.md` §105-тэза абноўленая pointer-ам.

## Крытэрый 2 — названыя сінтэтычныя сэнтынелы ў часовым checkout

✅ Выканана. Працэдура: `git clone file://<worktree> /tmp/…` + поўны
`npm ci` (root і web) + сінтэтычны файл паверх HEAD; стандартная каманда
`npm test` цалкам.

- Node-runner сэнтынел `test/g20-28-node-sentinel.test.mjs` («…sentinel-
  failure-g20-28-node»): `npm test` → exit 1; `ℹ tests 1913 / pass 1906 / fail 1`, адзінае падзенне — `✖ G20.28 node-runner sentinel must execute
  and fail (sentinel-failure-g20-28-node)`. Тэст выкананы (кіданне
  памылкі), не «знойдзены па тэксце».

  зялёны (1912), jest крок → exit 1; `Test Suites: 1 failed, 24 passed`,
  `Tests: 1 failed, 178 passed`, падзенне —
  `● G20.28 jest-runner sentinel must execute and fail (sentinel-failure-g20-28-jest)`.
- Выдаленне runner wiring выяўляецца: юніт-дэльты discovery-гварда
  (зняцце глаба/testMatch → уналежаныя named) + піны
  `tools/ci/check-required-checks.mjs` (блок «G20.28 revert guard»):
  зняцце `"tools/ci/*.test.mjs"`, `"test/*.test.mjs"`,
  `"contracts/**/*.test.mjs"`, `"spikes/**/*.test.mjs"` з npm test робіць

  discovery-гвард → пін → guard-required-checks.yml (уласны workflow) →
  required status замыкае самазняццё (residual #105 закрыты).

## Крытэрый 3 — engine:regressions у абавязковай праверцы

✅ Выканана (дазвол #493 зона 7, закрыты #493; G20.22 фіксуе межы).

- `required-checks.yml`: новы producing job `engine-regressions`
  (`npm ci` → `npm run engine:regressions`, ubuntu-latest, Node 24).
  Actions у новым job ўследаваныя з базы (поўныя 40-hex SHA, якія
  ўвёў G20.27, #500, змержана паралельна): гэтая задача дадае толькі
  крок выканання; пін самога выкліку —
  `tools/ci/check-required-checks.mjs` (missing_engine_workflow_step),
  семантыка мутацый — у самім runner-е.
- Лакальны прагон: `npm run engine:regressions` → `21/21 reviewed
  regressions rejected by the named guards. Repository engine unchanged.`,
  exit 0.
- Насаджаная прапушчаная мутацыя: у часовым клоне ўжыта мутацыя
  «autoplay locked stop» да `core/engine/reducer.ts`; suite
  `core/engine/model-parity.test.ts` падае з назвай гварда —
  `✖ C33: locked preview is excluded from manual and automatic playback
  and remaining list` (+ сувязны G01.01.b), 76 tests / 2 fail.
- Выдаленне выкліку выяўляецца: perl-зняцце кроку з
  `required-checks.yml` у часовым клоне →
  `node tools/ci/check-required-checks.mjs` → exit 1,
  `missing_engine_workflow_step: required-checks.yml does not run
  \`npm run engine:regressions\``. Гварды дададзены ў той самы файл
  (блок G20.28) і бягуць з уласнага workflow `guard-required-checks.yml` —
  па-за `required-checks.yml`, які яны пінуюць.

- Платформавыя межы: zone-глабы пераносныя (node сам іх перарасшырае,

  shortcut-налады, не кода.
