## The driver decision was deliberately not made

The operator's TR-10 analysis (comment on #59, 2026-09-19; `23` round 3) records that the SQLite driver is unpinned and the stack-baseline ADR is `decision-required`. This PR adds **zero npm dependencies** and touches no stack row: the schema, migrations, zone rules and transactions live over the minimal `SqlDriver` interface, and the tests run on the built-in `node:sqlite` (unflagged since Node 22.13.0 / 23.4.0; the CI matrix runs 22.x and 24.x, both fine). The SQL is standard SQLite dialect — partial expression indexes included — portable to whatever driver the founder pins (expo-sqlite or otherwise). Production adapter + driver pin remain the follow-up wiring once the stack baseline row is decided; nothing here freezes that choice.

## Schema inventory (sources copied, not paraphrased)

- **Zone A (derived, `09` §7):** `bundle_asset` (key `route_id, version, locale, tier, path`; status `pending/partial/complete`; `bytes_total`, `bytes_done`, `sha256`), `catalog_cache` (`route_id`, payload), `discovery_cache` (`21` §5.4 — name and zone fixed; column shape minimal, G15.03 owns it and may only grow it by a later step).
- **Zone B (durable):** `session` (ADR G01.03 §3.1 verbatim field set; partial unique index `one_live_session` copied verbatim from the ADR), `guide_hint_state` + `guide_hint_last` (ADR §3.9, session-scope uniqueness), `migration_log` (ADR §3.8 reverse record incl. the `legacy` flag; empty until the first data migration), `event_queue` (`09` §10: `event_id`, `type`, `at`, schema version, `payload`, `sent`), `settings` (`09` §7), `device` (one row, enforced by `CHECK (singleton = 1)`; secret stays in expo-secure-store), `feedback_local` + `feedback_outbox` (`21` §5.4, lifecycle states verbatim).

## Criteria

1. **Cache rebuild never deletes session/settings/events** — `rebuildDerived` drop-and-recreates only `ZONE_A_TABLES`; `db.test.ts` «criterion 1: rebuildDerived keeps every durable row…» writes session/checkpoint/settings/event/hint/device/feedback rows plus all three zone A tables, rebuilds, and asserts every durable row survived and zone A is empty; the rebuilt table accepts contract-shaped rows again. A TR-5 level-3 name guard fails if `rebuildDerived` ever names a zone B table, and a zone-list guard fails if the DDL and the zone lists drift apart.
2. **A migration error does not wipe progress** — `openDatabase` applies one step per transaction (ADR §3.8); a failing step rolls back its own DDL, keeps `user_version` and all rows, and the open throws `DbError` rule `migration-failed` with the original error as `cause` («criterion 2» test: version stays 1, session row intact, `half_applied` table absent, repaired steps then migrate forward). A store newer than the code fails with `schema-newer-than-code` — no silent downgrade.
3. **One unfinished session enforced in a transaction** — pre-checks run before the transaction (§3.3) and the verbatim `one_live_session` partial unique index decides simultaneous races at the schema level; Start failing mid-transaction (hint-transfer uniqueness) leaves no session row and no moved hints; switch rolls back both legs so the old row keeps its state; pause/resume/finish reject wrong states with named rules; finished rows do not compete for liveness.
4. **G16.02 feedback durable survives a discovery-cache purge** — `feedback_local`/`feedback_outbox` live in zone B; «criterion 4» test rebuilds the derived zone (which includes `discovery_cache`) and asserts both feedback rows and their values survive.

All four are also shown in the demo. Every criterion test fails if the corresponding code is reverted (index, rollback paths, zone-guarded rebuild).

## Interpretation decisions (anchored, not invented)

- `feedback_outbox.target` is a column although §5.4's prose column list omits it — §5.4 requires "максімум адзін in-flight запыт" per target, which needs a queryable target.
- `device` single-row is enforced structurally (`CHECK (singleton = 1)`), matching «адзін радок» in `09` §7.
- Start's R07 hint transfer takes the guide ids as a parameter (`carryGuideHints`): the foreground-window ownership is the nearby controller's (ADR §3.9), the store only moves the rows transactionally.
- `appendEvent` dedup targets `event_id` only (`ON CONFLICT(event_id) DO NOTHING`), so any other violation still fails loudly; queue retry/backoff stays G09.01.
- Zones are FK-free: cross-zone foreign keys would couple the zone A rebuild to durable rows.
- Row payloads are schema-constrained writes of this module; externally corrupted rows surface as read diagnostics rather than silent wrong values.
