# G17.03 — Media: photos paired with text

Issue #158 · branch `zcode/158` · 2026-09-25 · executor: Zcode session (GLM-5.3-Flash).

The collector's snapshot pipeline now carries the media stage (docs/24_web_collection.md
«Фота»): every `<img>` occurrence of a snapshot page becomes a `run_log` step
(kind `image`) that loads the bytes through the offline loader boundary, probes the
real pixel dimensions from the container headers (PNG IHDR, GIF, JPEG SOFn — no
decoding, no new dependencies), applies the 150 px content rule, writes the file
under the article's `media/` folder with the spec filename, inserts the complete
`media` row and places the markdown image at its source position in `text.md`.
New file `tools/collector/media.mjs` (probe, filename rule, markdown insertion, the
step) plus `media.test.mjs` (10 tests); `extract.mjs` gains the document-order image
extraction (paragraphs and standalone `<figure>` blocks, `figcaption` → caption);
`store.mjs` gains `insertMedia`, the `UNIQUE (raw_record_id, file)` index and
the `detail` work-order column on `run_log` steps (with an in-place migration for
pre-G17.03 databases); `runloop.mjs` gains the `image`
handler, the injected `loadImage` boundary (file:// only, like the page loader) and
a drain loop so steps enqueued mid-run finish in the same invocation; `testkit.mjs`
gains the image-header crafters. The suite is wired by the existing
`tools/collector/*.test.mjs` glob — no test-runner edit needed.

## Acceptance criteria — walked from the card

1. ✅ **Only ≥ 150 px images saved; the negative test names the size rule.**
   `probeImage` reads the real pixel dimensions from the bytes; a longest side
   below `MIN_CONTENT_IMAGE_PX` (150, the spec's «меньш за ~150 px па большай
   старане») skips the image — the step completes as `done` with a note naming
   the rule, no file, no row, no markdown reference. Tests: «AC1: only images of
   at least 150 px …» (200×120 and the 150×150 boundary case are saved, the
   100×90 icon is not) and «AC1 negative probe: a 149 px image is excluded,
   150 px is kept».
2. ✅ **Complete `media` rows, slug filenames, stable numbering on re-run.**
   Every row carries raw_record_id, position, alt, caption, source_url, file,
   content_hash (sha256 over the stored bytes, recomputed by the test from disk),
   width_px, height_px, rights, collected_at. Filenames are
   `<slug>-img-NN.<ext>` with NN from the image's document-order occurrence —
   derived from the snapshot alone, so a re-run computes the same names
   (no `-img-1-1` duplicates); the second full `runCampaign` changes nothing
   (rows, files, `text.md` byte-identical). A skipped small image leaves a gap
   in the numbering — recorded as the deliberate trade-off below. Test:
   «AC2: every saved image has a complete media row …».
3. ✅ **The markdown image sits at the paragraph index where it appeared.**
   `media.position` names the text.md block the image stands before (an image
   inside paragraph k renders after paragraph k's text; a standalone
   `<figure>` between paragraphs renders exactly where it stood). The anchor
   counts paragraph blocks only, so earlier insertions do not shift it — the
   insertion bug this rule prevents was found by this task's Showboat demo and
   fixed in the same session. Test: «AC3: the markdown image sits at the
   paragraph index …».
4. ✅ **Same image on two articles → equal hashes on both rows.** Each article
   keeps its own file copy («свая копія ў кожным артыкуле, сховішча танное»);
   the rows cross-reference by `content_hash`. Test: «AC4: the same image on
   two articles …».
5. ✅ **Broken image URL → diagnostic, no crash.** A missing file fails its step
   with the ENOENT reason, a foreign scheme fails with «the offline loader
   serves only file:// sources» (the same no-network boundary as the page
   loader; the real fetcher arrives with G17.02), corrupt bytes fail with
   «unsupported or corrupt image bytes» — each failure is one failed
   `run_log` row naming the URL; the run continues, no row/file/markdown
   reference survives. A resumed image step converges instead of duplicating:
   the file is rewritten from the same bytes, `UNIQUE (raw_record_id, file)`
   turns the row insert into a no-op, the markdown is keyed by its own
   presence. Tests: «AC5: broken image URLs …» and «AC2 resume: a step re-run
   after a mid-step crash converges …».

## Canon notes — decisions recorded (no shared doc edited)

- **Numbering by occurrence, gaps allowed.** The spec's example shows dense
  `img-01, img-02`; the implementation numbers by the image's document-order
  occurrence so the filename depends only on the snapshot, never on other
  steps' outcomes — that is what makes a resumed run compute the same name and
  a crash converge. The human-identification purpose of the naming rule
  («у файлавым менеджэры адразу відаць, адкуль фота») is unaffected.
- **`position` names the block the image stands before** in `text.md` — one
  insertion rule for both in-paragraph images (after their paragraph's text)
  and standalone figures (where they stood). Anchors count paragraph blocks
  only; image blocks from other steps do not shift the anchor.
- **Rights are inherited from the raw record** (`research_only` for web seeds):
  the photo is a protected work even when the text is free, and the v0 page
  carries no per-image license source; the per-photo rights refinement belongs
  to G17.04 (wiki sources) and the bundle gate stays the only promoter of
  `licensed`/`public_domain`/`author_own`.
- **Probe formats: PNG, GIF, JPEG (SOFn).** WebP and other containers answer
  `null` and the step fails with a diagnostic; the format list widens with the
  crawler when real pages demand it.
- **v0 regex boundary:** `<p>` inside `<figure>` is not extracted (the DOM
  parser arrives with G17.02); `src`-less `<img>` tags are markup garbage, not
  images, and are skipped at extraction; an unresolvable `src` is kept raw and
  fails later at load time — one broken-URL path, not two.
- **`run_log.detail` is the step's work order** (the image descriptor JSON);
  an outcome note is appended with ` | `, never replacing it — a resumed
  process re-reads the order. `runCampaign` drains the claimable list until it
  is empty, so seed-enqueued image steps finish in the same invocation (the
  pre-G17.03 loop snapshotted the list once and left the new steps pending).
