# G20.16 — вынік: зацверджаная праверка async/памылак для tools, 2026-10-02

Задача [#487](https://github.com/vokhandcrafts/KUDY/issues/487), спецыфікацыя
[verification-integration.md §V3](../../specifications/architecture-hardening/verification-integration.md),
эпік #470. Галінка `zcode/487` ад main `dc856c4`.

## Што зменена

Дэфект (межы доказу з задачы): лінт-скрыпта няма, вытворчыя `tools/**/*.mjs` не
маюць ані праверкі forgotten-await, ані пустых catch — файл з такім дэфектам
дае зялёны `npm test`.

- **Праверка:** `npm run tools:check` → `tools/validate/tools-check.mjs` —
  type-aware ESLint (flat config `eslint.config.mjs` + `tsconfig.tools.json` з
  `checkJs`) роўна дзвюх правілаў з §V3: `@typescript-eslint/no-floating-promises`
  (забыты чаканне / unhandled promise) і `no-empty` з `allowEmptyCatch: false`
  (пустая апрацоўка памылкі). Без фарматавання і стылявых правілаў.
- **Пакрыццё:** 56 вытворчых файлаў `tools/**/*.mjs` (улучна з самім раннерам).
  Выняткі, усе неабходныя і дакументаваныя ў каментары конфіга:
  - 44 `*.test.mjs` — гоняцца `node --test` са сваімі завучаннямі;
  - `tools/**/fixtures/**` — 7 файлаў: `arch-surface` (наўмысна зламаны імпарт
    і дадзеныя для арх-гарда), `corpus` (фікстура дадзеных), `validate`
    (негатыўныя/станоўчыя фікстуры самай праверкі, лінтуюцца праз `--no-ignore`).
- **Піны** (дакладныя версіі без `^` у devDependencies + lockfile):
  `eslint 10.11.0`, `typescript-eslint 8.71.0`, `@types/node 26.6.4` (патрэбны
  type-service для `node:`-імпартаў; root `typecheck` вывад байт-у-байт
  ідэнтычны да/пасля — гл. Праверкі).
- **Правадка:** сьют `tools/validate/tools-check.test.mjs` ідзе ў `npm test`
  праз ужо існы глоб `tools/validate/*.test.mjs`; абавязковы workflow гоніць
  `npm test` (required-checks.yml), таму CI-застасаванне дасягаецца без рэдагавання
  `.github/workflows` — гэта зона бегучай задачы G20.13 (#484), група workflow у
  індэксе выконваецца паслядоўна. Wiring-гард `tools/build-bundle/test-wiring.test.mjs`
  аўтаматычна пакрывае новы сьют праз `git ls-files`.
- **Вывад раннера** нармалізуе шляхі (`repoRoot/` прыбіраецца) — CI-логі і
  захопленыя дэмы не залежаць ад хоста.

## Па крытэрах

1. **Інвентарызацыя + найменшая канфігураца з яўным пакрыццём і выняткамі.**
   107 файлаў `tools/**/*.mjs` = 56 вытворчых (правяраюцца) + 44 тэсты + 7
   фікстураў (выняткі вышэй). Выбраны мінімум: type-aware lint на дзвюх правілах,
   які сапраўды ловіць названыя класы (становаўленне tsc-праверкі ўсіх 12.6k
   радкоў JS строгім рэжымам было б шырэй за задачу); піны ў package.json.
2. **Сінтэтычныя парушэнні адхіляюцца з імем правілы; карэктны код праходзіць.**
   `floating-promise.mjs` → `@typescript-eslint/no-floating-promises`, exit 1;
   `empty-catch.mjs` → `no-empty`, exit 1; `valid-async-handling.mjs` (тыя ж
   дзеі з `await` і catch, што паднімае памылку) → exit 0. Тры тэсты гарда
   ганяюць фікстуры праз committed-канфіг з `--no-ignore`.
3. **Пін + правадка ў стандартную каманду; зняцце праверкі чырванее.** Гард-тэсты:
   npm-спроўка `tools:check`; непустое пакрыццё (empty selection → exit 2);
   вытворчы прагон. Рэверц-эксперымент ніжэй.
4. **Наборы не падзяляліся** — `npm test` захаваў структуру; ledger застаўся ў
   стандартнай камандзе (`tools/docs-ledger/*.test.mjs`), `npm run ledger:check`
   — OK, 0 lost; існы гард ledger-а «removing a baseline item fails the check
   and names it» (`tools/docs-ledger/ledger.test.mjs:141`) працягвае трымаць
   кананічныя факты.

## Рэверц-эксперымент (implementation-rules 1)

- Правіла `no-floating-promises` выдаленае з `eslint.config.mjs`: гард 5/6 —
  чырвоны «missing-await fixture is rejected naming the rule» (фікстура болей не
  адхіляецца); аднаўленне → 6/6.
- npm-script `tools:check` выдалены: гард 5/6 — чырвоная спроўка каманды;
  аднаўленне → 6/6.
- Раннер заменены на `export {}`: сьют падае на загрузцы (1 fail); аднаўленне → 6/6.
- Зняцце глоба `tools/validate/*.test.mjs` з `npm test` трымае існы
  wiring-гард (`test/build-bundle` праз `git ls-files`); сам глоб не мяняўся.

## Платформавыя межы

- Праверка ганялася на Linux; на Windows не праганялася. Пераноснасць:
  раннер збірае файлы праз `path.join`/`path.relative` з нармалізацыяй сепаратара,
  eslint/typescript-eslint кросплатформавыя; гэта не праглядана на рэальным
  Windows-хасце — робіць G20.17 (#488).
- type-aware lint патрабуе `npm install` перад прагонам (як і ўсе іншыя гейты).
