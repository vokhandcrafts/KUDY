# G22.04 — Старонкі зборшчыка і індэкс спасылак: вынікі

Issue: [#609](https://github.com/vokhandcrafts/KUDY/issues/609). Дата: 2026-10-05. Уваходны main: `bc62d3a` (G22.02/#631). Спека: E4 у `docs/specifications/efficiency/2026-10-04-bounded-work.md`; брыф: `docs/agent-tasks/efficiency/G22.04.md`.

## Acceptance evidence

1. **Ідэмпатэнтны індэкс на `links(raw_record_id)`, без дубля ўнікальнасці медыя (AC1).** `createSchema` (`tools/collector/store.mjs`) дадае `CREATE INDEX IF NOT EXISTS links_record ON links (raw_record_id)` побач з існым ідыёмам `media_record_file`. Тэсты `store.test.mjs`: індэкс ёсць на новай краме і аднаўляецца на старой (`DROP INDEX` → пераадкрыццё праз `openStore` — шлях in-place міграцыі, якім ідуць старыя крамы; read-only дыспетчар ствараць аб'екты схемы не можа). `PRAGMA index_list(media)` — роўна `media_record_file`, ніякага дубля.
2. **Рэальны HTTP-запыт па 1000+ запісаў вяртае толькі старонку і спасылку на наступную (AC2).** `records_response_is_one_page` сеяць 1007 запісаў праз прадакшн-функцыі сховішча, падымае сапраўдны дыспетчар на эфемерным порце: GET `/records` — 200, роўна 50 адрэндэраных радкоў (злік ячэек картак-спасылак) і «Наступная старонка» з курсарам; `limit=100` — роўна 100; `limit=1000` — 400. Абмежаванне па-ранейшаму зверху поўнага савёй SQL-выбаркі: праход па курсарах збірае ўсе радкі крамы без паўтораў (кэйс AC3).
3. **Курсарныя старонкі захоўваюць парадак і фільтры, нічога не губляюць і не паўтараюць (AC3).** `cursor_preserves_filtered_order_with_nulls`: поўны праход `/records?limit=7` супадае з JS-аракулам парадку `collected_at DESC, url, id` — пустыя даты апошнія, звязаныя даты і адзін URL у дзвюх кампаніях разрэшваюцца `id`-тайбрэйкерам; фільтраваны праход `status=raw&city=gdansk&limit=5` ідзе па тым жа правіле ўжо ўнутры фільтра. Устаўка паміж запытамі: радок старэйшы за курсар дасяганы на наступных старонках (без прапуску), радок навейшы — правіла кэйсэта пакідае яго за курсарам (без паўтору), паўторных ідэнтыфікатараў ніякіх.
4. **Няправільныя ліміты і курсары — 400 з прычынай да SQL (AC4).** `invalid_page_input_is_400`: ліміты `0, -1, 2.5, 101, abc, +5, 1e2, « 5», 5.0` — 400 «патрэбны цэлы лік ад 1 да 100»; пусты `limit=` — «не параметр» (200). Курсары: мусарныя байты, не-JSON, не-аб'ект, пусты `u`, невядомы статус — 400 «Курсор не чытаецца»; курсар з іншымі фільтрамі (горад, статус, іх адсутнасць) — 400 «несупадае з фільтрамі запыта», той самы запыт без курсара — 200 (новы перабор). Прычына рэндэрыцца праз `escapeHtml` — `<script>` у значэнні застаецца тэкстам. Разбор ідзе да любога `db.prepare/.all` — рэгулярны шлях парсінгу цалкам перад запытам.
5. **Усё знешняе — параметры і экржаніраванне, межы не пашыраныя (AC5).** Курсарны прэдыкат мае дзесяць `?`-параметраў (значэнні `c/u/i` звязаныя, нідзе не склейваюцца з тэкстам SQL), фільтры горада/статусу — як і раней bound; увесь HTML — існы `escapeHtml`/`pageShell`. Сервер слухае `127.0.0.1` па-ранейшаму (`startDispatcher` не мяняўся), крама адчыняецца `readOnly: true`, ніякі запыт не піше ў сховішча (існы тэст «no request writes» зялёны).
6. **План запыту — індэксны пошук; картка захоўвае ўсе доказы (AC6).** `link_count_uses_record_index`: `EXPLAIN QUERY PLAN` карэляванага падзапыту лічбы спасылак (та самая форма, што ў `recordsData`) — `SEARCH l USING COVERING INDEX links_record (raw_record_id=?)`, без `SCAN links`; картка запіса па-ранейшаму рэндэрыць усе радкі спасылак (анкер/адрас/кантэкст).

## Кантракт → рэалізацыя

- **Курсар** — base64url JSON `{c, u, i, city, s}`: апошні ключ парадку (дата з пустымі значэннямі, url, id) + нармалізаваныя фільтры, пад якімі ён пабудаваны. Гэта даныя, не права доступу: палі тыпізуюцца пры чытанні, фільтравыя значэнні параўноўваюцца з запытам, у SQL — толькі як параметры.
- **Кэйсэт-прэдыкат** — чатыры сегменты: старэйшыя непустыя даты; любы радок пры пустой уласнай дате, калі ў курсара дата ёсць; звязаная дата, разрэшаная `(url, id)`; звязаныя пустыя даты, разрэшаныя `(url, id)`. `id` — PRIMARY KEY, таму парадак поўны, тайбрэйкэр вызначаны.
- **Наступная старонка** — толькі калі старонка поўная (кароткая старонка — канец); спасылка нясе фільтры, выбраны ліміт (калі не змаўчанне) і курсар — адрасны радок застаецца падзельным бачаннем, як і ў фільтравай бары. Лінкі фільтраў курсара не нясуць — змена фільтра = новы перабор.
- **Паводзіны заўвагі** — вядомыя параметры спісу пашыраныя да `status, city, limit, cursor` (абноўленае чаканне існага тэсту невядомых параметраў); ніякія іншыя паводзіны заўваг не змяніліся.
- **Схема** — адна строчка індэкса + каментар; `media_record_file` і ўнікальнасць медыя не кранутыя, іншая схема без зменаў.
