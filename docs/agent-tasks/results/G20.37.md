# G20.37 — шэсць пераносных набораў у Windows CI

Дата: 2026-10-22. Задача: [#817](https://github.com/vokhandcrafts/KUDY/issues/817). Галіна: `codex/817`.

## Межы і дазвол

Рашэнне аператара ў [#493](https://github.com/vokhandcrafts/KUDY/issues/493#issuecomment-5956926031) дазваляе portable Windows tests у `.github/workflows/*.yml` без змены правоў, назваў required statuses і налад dispatcher. Залежнасці #816 і #493 закрытыя.

## Прыёмка

1. Дазвол #493 правераны, спасылка змешчаная ў каментары да Windows-задачы.
2. `windows-portable` захоўвае ранейшыя праверкі і дадае `npm ci` у корані і `web/`, пасля чаго запускае шэсць файлаў: `adapter-revert-guard`, `windows-android-build-guard`, `check-messages`, `generate-messages`, `attribution-guard`, `exported-language`. Пачатковы Windows CI меў збой на SHA `95ce4d0`; пасля выпраўлення CRLF і дадання рэгрэсійных тэстаў патрэбны новы паспяховы запуск.
3. `tools/ci/check-required-checks.mjs` правярае поўную актыўную каманду менавіта ў `windows-portable`, а таксама абодва крокі `npm ci`. У `tools/ci/windows-android-build-guard.test.mjs` дададзены адмоўныя праверкі выдалення, каментавання, пераносу ў іншы job, згадкі ў каментары і выдалення аднаго набору. Пасля рэв’ю дадзены два адмоўныя тэсты на выдаленне root/web `npm ci` і станоўчая праверка workflow у CRLF-фармаце.
4. Правераны папярэдні CI run [39813156040](https://github.com/vokhandcrafts/KUDY/actions/runs/39813156040) на `95ce4d0`: `windows-portable` скончыўся з памылкай (49 тэстаў: 47 pass, 2 fail). Grok адзначыў памылку супастаўлення LF/CRLF і недастатковыя адмоўныя тэсты. Пасля выпраўленняў каміт `8d71f5d0850116f8a425649d3ed84e7683b3415c` у [CI run 39836509644](https://github.com/vokhandcrafts/KUDY/actions/runs/39836509644) прайшоў `windows-portable`: крок шасці набораў — 52 pass, 0 fail, 0 skipped; абодва `npm ci` паспяховыя, існыя Windows-крокі таксама паспяховыя. Новы SHA пасля гэтай дакументальнай праўкі патрабуе ўласнага CI; папярэдні вынік не пераносіцца аўтаматычна. Дакладныя наладкі required-status ruleset патрабуюць асобнай праверкі; іх не змянялі.

## Праверкі і абмежаванні

Каманда шасці набораў у workflow:

```bash
node --test --experimental-strip-types --experimental-test-module-mocks tools/ci/adapter-revert-guard.test.mjs tools/ci/windows-android-build-guard.test.mjs tools/i18n/check-messages.test.mjs tools/i18n/generate-messages.test.mjs web/lib/content/attribution-guard.test.ts web/lib/content/exported-language.test.ts
```

На 2026-10-22 незалежнае рэв’ю Grok на старым SHA знайшло 1 High і 2 Medium: памылка CRLF, адсутныя адмоўныя тэсты для `npm ci`, нязапісаны вынік CI. Памылка CRLF выпраўленая нармалізацыяй толькі пры чытанні YAML у guard. Дададзены рэгрэсійныя тэсты CRLF і адсутных крокаў root/web install.

Лакальны shell, які выконвае каманды ў працоўнай копіі KUDY, у гэтым падключэнні недаступны. Таму лакальныя `npm test`, `npm run typecheck`, `npm run arch:check`, `jscpd` і адмоўныя пробы пакуль не пацверджаныя; вынікі PR CI нельга падмяняць сцвярджэннем пра лакальны прагон. Showboat не патрабуецца: зменены толькі workflow, яго незалежная праверка і тэст, без runtime-паводзінаў.

## Самаправерка аўтара

Правераныя назвы ўсіх шасці файлаў, межы `windows-portable`, сталыя імёны job і незменныя правы і action SHA. Для папярэдняга SHA незалежнае code review праведзена, вердыкт адмоўны; на новых зменах яшчэ патрабуюцца паўторнае рэв’ю і новы рэальны Windows CI.
