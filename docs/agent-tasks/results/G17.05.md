   preference lives in exactly one place (`pickLanguage`: `subtitles` before
   `automatic_captions`, the video's original language first). The AC2 test

## Decisions and deliberate trade-offs

- **Two-phase invocation keeps the preference in this repo.** Phase 1 dumps
  the video JSON (`--dump-json --skip-download`), `pickLanguage` chooses
  kind+language, phase 2 writes exactly one VTT (`--sub-langs <lang>`). The
  AC2 revert proof targets repository code, not a yt-dlp flag combination; it
  also avoids downloading every automatic-caption language.
- **Paragraph = cue.** The transcript anchors each VTT cue at its start
  second; no pause-based paragraph merging (that is G17.06 cleaning work).
  Rolling auto-caption overlap collapses consecutive identical texts.
- **The passport row is untouched.** `raw_records` keeps the G17.01.a shell
  semantics; the pipeline fills content_hash/snapshot_path/media_dir via
  `fillYoutubeRecord` (named UPDATE, not an upsert-semantics change). Video
  metadata lives in `metadata.json` — the passport columns have no
  title/channel fields, and the schema is the spec's verbatim list.
- **The binary sits behind `createYoutubeFetch({ command })`.** Tests pass a
  stub command (`[node, stub.js]`) and drive the real spawn, stdout-JSON
  parsing, VTT reading and diagnostics — no mock of the pipeline, no network.
  The live yt-dlp run stays manual; **no yt-dlp version is pinned in this
  results file because the host has no yt-dlp installed** (checked
  2026-09-25) — the pin lands here when the operator installs it for the
  pilot run.
- **Shared loop-mechanics fixtures moved off the default youtube id.** The
  G17.05 youtube step now spawns the real binary by default, so
  `testkit.campaignYaml`'s default campaign carries `youtube: []`, and the
  loop tests that want a youtube step use the in-process
  `youtubeBacklogFetch()` (every video lands in backlog — deterministic, no
  spawn). The pipeline suites pass real video ids with the stub command.
