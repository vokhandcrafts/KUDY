## Decisions recorded

1. **File workspace, not the SQLite tool.** Doc 07's «тэхнічны мінімум» (CLI + SQLite + vector search) is the separate authoring tool — a future breakdown per the issue's out-of-scope line. G03.01 verifies the *process*: committed files + machine checks are sufficient and auditable; the tool can adopt the same file vocabulary later.
2. **The real input stops at `pending` — the agent does not self-approve.** The `approved` transition is machine-verified on the synthetic `valid-approved` fixture (with a recorded reviewer entry), because setting `approved` on the agent's own text would be exactly the auto-publish the task forbids. The founder's так/не marks on the six real claims are the next human step; the report is the review surface.
3. **Canon names verbatim (rule 2):** `review {by, at, decision}` and the `decision` enum come from the story schema; `rights` values from doc 07; the id pattern from the identifier schema. New authoring-local vocabulary (`mark`/`mark_by`/`mark_at`, block kinds) is documented in `authoring/README.md`, not smuggled into the bundle format.
4. **Locator convention:** `paragraph` counts from the article start (page breaks mid-sentence do not start a paragraph), `page` is the print page where the quote physically sits; documented in the workspace README and in the source register note.
5. **First source choice:** EB1911 «Danzig» (unsigned article, pre-1930s, public domain). The medieval crane (Żuraw) — the natural first-story candidate — is absent from that source, so the walkthrough subject is St Mary's Church; topic/stop composition of the first real guide remains the author's call in G03.02.
6. **The checker parses through corruption** (rule 14): null elements, wrong types, broken JSON all answer as named diagnostics; the report renderer refuses to render a workspace that fails the checker instead of half-parsing.
