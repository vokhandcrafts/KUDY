# G06.01.b — Guide preview: metadata and the single main button

**Status: complete.** Branch `zcode/314` (closes issue #314 on merge). The
third surface of the canonical chain — the guide preview (RouteDetail, 09
§6.5) — renders the published route facts with the one main button whose
meaning follows the real package state, `Download → Start`; after this part
the chain Горад → Гіды → прэв'ю works end to end and the parent issue #62
acceptance can be checked.

## What was built

- `services/catalog/types.ts` — the preview view model: `PreviewStop`
  (stopId, position, placeId, `placeName` — added by PR #359, tier,
  `locked`, name/announce localized or
  null, optional), `GuidePreview` (the card's canon facts plus the route
  document's: `routeAccess` verbatim `free_base`|`paid`, the recommended
  time as the offer's `estimated_duration` range or the route document's
  `duration_min`, `freeStopCount`, `baseSizeBytes` from the catalog entry's
  `sizes.base`, ordered `stops`, `degradedRouteDoc`) and
  `PreviewLoadState` (ready with a degraded note / `not-published` /
  error). `CatalogService` gained `loadPreview(routeId, previous)`.
- `services/catalog/catalogService.ts` — `loadPreview`: the envelope read is
  shared with `loadCatalog` through one `readEnvelope` helper (the 09 §4
  failure policy per caller: cards fall back to the cached list, the preview
  to its previous projection); the route document is fetched from the
  build-bundle public layout `bundle/<route_id>/<version>/route.json` through
  the same origin loader, the composed path checked against the shared
  `isSafeRel` idiom (catalog-sourced ids are untrusted input, 21 §3.3). The
  document is projected only into its public fields: identity faults
  (id/position/place_id/access_tier) drop the row, label faults render the
  row without the label, a foreign or corrupt document fails closed to
  `route-doc-corrupt` with `stops: null` — nothing is invented. Locked =
  an extended-tier stop or any stop of a `paid` route (11 §16.4); an unknown
  route `access` locks every stop (fail closed). A stops array whose every
  row failed the identity checks is corruption, not an honest zero —
  `stops: null` + `route-doc-corrupt`; a published empty array stays the
  true «Кропкі: 0». The preview's offer pick follows the #324 duplicate
  contract: the same sorted-first offer (editorial_order, then offer_id —
  the shared `byEditorialOrder` comparator) the city list dedups to, never
  an arbitrary duplicate. The offer→card mapping is
  shared with the city list through one `offerCard` helper (implementation-
  rules 3, 8).
- `controllers/catalog/previewController.ts` — the vanilla store (G06.09.b
  helper), one instance per opened route (the root hands a factory, the
  screen creates per mount), boot load at creation, the monotonic run
  counter (a superseded refresh never overwrites the newer result). The
  pure `derivePreviewButton` is the only place the button is written from
  the real facts: the asked base layer's inventory state (09 §7:
  `not_downloaded` → `partial` with the missing count → `ready` → `stale`)
  decides Download vs Start; when ready, the contentRepo verify verdict
  decides Start enabled vs disabled with its named reason; a paid route
  without an entitlement never starts and buys nothing (AC2, NAV6 — the MVP
  root has no entitlement source yet, G08 wires it); an absent port fails
  closed with its reason (11 §7), it never guesses a state. `download()`
  triggers the G04.02 activation port and re-derives from the refreshed
  inventory — the flip comes from the disk facts, never from the activation
  result (the task's Proof; the test keeps a `complete` result honest by a
  not-downloaded disk). `start()` gates the §4.1 dialog: a live session of
  another route opens the single confirm dialog with both titles,
  «Скасаваць» changes nothing (NAV8); the same route or no session hands
  over. The port set: `inventory`, `evaluate`, `download`, `runSession` —
  all optional, all absent on today's device build until their adapters
  land (TR-10 filesystem, G08 entitlement), so the device button is honestly
  fail-closed.
- `controllers/catalog/usePreviewController.ts` — the React binding (hooks
  as controllers, 19 §2.2) over the per-route factory; no preview service →

- `controllers/createServices.ts` — `Services.preview` (the per-route

- `app/route/[id].tsx` — the real preview surface (the G06.09.a placeholder

## Acceptance criteria (issue #314)

1. **Metadata is visible** — languages per `availability` (the text/audio
   split; L01 holds: no audio locales → no audio promise), the recommended
   time (`estimated_duration` range, else `duration_min`), open and locked
   stops distinguishable, locked stops show name, place, announce and lock
   only — the route document's stop entries carry only public preview
   fields, so no full text/transcript/media can render (NAV5).
   `previewController.test.ts` (assembly + derivation), `preview.test.tsx`
   (render).
2. **Tariff is not mixed** — the free/paid badge (the canon badge of
   G06.01.a); the paid preview shows `free_stop_count` and does not start —
   the button is disabled with «патрэбна пакупка» and pressing it starts no
   run and opens no purchase (NAV6, D06, 11 §7).
3. **One main button** — `Download` while the base layer is
   `not_downloaded`/`partial`/`stale`, `Start` when ready and verified; the
   state derives from the real inventory (the revert experiment proves the
   tests fail without the derivation); after the download completes the
   same button becomes `Start`; `Start` with an active/paused session of
   another guide opens the single §4.1 dialog and «Скасаваць» changes
   nothing (NAV8).
4. **Back to the source surface** — the opening records `city`/`rubric`
   (the MVP sources; the registry accepts collection/hint later), Back
   pops to the surface the preview was opened from, session/audio/progress
   untouched (NAV9, 11 §16.2).
5. **Verify failure and green gates** — a `needs-recovery`/`incomplete`
   verdict leaves Start unavailable with the named reason while Download
   stays the repair path; `npm run typecheck`, `npm test`, `npm run
   arch:check`, `npx expo-doctor` green; layer rules intact (arch:check, 0
   new violations).
