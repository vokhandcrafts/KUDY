## What was done

The schema-owned content locale allowlist is expanded from be/en/uk to be/en/uk/de/es/fr/cs/sv, and text vs audio availability stays independent verified facts:

- **Schemas (the owners)** — the locale enum `"be", "en", "uk"` grows to the eight codes in all seven schemas that carry it: `localized-text` (propertyNames — the allowlist owner), `catalog` (routes[].locales), `discovery-index` (3× propertyNames, `text_locales`, `audio_locales`), `media`, `voice`, `place`, `feedback-target` (2× locale). The `localized-text` description now states the eight-code allowlist and cites the G21.16 expansion instead of the reserved-locale MVP note.
- **Wire projection** — `contracts/wire/wire-types.ts` regenerated via `npm run contracts:wire` (`SCHEMA_LOCALES`, `Locale`); nothing hand-edited. The wire guard test expectation follows the derived owner order.
- **Publisher/validators** — the three verbatim restatements updated with their canonical-source comments intact: `tools/build-bundle/build-bundle.mjs` `LOCALE_ALLOWLIST` (packager tree narrowing — a non-allowlist top-level directory still fails as `unknown-author-entry`), `tools/validate/validate-authoring.mjs` `LOCALES` (locale-id-mismatch), `tools/validate/validate-package.mjs` `MEDIA_LOCALES` (media-locale-mismatch). The supabase feedback edge function mirror `REGISTRY_LOCALES` follows the `feedback-target.schema.json` enum it documents; the pglite guard expectation follows the schema contract.
- **Canon** — `docs/architecture/21_discovery_feedback_architecture.md` limits table row now states the eight-code allowlist with the G21.16 pointer (the «≤ 8 per object» limit and the max-8 coding note stay, now over 8 codes), and the «нельга незалежна перапоўніць» sentence reads «пры 8 кодах allowlist». Dated resolution pointers appended to `results/G14.04.b.md`, `results/G14.04.c.md` and `results/G21.09.md` whose triplet-time statements would otherwise mislead (implementation-rules 8).
- **New behavioral tests** — `tools/build-bundle/build-bundle.test.mjs` «G21.16: fr text yields from its shipped files; audio_locales stays fr-free»: a synthetic fr text layer (uk base shape + `voice-fr-1` + French demo strings, no fr audio) builds and the guide offer yields `{text_locales: ['be','en','fr','uk'], audio_locales: ['be','en']}`. `tools/validate/validate-package.test.mjs` «G21.16: fr text with shipped files passes audio-free; claimed fr audio without files fails»: the same tree validates clean with fr text and no fr audio, and the claimed fr audio without published audio files fails with exactly `audio-locale-without-files` at `discovery.json#offers[0].availability.audio_locales#fr` — the boundary behavior over the expanded domain, one violation per fixture (implementation-rules 14).
- No allowlist duplication added: readers/services keep consuming the computed facts (`text_locales`/`audio_locales` from files), and the new codes never widen to arbitrary strings (schemas stay closed enums; `pl`, `ua` and other codes stay rejected — the `index-invalid-unknown-locale.json` conformance fixture is untouched and still fails on `enum`).

## Acceptance criteria walk

1. **Schema-owned allowlist expanded to the eight codes, wire projection regenerated, no duplication in readers/services, no arbitrary strings.** All seven schema enums updated (localized-text is the owner the generator derives from); `contracts/wire/wire-types.ts` is the regenerated output and `contracts:wire:check` is fresh on the final tree; the generator's same-set assertions (owner ↔ catalog.routes[].locales) pass unchanged; the packer, the validators and the feedback registry still reject codes outside the enum (`unknown-locale`, `unknown-author-entry`, schema `enum` diagnostics).
2. **Owners updated consistently; existing limits, unknown-locale rejection, path checks and raw-byte pins retained.** localized text, catalog/discovery, media/voice and feedback-target enums plus their three tool restatements and the supabase mirror move together — the feedback suites read the constant against the committed schema file and stay green; limits (maxItems/maxProperties 8, byte/length caps), unsafe-segment checks and the sha256/bytes media pins are untouched and their tests pass unchanged.
3. **A valid fr-text/no-fr-audio package yields text_locales including fr while audio_locales stays limited to actual media.** The build-bundle G21.16 test proves the computed index; the validate-package G21.16 test proves the same tree passes the boundary; the Showboat demo prints both on a synthetic tree.
4. **Backward-compatible be/en/uk fixtures validate; malformed/unknown locale and an unbacked audio locale fail at the boundary.** The demo suite (be/en/uk) validates with no errors and no warnings, `index-valid.json` and the catalog fixtures pass, `index-invalid-unknown-locale.json` still fails on `enum` (criterion-5 conformance test); the claimed-fr-audio-without-files case fails with the named rule, and the corrupt-availability `type` diagnostics are untouched.
