# G21.09 result — Use one UI locale registry and complete typed message catalogues

Date: 2026-10-04 (claim [2026-10-04T00:58Z](https://github.com/vokhandcrafts/KUDY/issues/542#issuecomment-5975258366)). Branch: `zcode/542` from main `7539d8d`.

## What was done

The one UI-locale registry and the shared typed message contracts, built on the G21.24 canonical records (`46cddb1`):

- `contracts/ui-locales.ts` — the one registry: the eight requested UI codes with their native names verbatim (be/Беларуская, en/English, uk/Українська, de/Deutsch, es/Español, fr/Français, cs/Čeština, sv/Svenska), the `UiLocaleCode` union, the `CompleteUiLocaleCode` subset (be/en/uk — the codes with full catalogues today), the registration/completeness predicates, the native-name accessor and the `completeUiLocaleSelfNames()` record the chrome catalogs embed. UI display locales stay a separate vocabulary from the published content-locale allowlist (`contracts/schemas/localized-text.schema.json`, untouched).
- `contracts/ui-message-types.ts` — the reusable native message interfaces moved verbatim (comments and issue anchors included) into the pure contract zone: `AccessKind`, `UiStrings`, `PlaceDetailStrings`, `NearbyStrings`, `OfferStrings`, `GuideHintStrings`. The key/parameter contract is the TS projection of the G21.24 canonical records: every record resolves to its catalog leaf and the leaf's runtime shape matches the record (guarded by the new test). Deliberately not moved: `RunMapStrings` (bound to the engine's `StopStatus` in `core/engine/state.ts` — the contracts zone must not import core) and `PreviewStrings` (bound to the controller-owned `PreviewReason`/`PreviewDetail` vocabulary); their records are still guarded through the same runtime walk, and `web.ui` stays with the web channel's own parity tests.
- Adapters consume the registry: `controllers/uiLocaleStore.ts` derives its closed vocabulary from `COMPLETE_UI_LOCALES` (the unknown-input semantics unchanged — a planned code throws the same named `UiLocaleError`, the state never moves); the My KUDY language row (`app/(tabs)/my.tsx`) derives its options from `COMPLETE_UI_LOCALES` and its labels from `uiLocaleNativeName` — the picker advertises only registered complete catalogues; the chrome catalogs' `languageSelfNames` embed `completeUiLocaleSelfNames()` so the self-name words live only in the registry table; `web/lib/i18n/index.ts` ties its advertised routes subset to `CompleteUiLocaleCode` at the type level (uk keeps its complete strings file but stays off the live routes per the uk release unit — a subset, not equality).
- Tests (standard runner): `test/ui-locale-registry.test.mjs` — the eight entries verbatim, the complete subset, per-locale native family completeness, the store semantics; `test/ui-message-types.test.mjs` — the key/parameter walk of every native record against its catalog leaf (plain → string, template/composed/discreteForms → callable with the record's parameter count), with a structural assert that no imported domain dropped from the guard. The existing parity/inventory suites run untouched and green.

> Resolution 2026-10-06 (G21.22, issue #554): the web routes subset above is historical — the live web route set now equals the complete eight-locale set (be/en/uk/de/es/fr/cs/sv), overriding the uk release-unit coupling by the approved G21.00 decision; see `docs/agent-tasks/results/G21.22.md`.

## Acceptance criteria walk

1. **The eight requested UI codes and native names defined once; UI locale types distinct from content availability.** `contracts/ui-locales.ts` carries the verbatim table (asserted by the registry test); the file documents the separation, the content-locale allowlist file is untouched, and no content-availability semantics entered the registry.
2. **Reusable native message interfaces moved to the shared pure contract zone; key/parameter contract derived from the G21.24 canonical records; existing selector exports and dynamic-message behavior preserved; no i18n runtime dependency added; no second manually maintained source/context catalogue.** Five self-contained families moved verbatim into `contracts/ui-message-types.ts` (pure zone — relative imports only, no runtime code); `components/ui-strings.ts` and the three controllers import the types and re-export them (`export type { ... } from ...`), so every existing export and caller stands. The two engine-bound families stay put with the reason anchored in the contracts file header. The derivation is enforced the other way: the records walk the runtime catalogs (shape + arity), and tsc ties the catalog objects to the moved interfaces — neither side can drift without a red gate. No new runtime dependency; the authoring surface stays `contracts/ui-messages/source.json`.
3. **All message domains inventoried, including guideHintStrings with its uk fallback.** The canonical inventory (234 records over native.chrome/native.preview/native.run/native.place/native.nearby/native.offer/native.guideHint/web.ui) predates this task (G21.24); this task's guard walks every imported native domain and fails if one drops out; `GuideHintStrings` is typed in the contract zone with the uk→be fallback stated on the interface (the uk catalogue for this domain arrives with the translation data, not here). The registry test's family walk covers chrome/preview/run/place/nearby/offer per complete locale.
4. **The selector/picker exposes only registered complete catalogues; unknown inputs keep the approved semantics.** The store vocabulary is now literally `COMPLETE_UI_LOCALES`; the My KUDY row advertises exactly those codes with the registry's native names; the web routes subset is type-tied to `CompleteUiLocaleCode`. de/es/fr/cs/sv are registered, not complete, and advertised nowhere (asserted: `isCompleteUiLocale` false, `store.set('de')` throws `UiLocaleError`).
5. **Functional tests cover key/placeholder completeness and existing rendering; registry/key deletion detected through the standard runner; layer check clean.** The two new suites + the untouched inventory/parity suites; the deletion experiments ran in this session: removing a canonical record fails the inventory+guard suites (exit 1), removing a registry entry fails the registry suite (exit 1), both restored to green afterwards; removing an interface member fails `typecheck` (the catalog object no longer satisfies the moved interface). `arch:check` OK on the final tree.
6. **be/en/uk rendering unchanged; interfaces exposed for G21.25; authoring stays canonical.** No catalog word changed and no key was added or removed (the parity and inventory suites pass untouched; the only data-level change is `languageSelfNames` now embedding the registry-derived record — the same three values, from the single table). The moved interfaces plus the checker API (`loadUiMessagesSource`/`checkUiMessages`/`sourceHash`) are what G21.25 generates from; no callers changed.
