# G21.26 result — Reject missing, stale and unreviewed locale messages in the standard checks

Date: 2026-10-04 (claim [2026-10-04T11:02:00Z](https://github.com/vokhandcrafts/KUDY/issues/559#issuecomment-5979260006)). Branch: `zcode/559` from main `ff0bdc0`.

## What was done

The shipped-locale gate `tools/i18n/check-messages.mjs` now runs in the standard checks: a source change cannot pass `npm test` (the required CI path runs it on both node versions) while a shipped UI locale is missing, outdated or lacks the required review evidence, and message data that is not reflected in the generated outputs fails the same gate.

- The shipped-locale loop is derived from the shared registry — `COMPLETE_UI_LOCALES` from `contracts/ui-locales.ts`, never a fixed be/en/uk list. A language joins the gate the commit it joins the registry (G21.10–G21.14 need no gate change).
- Planned coverage, not assumed coverage: the required (locale → message ids) set is derived from the generator's output plan (`DOMAINS`, now exported from `tools/i18n/generate-messages.mjs` — the plan's single owner; the gate restates no plan data, and the two selection predicates it mirrors are guarded by the green-tree test and the freshness leg). The documented uk `guideHint` be-fallback (uk-release-scope §6.4) stays legal because the plan does not render those records for uk; a genuinely planned message without a record fails as `missing_locale_key` with locale/key/reason. A shipped locale whose translation file is absent fails as `missing_locale`.
- The per-file translation contract (`translations.mjs` — schema, extra/blank keys, placeholder and form compatibility, `stale_translation_denied` on a changed source) surfaces through the gate as `translation_contract` with the loader's named reason; the source contract surfaces as `source_contract`. Corrupt files answer with diagnostics, never a throw.
- Review evidence is enforced: a shipped record's `review.outcome` must be `approved` (`review_evidence_required` — the missing-evidence and blind-hash-bump cases). A review pass that is not the original migration (`provenance.kind` ≠ `migration`) must give every record its renewed-review reason (`review.reviewedSourceHash` may be bumped only together with a `review.note` — `review_reason_required`): a valid unchanged translation survives a source change with an explicit renewed review and reason, not a blanket hash swap. The pass format itself (what kind string the source-change commit uses, G21.19's process) is G21.19's to define; the gate rejects undocumented passes from day one.
- Generated freshness rides the generator's own `--check` (invoked through its `run` seam — the plan and the byte comparison stay single-owned): problems surface as `generated_output_stale`. The freshness leg runs only when the data-level gate is clean, so fixtures without generated outputs still produce precise diagnostics.
- Wiring: the behavioral suites live in `tools/i18n/check-messages.test.mjs`, discovered by the existing `tools/i18n/*.test.mjs` glob of the `npm test` script (the glob G21.25 joined) — no workflow edit. `test/app-jest-wiring.test.mjs`'s idiom is reused: `standard_runner_enforces_messages` asserts the script discovers the suite and its controlled removal cases (token dropped, token narrowed) flip the answer to false. Human/CI convenience script: `npm run messages:check`.
- `contracts/README.md` gained the «Гейт выпушчаных моў UI-паведамленняў (G21.26)» section replacing the forward reference in the G21.25 section.

## Acceptance criteria walk

1. **Every shipped locale validated from the shared registry; missing/extra/empty keys, incompatible placeholders/plural forms and mismatched reviewedSourceHash fail with locale/key/reason.** The loop is `COMPLETE_UI_LOCALES` (registry comment pins the catalogue-arrives-with-entry invariant). Missing key: `missing_locale_key` names locale, key and reason (`missing_locale_key` test on a controlled fixture, single problem, no unrelated noise). Extra/empty keys, placeholder/param and form mismatches, hash mismatch: the translation-set checker's named rules surface through `translation_contract` with the record path (`stale_source_hash` test asserts `stale_translation_denied` and `$.records[id=…].reviewedSourceHash` for every affected locale). Missing file: `missing_locale`.
2. **Changing source text/context/parameters while keeping old translation metadata fails; blind hash replacement without the required review record fails; a valid unchanged translation needs an explicit renewed review and reason.** The controlled source edit recomputes the record fingerprint (text + context changed, hash consistent) and the gate fails every shipped locale pinning the old hash (`stale_source_hash`); a bumped pin with `outcome: unreviewed` fails `review_evidence_required`, and a re-review pass that bumps pins without per-record reasons fails `review_reason_required` (`unreviewed_hash_bump`, both variants). The positive counterpart carries notes on every record (`valid_same_commit_update`).
3. **Missing/stale review evidence and required terminology provenance rejected; generator --check failure on edited data reflected in the gate.** Review evidence: outcome rule above. Terminology provenance: the file-level `provenance` (kind/reviewer/evidence) is enforced by the translation-set contract the gate loads through; the per-record terminology lookup provenance is assigned to G21.27 by the schema's own description («Паходжанне тэрмінаў … — G21.27») and will ride the same gate the commit its schema extension lands — no gate change needed. Generated freshness: `generated_output_stale` names the stale file when data is clean but outputs are not regenerated (`generated_output_stale` test).
4. **The actual repository check runs through the standard test/required CI path with controlled missing-key, changed-source, missing-evidence and removed-wiring cases; no optional-only green gate, no workflow edit.** The gate's real-tree green test plus every controlled case run inside `npm test` (`.github/workflows/required-checks.yml` runs `npm test` on node 22 and 24 — untouched). Removed-wiring: the guard's controlled cases (`standard_runner_enforces_messages`) fail when the discovery token is dropped or narrowed; the revert experiment ran in the shipping session — removing the token from `package.json` turned the guard red, restoring it turned the suite green.
5. **A fully reviewed same-commit update across all shipped languages passes.** The `valid_same_commit_update` fixture: source record edited (text + context, fingerprint recomputed), both shipped sets re-reviewed (kind, reviewer, evidence, per-record notes, renewed pin), outputs regenerated into the fixture root — the gate returns clean end to end, freshness leg included. The check proves mechanical completeness/freshness/evidence, not semantic translation quality (criterion 5's own wording); the semantic responsibility stays with the recorded review.

## Notes

- `contracts/README.md` also fixes the pre-existing mixed-script token «Versіяваны» → «Версіяваны» (implementation-rules 12 scan hit on the file the gate section lands in; one character, no behavior).
- Stateless-gate residual, stated openly: a hash bumped while the file's `provenance.kind` still reads `migration` and the outcome stays `approved` is indistinguishable from the original migration without external state — the gate cannot see it, and the criterion-5 framing (mechanical completeness, recorded review responsibility) plus G21.19's mandated pass format (kind + per-record reasons) close it at the process level. The gate rejects every undocumented re-review pass it can see.
- The `messages:check` script is a convenience surface for humans and demos; the enforcement path is the npm-test-discovered suite, and its wiring is guarded (the guard's own removal — deleting the suite file — remains the corpus-accepted residual, implementation-rules 7).
