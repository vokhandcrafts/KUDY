# G06.06 — Screen schemes and transitions

Issue #179 · branch `zcode/179` · 2026-09-23 · executor: Zcode session (GLM-5.3-Flash).

Deliverables: `docs/design/screens-and-transitions.md` (canonical per-screen
schemes: transitions, Back/surface-source mapping, honest states, NAV mapping
table) and `test/screen-schemes.test.mjs` (coverage guard, wired into
`npm test`). State and screen names are copied verbatim from
`spikes/G06.08-prototype/package/screens.md`; the doc restates accepted
contracts (ADR G01.01–G01.03, `11` §16 NAV1–NAV11, `20/21`, `09` §6.5) and
changes none of them.

## Acceptance criteria — walked from the card

1. ✅ **Every package screen has a scheme with transitions and Back mapping,
   transitions citing NAV1–NAV11/ADR.** All 11 screens of `screens.md`
   (Explore, Guides, Guide preview, Place card, Collection card, Discovery
   result, Побач, Run, End, My KUDY, Feedback form) get a `### ` section with
   a «Пераходы» block; guard asserts verbatim heading equality with the
   package inventory, ≥1 NAV citation, ≥1 ADR/section citation and an explicit
   Back/«Прагулка» return per screen.
2. ✅ **Empty/offline/denied/error states described at scheme level.** The
   «Кантроль покрыцця станаў» table gives every screen one row × four state
   families; a family that cannot occur is refused with a reason («Няма — …»),
   not omitted. Canonical state names are used verbatim (`locked/playing/
   played/available/pending`, `draft → pending → sending → sent`,
   `conflict`, `action_required`, `finished`).
3. ✅ **One card, one path; exact/alternatives; temporary rating surface;
   delivery states.** Scheme sections 16.5–16.7 of `11` are mapped onto
   Place card / Collection card / Discovery result / Feedback form with the
   rules cited (21 §3.1, §4 rule 7, §5.1/§5.4; D02/D04/D06/D07; F01–F03; L01/L02
   in their host sections).
4. ✅ **Machine guard.** `test/screen-schemes.test.mjs`, 3 tests: inventory
   equality, per-screen transition citations, coverage-table completeness.
   Revert-verified: removing the doc → 3 failures; emptying one state cell →
   the coverage test fails; restored → 3/3 pass. Wired into the `npm test`
   file list so CI runs it.
5. ⏳ **Founder approval — human gate.** The PR review is the approval step;
   recorded in `docs/human-actions.md` for the merge moment.
