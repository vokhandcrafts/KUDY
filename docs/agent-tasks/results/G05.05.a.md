# G05.05.a — Durable Start and checkpoints (useRunController)

Issue #216 · branch `zcode/216` · 2026-09-25 · executor: Zcode session (GLM-5.3-Flash).
Note: the branch grew on the pre-scrub main (7c9e50d) and was rebased onto the
history-scrub rewrite of main (4d07bb4, which carries #266) before review; the
controllers tree is identical across the rewrite, and every gate below ran
fresh on the rebased HEAD.

`useRunController` is now the only writer of the durable `session` row: Start
gates on G04.03 readiness for the selected tier, inserts the row (version,
locale, play_seq=0, the R07 hint carry-over) in **one** transaction through
the services/db public API, and only after that commit dispatches the
engine's Start and lets it arm the location effects. The G05.04 orchestrator
gained two optional durability deps (its header note 7): the services/download
capability port — the only AccessReady delivery path into the engine, and the
`onCommitted` hook — the durability point that runs after `step()` committed
an event and before its effects fire, where the controller checkpoints the
monotonic sets and write-throughs `play_seq`. 15 scenario tests in
`controllers/useRunController.test.ts` drive the real orchestrator, pipeline,
reducer, both services (fake OS ports), the real db over the node:sqlite
adapter of G04.01 and the real contentRepo fixture package route-x@1.

## What was decided

- **Ports instead of service imports.** The arch matrix (issue #209 AC1)
  allows value-imports only in the composition root, so the controller
  declares `RunSessionStore` (start/checkpoint over services/db's public
  API), `RunReadiness` (G04.03 evaluation) and `RunPackageStops` (route.json
  parsing per layer); the tests wire them over the real services — the
  production path, not mocks (implementation-rules 15). The expected refusal
  of the store — the one-unfinished-session rule — comes back as a named
  result through the port; any other store failure keeps its original error
  and propagates.
- **Start order** (ADR G01.03 §3.3): conditions before the transaction
  (readiness → refusal names `package-incomplete` / `package-needs-recovery`
   / `package-access-locked`, straight from the G04.03 statuses), then the one
   INSERT + R07-carry-over transaction, then the engine dispatch and the
   location effects (armed subscription, seeded window). A document that
   vanishes between the readiness pass and the layer read (the fault injected
   at the stops port) refuses as `package-incomplete` with no effects armed
   — the guard's own negative test. The seed of
  `accessible_stop_ids` is derived per verified layer from route.json — the
  unlocks of past activations had no live session as addressee (ADR §3.5
  scope (b)), so Start carries them in; a document that changed under the
  Start refuses as `package-incomplete` instead of starting an unplayable
  walk.
- **The delta is a compare, not a re-statement.** `onCommitted` diffs
  `heard`/`auto_fired`/`play_seq` before and after the commit; anything that
  mutates nothing (a callback the reducer rejected, an AccessReady unlock —
  derived state only) writes nothing (criteria 3/4). One transaction per
  committed event, in event order; the store writes verbatim (G04.01).
- **play_seq write-through before effects.** Because the hook runs before
  `applyEffects`, the row carries the new `play_seq` before the audio command
  leaves; a failing write aborts the pending effects (ADR §3.3: effects only
  after commit) and surfaces — the store rollback semantics of a plain
  checkpoint stay the store's (§3.3: the next checkpoint writes the newer
  state).
- **AccessReady has no public entry.** The port's handler is registered
  inside the orchestrator where `dispatch` is private; no controller or
  orchestrator method accepts an AccessReady-shaped event, and a foreign port
  (real emitter, real payload, no handler of this controller) delivers
  nothing — the delivery path itself is the trust boundary (ADR §3.5).
- **G05.05.b surface deliberately absent.** Pause/Resume/End transactions,
  restart recovery and the pinned-version restore are not exposed: a
  half-durable Pause (checkpoint without the state UPDATE) would be worse
  than none, and the card's Out of scope is binding.

## Acceptance criteria — walked from the card

1. ✅ **Start runs only on a ready package, one transaction.** The suite
   covers the happy start (row fields verbatim: version, locale,
   `tier ['base']`, play_seq 0, state active, started_at from the injected
   clock), the R07 carry-over (carried guide ids move to session scope inside
   Start; an uncarried one stays foreground), the injected mid-transaction
   failure (two foreground rows for one guide → `guide-hint-transfer-failed`
   → zero session rows, both hints still foreground — no row, no half
   carry-over) and the three named refusals, each leaving zero rows.
   An extended start (`tier: 'extended'`, both layers granted) lands
   `['base','extended']` in the row and the engine.
2. ✅ **The one-unfinished-session rule holds through the controller.** A
   second Start over an active session returns
   `{ ok: false, reason: 'live-session-exists' }` — no throw, one row; the
   same refusal over yesterday's paused row arranged through the db's own
   public API. The store itself (pre-check + the `one_live_session` index)
   remains the arbiter.
3. ✅ **play_seq write-through before the audio command.** A subclassed audio
   service reads the durable row at the moment `play` runs: it already shows
   the launch's `play_seq = 1` before the fake port records the command. The
   crash-between scenario: the play call dies synchronously after the
   write-through — the row keeps `play_seq = 1` while no physical launch
   exists, and a later tagged `finished` pairs with nothing (no heard credit,
   no command). The demo's mutation (effects before the durability hook)
   turns both criterion-3 tests red.
4. ✅ **Checkpoints after accepted progress; rejected writes nothing.** An
   accepted AudioFinished checkpoints `heard ['story-b']` +
   `auto_fired ['stop-1']`; a suspended DwellCompleted checkpoints
   `auto_fired ['stop-2']`. A callback rejected by `step()` (focus regained
   past the 10-minute threshold closes the launch; the service's later
   `finished` still reaches the engine) leaves the row byte-identical.
5. ✅ **AccessReady only through the capability channel.** The real channel
   (emitAccessReady over the fixture's route.json) widens `tier_available`
   and `accessible_stop_ids`, rebuilds the geofence window and touches no
   durable fact (same-version unlock, ADR §3.5); a look-alike emission on a
   foreign port of the same run delivers nothing — tier, stops, window and
   row all unchanged.
6. ✅ **No clock, no GPS of its own.** Every timestamp comes from the
   injected clock (started_at = 42, not a wall clock), fixes arrive only
   through the location service, session ids through the injected mint; the
   wiring guard fails if a clock or geolocation API ever appears in the
   controller source.

## Rule-1 revert experiments (all in this session, all restored byte-identical)

- Dispatch order swapped (effects before the durability hook) → both
  criterion-3 tests fail (the issue's Proof).
- Access handler registration removed → the real-channel criterion-5 test
  fails (the look-alike test passes trivially without any channel — it guards
  isolation only on a wired channel; the pair is the guard).
- Checkpoint call removed → both positive criterion-4 tests fail; the
  rejected-callback test passes trivially (writes nothing either way — its
  value is the byte-identical row, not the revert).

## Proof

The demo's mutation run: on a temporary copy of the tree, the orchestrator's
dispatch order is swapped so the play command leaves before `play_seq` is
persisted — both criterion-3 tests fail (`not ok`, exit 1); on the repository
tree they pass. `node controllers/useRunController.test.ts` is wired into
`npm test` through the existing `controllers/**/*.test.ts` glob (the wiring
guard of G06.09.b keeps the glob enforced).
