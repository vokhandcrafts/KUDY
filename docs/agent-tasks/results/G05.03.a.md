# G05.03.a — Audio service: the single player and tagged callbacks

Issue #213 · branch `zcode/213` · 2026-09-24 · executor: Zcode session (GLM-5.3-Flash).

The first `services/` slice of the audio boundary: `services/audio/` adds
`types.ts` (the player port contract, the `PlayToken` shape restated from
`09` §6.1 — the module stays outside the engine zone, criterion 6),
`service.ts` (`AudioService`, a plain class over the injected port) and
`fake-port.ts` (the scripted test port). The port is created lazily on the
first play through a factory; `dispose()` drops the instance whole and the
next play re-creates it (19 §3.4 — re-creation, never reset). Each play
command carries the controller's token and an opaque service-issued source
key the port echoes on source-scoped events; that key is what lets the
service tag callbacks with the token of the source that produced them and
ignore a late event of a replaced source entirely (ADR G01.02 §3.5). Focus
events pass through verbatim and are never converted into finished. Playback
state is computed from a fresh port snapshot on every read; NaN, infinite or
negative millisecond values become a `failed` state with a reason, never a
number (09 §6.3). The acceptance suite is `services/audio/service.test.ts`
(17 tests); the expo-audio adapter itself is G05.03.b.

## Acceptance criteria — walked from the card

1. ✅ **One player: a second `play` stops the first by command before
   starting; rapid play/stop sequences end in the state of the last
   command.** `play()` issues `port.stop()` before the next `port.play()`
   whenever a launch is current; the fake port records the exact command
   sequence `play 1:a → stop → play 2:b` and counts a missing stop as a
   violation (empty in every test — reverting the stop turns criterion-1
   tests red). The rapid-sequence test walks play/play/stop/play and ends in
   `playing` with the last command's token, then `stop` → `idle`; only the
   last source can still finish.
2. ✅ **Every callback carries the exact token of its play command; after
   dispose and re-creation an old instance's callback is not forwarded.**
   The tagged test asserts the finished / `story_play_failed(token, reason)`
   / paused / resumed sequence across guide and moment plays with
   distinctive seqs. The event handler is bound to its port session: after
   `dispose()` the old instance's late `finished` and focus events reach
   nothing (per-session `alive` flag), while the re-created player's
   callbacks carry its own token.
3. ✅ **An interruption is reported as `FocusLoss` / `FocusRegain`, never as
   finished — for guide and moment plays alike.** The focus events are
   forwarded verbatim as physical facts (no token, no attribution); one test
   per owner kind simulates the call (focus loss + regain) and asserts the
   exact callback list `[FocusLoss, FocusRegain, finished(token)]` — the
   launch survives the interruption and its natural finish is still tagged.
4. ✅ **Playback state is computed from the port on read, not stored;
   position in milliseconds, never a 0..1 ratio; NaN / negative durations
   become a failure, not a number.** `playbackState()` reads the port
   snapshot on every call — the test rewrites the fake's snapshot between
   reads with no service call in between and observes the new state. The ms
   values pass through verbatim (`positionMs: 61000, durationMs: 125000`).
   Four corrupt snapshots (NaN, −1 and +∞ duration; NaN position) each yield
   `{kind: 'failed', token, reason}` with no numeric field; a port reporting
   playback while no launch is current yields a `failed` diagnostic with
   `token: null`.
5. ✅ **Dispose followed by play re-creates the player (no reset of a
   disposed instance).** The factory is called lazily — zero ports before
   the first play (19 §3.4 «стварэнне на першы Play»), one after, two after
   dispose + play; the disposed instance's command log ends at `dispose`
   and never grows, the new player receives the commands.
6. ✅ **The service imports nothing from `core/engine` and never decides
   about `heard`, queue or automation.** The suite tripwires the boundary:
   it scans all four module sources for `from '…core/engine…'` imports and
   fails naming the file (the prose may name the boundary it guards). The
   service surface carries only tokens, paths and physical facts — the
   tests prove it echoes tokens without interpreting them (the controller
   would derive `heard`, queue and automation from the callbacks). The
   zone-level gate `arch:check` stays green.

## Proof

Tag each callback with the *current* token instead of the token of the
source that produced it → the late-finish test fails. Verified in this
session: dropping the source-key check (`if (!launched) return;` instead of
`if (!launched || event.key !== launched.key) return;`) turns exactly
«criterion 2 proof: a late finish of play A after play B started is ignored,
not credited to B» red (A's finish would be credited to B) together with
«criterion 1: after rapid commands only the last source can still finish»
(15 pass / 2 fail); restored → 17/17. Showboat demo (required — runtime
behaviour, audio interruptions):
`docs/demos/2026-09-24-g0503a-audio-service.md`, `showboat verify` ✅
(exit 0), two consecutive runs of the script block byte-identical.

## Canon notes — decisions recorded (no shared doc edited)

- **19 §3.4 vs G01.02 (the brief's canon note):** the 19 §3.4 sketch tags
  callbacks by `(sessionId, playId)` only and shows
  `play(request {storyId, path, sessionId, playId})`. The implemented
  contract follows the canon source (ADR G01.02 §3.2, `09` §6.1): the
  command carries the controller's `play_token {kind, ref, seq}` (for guide
  tokens that IS the `(session_id, play_id)` pair), the finished callback
  echoes the token, and `story_play_failed(token, reason)` keeps its
  contract name. 19 §3.4 was not edited.
- **The port echoes an opaque source key, not the token.** The port cannot
  attribute a physical event to a launch without help, and the rejection
  rule needs that attribution to survive the async race (a replaced
  source's late `finished`). The service hands each play an opaque numeric
  key and maps it to the token; the port never invents or interprets one.
  This is the tagged-callback idiom one level down and it is what the proof
  scenario exercises.
- **`PlayToken` is restated in `services/audio/types.ts`,** structurally
  identical to `core/engine/state.ts`'s — the engine zone must stay
  unimported (criterion 6); the same camelCase boundary comment is declared
  once, as `state.ts` does. Mixed `type` discriminants
  (`story_play_failed` lowercase contract name, `FocusLoss`/`FocusRegain`
  verbatim event names) copy the canon spelling (implementation-rules 2).
- **`resume(token)` returns a boolean refusal** — ADR G01.02 §3.5: a resume
  with a closed or stale token is a command refusal, not a resume; the port
  is not touched. No invented callback, the boolean is the observable
  result.
