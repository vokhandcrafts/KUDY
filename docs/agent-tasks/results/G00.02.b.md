**Дата:** 2026-09-15

## Праверкі і доказы

Асяроддзе: Windows 10 (10.0.19045), Node `24.13.0`, npm `11.6.2`, git
`core.autocrlf=true`, `.gitattributes` адсутнічае.

1. `cd spikes/G00.02-offline-map && npm ci --offline`
   - Чакалася: lockfile усталёўваецца без сеткі.
   - Фактычна: exit 0, `found 0 vulnerabilities`.
2. `npm run reset-test-data && npm run prepare-data`
   - Чакалася: паводле README .a — чысты staging правяраецца і становіцца
     `status: ready`.
   - Фактычна: **збой** `Error: integrity mismatch: index.html` на
     `lib/package.mjs:16` да актывацыі.
   - Корань: `sha256(source/index.html) на дыску = d6d21bf763…`, у
     `source/lock.json` — `7952b44030…` (bytes 896); LF-нармалізаваная копія
     таго ж файла дае дакладна lock-хэш. На дыску файл мае 17 `CRLF`.
     `core.autocrlf=true` пераўтварыў LF у CRLF пры checkout; хэш-праверка
     пакета байт-дакладная — і таму чэсна падае. Спайк напісаны без уліку
     line-ending палітыкі checkout; гэта дэфект асяроддзя/спайку, не дадзеных.

   - Чакалася: 4/4 pass паводле result .a.

     `integrity mismatch: index.html` замест мэтавых сцэнараў (напрыклад тэст
     «missing style» атрымаў mismatch па `index.html`, а не чаканы `ENOENT`).
4. Ізаляцыя кораня: копія спайку ў часавы каталог з LF-нармалізаваным `source/`

   - Заўвага: гэта дыягностыка прычыны, не замена праверак на рэальным дрэве —
     на ім збой застаецца фактам (праверкі 2–3).
