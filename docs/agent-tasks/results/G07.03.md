# G07.03 result — Moments пры актыўным Run: сесія жывая, адзін уладальнік гуку і GPS

**Status: complete.** Branch `zcode/283-g0703` (closes issue #283 on merge).

## What was built

- `controllers/createServices.ts` — the root's own session routing (ADR G01.02
  §3.4/§3.8): the root resolves the ONE live walk surface from the G06.04 cache
  (`runSurfaces` — at most one live walk per the one-live-session rule, ADR
  G01.03 §3.1) and routes a place card's Play Moment, its manual stop and its
  live-pause resume into that surface's engine (`rootSessionMoment`:
  `playMoment`/`stopMoment`/`resumeMoment`). No registry, no second token mint —
  the resolver finds the live surface per call. The `ServicePorts.sessionMoment`
  provider value (the tests' port-shaped arrangement) overrides the root's
  resolver; without the provider the app build now routes instead of refusing.
- `controllers/run/runOrchestrator.ts` — `playMoment(momentId, storyId, path?)`
  carries the caller's resolved teaser path to the `PlayMoment` audio command
  (a one-shot `pendingMomentPath` carry by token seq — content resolution stays
  the controller's, the engine reads no manifest) and returns the port's
  acceptance fact: true iff the engine took the player for exactly this minted
  launch (ADR §3.4). Without a resolved path the launch keeps the G05.03.a safe
  failure (empty path → the real adapter fails it).
- `controllers/moment/momentPlayController.ts` — the sessionMoment port is
  extended with the routed `stopMoment`/`resumeMoment` (§3.4/§3.5): the manual
  stop and the live-pause resume of a session-owned moment launch this
  controller did not mint are routed back to the same engine — never a second
  command over the one player; a guide-owned launch is not the card's to stop.
- `controllers/useRunController.ts` — `RunControllerState.playMoment` exposes
  the engine's acceptance boolean and the teaser path parameter (the session
  entry the root resolver calls).
- No screen changes: the place detail's existing Play/Stop/Resume taps now
  route correctly through the controller decisions (`app/place/[id].tsx`
  untouched); the Run panel's re-entry already reads the cached surface (G06.04
  NAV7) and the engine's honest audio state.
- The named refusal over a session-owned player changes in the root-wired
  world: with the resolver present but no live walk to route into, the play
  answers `moment#session-refused` (the session entry declined) instead of the
  pre-G07.03 `moment#session-unroutable` (no session entry at all) — the
  unroutable case remains the controller-level one and keeps its coverage
  (`momentPlayController.test.ts`); `app/place/place.test.tsx` asserts the new
  root-level name.

## The honest boundaries (not-verified / named gaps)

- **The device player**: the suites and the demo prove the controller and the
  engine contracts over the fake player port (the G05.03.a harness idiom); the
  physical focus/ducking behavior on a real OS stays G00.01/G05.03's device
  proof — not verified on a device here (the same boundary G07.02 recorded).
- **The app build today passes no audio/location device adapters**
  (G05.02.c/G05.03.b are not landed), so the routed scenario stays unreachable
  on a device until they arrive; the wiring exercised here IS the root's
  production wiring — the same `createServices` call shape the app build makes
  once the adapters are provided.
- **The moment routing ignores a session-owned launch in `Idle`/`Ended`**: the
  resolver targets only `Active`/`Paused` walks (the engine's PlayMoment is
  reachable there only); an Ended walk's sounding moment stays the idle
  controller's launch (ADR §3.8 — a moment survives End), unchanged by this
  task.
