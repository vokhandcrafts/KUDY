## Вынік

Створаны негатыўны набор `spikes/G00.03-sandbox-grant/tests/` (zero-dependency, `node:test`, падключаецца да кода .а праз імпарты, код .a не зменены):

- **`harness.mjs`** — уласная пастаўка асяроддзя, адрозная ад .a: лічыльнік зваротаў да правайдара (`providerAsks`), вяртае `signingKey` (для падпісання токенаў «ад імя ўладальніка ключа»), магчымасць дзяліць `devicesFile` паміж дзвюма серверамі і падаваць `factory` (для мутата-копій).
- **`negative-grant.test.mjs`** (15 тэстаў): усе крывыя формы `Authorization` (адсутнічае, ніжні рэгістр схемы, Basic, пусты сакрэт, сакрэт без схемы) → 403 `device_auth_failed`; зламаны JSON з правiльным bearer → 400 `invalid_request`; 21 шлях (> MAX_PATHS) → 400; GET /v1/grant → 404 `not_found`; **адзін крывы шлях у batch адхіляе ўвесь запыт** — ніводзін URL не выдаецца і новага `grant_issued` у логу няма (няма частковага выканання); перавышэнне цела (70 КБ) — fail-closed: злучэнне скінута, ніводзін grant не выдадзены, сервер выжывае і далей абслугоўвае; **адмова не кэшуецца** — чужая прылада без пакупкі атрымлівае 403 `no_entitlement` пры кожнай спробе, падчас збою правайдара — 503 `entitlement_unavailable` (не grant, не кэшаваная адмова), пасля аднаўлення — зноў 403, і кожная спроба сапраўды пытае правайдара; **кэш падзелены па device** — паўторны grant уладальніка трапляе ў кэш (раўна 1 `entitlement_cache_hit`), а першыя grants дзвюх прылад абодва пытаюць правайдара; `cacheTtl=0` → тры grants = тры звароты да правайдара, нуль cache-hit; **кэшаванае права не абыходзіць manifest guard** — нячленскі шлях адхілены і з цёплым кэшам, наступны карэктны ідзе з cache-hit; **падпісаны токен — недастаткова** (6 варыянтаў са спраўджанай запошенай рыскай): чужы ключ, нячленскі шлях, traversal, backslash, абсалютны шлях, невядомы manifestBase → 403 `url_invalid` без байтаў файла; production-права супраць sandbox-сервера → 403 `environment_mismatch` (люстра .a-праверкі) + кантроль «аднолькавыя асяроддзі граюць»; пратэрмінаваны URL не ажывае пасля regrant (403 `url_expired`), новы URL працуе; гігіена логаў новых проб: ні сакрэтаў, ні device_id, ні `Bearer `/`receipt`, device_hash толькі 16-hex.
- **`guard-mutations.test.mjs`** (3 мутаты, mock-only): аднолькавы проб праганяецца праз **рэальны сервер** (адхілены) і праз **часовую in-memory мутата-копію `grant-server.mjs`** з адной выдаленай аховай (файл .a не рэдагуецца; копія пішацца ў temp, адносныя імпарты перапісваюцца на абсалютныя; супадзенне цэлі замены правяраецца `=== 1` — пры змене кода .a мутат гучна падае):
  1. выдалены device auth → ананімны проб выдае 200 з URL (рэальны: 403 `device_auth_failed`);
  2. выдалены manifest guard гранта → нячленскі шлях выдае 200 (рэальны: 403 `path_not_allowed`);
  3. выдалена download-ахова на `/private/` (membership + `startsWith(root)`) → падпісаны правiльным ключом escape-токен (`../../../..../server/grant-server.mjs`) чытае адвольны файл — 200 + байты зыходніка (рэальны: 403 `url_invalid`).
  Гэта і ёсць патрабаванне задання «праверка павінна падаць пры выдаленні auth або manifest guard», даказанае ў два бакі.
- **`live-remote.test.mjs`** (6 проб): ранер адрознівае рэжымы — без `G00_03_B_LIVE_URL` файл сама-скіпаецца з тлумачэннем (mock-рэжым); з URL живага сервера праганяе вонкавыя негатывы (ананім/крывыя bearer → 403; прылада без пакупкі → 403 `no_entitlement` альбо 503 `entitlement_unavailable` — fail-closed у абодвух выпадках; крывыя шляхі → 403; зламаны JSON → 400; GET → 404). Мутаты і падпісанне «сваім» ключом у live-рэжыме недасяжныя па дызайне (патрабуюць унутранага стану сервера).

Знойдзены **няма дэфектаў кода .a**, якія б прыйшлося вяртаць: усе аховы (auth, unsafe-path, manifest membership гранта, manifest membership + шляховая ахова на /private/, environment, fail-closed правайдара) вытрымалі пробы, у тым лічбе мутата-адваротныя. Адна задакументаванае назіранне (не дэфект бяспекі): перавышэнне `MAX_BODY_BYTES` скідае злучэнне замест чыстага 400 `invalid_request` — fail-closed выконваецца, сервер выжывае; калі .a захоча чысцейшы адказ кліенту — гэта ўладальніку .a, праверкa свядома не патрабуе 400.
