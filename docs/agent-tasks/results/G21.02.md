# G21.02 result — Render map attribution with MapLibre styles

Date: 2026-10-03 (claim 2026-10-03T18:44Z). Branch: `zcode/535` from main `a73d734`, rebased onto `25e55e0` (G21.01/PR #569 merged while this task ran — no file overlap, web app route groups). The map component never imported the MapLibre stylesheet, so the attribution control rendered in static flow, overflowed the map container and collided with the server-side ODbL attribution paragraph (reproduced live at 390px before the fix).

## What changed

- `web/components/city-map.tsx` — imports the pinned `maplibre-gl/dist/maplibre-gl.css` (maplibre-gl 5.24.0 from the web lockfile) at the single web stylesheet import boundary; the MapLibre controls are positioned only by this stylesheet. No behavior code touched.
- `web/map-css.test.ts` — new guard in the standard runner (`web/**/*.test.ts` glob): the boundary import exists in `components/city-map.tsx`, no other web production file imports the package CSS, and the pinned dist CSS still defines `.maplibregl-ctrl-attrib` / `.maplibregl-ctrl-bottom-right`.
- `tools/web/map-attribution-regression.mjs` — new Playwright browser regression, two strictly separated modes: default deterministic (static export served from 127.0.0.1, every external request aborted — no provider contact; asserts `map_css_loaded`, the bottom-right absolute anchoring, and non-overlapping attribution bounds at 320/390/1440px) and `--live` (real OpenFreeMap style load, waits for `data-map-ready="fitted"`, asserts retained credits and accessible links). It reuses `tools/serve-static.mjs` and dynamically imports playwright like the collector does; it is not wired into `npm test` (chromium is not a standard-runner dependency).
- `docs/demos/2026-10-03-g2102-map-attribution.md`, `docs/testing/evidence/2026-10-03-g2102-map-attribution/` — demo and proof screenshots.

1. **Load a real map and reproduce overlapping provider attribution at 390px.** Done before the fix: static export of main `a73d734` served locally, Chromium viewport 390px, real provider style loaded (`data-map-ready="fitted"` reached). 2. **Load the pinned MapLibre stylesheet through the supported web build boundary; retain provider/license credits and accessible links.** The import sits in `components/city-map.tsx` (App Router global-CSS boundary); `next build` emits the CSS chunk and links it in `/map`. Live run (real provider, 2026-10-03): attribution text "MapLibre | OpenFreeMap © OpenMapTiles Data from OpenStreetMap" with links `maplibre.org`, `openfreemap.org`, `openmaptiles.org`, `openstreetmap.org/copyright`; the server-side ODbL link stays untouched.
3. **Assert the required computed positioning and non-overlapping attribution bounds at 320/390/1440px; validate a real provider load separately from deterministic local checks.** The deterministic mode asserts: a loaded stylesheet defines the attribution rules (`map_css_loaded`); `.maplibregl-ctrl-bottom-right` is `position: absolute; bottom: 0; right: 0` in the map container; the attribution rect stays inside the container rect and clear of the heading, the server-side ODbL paragraph and the routes list — all green at 320/390/1440. The real provider load is the separate `--live` mode (network required), green at all three widths; deterministic and live never mix in one run.
4. **Reverting the stylesheet change fails the layout assertion; record network limitations instead of passing a mocked-provider run as live proof.** Revert experiment ran in this session (implementation-rules 1): `git stash push -- web/components/city-map.tsx` → rebuild → regression exits 1 with `map_css_loaded` failures on all three widths → restore, rebuild → exit 0. Network limitation recorded: the deterministic mode aborts the provider style fetch by design and observes the settled error state (`data-map-error`); it asserts control layout, never tile rendering, and is never presented as a provider-load proof — the live mode is the only run allowed to claim that, and it needs external network to `tiles.openfreemap.org`.
