[verification-integration.md §V6](../../specifications/architecture-hardening/verification-integration.md),

камандныя доказы або іменаваныя skip-прычыны.

## Што зменена

- `tools/ci/fetch-gitleaks.mjs` (новы) — адзіны ўладальнік канвеера сканера:
  канстанты `GITLEAKS_VERSION` (8.24.3) і `GITLEAKS_SHA256` (digest архіва),
  URL выводзіцца з версіі; пайплайн строгага парадку fetch → праверка HTTP-поспеху
  (`response.ok`) → sha256 → параўнанне з пінаваным digest-ам → толькі потым
  `tar -xzf … gitleaks` → выкананне сканера з `--redact`. Любы збой (адсутная/
  няправільная сума, HTTP-адмова, збой tar, ненулявы выхад сканера) — nonzero
  exit з іменаванай дыягностыкай stage і НУЛЁМ выкананняў сканера; часовая
  дырэкторыя чыстацца ў `finally`. Прадукцыйны шлях (`main()`) не мае
  env-аверрайдаў сумы — digest толькі з закамічанай канстанты, ніколі з таго ж
  спампоўвання; імпарт модуля нічога не спампоўвае (ідыёма main-гварда
  `deno-typecheck.mjs`).
- `.github/workflows/required-checks.yml` — усе 11 рэфаў `uses:` (6×checkout,
  4×setup-node, 1×setup-deno) цяпер поўныя 40-hex SHA upstream-камітаў, тэг —
  толькі подпіс версіі (`# v4`); крок gitleaks цяпер
  `node tools/ci/fetch-gitleaks.mjs` замест curl|tar; каментар job'а
  server-typecheck абнаўлены (піны больш не «scope G20.27» — яны ўжо
  паставіліся).
- `.github/workflows/guard-required-checks.yml` — `checkout` запінаваны.
- `.github/workflows/jscpd.yml` — `checkout@v6` і `setup-node@v6` запінаваныя
  (стары каментар про self-contained gate не крануты).
- `tools/ci/check-required-checks.mjs` — секцыя G20.27: ва ЎСІХ трох workflow
  кожны `uses:` мусіць быць `owner/repo@<40-hex>`; required-checks мусіць
  выклікаць `node tools/ci/fetch-gitleaks.mjs` (канец-анкер, як arch:check) і
  НЕ мусіць спампоўваць сканер праз curl/wget; `fetch-gitleaks.mjs` мусіць
  трымаць абедзве канстанты (версія semver + 64-hex digest).
- `tools/ci/gitleaks-fetch.test.mjs` (новы) — workflow-equivalent фікстуры:
  сапраўдны tgz з фейкавым сканерам-лёгерам, лакальны HTTP-сервер на дынамічным
  порце, увесь сеткавы ўвод праз `fetchImpl`-ін'екцыю (ноль рэальнай сеткі ў
  npm test). Файл пад glob `tools/ci/*.test.mjs` — праводка ўжо існавала.

Не кранутыя: спіс required jobs (tests, windows-portable, lint,
server-typecheck, web-build, gitleaks + guard + jscpd workflows),
`permissions: contents: read` ва ўсіх файлах, `fetch-depth: 0` у gitleaks,
jscpd-гейт і яго self-contained каментар, `persist-credentials: false`.

## Працэдура абнаўлення версій/provenance

1. **Сканер**: узяць новы рэліз gitleaks → `checksums.txt` рэлізу і асобны
   лакальны `sha256sum` архіва; абедзве сумы мусяць супадаць. Абнавіць
   `GITLEAKS_VERSION` + `GITLEAKS_SHA256` у `tools/ci/fetch-gitleaks.mjs`
   адным камітам; сюіт `gitleaks-fetch.test.mjs` паўторна даказвае ўсе чатыры
   выпадкі; provenance новай сумы запісаць у results гэтага PR.
2. **Actions**: для новага тэга — рэзалюцыя SHA дзвюма выклікамі API
   (`commits/<tag>` + `git/refs/tags/<tag>`), абнаўленне рэфа і `# vX`-анатацыі
   адной праўкай; агляд дыфа = параўнанне SHA з вывадам абодвух выклікаў.
3. Гард не дае працэдуру прапусціць: unpinned ref, прамы curl/wget,
   апустошаная канстанта — чырвоны `guard-required-checks`; зняцце
   digest-брамы ў пайплайне — чырвоны сюіт.

## Па крытэрах

1. **Піны actions** — 14 `uses:`-рэфаў у трох файлах: 8×checkout (v4 + v6),
   5×setup-node (v4 + v6) і пінаваны яшчэ G20.13 setup-deno. Падлік праз
   `grep -cE "uses: [a-z-]+/[a-z-]+@[0-9a-f]{40}" .github/workflows/*.yml`:
   required-checks **11**, guard **1**, jscpd **2**; unpinned у
   required-checks — **0**. Гвард G20.27 праганяе той самы рэгэксп па ўсіх
   трох файлах — OK.
2. **Digest-верыфікацыя спампоўвання** — пайплайн у `fetch-gitleaks.mjs`:
   HTTPS (URL канстанты) + `response.ok` + параўнанне sha256 ДА `tar` і ДА
   выканання; сканер заўсёды з `--redact` (каб знаходкі не друкавалі сакрэты ў
   журнал); дыягностыкі stage названыя, кантэнт архіва не эхоіцца. Сапраўдны
   прагон: `node tools/ci/fetch-gitleaks.mjs` → exit 0, «no leaks found».
3. **Workflow-equivalent фікстуры** — `tools/ci/gitleaks-fetch.test.mjs`:
   genuine → ok + роўна адно выкананне з `--redact` у аргументах; altered
   archive → `digest-mismatch`, нуль выкананняў (маркер-файл не з'явіўся);
   missing checksum → `missing-checksum` да любога fetch (сігнальны
   `fetchImpl` кідае, калі да яго дайшло); HTTP 500 → `http`, нуль выкананняў.
   Лічбы сюіта — у дэме.
4. **Гвард + працэдура** — секцыя G20.27 у `check-required-checks.mjs`
   (выклікаецца ўласным workflow `guard-required-checks`, па-за npm test і
   па-за required-checks.yml — адключыць яе разам з тэстамі нельга);
   працэдура абнаўлення — вышэй; усе required jobs захаваныя (спіс — у
   «Што зменена»).
