# G17.07 — Search, basket, draft export

Issue #162 · branch `zcode/162` · 2026-09-26 · executor: Zcode session (GLM-5.3-Flash).

The collector gained the library tools of the author-driven guide assembly
(docs/24_web_collection.md «Зборка гайдаў — рукамі»): search over the library,
a basket of fragments, and a markdown draft export with citation lines.
The model is the spec's single library — none of the new commands takes a
campaign; the filters are the passport fields, and the basket is global.

Search (`search --city/--topic/--type/--query`) reads the passport fields from
`raw_records` (city exact, topic as an exact member of the topics JSON via
`json_each`, source type exact) and the full text from an FTS5 index over the
latest cleaned documents (`cleaned_fts`; node:sqlite ships FTS5 — verified on
this Node before the design landed). The index is derived state:
`syncSearchIndex` (library.mjs) brings it in line with `cleaned_versions`
before every search — a new version re-indexes its record, a record whose
cleaned versions disappeared loses its row. The author's query is a phrase
from the text, not an FTS5 query expression: it is wrapped into one quoted
phrase (`"shipyard history"`), so hyphenated words (`ціна-якасць`), quotes and
brackets stay literal input — a bare hyphen otherwise collides with FTS5's
column-filter syntax and errors. The result rows carry the passport and the
fragment title (from the cleaned document's front matter, indexed with the
body).

The basket (`basket add --record <id>` — repeatable, `list`, `clear`) is a
global table keyed by the record id: a repeated add is a no-op, so a repeated
export never duplicates a fragment. `add` accepts only records that have a
cleaned document — the draft exports cleaned fragments only.

`export-draft --out <file>` renders one fragment per basket record in stable
url order: the cleaned body under the fragment title, with the citation line
`Крыніца: <url>` / `Забрана: <collected_at> · Запіс: <record_id>` — the review
bundle's citation voice plus the record id, the provenance `07` needs to walk
a fragment back to its raw record. The export moves the records
`cleaned → used` (already `used` records stay used and are not counted as
moved); an empty basket answers with a diagnostic and writes no file; the
previous draft survives an export that cannot read a cleaned file (all bodies
are read before anything is written — the review bundle's rule). The output is
deterministic (no timestamps), so a repeat export of an unchanged basket
produces the same file.

## What was decided

- **Full text = FTS5 phrase match; vector search stays with `07`.** The spec
  names «тыя ж SQLite + sqlite-vec, што ў 07» — the sqlite-vec half describes
  `07`'s stack (a native extension load), and this task's criteria demand
  filters + full text only. Recorded as a scope line, not silently dropped.
- **The query is quoted as a whole phrase** (not passed as an FTS5 expression):
  the AC says «finds a record by a phrase from its cleaned text», and the wrap
  removes the operator surface that turned hyphenated input into `fts5`
  syntax errors.
- **The draft keeps media blocks as they are in the cleaned text**: the
  `media/…` links are relative to the snapshot dir and do not resolve inside a
  draft written elsewhere. The text and the citation line (the part `07`
  consumes) are unaffected; copying media into the draft is a separate
  decision for the runbook.

## Acceptance criteria — walked from the card

1. ✅ **Search hits expected records under city/topic/type filters; full text
   finds a record by a phrase from its cleaned text.** The fixture library
   (gdansk/krakow, history/architecture, web/wiki, one raw record) is asserted
   per filter and combined; full text finds by phrase and composes with the
   filters; the raw record stays invisible to full text. Tests: «passport
   filters hit the expected records», «full text finds a record by a phrase».
2. ✅ **Export produces a markdown draft where each fragment carries its
   citation line (URL + date).** The test asserts the exact two-line citation
   block per fragment (`Крыніца: <url>` / `Забрана: <collected_at> · Запіс:
   <record id>`) plus the fragment title and body; reverting the citation
   writer in library.mjs fails these assertions (checked by the revert
   experiment below). Tests: «export writes a draft whose fragments carry the
   citation line», CLI «search, basket and export-draft drive the draft
   handoff».
3. ✅ **Exported records have `status=used`; repeat export does not duplicate
   fragments.** After export the passport rows read `used`; the repeat export
   reports `0 moved to used`, renders byte-identical output and keeps exactly
   one `Запіс:` line per id. Tests: «exported records move cleaned to used».
4. ✅ **Empty basket → diagnostic, no empty file; suites wired into
   `npm test`; jscpd clean.** The empty-basket export throws the named
   diagnostic and the CLI answers exit 1 with no file written; the suites run
   under the existing `tools/collector/*.test.mjs` glob; jscpd reports
   0 clones (the `collectAndClean` fixture moved to testkit.mjs instead of
   being cloned).

## Revert experiments (run before push, on the final HEAD)

- Removed the citation writer's two `lines.push(...)` calls in
  `exportDraft` → «export writes a draft whose fragments carry the citation
  line» fails on the missing `Крыніца:` match (criterion 2's guard).
- Removed the `basketAdd` PRIMARY KEY handling (`ON CONFLICT DO NOTHING` →
  plain INSERT) → «basket rows carry the fragment title…» fails on the second
  add (the idempotency guard).
- Removed the FTS re-index on version bump (`syncSearchIndex`'s version
  compare) → «the search index follows the latest cleaned version» fails on
  the stale phrase match — the test warms the index on v1 before the bump,
  so the guard covers the re-index, not the cold first index. All three
  reverted back; `git status` clean.
