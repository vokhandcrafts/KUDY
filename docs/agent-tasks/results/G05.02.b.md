# G05.02.b — Location service: one subscription, geofence window, watchdog

Issue #211 · branch `zcode/211` · 2026-09-24 · executor: Zcode session (GLM-5.3-Flash).

`services/location/` is a plain class over an injected OS port (the `services/db` /
`services/contentRepo` pattern): `types.ts` (the port contract, `LocationMode`,
`LocationStatus`, the canon constants), `service.ts` (`LocationService` + the
`systemLocationClock` composition-root clock), `fake-port.ts` (the test fake that
counts subscriptions and flags violations) and `service.test.ts` (23 acceptance
tests). The service owns the one OS subscription, the ≤ 20-region geofence window
and the watchdog; it does not own the position and makes no trigger decision —
raw fixes are forwarded to the controller unchanged and the pipeline runs there
(19 §5.2, AR-5). It imports nothing from `core/engine` (criterion 5, tripwired)
and reuses the pure `core/geo` haversine of G05.02.a for the window ranking.
The real `expo-location` adapter is G05.02.c; no file outside `services/location/`,
the shared guard (below) and the allowed docs was touched.

## Canon deviations resolved in-code (implementation-rules 2/6)

Anchored in the `types.ts` header, restated here for the reviewer:

1. **`setGeofenceWindow` carries the stops, not bare ids.** 19 §3.3 sketches
   `setGeofenceWindow(stopIds: StopId[])`; a bare id array cannot compute
   «бліжэйшыя прыдатныя stops» nor hand the port its regions. The call carries
   `GeofenceStop { stopId, lat, lng, radius }` — the controller's selection
   data, not a second candidate channel; the service still knows nothing about
   `heard`/`auto_fired` (AR-5).
2. **`status()` extends the four watchdog states** with `'idle'` (the disarmed
   service holds no subscription — criterion 1) and `'permission-denied'`
   carrying a reason `'denied' | 'revoked-mid-session'` (19 §3.3: «дазволу
   няма — асобны стан status(), не выкітак»; criterion 4 asks for a reason).
3. **The recompute channel.** The pipeline lives in the controller and the
   sketch defines no accepted-fix channel back to the service, so the window
   recomputes on the latest raw fix the service forwarded; «пасля спрацоўкі»
   (a trigger) and the AccessReady widening are the controller re-calling
   `setGeofenceWindow` — the sketch's only controller → service channel.
   With no fix yet nothing is pushed: no position, nothing to rank by.
4. **`FixInput` is imported type-only from `core/pipeline/types.ts`** (the
   single spelling; erased at runtime), `StopId` is restated locally —
   criterion 5 forbids `core/engine` imports in this module, even type-only.
5. **The watchdog backoff numbers are this implementation's, not canon:**
   resubscribe attempt 1 fires when the 15 s gap is detected (09 §6.3 canon),
   the next attempts follow 1 s, 2 s, 4 s, 8 s; when the list runs out the
   watchdog stalls and stops scheduling. The last subscription stays live on
   purpose — a fresh fix of it returns the service to live.

## Acceptance criteria — walked from the card

1. ✅ **One OS subscription at most.** The service arms through
   `port.startFixes(sub)` / `port.stopFixes(sub)`; a repeated `setMode` is a
   no-op, a change between `city-surface` and `active-guide` carries the one
   subscription over, `idle`/`paused` disarm and clear the regions
   (ClearGeofences, 19 §4.3). The fake counts live subscriptions and flags a
   second concurrent start as a violation; every test asserts `violations` is
   empty. Tests: «criterion 1: …» (3 tests).
2. ✅ **Window ≤ 20, nearest of the whole set by the latest fix.** The 25-stop
   fixture sits on one meridian with ids running opposite to the distance
   order, so the choice is provable by construction: the window is exactly
   the 20 nearest (cap), the route-first but geo-farthest stop-01 never makes
   it (not route order). Recomputed on every forwarded fix and on every
   `setGeofenceWindow` re-call (widening test: a near unlocked stop enters,
   the farthest member drops out). Distances via `core/geo` haversine, ordered
   by distance then stable `stop_id` (the 09 §6.2 stage 5 idiom). Invalid or
   duplicate stop geometry is dropped with a diagnostic count, never crashed
   on (implementation-rules 14). Tests: «criterion 2: …» (6 tests).
3. ✅ **Watchdog with injected clock.** `acquiring → live → recovering →
   stalled`: a 15 s gap (canon) resubscribes with a fresh generation and the
   bounded backoff of deviation 5; a fix of a previous generation (after a
   resubscribe) or of a previous session (after a disarm) is dropped whole —
   the port tags every fix with the service-minted generation and the service
   drops any other. Tests: «criterion 3: …» (6 tests, incl. the proof test).
4. ✅ **Permission is a status value, never an exception.** Denied at arm →
   `{ state: 'permission-denied', reason: 'denied' }` without a throw;
   undetermined waits honestly as `acquiring` (the permission question itself
   belongs to the UI, 09 §9); a mid-session revocation releases the
   subscription, the window and the fix memory — no stale `live`, and a later
   grant re-arms from zero (the old window does not come back). Tests:
   «criterion 4: …» (4 tests).
5. ✅ **Raw fixes unchanged; no engine import.** The controller sink receives
   the port's fix object by reference, unmutated (also after the window
   recompute around it); a second `onFix` replaces the sink. The module
   imports nothing from `core/engine` — source tripwire through the shared
   guard `services/engine-zone-guard.ts`, zone matrix enforced by
   `npm run arch:check`. Tests: «criterion 5: …» (3 tests).
6. ✅ **No coordinates logged or emitted.** The diagnostic sink (optional
   `log` dep) records state transitions and counts only; the test captures
   the log while fixes flow and asserts no coordinate value appears, and
   `status()` shapes are asserted exact (no coordinate fields). Test:
   «criterion 6: …».

**LocationMode transitions covered (the brief's canon note):** `idle →
active-guide` (arm), `active-guide → city-surface → active-guide` (carry-over),
`active-guide → paused` and `→ idle` (disarm, ClearGeofences), re-arm
`idle → active-guide` (fresh generation). Not covered here and not required by
the card: arming `city-surface` from `idle` directly (same `arm()` path as
`active-guide`), and permission flips are port-event-driven regardless of mode.
