## Спіс persisted і transient палёў — перадача G01.03

Кантракт G01.02 **не дадае аніводнага durable-поля** (ADR §3.3, §3.9). Зверана супраць §3.1–§3.2 ADR G01.03 — канфліктаў няма.

**Durable (зона B, радок `session`; крыніца — ADR G01.03 §3.1, без зменаў):** `session_id` (PK), `route_id`, `version` (нязменная да End), `state` (`active`/`paused`/`finished`), `locale`, `tier` (інфармацыйны), `auto_fired[]` (`stop_id`), `heard[]` (`story_id`), `last_stop_id`, `started_at`, `finished_at?`, `play_seq` (write-through лічыльнік запускаў — адзінае durable поле, датычнае ідэнтычнасці запускаў). Астатнія durable-табліцы па-за G01.02: `guide_hint_state`/`guide_hint_last` (R07), `migration_log`, `event_queue`, `settings`, `device`, `feedback_*` (`21`).

**Transient (у SQLite не пішацца):**

| Поле | Змест | Жыццё / аднаўленне |
|---|---|---|
| `playing` | `{owner:'guide', stop_id, story_id, play_id} \| {owner:'moment', moment_id, story_id, seq} \| null` — люстра фізічнага плэера | працэс; заўсёды `null` пасля аднаўлення (ADR G01.03 §3.2, G01.02 §3.3) |
| `play_token {kind, ref, seq}` | guide — пара `(session_id, play_id)`; moment — `moment_id` + працэсны манатонны лічыльнік | працэс; callback не перажывае закрыцця (ADR G01.02 §3.2) |
| жывая паўза | offset у плэеры (мс), токен бягучага запуску | плэер; дакладны offset пасля закрыцця працэсу — не абяцанне MVP (R03) |
| `focus_lost_at?` | старт адліку парога 10 хв пасля `FocusLoss` (ADR §3.7) | сесія; знікае са спыненнем запуску |
| `queued` | адна ячэйка `{stop_id, radius, at}` | ачышчаецца на `Pause`/`End`/яўным Play Moment; пасля аднаўлення пустая |
| `autoplay_suspended` | блакіроўка аўтаматыкі | не захоўваецца; пасля аднаўлення заўсёды `true` (ADR G01.03 §3.2), здымка толькі яўным дзеяннем чалавека |
| `playingNow` | ін'екцыя граючага moment у `start()` — давераны ўвод кантролера | транзакцыя Start |
| `inspected`, становішча панэлі | UI-стан Run | не engine і не SQLite (`11` разд. 11) |

## Што можа браць наступнік

- Кананічныя імёны для G05.03/G07.03 (рэалізацыя C38–C45): уладальнікі `guide`/`moment`, `play_token {kind, ref, seq}`, падзеі `PlayMoment`, `MomentFinished`, `AudioFailed` (= `story_play_failed`), `UserStoppedAudio`, `ResumeAudio`, `GuideResume`; чарга ачыўнаецца яўным Play Moment; lock-screen не запускае ручны кантэнт; паўза сесіі/End не спыняюць moment.
- Спіс persisted/transient палёў вышэй — уваход для G04.01/G05.05 (SQLite-зона B і аднаўленне): нічога новага ў durable-зону не дадаецца; пасля аднаўлення `playing = null`, `autoplay_suspended = true`, чарга пустая.
- G01.05 (табліца падзей): кантракт G01.02 не ўводзіць аналітычных падзей ручнога кантэнту (ADR §3.9) — `moment_shown/opened/dismissed` з `09` §10 застаюцца без зменаў; імёны callback'аў — §3.5 ADR.
- Бацькоўскі эпік G01.02 (issue #5) і G01.03 закрываюцца толькі пасля запісу іх бацькоўскіх results; G00.04 не запускаць адначасова з G01-запісам агульных дакументаў (`agent-tasks/README.md`).
