# G21.20 — Approve separate text and audio identity for one guide

**Issue:** [#552](https://github.com/vokhandcrafts/KUDY/issues/552) · **Epic:** [#532](https://github.com/vokhandcrafts/KUDY/issues/532) · **Date:** 2026-10-04 · **Branch:** `zcode/552` (base a46d39d)

## Outcome

The language-identity ADR is written: `docs/architecture/decisions/G21.20-language-identity.md`.
It defines two pins over one route/version — the existing text pin and a new optional
`audio_pin = (route_id, version, audio_locale)` — with per-layer readiness and
authorization, additive persistence (`ALTER TABLE session ADD COLUMN audio_locale TEXT NULL`),
rollback plan, feedback/analytics attribution and the acceptance-case table.

**ADR status at merge time: `decision-required`.** Criterion 2 requires *explicit founder
approval* of the design. The approval was requested (PR + issue) and is recorded as a human
follow-up in `docs/human-actions.md`; no runtime code or migration exists before that
written approval (criterion 5 keeps its own gate). G21.21 implementation remains gated on
the approval per the specification (`2026-10-03-completion-and-locales.md`: «Рэалізацыя
G21.21 пачынаецца толькі пасля разгляду і выразнага зацвярджэння гэтага рашэння»).

## Criteria walk (from the issue card)

1. **Inventory the single-locale contract** — ADR §1. Facts anchored verbatim: audio path
   built from `s.locale` (`core/engine/reducer.ts:495`); grant identity requires
   `event.locale === s.locale` (`core/engine/reducer.ts:561-566`, canonical
   [ADR G01.03 §3.5](../architecture/decisions/G01.03-session-access.md)); one `locale`
   field in session state (`core/engine/state.ts:87-89`), Start event
   (`core/engine/events.ts:33`), disk layout (`09` §7) and the `session` row
   (`services/db/schema.ts:69-85`). The four reasons a dictionary swap cannot enable
   fr text/en audio are §1 items 1–4 (UI-registry boundary quote
   `contracts/ui-locales.ts:5-10`; spec prohibition of grant-locale weakening).
2. **Design with separately pinned text and optional audio locale/version** — ADR §3.1–§3.4.
   Write-half done; **approval half pending** (`decision-required`, human action logged).
   Single-language compatibility: `NULL` → audio follows the text locale; additive
   migration step (only adds a column, ADR G01.03 §3.8 idiom); rollback = stop
   writing/reading, column stays dormant, rows read as single-language.
3. **Readiness and authorization per actual layer** — ADR §3.3: per-layer grant over
   `LayerKey` (`services/contentRepo/types.ts:36-41`), paths locked to the layer's own
   lock.json (`services/download/grant.ts:186-192`), server-side per-key entitlement —
   an en grant cannot authorize fr bytes (triple boundary). Deny-safe table for missing
   configuration, unavailable media, malformed cross-language mapping and unauthorized
   layers.
4. **Feedback attribution and analytics minimization** — ADR §3.5: feedback target stays
   `{kind: guide, route_id, version, locale}` with locale = the text locale of the used
   content (`contracts/schemas/feedback-target.schema.json:4`, `21` §5.1); no audio-locale
   dimension added to the target or to analytics context; forbidden content rules
   (`event-table.v1.json:78-89`, `21` §6) untouched.
5. **Acceptance cases; no runtime code before approval** — ADR §4: fr text/en audio,
   text-only, same-language, restart, refund/expired grant, unavailable voice, UI switch,
   plus malformed mapping and unauthorized layer. The diff contains documentation only —
   no runtime code, no schema change, no migration.
