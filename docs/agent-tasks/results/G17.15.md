# G17.15 result — the robots.txt gate

- Status: `complete`
- Task: issue #374, branch `zcode/374` (worktree `KUDY-wt-374` off `main` @ bae595e)
- What: the crawl pipeline (tools/collector) gained a robots.txt gate
  (`robots.mjs`): before the politeness gate and the page fetch, every http(s)
  seed and crawl step is checked against the host's robots.txt — fetched once
  per host per run through the production transport (`defaultFetchRobots`, a
  plain GET; the request itself goes through the politeness gate). A disallowed
  path is never fetched; the refusal lands in the fence audit as a
  `robots-denied` line with a trailing `reason` field (fence.mjs
  `serializeAuditLine` gained the optional field; three-field lines stay
  byte-identical). The parser reads only the collector's own product token
  (`ROBOTS_AGENT`, `KUDY-collector`) or the `*` group: longest matching pattern
  wins, an equal-length tie resolves permissively, `*` wildcard and `$` anchor
  supported, empty `Disallow` / no matching group / garbage text mean
  «everything allowed». Missing robots.txt (404/410) is «everything allowed»;
  any other HTTP error or a network failure closes the host for the rest of the
  run («unavailable») — read conservatively per the issue.

## Proven (criteria of issue #374)

1. **A robots-disallowed path of an allowed domain is not fetched; the audit
   carries the reason** — robots.test.mjs AC1 runs a campaign whose seed links
   a disallowed `/secret` and an allowed `/open` through the real `runCampaign`
   and the real robots transport against a local fixture server: no request for
   `/secret` ever reaches the server, the refusal is audited as
   `{"url": …, "decision": "robots-denied", "fetched": false, "reason": "robots.txt of 127.0.0.1 disallows /secret"}`
   and the collected records are exactly `/open` and the seed.
2. **An allowed path goes as before; missing robots.txt means everything
   allowed** — AC2 (no robots.txt route → the 404 is read as allow-all, the
   page is fetched as before; the robots.txt request in the server log proves
   the gate ran and is itself revert evidence) and AC5 (two page fetches of one
   host produce exactly one robots.txt request — the cache spans the run).
   crawler.test.mjs AC5 additionally pins that the robots.txt request is
   politeness-gated like a page fetch (both consecutive gaps ≥ the minimum).
3. **A robots.txt server error is read conservatively — the host is not
   visited this run, the audit carries the reason** — AC3: robots.txt answers
   500 → the seed step fails with `robots.txt of 127.0.0.1 unavailable
   (HTTP 500) — host is not visited this run — seed not fetched`, the server
   log shows only the robots.txt request (no page fetch), the audit line names
   the reason.
4. **A campaign whose every seed is refused ends with a readable diagnostic,
   not an empty success** — AC4: two seeds, `Disallow: /` → both seed steps
   fail with the per-seed diagnostic and `runCampaign` reports
   `stopped: all 2 http(s) seed(s) refused by robots.txt — run stopped, nothing
   collected` (the CLI surfaces it on stderr as `collector: run stopped — …`).
   The refusal is a `RobotsBlockedError`, which the crawler's error series
   never counts and which never stops other work: three consecutive refusals of
   discovered links complete as `done` skips and the run finishes green
   (robots.test.mjs series test).
5. **Tests on local fixtures; red on revert** — the suite serves robots.txt
   from the fixture-server routes like any real host (every network byte stays
   on 127.0.0.1; the production transport is exercised end-to-end). The revert
   experiment ran in this session: with the `crawlStep` robots verdict replaced
   by a constant allow, 6 of the 11 robots.test.mjs tests fail (AC1–AC5 and the
   error-series test — the disallowed page gets fetched, no robots request
   happens, no stop diagnostic); the 5 pure parser tests stay green by
   construction and guard the parser rules instead. Restored, suite green.
   The CLI-level stop line has its own case in cli.test.mjs (must-flag
   `missing-cli-stop-test`): a run whose seed is robots-refused prints
   `collector: run stopped — all 1 http(s) seed(s) refused by robots.txt …` on
   stderr, exits 0 and never launches the browser.
