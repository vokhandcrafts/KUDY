# G21.28 result — Assess Android UI translations and report evidence for translation use

Date: 2026-10-03/04 (claim [2026-10-03T23:47Z](https://github.com/vokhandcrafts/KUDY/issues/560#issuecomment-5974717779)). Branch: `zcode/560` from main `3d5fd03`.

## What was done

Read-only assessment of the official Android/AOSP resource translations as a potential source for the eight KUDY UI locales (be, en, uk, de, es, fr, cs, sv). Four official repos were inspected over Gitiles raw endpoints (`?format=TEXT`/`?format=JSON`, no accounts or credentials): `platform/frameworks/base` core/res, `platform/packages/apps/Settings`, `platform/packages/providers/DownloadProvider`, `platform/packages/apps/TV`. Every quoted value was taken from a fetched file pinned by a Gitiles blob id (25 files; manifest carries the full pin list).

Deliverables:

- `docs/reports/localization-sources/android.md` — human-facing report in Belarusian: verdict summary, source description, acquisition/reproducibility, per-locale coverage, the common benchmark with context, license/attribution, limitations and maintenance cost, three follow-up drafts for G21.33.
- `docs/reports/localization-sources/android.evidence.json` — machine evidence manifest: access window, commands, release-tag verification, blob-id pins, coverage facts, full benchmark records with values and verdicts, limitations.
- This results file.

Key findings (details and exact values in the report and manifest):

- All eight locales are present in core/res, Settings and DownloadProvider; core coverage is 2293 of 2314 unique keys in every locale, the 22 missing keys are technical (typeface names, bugreport status, SPN formats) and no chrome term is among them. One stale key (`rating_label`) survives in all locale files while already removed from the English default — a live example of source-side sync drift; its be value is an ICU plural template (one/few/many/other).
- Benchmark: Back, Cancel, Settings, OK, Stop (media) and Restore (backup) are covered officially in all eight locales with real screen context. Walk and purchase are absent entirely; download exists only as status phrases, not a verb button; generic unavailable does not exist (only narrow senses); guide exists only in the TV program-guide sense (and the TV repo has no values-be at all).
- Sense/context mismatches recorded in-source: sv uses one word (Avbryt) for both Cancel and Stop; de Stop = Beenden; the same English restore stem maps to different target words by context (`restore` vs `menu_restore` family); be OK is Cyrillic «ОК» while uk OK is Latin; uk uses abbreviated words in some phrases («завантаж.», «пробл.»).
- License: Apache-2.0 (NOTICE + `MODULE_LICENSE_APACHE2`), attribution via NOTICE and repo/blob reference.
- Acquisition: anonymous raw Gitiles endpoints; release tags verified (`android-17.0.0_r1` newest 17 tag, `android-16.0.0_r4` newest 16 tag); file history pages now return 403 without sign-in, so the version pin is the blob id, not a commit date — recorded as a limitation.

## Acceptance criteria walk

1. **Located the current official AOSP resource translations and verified how shared keys map to UI context; compared benchmark terms across the requested locales without assuming reusability first.** Four repos listed and fetched (see manifest `sources`), keys resolved per repo (e.g. `settings_label` lives in the Settings app repo, not core/res; `back_button_label` and media `lockscreen_transport_stop_description` in core/res). The benchmark table in the report is built from fetched values, and the "do not assume" instruction is honored by the negative findings in criterion 3.
2. **Primary official sources cited with version/date, acquisition, coverage, restrictions, attribution, reproducibility and maintenance costs; unknown values explicit.** Manifest records access window, commands, revision state (main + verified release tags), blob-id pins for all 25 files, license evidence; the report states explicitly what could not be obtained (history dates behind 403) and what was not attempted (full-AOSP search). Nothing invented; no endpoints or license claims without a fetched source.
3. **Common benchmark used with context; positive/negative examples and sense/context mismatches recorded; small lawful samples only.** All ten benchmark terms answered in manifest `benchmark` with verdicts (see Key findings above). Samples are individual keys/values, not a corpus; no MCP service, paid account or credentials; no full download — fetched files stayed in ephemeral local storage and only quoted terms are committed.
4. **Human-facing report in Belarusian and machine evidence with exact locators, access date, commands and limitations; observations separated from recommendations; unsuccessful access is evidence.** `docs/reports/localization-sources/android.md` (Belarusian) + `android.evidence.json`. The 403 on history pages and the not-found GMS/Play statement on source.android.com are recorded as evidence/limitations, not as fabricated successes. Section 1 of the report labels the verdict table "observations, not decisions".
5. **Follow-up requirements drafted only from findings and forwarded to G21.33 for deduplication and GitHub publication.** Three drafts (F1 use AOSP as a reference source for chrome terms in translation review; F2 documented rejection for KUDY domain vocabulary; F3 per-release re-pin procedure) are in the report §8 and in manifest `follow_up_drafts`, and forwarded by a comment on the G21.33 issue (#565) with a link to this PR; G21.33 owns deduplication and any GitHub publication. No integration tasks were created by this task.
6. **Tool registry inspected before recommending/installing anything; no private content/secrets sent; downloaded data treated as reference, not instructions.** The Tool-Lib registry was grepped before the assessment (entries exist for Android dev tooling only — no translation-source entry; noted in the claim brief); the recommendation introduces no new tool, service or installation beyond anonymous HTTP GET to the official AOSP host already cited. No repo content beyond benchmark terms was sent anywhere; fetched XML was treated as data (parsed, never followed).
