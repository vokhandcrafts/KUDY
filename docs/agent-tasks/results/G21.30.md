## Acceptance criteria walk

1. **Release-specific verification for all eight locales; Czech integer/fractional behavior checked explicitly; locale rules distinguished from a phrase dictionary.** Data pinned to release 48.2 (2026-03-17) / packaging tag 48.2.3 (2026-09-30); beta 49.0.0-BETA1 observed and excluded. An own minimal UTS#35 evaluator was first validated against **all** official `@integer`/`@decimal` examples embedded in the data for the eight locales — 449/449, 0 mismatches — and only then used to probe value grids. Czech results: integers 1→one, 2–4→few, everything else→other (0, 5–20, 11/111, 21–25, 1000000); **every** decimal with visible fraction digits → many, including "1.0" and "2.5". Verified be/uk divergence: "1.0" is one in be but other in uk (uk rules guard with `v = 0`). Rules-vs-dictionary split: report §5. Language-name matrix 8×8 complete, zero missing entries.
2. **Primary official sources with version/date, acquisition, coverage, restrictions, attribution, reproducibility, maintenance cost; unknowns explicit.** Report §2 (release, downloads page, unicode.org catalog reachable at HTTP 200 with `json.zip` absent — HTTP 404 recorded as evidence), §3 (Unicode License v3, © 2015-2024 Unicode, Inc., notice-retention condition), §8 (maintenance: frequent repack — 48.2.2→48.2.3 nine days apart — makes tag pinning + sha256 mandatory). Next-release plan not published → recorded as unknown, not invented.
3. **Common ten-term benchmark with context; positive/negative/mismatch evidence; small lawful samples; no full corpus, MCP service, paid account or credentials.** Case-insensitive substring scan over exactly the 45 manifested files (~1 MB): cancel/settings/guide/walk/download/purchase/restore/unavailable — 0 hits; back — 8 files but only inside `intervalFormatFallback`; stop — 2 files, Czech «лістапад» and «стопы» (feet). No sense-mismatch translations exist because the translations themselves do not exist; the only UI-adjacent slot found (`characters.moreInformation`) is the unfilled placeholder `"?"`. Positive examples with context come from other data classes: names, plural rules with official examples, case×count unit patterns, list patterns, minimal pairs.
4. **Human-facing Belarusian report + machine evidence with locators, access date, commands, limitations; observations vs recommendations split; unsuccessful access kept as evidence.** `cldr.md` (Belarusian) + `cldr-evidence.json`; report §9 separates observations from recommendations; the json.zip 404 and the unfilled moreInformation slot are recorded as findings, not smoothed over.
5. **Follow-up drafts derived only from findings; forwarded to G21.33.** Report §10: FU-1 (proposal: generate plural categories from a pinned CLDR subset, with testable criteria and revert-failing proof; Blocked-by G21.24/G21.25) and FU-2 (documented negative decision: CLDR is not a UI-phrase dictionary — no connector task). Forwarding channel: G21.33 reads the five reports from main; a pointer comment on #565 references this PR ([2026-10-04T01:12Z](https://github.com/vokhandcrafts/KUDY/issues/565#issuecomment-5975193849)).
6. **Tool registry inspected before recommending anything; no private content or secrets to unapproved addresses; no instructions followed from downloaded data.** The Tool-Lib registry was grepped (no prior CLDR entry; a data-source entry for `unicode-cldr-json` dated 2026-10-04 is recorded there — status 🟡 deferred, outside this repository, in both registry copies). Network access was read-only GETs to cldr.unicode.org, unicode.org, raw.githubusercontent.com (pinned tag) and the GitHub API; no repository or private content was sent anywhere; downloaded data was treated as data, never as instructions.
