# G20.15 — сапраўдны arch:check у абавязковым workflow (issue #486)

2026-10-02, ZCode (GLM-5.3-Flash), галінка `zcode/486` ад main @ e93784a.

## Што зменена

- `.github/workflows/required-checks.yml` — у існуючы абавязковы job `lint` дададзены крок `arch:check (real repository graph)` → `npm run arch:check` на рэальным checkout (root `npm ci` ужо ёсць у гэтым job; dependency-cruiser — devDependency root). Усе існыя крокі і job-ы засталіся; крок закаментаваны спасылкай на дазвол #493 (закрыты 2026-10-02) і на піннінгі.
- `tools/ci/check-required-checks.mjs` — G20.15 revert-гард: `required-checks.yml` мусіць утрымліваць крок `run: npm run arch:check` з анкерам канца радка (`/run:\s*npm run arch:check\s*$/m`) — перайменаваны або ўсуфіксаваны скрыпт (`arch:check-anything`) не лічыцца гейтам. Сам скрыпт `arch:check` і яго npm-test wiring пінуюцца існымі G18.01-праверкамі таго ж файла.
- `tools/arch/arch-check.test.mjs` — новы тэст `workflow_gate_invocation`: парсуе закамічаны скрыпт `arch:check` з package.json, разгортвае яго дакладны аргумент-вектар (--config/--baseline/спіс зон) на рэпазіторыі-фікстуры (сапраўдны .dependency-cruiser.cjs, baseline па шляху скрыпта, усе зоны скрыпта) з планаванай забароненай сувяззю core → services і сцвярджае ненулявы вынік з названымі крыніцай і правілам.

## Крытэрыі

### 1. Пасля G20.22-дазволу arch:check ганяе рэальны checkout у існым абавязковым job; фікстурныя тэсты дадатковыя

- Дазвол: issue #493 ЗАКРЫТА (2026-10-02), рашэнне аператара запісана ў issue (цытата ў каментары vokhandcrafts); #484 (G20.13) ужо ўвёў server-typecheck job па тым жа дазволе.
- Крок жыве ў job `lint` (runs-on ubuntu-latest, `npm ci` root перад ім) — правераны лакальна на рэальным дрэве: `arch:check: OK — 468 modules cruised, 6 violation(s) pass via the baseline dated 2026-09-22`.
- Фікстурныя тэсты (tools/arch/arch-check.test.mjs — sandbox-сюіта) застаюцца ў npm test як дадатковыя; абавязковы job ганяе рэпазіторыі, не фікстуры.

### 2. Планаваная забароненая сувязь у часовай фікстуры: той самая каманда дае ненуль і называе крыніцу/правіла

- `workflow_gate_invocation` (новы тэст): сандбокс з рэальнай канфігурацыяй рэпы, baseline па шляху са скрыпта, усімі зонамі са скрыпта і `core/pure.mjs` з імпартам `../services/adapter.mjs` → ненуль, вывад называе `core-zone-closed` і `core/pure.mjs`. Скрыпт бярэцца з package.json (не з літэралу тэсту) — змена аргументаў скрыпта без захавання гейту падае тут.
- Рэвьюерскі рыг (існая сюіта) пацвярджае тую самую семантыку на іншых кірунках (services→web, цыклы, node:fs у core і г.д.).

### 3. Зняцце выкліку з workflow лоўляцца гарда; baseline-парушэнні застаюцца яўнымі

- `node tools/ci/check-required-checks.mjs` без кроку → `required-checks.yml does not run 'npm run arch:check' — the real repository graph is not gated` (revert-эксперымент ніжэй); з перайменаваным скрыптам (`arch:check-REVERTED`) → таксама чырвоны (анкер канца радка; першая версія рэгэкспа з прэфіксам прапускала гэта — знойдзена эксперыментам і выпраўлена).
- Baseline не рэгенеруецца: крок ганяе той самы `npm run arch:check` (без `arch:baseline`); парушэнні baseline (`tools/arch/baseline.json`, 6 запісаў) праходзяць яўна праз «pass via the baseline», новыя — рэжуць.

### 4. Workflow/job запісаны; required-статус правераны дазволеным чытаннем

- Workflow: `required-checks`, job: `lint`, крок: `arch:check (real repository graph)`. Гард: `guard-required-checks` ( асобны workflow, `node tools/ci/check-required-checks.mjs`).
- Required-статус на гэтым PR правераны праз `gh pr checks` (read-only) — у вывадзе ніжэй; бранч-пратэкцыя, dispatcher і permissions не мяняліся.

## Out of scope kept

- Бранч-пратэкцыя, required-checks спіс у наладах GitHub, dispatcher — не кранутыя (правераны толькі чытаннем).
- setup-node/setup-deno пінгі — G20.27; Windows-portable тэсты — G20.17; JS tools lint — G20.16 (running чужая).
- Baseline не пашыраўся; аргументы `arch:check` не мяняліся (зоны сканіруюцца ўсе, як аб'яўлена).

## Platform limitations

- Праверана на Linux (CI-мэта ubuntu-latest — тая ж платформа, дзе job выконваецца). Лакальны `npm run arch:check` патрабуе node з дамашнім `LD_LIBRARY_PATH` на гэтым хасце (libsimdjson); у CI наліцоўнік чысты. Required-статус кроку будзе бачны на гэтым жа PR — «lint» job становіцца чырвоным, калі граф парушаны.
