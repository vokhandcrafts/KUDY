## Крытэрыі

### 1. Бяспечная праверка ідэнтыфікатара — адзін уладальнік; спажыўцы захоўваюць адмовы на invalid-ID

- `contracts/identifier.mjs` — узор даслоўна стары (`/^[a-z0-9._-]{1,64}$/`); зборшчык і interim-вывадка імпартуюць аднаго ўладальніка.
- Існыя тэсты адмовы застаюцца зелёнымі бяз зменаў: `entry-boundary.test.ts` (unsafe bundle entry name на `bad name`, `bad\u000aroute` і г.д. — 11/11), `contracts.test.mjs` (ідэнтыфікатары схем), grant-сюіты.

### 2. Прэбілд выклікае падтрыманы CLI з апрацоўкай exit/stderr; leak/parity праверкі захаваныя

- `build-content.ts`: spawnSync `node tools/build-bundle/build-bundle.mjs --in/--out`; не-нулявы код → stderr інструмента даслоўна + exit інструмента; `build.error` (spawn) → названае паведамленне + exit 1.
- `npm --prefix web run build` — exit 0, `rendered-output scan: clean` (лівы скан вэба працуе на збудаваным дрэве).
- `web/lib/content/*.test.ts` — 75/75 (readers, pages, leak-guard, leak-parity, entry-boundary, wiring…).

### 3. Шэсць baseline-запісаў змытыя толькі пасля знікнення кожнага рэбра; новай забароненай сувязі або пашырэння baseline няма

- `command npm run arch:check` на фінальным дрэве: `OK — 476 modules cruised, 0 violation(s) pass via the baseline dated 2026-10-02` — baseline ПУСТЫ, гейт зелёны: ніводнага рэбра web/↔tools не засталося (грэп `from '.*tools/build-bundle` па web/ — толькі каментары і радкі spawn-шляхоў).
- `tools/arch/README.md` — табліца змыта паводле ўласнай палітыкі; датаваны рэзалюцыйны блок.
- Эксперымент-балансіроўка: агент імгненна праверыў адваротны кірунак — кароткія plant-файлы ў web/ з імпартам tools/build-bundle → `web-zone-closed` спрацоўвае (гл. ніжэй пра выключэнне неварыўтных імпартаў).

### 4. arch:check і web build зелёныя; parity/invalid-ID тэсты падаюць на адкатах гардаў

- Гейты на фінальным HEAD: `npm test` 1835/1835 + jest 175/175; typecheck exit 0; `npm --prefix web run build` exit 0.
- Revert-эксперыменты (implementation-rules 1): (1) сумленны рэверт — у test-fixture.ts вернуты імпарт buildBundle З выклікам (як у зыходным кодзе) → `arch:check: FAIL` з `web-zone-closed: web/lib/content/test-fixture.ts -> tools/build-bundle/build-bundle.mjs`; (2) неварыўтны (unused) імпарт — гейт НЕ чырвонее: dependency-cruiser элізнуе неварыўтныя імпарты ў TS-extraction (выпадкова адкрыта падчас эксперыменту; для.paritety-гардаў гэта не мае значэння — рэальны рэверт аднаўляе выклік, не цяжкі імпарт). Абодва зафіксаваныя з рэальнымі вывадамі ніжэй; адкат → 0 violation(s).
- Парытэт і invalid-ID: перасоўванне вывадкі захоўвае паводзіны дакумент-у-дакумент (`entry-boundary.test.ts` 11/11 на contracts-імпарце); parity-тэсты leak-scanner-вэб vs зборшчык працуюць праз той самы CLI-вывад.

## Выключэнне неварыўтных імпартаў у дэдлайн-гейце (знойдзена і зафіксавана)

Падчас эксперыменту выяўлена: dependency-cruiser (праз extraction з typescript 5.9.2) **апускае з графа невыкарыстоўваныя імпарты** — файл з `import { buildBundle } …` бяз выкліку для гейта нябачны, а з выклікам — ловіцца. Для гэтай задачы гэта не праблема: рэальны рэверт аднаўляе выклік (як у эксперыменце 1), а імпарты бяз выкарыстання ўсё роўна павінны быць выдаленыя — гэта праца лінтэра. Зафіксавана тут як вядомая мяжа гейта.
