# G21.01 result — Set the actual document language on exported web pages

Date: 2026-10-03 (claim 2026-10-03T17:30:56Z). Branch: `zcode/534` from main `a73d734`.

## What was changed

The single hardcoded root layout (`<html lang="be">`) was replaced by one root
layout per exported locale tree — Next's route-group structure for
per-locale documents — so the static export server-renders the language of
each page's own URL locale. No client-side mutation, no URL or href changes
(`localePath` stays the single href mapping point; it now derives the default
from the new `defaultUiLocale` export in `web/lib/i18n/index.ts` instead of a
literal):

- `web/app/(be)/layout.tsx` + `web/app/(en)/layout.tsx` — thin per-locale root
  layouts over the shared `web/components/locale-root.tsx` shell (the only
  place an `<html lang>` is written); the be tree moved under `app/(be)/`, the
  en tree under `app/(en)/en/` — both keep their exact public URLs.
- `web/app/global-not-found.tsx` — the shared 404 now uses the
  `global-not-found` file convention (`experimental.globalNotFound` in
  `web/next.config.ts`). On the base the single top-level root layout gave
  the old `app/not-found.tsx` its `lang="be"`; once the locale root layouts
  replaced it (the intermediate state of this change), no root layout sat
  above the top-level not-found and the exported `404.html` rendered a bare
  attribute-less `<html>` — reproduced during this task. The
  global-not-found renders its own document with the site default `be` and
  keeps the bilingual content of the old page.
- `web/lib/content/exported-language.ts` — the planned
  `exported_document_language` behavioral check: every exported `.html` must
  declare the language of its URL locale (first URL segment; the default
  locale sits at the root, the shared `404.html` has no URL locale and carries
  the default). Wired into `web/scripts/scan-rendered.ts` beside the leak
  scan — a violation fails `npm run build` (exit 1).
- Guards pinned to the old tree updated in the same change:
  `collectRoutes` in `web/lib/content/internal-links.test.ts` skips route-group
  segments (Next maps them to no URL segment), `web/lib/content/stop-page.test.ts`
  and `web/privacy-page.test.ts` point at the moved page files; `listFiles` in
  `leak-guard.ts` is exported and reused by the new scan (one tree walk, not
  two).
