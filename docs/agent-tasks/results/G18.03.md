## Мімоза-брама і перайменаванне `SqlDriver.exec` → `execSql`

L3-гіт-брама Mimosa блакуе каміт на статычнай знаходцы HIGH
`command-injection` у `services/db/types.ts:32` — радок
`exec(sql: string): void;` інтэрфейсу `SqlDriver` (праект гатовых змен гэта
файла не датыкаўся; па імені метаду ён мачыцца на `child_process.exec`,
CWE-78; ацэнка эксплуатавальнасці: ніводнага shell-выкліку ў рэпо няма —
гэта дэкларацыя SQL-драйвера). Брама цвёрдая: «знешні код павінен змяніцца»,
запячатаны рэскан яе не здымае. Рашэнне — мінімальнае ўмяшанне:
перайменаванне метаду ў `execSql` (яно дакладней кажа сэнс: выконваецца SQL
скрыпт, не каманда) па ўсіх кропках: `types.ts` (інтэрфейс + каментар
«SQL only, never a shell»), `db.ts` (6), `db.test.ts` (4), `schema.ts` (1),
`test-fixture.ts` (адаптар: `execSql: (sql) => db.exec(sql)` — адзіная кропка
адлюстравання на натыўны `node:sqlite` `.exec`). Гэта па-за аб'ёмам G18.03,
раскрыта ў PR; у дэме G04.01 інлайн-крыпт абноўлены (`x.execSql`), яе вывад
перазахоплены байт-у-байт (verify exit 0), указальнік — у
[results G04.01](G04.01.md).

## Рэвью-раунд 1 (PR #177)

Рэвью (0 Crit / 0 High / 1 Medium / 1 Low) прынята да выканання да постынгу
каментара, каб суддзёўскае 👍 пакрывала фінальны HEAD:

- `process.exit(main(...))` → `process.exitCode = main(...)` — яўны выхад
  мог абрэзаць уласны stdout у pipe на macOS (асінхронныя запісы); exit-коды
  і дыягностыкі не змяніліся.
- файл, які не чытаецца, больш не друкуецца як «пусты»: маркер
  `(unreadable)` у абодвух радках + stderr-дыягностыка; тэст з `chmod 000`
  сам-скіпаецца на Windows з бачнай прычынай (`POSIX file permissions`).

Поўны suite перазапушчаны пасля гэтых праўак: 409/409 (лік абноўлены вышэй).
