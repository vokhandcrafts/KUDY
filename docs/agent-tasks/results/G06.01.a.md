# G06.01.a — City and Guides surfaces on the published catalog

**Status: complete.** Branch `zcode/313` (closes issue #313 on merge). The
canonical chain's first two surfaces — Explore (city) and the «Гіды» rubric —
render the published catalog through a ports-injected service and a vanilla
controller store; nothing on the surfaces is invented. The third link of the
chain (the guide preview and its Download/Start button) is G06.01.b
(`docs/agent-tasks/app/G06.01.b.md`, issue #314).

## What was built

- `services/catalog/types.ts` — the ports and the view model: the text loader
  by origin-relative path (`CatalogPathLoader`, 21 §3.3 — only the configured
  public origin), the `Sha256` port (re-exported from contentRepo's contract),
  `CatalogRouteEntry` (verbatim route-entry shape), `CatalogOfferFacts`
  (the guide-facing projection of `DiscoveryOffer`, 21 §3.2), the
  `CatalogGuideCard` view (offer cards carry the availability split; route-only
  cards say `localesKnown: false` instead of inventing one) and the
  `CatalogLoadState` families named after the state coverage table
  (ready / offline / error).
- `services/catalog/envelope.ts` — the G01.06 reader decision for the device
  path: status routing (v1 / legacy-v0 / unknown-major / invalid) and the
  pointer size check (≤ 512 KiB before fetching). contracts/reader.mjs is
  Node-stdlib only (node:fs for schema files) and cannot join the RN bundle,
  so this module projects only the decision, performs **no deep validation**
  (publication owns the schema verdict), and a parity block in the test suite
  pins every status/degraded/routes/pointer verdict to `readCatalogDoc` on the
  committed fixtures — a drift turns CI red.
- `services/catalog/catalogService.ts` — `loadCatalog`: fetch `catalog.json`
  → envelope → if the pointer is present, validate its path against the
  shared `isSafeRel` idiom (reused from services/contentRepo/inventory.ts,
  implementation-rules 3), fetch, pin the fetched bytes to the pointer's
  declared size and sha256, then project offers (drop unpublished refs and
  corrupt entries with diagnostics, never a crash). `projectGuides` merges:
  offers sorted by `editorial_order` then `offer_id` (21 §4), route-only
  entries after them by route_id (the canon orders offers only; the tail
  takes a deterministic order). Failure semantics of 09 §4: a load failure is
  fatal only with no previous result — with one, the last valid projection
  returns as `offline` with the reason.
- `services/catalog/loader.ts` — `createOriginCatalogLoader(origin)`: the
  origin-binding fetch adapter (one adapter for the device build and a local
  test server; fetch is global in both runtimes).
- `controllers/catalog/catalogController.ts` — the vanilla store (G06.09.b
  helper): boot load at construction (09 §4 — the catalog refreshes at every
  start), the monotonic run counter of the sample-controller pattern (a
  superseded refresh never overwrites the newer result), `refreshing` while a
  revalidation keeps the cached surface visible.
- `controllers/catalog/useCatalogController.ts` — the React binding (hooks as
  controllers, 19 §2.2); a build without the catalog port yields `null` and
  the surfaces render their honest unavailable state — no inert fake
  controller.
- `controllers/createServices.ts` — the root constructs the catalog service
  and controller only when both ports are provided (`catalogOrigin` string
  port + `catalogSha256`); the loader factory is called here, keeping app/
  free of services imports (the `app-no-services` rule). The device build
  passes `EXPO_PUBLIC_CATALOG_ORIGIN` when set; the digest adapter joins with
  the device crypto task, until then the device surfaces show their honest
  unavailable state — no fake stands in for a device adapter.
- `app/design-tokens.ts` — the visual values the surfaces consume, verbatim
  from the G06.07 canon (`docs/design/visual-language.md`, machine block),
  each entry anchored to its token name; `test/design-tokens.test.mjs` gained
  a guard that fails when a value drifts from the canon or the anchor drops
  (implementation-rules 1).
- `app/guide-card.tsx` — the shared chrome: the ordinary guide card (canon
  card kind: white, line border, radius 10, padding 12), the tariff badge
  (free/paid/mixed — the contract values verbatim; the tariff is a badge, never
  a rubric axis, 11 §16.1/20 §6), the honest-state banner (notice/error pairs)
  and `CatalogStateView` — the state mapping both surfaces share (null →
  unavailable; loading; ready incl. the NAV3 empty city «не апублікавана»;
  offline → banner over the last valid cache; error → named reason, 11 §7).
  The rubric section renders only with published content (NAV2). Responsive
  split of the scheme: one column below 821 px, two above
  (`isWide` + a wrapping grid); big text is honored through RN font scaling
  (allowFontScaling stays on; no fixed line heights).
- `app/(tabs)/explore.tsx`, `app/city/[id]/guides.tsx` — the two surfaces:
  city name (NAV3) + rubric section with the guide cards (the same card both
  surfaces show, D02) / the full rubric list with Back to the city (NAV9).
  Cards open `/route/<route_id>` — the same preview every path opens; the
  preview surface itself stays the G06.09.a placeholder until G06.01.b.
- `services/catalog/demo-g0601a.mjs` — the Showboat driver (tools/ must not
  import services/, so the driver lives in the service module like
  demo-g0403.ts before it).
- `docs/demos/2026-09-26-g0601a-city-guides.md` — the demo (below).

## Tests

- `services/catalog/catalogService.test.ts` (node --test, 15 tests): the
  envelope parity block (six canon verdicts including the oversized pointer),
  the published fixtures through the production load path (offer card facts:
  title, access, editorial_order, availability split, estimated duration;
  route-only card honesty), the ordering rules (editorial_order, offer_id
  tie-break, route-only tail), the NAV3 empty city, degradation when the index
  is unreachable/unsafe/tampered (the unsafe path is never fetched), drop of
  unpublished refs and corrupt offers (null array elements — diagnostics, not
  a crash), corrupt catalog text → named state, loader failure with/without
  cache, and the origin loader against a local HTTP server.
- `controllers/catalog/catalogController.test.ts` (4 tests): boot into ready,
  revalidation failure keeps the cached guides with the reason (09 §4), the
  no-cache error path, the superseded-refresh guard.

## Acceptance criteria (issue #313)

1. One/many guides from the real catalog, no invented cards, same card on both
   surfaces (D02), each exactly once, `editorial_order` → `offer_id`, legacy
   route-entry fallback — the fixture, ordering and parity tests + the render
   tests.
2. Tariff as a canon badge, never a rubric axis; NAV2 (empty rubric does not
   render); NAV3 honest empty city with Побач and My KUDY untouched (the
   `/my` and `/map` placeholder tests still pass).
3. Languages per availability on offer cards (text/audio split), layer
   locales declared as such on route-only cards; offline banner over the last
   valid cache; error without cache → the normal city page with the named
   reason.
4. One column below 821 px, two at 821 px (`isWide` boundary test + wrapping
   grid); canon tokens verbatim with the guard; big text via platform font
   scaling.
5. All four gates green (counts above); layer rules hold — screens import
   controllers only, the root is the only services constructor, no new
   baseline entries.
