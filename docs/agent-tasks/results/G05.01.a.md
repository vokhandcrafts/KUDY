# G05.01.a — Engine types and session lifecycle

Issue #197 · branch `zcode/197` · 2026-09-23 · executor: Zcode session (GLM-5.3-Flash).

The first production-reducer slice lives in `core/engine/`: `state.ts` (state
types + derived views), `events.ts` (RunEvent union), `commands.ts` (RunCommand
union), `reducer.ts` (pure `step()` with the session lifecycle and the
`AccessReady` trust boundary) and the acceptance suites `reducer.test.ts` /
`state.test.ts`. Semantics mirror the frozen documentation model
`docs/run-model/run-model.mjs` (its README, «Як перанесці ў дадатак»); the
model files were not edited.

## Acceptance criteria — walked from the card

1. ✅ **Names are copied verbatim from 09 §6.1; the snake_case ↔ camelCase
   mapping is declared once (the 19 §3 boundary).** The mapping is declared in
   the `core/engine/state.ts` header — the single mapping point; event and
   command names in `events.ts`/`commands.ts` carry 09 §6.1 wording with
   anchored comments. The full session field surface is pinned by
   `reducer.test.ts` «criterion 1: the session state carries the 09 §6.1
   Active fields under one mapped spelling». Types follow 19 §3.1 plus the
   moment-variant events 09 §6.1 carries after the G01.02 synchronization
   (canon note below).
2. ✅ **`step(state, event, now, config)` is pure; `npm run arch:check` is
   green.** No clock read, no I/O, no React Native import — the input state is
   `structuredClone`d and effects are only commands. Pinned by
   «criterion 2: step() does not mutate the previous state and is
   deterministic»; arch:check: `OK — 123 modules cruised, 6 violation(s) pass
   via the baseline dated 2026-09-22` (the 6 web↔tools entries are the
   pre-existing baseline; `core-zone-closed` holds for the new files).
3. ✅ **States Idle/Active/Paused/Ended; Ended never returns to Active; Pause
   and End clear `queued` and emit `ClearGeofences`.** `reducer.ts` handles
   `Start` only from Idle, `Resume` only from Paused; on `Ended` every event
   is ignored (invariant 9). Tests: «Pause retires the queued stop to
   auto_fired…», «End retires the queue…», «Ended never returns to Active —
   Resume and Start are ignored there», «a live session ignores a second
   Start», «with no session only Start exists».
4. ✅ **Start refuses a package without a verified tier or with
   `accessible_stop_ids` outside the pinned package.** `startSession()` throws
   `RangeError` — the reducer counterpart of the model's `start()` refusal
   (readiness is verified before the Start transaction, ADR G01.03 §3.3/§3.6).
   Tests: the four «criterion 4: Start refuses…» cases (empty tier, unknown
   layer, foreign stop id, duplicated entry).
5. ✅ **`AccessReady` accepted only when all six checks of ADR G01.03 §3.5
   pass; on mismatch the state stays deep-equal; on acceptance
   `tier_available` widens, `accessible_stop_ids` recomputes and
   `SetGeofenceWindow` is emitted, with no Play; a repeat is a no-op.**
   `applyAccess()` implements checks 1–4 (identity + issuer value) and 5
   (payload inside the pinned package); check 6 (capability channel) is the
   typed event path itself — the engine cannot see the disk, the channel
   trust lives in services/download (ADR §3.5, «Няздольная да падробкі мяжа
   выдаўца»). Tests: accept / other version (proof) / other route, locale,
   issuer / unknown stop, wrong runtime tier / repeat no-op / tier-only
   payload / paused-session addressee.
6. ✅ **Stop status is computed, not stored.** `stopStatus()` in `state.ts`
   follows ADR G01.01 §4.5 (locked → playing → played → available → pending,
   first match wins; `story_accessible` per §4.2, primary story derived per
   §4.1). Tests: `state.test.ts` — all five statuses, the paid-only stop
   staying locked until the same-version unlock, and the status derived
   through the reducer flow.

## Canon note — differences recorded (no shared doc edited)

- **19 §3.1 predates the G01.02 synchronization** (canon note in the brief):
  it lacks the `moment` variant of `playing`, `PlayToken`, `MomentFinished`,
  `AudioFailed`, `PlayMoment`, `UserStoppedAudio`, `ResumeAudio` and
  `GuideResume`. The types here follow 09 §6.1 as the name source; 19 is not
  edited (its §7.2 assigns that to a separate task).
- **The `Start` event carries `stops`** — the pinned package. 09 §6.1 names
  Start without fields and 19 §3.1 lists identity fields only; the pin check
  (criterion 4) and the derived status read the package, mirroring the model's
  `start(sessionId, routeStops, …)`.
- **`AccessReady` emits `SetGeofenceWindow`** with the recomputed eligible
  stops on acceptance; the frozen model emits no command there (09 §6.1
  command `SetGeofenceWindow(stop_ids[])`, ADR G01.03 §3.5 «акно геафенсаў
  пералічваецца», criterion 5 of the card). A repeat widens nothing and emits
  nothing.
- **`Resume` clears `autoplay_suspended`** — 09 §6.1 invariant 7 lists «Resume
  сесіі» among the clearing human actions and the model sets it; ADR G01.03
  §3.3's «autoplay_suspended=true да яўнага дзеяння» is read as the
  restore-after-restart rule (ADR §3.2), not a second norm for the explicit
  Resume action. No doc edited; flagged here for the G05.01.d parity pass.
- **Deferred to the slice that owns them**: the live-pause `paused` flag of a
  launch (model parity, marker nuance — G05.01.c), the `last_fix` update on
  `LocationAccepted` and the `DwellCompleted` radius payload (freshness and
  queue checks — G05.01.b), `EmitEvent` payload allowlist (G01.05, issue
  #185).
