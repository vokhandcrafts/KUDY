## What was decided

- **Адзін даслоўны экзэмпляр закрытага спісу.** `GRANT_ERRORS` у `grant.ts` — машынная праекцыя `19` §3.6 з анкерам на кананічны тэкст у каментары; `STATUS_OF` і `OUTCOME_BY_CODE` выводзяцца з яе (табліца вынікаў exhaustive на ўзроўні кампіляцыі: код без выніку ламае зборку). Першапачатковы план меў другую даслоўную копію ў фэйку тэста з deep-equal гардам — jscpd правільна злавіў гэта як клона (13 радкоў/114 токенаў), і па правіле 8 копія заменена на вывядзенне: фэйк адказвае кодамі з тае самай табліцы, а цыкл «кожны код → свой вынік» праганяе ўсе 11 кодаў праз сапраўдную машинерыю. Live-парытэт — абавязак G08.04 (правіла 15), зафіксавана тут.
- **Адзін вынік на код (крытэрый 2):** `no_entitlement` → `purchase`; `entitlement_unavailable` → `unavailable` з `retryAfterMs` і лікам рэтраў (рэтрай можна паўтараць); `invalid_request` → `executor-error`; `url_expired` → `regrant` (выконваецца крыніцай байтаў); астатнія закрытыя коды → іменаваны `failed`; невядомы статус/код або разбітая пара статус↔код, сапсаванае цела поспеху → `unknown` (fail closed: ніколі не granted, ніколі свабодны доступ). Лакальны адхільны ўвод → `invalid-input` да першага выкліку транспарту; адмова транспарту → `offline`, без кідання да выклікальніка.
- **Дзве кропкі мапінгу snake_case ↔ camelCase** (правіла 2): цела запыту `GrantRequestBody` і `parseGrantSuccess` — адзінае месца, дзе правадная форма пераўтвараецца ў сэрвісную; астатні код працуе ў camelCase.
- **Рэтрай-палітыка:** толькі `503 entitlement_unavailable`, межы `maxRetries` (2 па змаўчанні), затрымка з загалоўка `Retry-After` (секунды, як у кантрактнага рэфэрэнса) праз ін'ектаваны `delay`; адсутны/непарсавальны загаловак → `defaultRetryAfterMs` (30 с, анкер на спайк). Фінальны адказ пасля вычарпання бюджэту нясе свой уласны `Retry-After` — наступнае чаканне ўжо гатовае. Выдаленне разбору загалоўка ломіць 503-тэст — гэта Proof з issue, праверана revert-эксперыментам.
- **Порцыі:** `requestGrant` грантуе ўсе шляхі верыфікаванага lock часткамі па ≤20 (`09` §5: ліміты кантрактныя; анкер — `MAX_PATHS` спайку); крыніца байтаў мінтуе леніва — вакно ад бягучага файла, з перамінтам, калі да `expires_at` менш за 60 с (`09` §5.1 «пераміньвае… калі наблізіўся»).
- **Заканчэнне URL па дарозе (крытэрый 3):** `403 url_expired` на запыце файла → перазапыт порцыі, што засталася, пачынаючы з гэтага файла → паўторная загрузка; правераныя файлы трымае рэзюм актывацыі па хэшу — яны не перакачваюцца (лічыльнікі запытаў у тэсце і дэме).
- **Порт без дэфолту:** транспарт, credential, `delay`, `now`, `fetchBytes` — усё ін'ектавана, рэальнага HTTP і платформенных API у ядры няма; прыладны HTTP-адаптар — па-за scope'ам issue, таму дэфолтнага транспарту не існуе ў прынцыпе (сеткавы гард ядра `download.ts` не закрануты).
- **Ніякіх сакрэтаў у назіраным (крытэрый 5):** дыягностыкі — толькі іменаваныя падзеі; паведамленні памылак — канстантныя іменаваныя радкі без URL; кліент нічога не піша і не логіруе сам (sink апцыянальны). Тэст-транскрыпт (дыягностыкі + усе SQL-запісы драйвера) скануецца на `SECRET`, `Bearer `, `/private/`, маркер токена.
- **`activate()` павярхоўна чыннік:** даданае surfacing паведамлення адмовы порта ў дыягностыках `partial` — інакш `grant-fetch#grant-offline` губляўся ў `catch`. Гарда: тэсты крытэраў 4–5 падаюць пры адкате (праверана).

## Criteria

1. **Форма запыту:** тэст фіксуе дакладны набор ключоў праваднога цела (`locale, paths, route_id, tier, version`), значэнні з ключа плясту, Bearer з ін'ектаванага порта; 25 шляхоў lock → дзве порцыі 20+5; шляхі не прымаюцца ад выклікальніка — сігнатура іх не мае, `requestGrant` выводзіць іх з lock праз агульны `parseLock`; сапсаваны lock/небяспечны ключ → `invalid-input` да першага выкліку транспарту (нуль выклікаў).
2. **Закрыты спіс:** таблічны тэст праганяе ўсе 11 кодаў — кожны мае ўласны вынік і не рэтраіцца; `503` з `Retry-After: 7` → чаканне 7000 мс праз ін'ектаваны `delay` (Proof), без загалоўка → дэфолт; вычарпаны бюджэт → `unavailable` з `Retry-After` фінальнага адказу; `418 teapot`, разбітыя пары, `503` без кода, сапсаванае цела поспеху → `unknown`; офлайн → `offline` без кідання.
3. **URL expiring mid-download:** e2e праз `activate()`: першы запыт `audio/…` адказвае `403 url_expired` → другі раунд гранта з порцыяй, што засталася (`audio/…`), → актывацыя `complete`; `stops.json` — адзін запыт за ўвесь запуск; асобны тэст — перамінт пры TTL 55 с < маржа 60 с; крыніца адмаўляе шлях па-за lock (`grant-fetch#path-not-in-lock`, fail closed).
4. **Офлайн:** `requestGrant` → `offline` без кідання; e2e: транспарт кідае → `activate` вяртае `partial` з `grant-fetch#grant-offline`, фінальнага плясту няма, радкі `bundle_asset` pending; пасля аднаўлення сеткі паўторны запуск → `complete` без паўторнай аплаты і без зманкі частковага стану.
5. **Сакрэты:** найгоршы сцэнар (офлайн + 503-рэтрай + адмоўлены файл + завяршэнне) на адным драйвере-запісавальніку: дыягностыкі, паведамленні памылак і ўсе SQL-запісы скануюцца — нулявы ўдзел `SECRET`, `Bearer `, `/private/`, маркера токена; іменаваныя чыннікі (`grant-fetch#file-denied:path_not_allowed`) захоўваюцца без краплю.
6. **Фэйк і live:** спіс адказаў фэйка — машынная праекцыя `GRANT_ERRORS` (адзіная даслоўная копія `19` §3.6 — у `grant.ts`, з анкерам); цыкл крытэрыю 2 адказвае ўсімі кодамі праз сапраўдны `requestGrant`. Live-парытэт спісу — абавязак G08.04 (правіла 15); рашэнне аб адным экзэмпляры спісу прынята тут свядома (правіла 8, jscpd).
