# G05.06.a — Deterministic simulator on production functions

**Status: complete.** Branch `zcode/218` (closes issue #218 on merge). The simulator
imports the production run stack — real `RunOrchestrator` (which itself runs
`acceptFix` and `step`), real `LocationService`/`AudioService` over
deterministic OS ports — and replays a JSON trace with one deferred-action
queue, fault injectors and a byte-stable report.

## What was built

- `tools/simulate/clock.mjs` — `DeterministicClock`: the single time source
  (RunClock + LocationClock shapes) with the one deferred-action queue of
  09 §11, ordered by due time then insertion order; `pending()` feeds the
  report's never-fired list. No `Date.now`, no `Math.random` anywhere in the
  tool (test-guarded by source grep).
- `tools/simulate/ports.mjs` — `SimLocationPort` / `SimAudioPort`: the OS
  boundary as queue-driven stand-ins. Audio completions are scheduled at
  play + duration; pause freezes the remaining time, resume re-arms it (the
  live-pause semantics of ADR G01.02 §3.4 as a queue entry); focus events pass
  through verbatim, never as finished.
- `tools/simulate/trace-schema.mjs` — the trace document (route, stops,
  config, events: `GpsFix`, `AppBackground`, `AppForeground`, `UserCommand`,
  plus the four injector directives `AccuracyDegradation`, `TimestampJump`,
  `SignalGap`, `IncomingCall`/`CallEnded`) and its validator: named
  diagnostics (`unknown-event`, `missing-field`, `non-monotonic-time`,
  `unknown-action`, `bad-value`, `duplicate-stop`), the whole document
  rejected on any diagnostic — no partial runs, no crashes (AC3).
- `tools/simulate/run.mjs` — the replay: composes the production stack with
  the injected clock, applies injectors at the OS boundary (worse accuracy,
  shifted timestamps, dropped fixes), maps user commands onto the
  orchestrator's session intents, and observes the committed engine states
  through the production `onCommitted` hook — launches, phase changes and
  accepted-fix distances are read from the reducer's state, never re-derived.
  The production `defaultEngineConfig` (30 s freshness, 2 × queue multiplier,
  10-min focus window) is used as-is; `dwellMs` and audio durations come from
  the trace config.
- `tools/simulate/report.mjs` — the observer and the byte-stable report:
  fired stops with per-stop trigger latency (first accepted fix inside the
  radius → launch), manual plays, the command stream with applied/no-op
  outcomes, timers that never fired, `stuck_playing`, counters, diagnostics.
  No wall-clock fields anywhere — the same trace run twice is byte-identical
  (AC2, asserted in a test and demonstrated by the demo's sha256 block).
- `tools/simulate/cli.mjs` — `node tools/simulate/cli.mjs --trace <file>
  [--out <file>]`; exit 0 clean or partial walk, exit 1 stuck_playing, exit 2
  corrupt trace with named diagnostics on stderr.
- `tools/simulate/simulate.test.mjs` — 17 tests wired into `npm test` (the
  `tools/simulate/*.test.mjs` glob, plus its line in the
  tools/build-bundle/test-wiring.test.mjs enumerator), covering AC1–AC5 plus
  queue-unit and CLI-level cases.

## The arch gate amendment (conscious, implementation-rules 18)

AC1 requires `tools/simulate` to import `core/`, `services/` and
`controllers/run/` — a deliberate exception to `tools-zone-closed`
(19 §2.4), which 09 §11 mandates («Сімулятар імпартуе прадакшн-функцыі»).
`.dependency-cruiser.cjs` now carves `tools/simulate` out of the tools rule
and pins what it may import with four rules: `simulate-no-other-zones`,
`simulate-run-controllers-only`, `simulate-no-npm` (node:* only), and
`simulate-no-run-model` — the frozen executable reference (19 §7.2) is not
importable by the simulator. `arch:check`/`arch:baseline` scan `docs/run-model`
so the last rule is real; the scope substring in the wiring guard
(tools/arch/arch-check.test.mjs) still matches. Verified both ways in this
session: a deliberate `run-model` import in `tools/simulate/cli.mjs` failed
`arch:check` naming the rule and the path; with the import removed the gate is
green.

## Acceptance criteria — expected/actual

1. **Production imports + the arch rule** — expected: the simulator imports
   `acceptFix`, `step`, the run orchestrator; a deliberate violation fails
   `arch:check`. Actual: `run.mjs` value-imports `RunOrchestrator`,
   `LocationService`, `AudioService` and re-exports `acceptFix`/`step`
   (identity-asserted against the production modules in AC1 tests);
   the planted-violation experiment failed the gate as above.
2. **Determinism** — expected: one queue (due time, then insertion order), no
   wall clock/randomness, byte-identical reports. Actual: `DeterministicClock`
   unit test pins the ordering and cancellation; the source-grep test pins the
   absence of `Date.now`/`Math.random`/`new Date`; two runs of the M1 trace
   produce identical report strings (test) and identical sha256 (demo).
3. **Trace events + injectors + corrupt traces** — expected: the four event
   kinds, the four injectors, diagnostics not crashes. Actual: all four event
   kinds replay; accuracy degradation keeps a stop silent through the 40 m
   gate, a timestamp shift forward rejects every later fix as future-dated, a
   signal gap trips the production watchdog (15 s threshold, bounded backoff)
   and the walk resumes with the dwell restarted, an incoming call is a live
   pause with the 10-minute window honored; corrupt traces answer with named
   diagnostics at the library level and exit 2 at the CLI (no stack traces).
4. **The report** — expected: fired stops, command stream, per-stop trigger
   latency, timers never fired, `stuck_playing`. Actual: all five sections in
   the report; the stuck scenario asserts exit 1 with the pending audio
   completion in `timersNeverFired`.
5. **M1 acceptance** — expected: a synthetic 5-stop route where all stops
   fire, none twice, nothing hangs; partial walk not a failure; `Ended` only
   after an explicit End. Actual: the M1 trace fires all five stops in route
   order with latency 10000 ms each (two dwell fixes after the entry fix),
   the walk back over the route fires nothing twice, `autoFired`/`heard` are
   complete, no `stuck_playing`; the partial walk exits 0 with `Ended`
   unreached; a manual `PlayStop` is reported as a manual play, never as an
   auto fire (and the tapped story never auto-replays, 11 C12).

## Proof

The brief's proof names `step`; the dwell requirement itself lives in the
pipeline (19 §1.3 AR-5: acceptFix owns dwell; `step` owns the trigger
conditions) — replacing `step` cannot change when a stop becomes triggerable.
The executable proof therefore replaces the imported production module that
carries the requirement: a module-loader hook swaps `core/pipeline/pipeline.ts`
for a copy with the dwell gate `>= 0`, and the M1 expectation fails exactly as
required — every stop fires on the first fix inside its radius with latency 0
(demo block «mutated pipeline latencies: 0, 0, 0, 0, 0»). The wording gap is
recorded here per implementation-rules 6; the intent (the simulator exercises
the imported production logic, and a re-implementing copy is detectable) is
demonstrated. Additionally, the AC1 identity tests fail if either production
function is swapped for a look-alike.

## Out of scope kept

- Generated trace set, field-trace fixtures and the CI comparison (G05.06.b):
  the CLI takes a trace document as input; no generator ships here.
- `readiness` CLI; recorded Gdańsk walks (G11.02).
- `AppBackground`/`AppForeground` are validated and counted, but have no
  engine effect: their wiring into location/audio modes belongs to the device
  adapters (G05.02.c) — the simulator deliberately does not re-implement it.
- The engine's `ScheduleTimer`/`CancelTimer` commands remain unconsumed
  upstream (G05.05 surface); the sim's queue serves the simulator's own
  deferred actions (audio completions, watchdog timers).
