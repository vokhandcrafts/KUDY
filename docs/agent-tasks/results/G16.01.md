## Contract decisions (single mapping points)

- Registry key columns `(target_kind, target_id, target_version, locale)` ← wire target: `route_id|place_id` → `target_id`, `version|content_version` → `target_version` (schema `contracts/schemas/feedback-target.schema.json` is canonical; drift-guarded in `feedback-core.test.ts`).
- The schema's locale enum `{be,en,uk}` is the **registry** contract (`REGISTRY_LOCALES`, drift-guarded against the schema file); request validation stays structural, so the fixture's reserved `pl` reaches the registry check and answers `422 unknown_target` (fixture `cas-unpublished-locale`).
- Feedback auth reuses the G08.01 bearer verification (no second identity) but answers **401 `unknown_device`** per 21 §5.3 and the fixture — deliberately not the device/events 403.
- Port faults (storage unavailable, incl. missing DATABASE_URL) answer **503 `feedback_unavailable`** per 21 §5.3 («часовая немагчымасць праверыць або захаваць») with a redacted diagnostic; `prepared` targets answer 503 `target_not_published`.
- Reasons are a set: canonical form is sorted, so a reordered retry replays instead of conflicting; the mutation payload hash is built from validated fields only (never raw JSON).
- Idempotency: identical mutation_id + payload replays the stored revision; different payload → 409 `mutation_conflict` (the fixture pins only `revision_conflict`; the second 409 code is named here).
- Rate limits are the spec's own numbers: 8 KiB body (413), 30/min device, 120/min IP (429 + Retry-After), 60 s fixed windows; reads count too; counters persist across rejected requests.

## Rollback / recovery (additive migration)

The migration only creates tables: rollback is `drop table feedback_ip_rate, feedback_send_rate, feedback_mutations, feedback_current, feedback_target_registry` (reverse dependency order) — it disables collection but drops ratings written after it (21 §10: the runbook backs up before migrating; the client's durable zone survives). Recovery re-applies the migration and re-imports the past release exports (`importFeedbackRegistry` + `publishFeedbackTargets` are idempotent); rollback never erases historical published targets that predate it.
