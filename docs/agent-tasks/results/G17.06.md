# G17.06 — Cleaning rules engine v1

Issue #161 · branch `zcode/161` · 2026-09-25 · executor: Zcode session (GLM-5.3-Flash).

The collector gained the cleaning stage (docs/24_web_collection.md «Ачыстка»):
rule packages as data (`news-v1`, `wiki-v1`, `youtube-v1`; the schema's `web`
type shares the news package — one article-page family) turn a raw snapshot
into a versioned cleaned document. The engine (clean.mjs) prunes non-content
paragraphs with the package's `drop` rules, applies the package's `strip`
rewrites (wiki citation markers) and preserves everything else byte-for-byte:
anchors stay in their `[label](url)` form, media blocks stay at their
positions with captions. Date and language move into the document's front
matter from metadata.json (the YouTube `upload_date` `YYYYMMDD` normalizes to
an ISO date — the mapping is declared once in clean.mjs).

Versioning follows the spec's «сыро не перазапісваецца»: a cleaning run whose
package version differs from the latest writes the next `cleaned/v<N>.md`
beside the raw files and records the version in the new `cleaned_versions`
table; the record's status moves `raw → cleaned`. Every cleaning step is a
`run_log` row (kind `clean`) whose work order carries the record id, package
and target version, and whose ref (`<record>:<package>#v<target>`) makes the
enqueue idempotent per attempt — a re-run of the same package version
enqueues nothing (convergence), a rule bump or a rollback re-run of an older
package version enqueues a fresh attempt, and a step left `running` by an
interrupted process converges on the `unchanged` outcome instead of
duplicating a version file. The note appended to the step's detail names the
package version (`package news-v2: wrote version 2`).

`export-review` writes the author-review bundle into the campaign's snapshot
dir: `review/index.md` listing every record's latest cleaned version plus one
document file per record that opens with the visible citation (`Крыніца:` —
source URL, `Забрана:` — collection date, package and cleaning version). The
bundle is derived output — a re-export rewrites it deterministically and
never touches raw or cleaned files.

New files `tools/collector/packages.mjs` (the rule-package tables and the
closed `source_type → package` mapping), `tools/collector/clean.mjs` (block
parser, rule application, document builder, `cleanRecord` versioning
orchestrator, the `clean` step handler and `cleanCampaign`), and
`tools/collector/review.mjs` (the bundle writer). `store.mjs` gains the
`cleaned_versions` table plus the lookup/insert/status helpers and the
lookup-only `registeredCampaignId` (cleaning and export answer "run it
first" for a never-run campaign instead of creating a phantom row).
`collector.mjs` gains the `clean` and `export-review` commands (exit 1 for an
unregistered campaign, the shared `readCampaignOrExit` preamble with `run`).
`clean.test.mjs` walks the acceptance criteria; it is wired by the existing
`tools/collector/*.test.mjs` glob — no runner edit needed.

## Acceptance criteria — walked from the card

1. ✅ **Per type, a raw fixture cleans with no nav/ad/«read also» markers and
   with every content paragraph present.** The news fixture (CLI end-to-end
   over a `file://` seed) carries three marker paragraphs, each matching
   exactly one `news-v1` drop rule, and three content paragraphs; the cleaned
   document asserts each marker absent by name and every content paragraph
   present. The wiki fixture asserts the citation strip (`[1]` gone, content
   kept) and the hatnote drop («Zobacz też:»); the YouTube fixture asserts
   the stage-direction drop (`[музыка]` after its timecode anchor) with the
   timecode paragraphs kept. Tests: «news snapshot cleans to a document
   without markers…», «wiki snapshot cleans…», «youtube transcript cleans…».
2. ✅ **Raw bytes on disk are identical before and after cleaning.** The
   «cleaning never rewrites the raw snapshot» test hashes `text.md`,
   `snapshot.html` and `metadata.json` before the cleaning run and compares
   after.
3. ✅ **Changing a rule and re-running produces version 2; both versions
   retained; the run log names the package version.** The versioning test
   cleans with `news-v1` (v1), re-runs it (converges, still only `v1.md`),
   cleans with a changed package (`news-v2`, one extra drop rule) and asserts
   `v1.md` and `v2.md` both exist with the right front matter, then rolls
   back to the registry package and asserts `v3.md` written from the
   untouched raw. The run-log assertion greps the `clean` rows for the work
   order (`"package":"news","package_version":2`) and the note (`package
   news-v2: wrote version 2`). Tests: «a rule change re-runs into version
   2…», «a cleaning step left running by an interrupted process converges…».
4. ✅ **Anchors keep anchor+URL form; photos stay at their positions with
   captions.** The news fixture's figure (a real file:// image step through
   the production `processImageStep`) lands in `text.md` as
   `![Stocznia](media/gdansk-shipyard-turns-into-a-museum-img-01.png)` with
   the `_Stocznia Gdańska, 1980_` caption line; the cleaned document keeps
   the block verbatim between the content paragraphs it stood between, and
   the markdown anchors are asserted verbatim including the resolved
   relative `file://` URL. Test: «news snapshot cleans to a document…».
5. ✅ **The review export bundle is generated and its markdown opens with
   visible citations; suites wired into `npm test`; jscpd clean.** The
   export test runs `export-review` through the CLI and asserts the bundle
   document opens with `# <title>`, `Крыніца: <url>`, `Забрана: <collected_at>`,
   and that a second export is byte-identical. The suite rides the
   `tools/collector/*.test.mjs` glob of the root `npm test`; the local
   jscpd gate reports 0 clones (see Verification).

## Proof — revert experiments (run in the shipping session)

- **Overwrite the raw instead of writing a new version file** (the write path
  pointed at `text.md`/`transcript.md`): 6 of the 13 cleaning tests fail,
  including «cleaning never rewrites the raw snapshot» (criterion 2's
  byte-identity assertion). Restored → 13/13 green.
- **Remove the versioning** (`const version = 1` — every run rewrites the
  same file): «a rule change re-runs into version 2, both versions retained»
  and the interrupted-step convergence test fail. Restored → 13/13 green.
