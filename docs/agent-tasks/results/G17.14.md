# G17.14 result — дыспетчар: картка запіса (тэкст з выявамі, спасылкі, журнал)

- Status: `complete`
- Task: issue #371, branch `zcode/371` (worktree `KUDY-wt-371` off `main` @ dafef84)
- What: the `/record?id=…` card in the read-only collector dispatcher — the
  editor's reading place for one record. The snapshot text renders block by
  block from `text.md` (for YouTube records `transcript.md`): paragraphs with
  inline `[anchor](url)` links, the media blocks the image steps wrote
  (`![alt](media/file)` with the emphasis caption) as `<figure>` with
  `<figcaption>` at their archive positions. Below it: the metadata table
  (source with a canonical address when it differs, collected date, and from
  `metadata.json` — publication date, author, language, rights, and the wiki
  attribution whenever the file carries one), the full link table (anchor,
  address, paragraph context), and the record's own journal steps. The card
  shares `pageShell`, `notesHtml` and the journal row markup with the overview
  and the records list (one `stepRowHtml`/`stepsTableHtml` pair — the
  overview's column set is the parameterized superset). An anchor or record
  url renders clickable only for http/https/mailto; everything else is shown
  as text. The card shows the raw archive, not the cleaned versions — those
  are separate artifacts for guide assembly.

## Proven (criteria of issue #371)

1. **Тэкст запіса з выявамі на сваіх пазіцыях і подпісамі** — `textHtml`
   renders `text.md` blocks; image blocks become `<figure><img …><figcaption>`
   with the file served by the existing `/media` route, its existence checked
   on disk (`fs.statSync` under the record's snapshot dir). Dispatcher test
   «record card shows snapshot text with the image at its position, links and
   metadata» asserts the paragraph, the figure with src/alt/caption and the
   inline anchor; demo block 1 prints the same fragments
   (`docs/demos/2026-09-29-g1714-dispatcher-record-card.md`).
2. **Табліца спасылак: анкер, адрас, кантэкст абзаца** — `linksTableHtml`
   over the `links` rows in id order, `links` empty state included; asserted
   for both fixture rows in the same test.
3. **Метаданыя: крыніца, дата, правы, атрыбуцыя (калі ёсць)** —
   `metadataRowsHtml`: source (clickable, canonical as a code row when
   different), collected date, publication date (`published_at`, youtube
   `upload_date`), author (`author`/`channel`), language, rights (Belarusian
   word next to the canonical key), and the attribution object
   (`site`, `license`, `revision_id`, `contributors_url`) rendered only when
   `metadata.json` carries it — asserted with the fixture attribution row.
4. **Журнал крокаў запіса: статус кожнага крока, чытальныя дыягностыкі** —
   `recordSteps` matches only the record's steps: seed/crawl by url, image and
   clean by the `recordId:` ref prefix, and — scoped to the source type that
   kind produces — youtube by the video id inside the record url, wiki-article
   by the title mapped back from the `/wiki/` url (`wikiTitleFromUrl`, the
   declared inverse of `wikiArticleUrl`, unit-tested round-trip in
   wiki.test.mjs). The type scoping keeps a web record whose url merely embeds
   `watch?v=` from inheriting a youtube step (negative fixture G). The time
   cell is asserted with the row — a snake_case field left unmapped would
   render the `—` fallback (caught and fixed during the demo verification).
   Test «the card step log matches steps by url, record prefix, video id and
   wiki title» covers the positive shapes, the type-scoping negative and the
   readable empty state; another campaign's image step stays out.
5. **Адсутны файл выявы або снапшота — чытальная прыкметка, сервер не падае** —
   a missing image file renders a note in place (with its caption), a hostile
   image ref (no `media/` prefix, or a `media/` ref escaping the media dir)
   renders «Нераспазнаная спасылка на выяву» and never becomes a path or URL,
   an empty snapshot dir names both text forms, corrupt `metadata.json`
   renders a metadata note (the heading falls back to the search-index title),
   a record without a snapshot renders «Здымак не запісаны», and a snapshot
   outside the snapshots root answers the containment note even when its files
   exist — all cards answer 200 and the list page answers normally afterwards
   (test «missing snapshot files render readable notes and the server stays
   up»; each guard fails on removal — revert-run in the shipping session). An
   unknown record id, a missing `id`, and an unknown parameter answer a named
   404 page (test «unknown record id, missing id and unknown parameter answer
   readably»). The attribution's `contributors_url` goes through the same
   scheme allowlist as every anchor — a non-http value arrives as text
   (`<code>`), never as an anchor.
6. **Тэст: fetch карткі з фікстурнай БД + выпадак адсутнага файла; чырвоны
   пры адкатзе** — `dispatcher.test.mjs` boots the real server over the
   production store fixture extended with snapshots on disk (full, corrupt,
   empty and absent) and four more records/steps; 4 new card tests + the
   `wikiTitleFromUrl` unit test. Red-on-revert ran in the shipping session:
   dropping the `/record` route fails all 4 card tests (12 pass / 4 fail);
   restoring → 16/16.
