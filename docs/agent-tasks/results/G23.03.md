# G23.03 — Android E2E driver and smoke suite

Issue: [#661](https://github.com/vokhandcrafts/KUDY/issues/661) (эпік #658).
Выканана 2026-10-11, сесія ZCode (GLM-5.3-Flash), галінка `zcode/661`,
worktree Linux-хоста (CachyOS, adb з SDK platform-tools, эмулятар AVD
`kudy-e2e`, вобраз `system-images;android-36;google_apis;x86_64`).

## Што зроблена

Нулявы-залежнасны Node-драйвер Android-эмулятара праз `adb` і smoke-сьюіт
пад адной камандай `npm run e2e:android` — Android-адпаведнік CDP-драйвера
сайта (G21.03) і вэб-E2E (G23.02). Каманда кампануе існыя інструменты, не
капіючы іх начынкі: сінтэтычны каталог паднімае існы G23.01-інструмент
(`tools/e2e-origin/serve-e2e-origin.mjs`), JS-бандл — дакументаваны дэв-шлях
`expo start --dev-client`, усе дотыкі прылады — праз уласны драйвер.

### Кампазіцыя (`tools/e2e-android/`)

- `driver.mjs` — адзіны ўласнік adb: рэзалв скрыпта (`KUDY_ADB` →
  `ANDROID_HOME` → PATH, інакш null для бачнага SKIP-а), спіс загружаных
  прылад, install, deep-link launch, uiautomator dump (пратакол G21.36:
  стары файл на прыладзе зносіцца перад дампам, няўдача паўтараецца,
  дампа без файла не існуе — стары экран ніколі не чытаецца як чаканы),
  tap па цэнтры вузла, Back/Home, force-stop, geo fix, screenshot,
  умовнае чаканне `waitFor` з дэдлайнам (ніводзін фіксаваны sleep).
  Парсер дампа — quote-aware сканар тэга `<node>` (значэнні атрыбутаў
  могуць утрымліваць `>`), каруптаваны ўвод дае дыягностыку, не падзенне.
- `run-e2e.mjs` — ранер: рэзалв мэты (adb/serial/APK → бачны SKIP са
  спісам прылад), фаза A без origin (Metro свайму жыццёваму цыклу),
  фаза B з G23.01-origin (`EXPO_PUBLIC_CATALOG_ORIGIN=http://10.0.2.2:<порт>`,
  новы цыкл Metro — значэнне запякаецца ў бандл), `adb reverse`, усталяванне
  APK з PIN-ам SHA-256 у справаздачу, Metro/origin у ўласных
  працэс-групах — стоп па group id, порт-полінг гатоўнасці, адзін аўтаматычны
  рэтрай Metro (артефакт FallbackWatcher-а на не-ext4). Артефакты няўдач —
  скрыншот + апошні дамп + журналы працэсаў — у git-ігнараванай
  `tools/e2e-android/artifacts/<run>/`.
- `driver.test.mjs` — юніт-тэсты па запісаных дампаў-фікстурах
  (`fixtures/dump-explore.xml`, `fixtures/dump-not-found.xml`,
  `fixtures/adb-devices.txt` — жывыя запісы з эмулятара): селектары,
  entity-дэкодыўка, каруптаваны ўвод, bounds, чаканне-таймаўт, адсутны
  элемент, тэсты `waitFor` ідуць праз вытворчы `findNode`.
- `wiring.test.mjs` — гарды (implementation-rules 1/5/7): npm-test глыб,
  сцяг `e2e:android`, git-ignore артефактаў, наяўнасць запісаных фікстур —
  зняцце любога чырванее.

### Змены на экранах (без паводзін)

- `app/route/[id].tsx` — недаступны стан без кантролера атрымаў
  `testID="route-unavailable"` (тэкст `catalogUnavailable` быў без меткі).
- `app/run/[id].tsx` — недаступны стан (surface === null) атрымаў
  `testID="run-unavailable"` на загалоўку: без origin рэальны стан малюе
  толькі «Сесія недаступная» без reason-вузла, таму існага
  `run-unavailable-reason` там няма.
- Астатнія маркеры ўжо існавалі: `screen-*` на ўсіх экранах,
  `place-unavailable`, `city-message`, `run-unavailable-reason`,
  `guide-card-<routeId>`, `link-*`, `btn-*-back`.

### Два вынікі абнаўлення dev-client-выявы

- Халодная глыбокая спасылка проста ў роўт (`kudy://route/…`) на
  development build трапляе ў лаўнчэр dev-client (бандл яшчэ не выбраны),
  а не ў дадатак. Роўтавыя кейсы ідуць па цёплай схеме: халодны старт праз
  dev-client URL, потым спасылка ў жывы дадатак — так спасылка і прыходзіць
  карыстачу. Для production-зборак гэтага не існуе.
- One-time onboarding-шкінка dev-client («This is the developer menu») —
  уласнае фокуснае акно: uiautomator бачыць толькі яе. `coldStart` ранера
  памірае на ўмове: пакуль у дампе ёсць «Continue» — Back-dismissal,
  потым чаканне `screen-Explore`.

## Адказ на крытэрыі прыёмкі

1. **Умовныя чаканні з дэдлайнамі, чытэльныя адмовы, артефакты** —
   `waitFor` паліць свежыя дампы з дэдлайнам (ніводзін sleep-чаканне),
   таймаўт называе селектар і шлях да апошняга дампа; няўдача кейса захоўвае
   скрыншот, дамп і журналы ў `artifacts/<run>/<кейс>/` (гл. жывы прыклад
   `unavailable-run` з прагону 16:54 UTC — artifacts запісаныя да фіксу
   маркера).
2. **Smoke: халодны старт, табы, Back, невядомая спасылка** — жывы прагон
   2026-10-11 17:06 UTC (вынік ніжэй): `cold start reaches Explore`,
   тры напрамкі з Explore (`link-nearby` → `screen-Map`,
   `link-discovery` → `screen-Discovery`, `link-kudy` → `screen-KUDY`) і
   апаратны Back (`input keyevent 4`) → `screen-Explore`;
   `kudy://e2e-no-such-screen` → `screen-Not found` → Back → Explore.
3. **Сумленныя unavailable-станы без origin** — пяць роўтавых кейсаў:
   route → `screen-Route preview` + `route-unavailable`, run → `screen-Run`
   + `run-unavailable`, place → `screen-Place detail` + `place-unavailable`,
   collection → `screen-Collection` + `city-message`, city guides →
   `screen-Guides` + `city-message`. Спіс 2026-10-06 рэтэсту ў main не
   апублікаваны (фіксуе картка эпіку #658), таму маркеры ўзятыя з
   рэндэра экранаў; app-тэсты тых жа станаў — `app/navigation.test.tsx`,
   `app/back-navigation.test.tsx`.
4. **З G23.01-origin каталог грузіцца** — фаза B: Metro з
   `EXPO_PUBLIC_CATALOG_ORIGIN=http://10.0.2.2:8793`, origin-сервер
   `tools/e2e-origin/serve-e2e-origin.mjs --port 8793` (два пакета,
   дэфолт), на Explore бачная картка фіксстурнага гіда
   `guide-card-e2e-free-guide`.
5. **Бачны SKIP, ніколі не фальшывы pass** — праверана жывым чатыры разы
   за сесію: без adb (`KUDY_ADB` у пустае), без загружанага эмулятара,
   з неснаходным serial, без APK — кожны раз адзін радок `SKIP …` са
   спісам прылад і exit 0; ніводзін PASS пры гэтым не друкаваўся.
6. **Юніт-тэсты па запісаных дампаў** — `node --test
   tools/e2e-android/*.test.mjs`: 14/14 pass (селектар-пошук, таймаўт
   чакання, адсутны элемент, каруптаваны ўвод, wiring-гарды). У `npm test`
   глыб дададзены і ахаваны `wiring.test.mjs`.
7. **Зняцце testID чырваніць іменаваны кейс** — revert-эксперымент:
   з `app/route/[id].tsx` зняты `testID="route-unavailable"`, поўны прагон
   на тым жа эмулятары павярнуў `FAIL guide route shows its unavailable
   state — timeout … waiting for testID "route-unavailable"` (адзіная
   няўдача прагону); адкат — усё зялёнае. Вынік прагону — у раздзеле
   доказаў.

### Revert-эксперымент (крытэрый 7)

З `app/route/[id].tsx` зняты `testID="route-unavailable"`, поўны прагон
на тым жа эмулятары (свежа сабраны ў гэтым worktree dev-client APK,
SHA-256 `0c7796753b…3b823056b5`; паралельная сесія знесла стары білд у
main-checkout):

```
FAIL guide route shows its unavailable state — timeout after 30000 ms
     waiting for testID "route-unavailable"   # адзіная няўдача
smoke: 10 passed, 1 failed                    # артефакты 2026-10-11T20-05-56-576Z
```

Адкат (testID вернуты, дрэва тоеснае зялёнаму прагону) — усе іншыя 10
кейсаў прайшлі ў тым жа прагоне, што пацвярджае ізаляцыю няўдачы.

## Асяроддзе і наезды

- Эмулятор: асобны AVD `kudy-e2e` (не `kudy-test` — яго базавы вобраз
  залочаны паралельнай сэсіяй), `-read-only` + COW-overlay: устаноўкі
  нясуць толькі overlay, база застаецца чыстай.
- На хасце два adb (SDK і сістэмны): яны змагаюцца за сервер :5037 —
  бачны SKIP «serial is not a booted device» мог быць ад пераўтварэння
  сервера. Парадак, які стабільна працуе: `adb start-server` ад аднаго
  бінарыка → буц эмулятара → прагон тым жа бінарыкам.
- Некалькі разаў за сесію эмулятар-інстанс ціха паміраў разам з падзеннем
  ZCode (фонавыя задачы харнэса пасякаюцца) — аддзелены `setsid`-запуск
  эмулятара і сюіта праблему здымае.
