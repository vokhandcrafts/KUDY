# G03.04 result — agent-side checks: media rights, locked previews, manual moments, text/audio boundary

Issue #301 — branch `zcode/301` — 2026-09-26 — executor: Zcode session (GLM-5.3-Flash).

## What was done

The row's agent part is the checks: the authoring/content side (voice recording,
photos, EN translation) stays with the founder. Every rule below is anchored on
already-published canon — `media.schema.json`/`moment.schema.json` (09 §3 Media
and Moment), stop schema's previews allowlist, 09 §3 invariant 1 and §8 — no
contract doc or schema was edited.

1. **License/credit on every media element (criterion 1).** The validator
   (`tools/validate/validate-package.mjs`) now reads an optional root
   `media.json` manifest of `media.schema.json` records and enforces:
   per-record schema (license/credit are schema-required), unique `media_id`,
   every `.m4a`/`.webp` file in the tree (the two mimes the schema allows)
   covered by a record — `unlicensed-media`, each record's `sha256` matching a
   real file — `media-sha-unmatched`, the record not drifting from the
   covered file's own facts (`media-bytes-mismatch` for a stale size,
   `media-locale-mismatch` when a record claims a locale the covered path
   does not carry), `place.name_audio_refs` ids resolving — `unknown-ref`,
   record `voice_id` resolving and speaking the record's locale —
   `unknown-ref`/`voice-locale-mismatch`. Coverage is mandatory whenever the
   tree ships media files; a tree without media files needs no manifest. The
   author template (`content/author-template[-invalid]`) ships a valid
   `media.json` now, and `content/README.md` documents the rule and the
   media-swap workflow (update the record's sha+bytes with the file).
   `build-bundle` accepts and carries `media.json`/`moments.json` as public
   bundle-root files (it previously failed `unknown-author-entry` on them).
2. **Locked preview without full text (criterion 2).** The public-layer
   collector (`tools/build-bundle/build-bundle.mjs`) is the last line
   (09 §11): a story whose `tier` contradicts the layer it ships in fails the
   build — `story-tier-mismatch` (paid full text cannot ride in the public
   base layer under a wrong label), and a locked stop's `preview`
   `name`/`announce` must not contain the full normalized `text`/`transcript`
   of the stop's own story in any shipped locale —
   `preview-reveals-full-text`. The existing 8-gram `private-text-leak` scan
   covers copies of shipped private text; the containment check names the
   violation directly and closes the sub-8-word story gap. The validator
   flags the same tier drift at authoring time (`tier-mismatch`, existing).
3. **Moments manual-only (criterion 3).** A root `moments.json` manifest of
   `moment.schema.json` records: per-record schema — the schema's
   `additionalProperties: false` rejects any invented auto-trigger field, so a
   package cannot encode a moment that opens itself (ADR G01.02 §3.1 anchors
   manual-only playback) — unique ids, `place_id`/`story_id` resolving to
   package entities (`unknown-ref`), corrupt manifests answering
   `invalid-json`/`type` instead of crashing.
4. **EN text is not EN audio (criterion 4).** `validateDiscoveryIndex` rejects
   an offer claiming `audio_locales` entries missing from its own
   `text_locales` — `audio-without-text` (09 §3 invariant 1: audio never
   without transcript). The built surfaces stay truthful by test: the built
   index separates text locales from recorded-audio locales, and the catalog
   lists locales by the fact of a published base stops.json (09 §8, unchanged
   canon) — the catalog carries no audio field, so nothing claims unrecorded
   audio. The demo shows the end-to-end scenario: EN text translated, EN audio
   not recorded.

## Decisions worth a reviewer's attention

- `media.json`/`moments.json` are optional manifests: a tree with no media
  files needs no records. Coverage becomes mandatory the moment the tree
  ships any `.m4a`/`.webp` — making the manifest unconditional for every
  package is a publication-gate decision left to G03.05.
- The catalog derivation (`deriveCatalogEntry`, `deriveInterimCatalog`) is
  intentionally unchanged: 09 §8 keeps locales-by-fact for the catalog, and
  the audio truth lives in the index `availability` (schema has no audio
  field on the catalog). The new `audio-without-text` guard plus the parity
  test close the misrepresentation path.
- `tools → web` import was caught by `arch:check` when the parity test
  imported `deriveInterimCatalog` directly; the test now asserts the index
  (the only audio-claiming artifact) and the demo doc shows the catalog
  derivation — no new baseline entry.
