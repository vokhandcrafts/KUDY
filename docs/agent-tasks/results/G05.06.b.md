# G05.06.b — Generated traces, scenario fixtures and the CI check

**Status: complete.** Branch `zcode/219` (closes issue #219 on merge). The
committed set under `tools/simulate/traces/` carries the four seeded
generators of 09 §11 plus the five remaining scenario fixtures of the
16 G05.06 row; `tools/simulate/verify.mjs` replays every trace through the
production stack and compares it with its own expectation — the explicit
`mustFire`/`mustNotFire` lists, then the byte-stable report line by line.

## What was built

- `tools/simulate/generate.mjs` — the seeded trace builders: mulberry32 PRNG
  (the only randomness source; the determinism grep stays clean), the
  synthetic five-stop street, the four generators of 09 §11 (clean walk,
  standing at every stop, fast walk, mid-route start) and five scenario
  builders (replay of a heard stop, reverse order, GPS gap, focus loss during
  guide audio, locked stop unlocked mid-walk by `AccessReady`). `TRACE_FILES`
  pins one named seed per committed file; `serializeTrace` is the byte form.
- `tools/simulate/traces/*.json` — the nine committed artifacts (4 generator
  walks + 5 scenario fixtures), regenerated byte for byte by the test suite.
- `tools/simulate/expectations/*.json` — one expectation per trace:
  `{ trace, exit, mustFire, mustNotFire, report }` where `report` is the
  pinned byte-stable report; `mustFire` names what must fire, `mustNotFire`
  what must not.
- `tools/simulate/verify.mjs` — the runner: per-trace pairing (orphans in
  either direction are failures — a shared "all stops" expectation cannot
  hide), `mustFire`/`mustNotFire` equality, exit code, then a line-by-line
  diff of the pinned report; the failure message names the trace and the
  first differing report line. Corrupt inputs answer with named diagnostics,
  never a thrown error. The report name is pinned as the stable relative
  `traces/<file>` — no host paths in expectations.
- `tools/simulate/traces.test.mjs` — 12 tests wired into `npm test` through
  the existing `tools/simulate/*.test.mjs` glob (no new catalog, the wiring
  enumerator already covers the directory): the whole set verifies (AC5/CI
  behavior), byte-reproducibility (AC1), scenario presence and per-expectation
  lists (AC2), no auto-finish without an explicit End (AC3), per-trace pairing
  (AC4), the edited-expectation failure naming trace + first differing line
  (AC5), the corrupt-trace diagnostic, the isolating negatives of the
  `AccessReady` schema rules, the orphan pairings in both directions, the
  empty field-trace slot (AC6) and the stable-name guard.
- `tools/simulate/README.md` — the trace document (including `AccessReady`),
  the generators and seeds, the expectation format, the runner and the
  field-trace slot.
- `tools/simulate/traces/field/` — the recorded-walk slot, empty (AC6);
  recording a real walk stays a `not-run` step for G11.02.

## Simulator amendments the fixtures required (no engine rule change)

- **`AccessReady` as a trace event** (`trace-schema.mjs`, `run.mjs`): the
  unlock arrives through the download capability channel exactly as
  ADR G01.03 §3.5 prescribes — the orchestrator's `deps.access` port was
  already the only AccessReady delivery path (runOrchestrator header note),
  the replay now hands trace events to it. The engine re-checks the identity
  and the pinned package itself; an unknown stop id opens nothing (schema
  diagnostic). The `core/` reducer is untouched.
- **The physical pause on focus loss** (`ports.mjs` `emitFocus`): the
  G05.06.a port forwarded the focus event but kept the completion timer
  running — the story "finished" while muted, and `ResumeAudio` became a
  no-op. ADR G01.02 §3.4 and `11` (§FocusLoss) say the interruption is a
  physical pause owned by the OS («фізічнае перапыненне, не finished»,
  «пасля званка — не аўтапрацяг»): the port now freezes the running source on
  `focus-loss` and regains nothing by itself — only the explicit `ResumeAudio`
  chain re-arms the remaining time. The G05.06.a call scenario keeps its
  expected outcome (same assertion, now through the correct mechanism); a
  dated pointer is appended to `results/G05.06.a.md`.

## Acceptance criteria — expected/actual

1. **Seeded generators, byte-reproducible** — expected: clean walk, standing
   at every stop, fast walk, mid-route start, each seeded and byte-stable.
   Actual: four generators in `generate.mjs`, one named seed each in
   `TRACE_FILES`; `traces.test.mjs` regenerates all nine committed files and
   compares bytes — the suite is green, and editing a builder without
   regenerating fails it naming the file.
2. **Scenario fixtures with explicit expectations** — expected: replay of a
   heard stop, mid-route start, reverse order, GPS gap, focus loss during
   guide audio, locked stop unlocked mid-walk by `AccessReady`; each names
   what must fire and what must not. Actual: all six are committed traces
   (mid-route-start doubles as the generator walk); every expectation carries
   `mustFire`/`mustNotFire`. Outcomes worth naming: reverse order fires
   stop-5→stop-1 (C31); the GPS gap fires stop-2 15 s later than the clean
   walk (dwell restarted, 199905 ms vs 184913 ms); the locked stop fires only
   after `AccessReady` widens `extended` — heard gains `story-3-ext`; the
   focus-loss trace keeps the launch paused through the call and credits
   `story-1` exactly once after the explicit `ResumeAudio`.
3. **No auto-finish** — expected: without an explicit End the final state is
   `Active` or `Paused`. Actual: standing-every-stop and mid-route-start end
   without `End` and pin `Active`; the `Ended`-iff-explicit-End implication is
   asserted for all nine traces in `traces.test.mjs`.
4. **Per-trace expectations** — expected: a partial walk passes with its own
   expectation, not "all stops". Actual: mid-route-start (3 of 5 stops) passes
   with its own expectation and fails against clean-walk's; the runner treats
   orphan expectations and unexpectated traces as failures.
5. **Runs in `npm test`; a changed expectation fails with the trace name and
   the first differing report line** — expected: CI-visible regression
   behavior. Actual: `traces.test.mjs` is covered by the existing
   `tools/simulate/*.test.mjs` glob of the `npm test` script; the
   edited-expectation test rewrites `clean-walk.json`'s `heard` in a temp copy
   and the failure quotes the trace name, the line number and the differing
   line. The demo additionally mutates the engine (see Proof).
6. **The field-trace slot exists, is empty, format documented; a real walk is
   a `not-run` step for G11.02** — actual: `traces/field/` exists (`.gitkeep`
   only) and the test fails if a `.json` appears; the format is documented in
   `tools/simulate/README.md` §«Слот паляговага трэйса»; recording a real
   walk is listed below as the `not-run` step of G11.02.

## Proof

In a module-load copy of the engine, the `FocusLoss` case is swapped for an
`AudioFinished` call of the live launch — the focus-loss fixture fails with
its trace name and the first differing report line (the `ResumeAudio` outcome
turns from `applied` into `no-op`), the other eight traces hold, and no
repository file changes. Demo: `docs/demos/2026-09-26-g0506b-trace-set.md`
(`uvx showboat==0.6.1 verify` — exit 0). The committed expectations
themselves fail on edit per criterion 5's test.
