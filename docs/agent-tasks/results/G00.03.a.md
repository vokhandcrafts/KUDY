# G00.03.a — Sandbox-кліент і ізаляваны grant

**Дата:** 2026-09-15  
**Статус:** `complete` (для названага выніку гэтай атамарнай часткі; рэальныя store-прагоны — `not-run`, яны не ўваходзяць у .a і бяруцца G00.03.c)

## Вынік

Створаны мінімальны zero-dependency спайк `spikes/G00.03-sandbox-grant/`:
purchase/restore кліент + сервер grant для аднаго сінтэтычнага прыватнага
файла. API следуе кананічнаму кантракту `09` §5: `POST /v1/device` выдае
`device_id` (UUID) + `device_secret` (32 байты, адзін раз; захоўваецца толькі
SHA-256 хэш, аўтарызацыя `Bearer <device_secret>`); `POST /v1/grant`
прымае `{route_id, version, locale, tier, paths[]}`, сам мапіруе
`route_id × tier → product` (кліент не выбірае product_id/storage bucket),
правярае manifest membership кожнага шляху, пытае права ў правайдара для
аўтэнтыфікаванай прыяды (`app_user_id = device_id`, без кліенцкага user_id) і
вяртае `{lock_url, urls:[{path, url, expires_at}]}` з кароткачасовымі
HMAC-падпісанымі токенамі. Памылкі — закрыты спіс кодаў без шляхоў:
`403 no_entitlement`, `503 entitlement_unavailable` + `Retry-After` (fail-closed
без fallback), а таксама `invalid_request`, `device_auth_failed`,
`unknown_route_tier`, `manifest_not_found`, `path_not_allowed`,
`environment_mismatch`, `url_expired`, `url_invalid`. Пазітыўны кэш права на
`(device_id, route_id, tier)` з TTL (09 §5.1) трымае рэзюмаванне пры збоі
правайдара і не абыходзіць праверку асяроддзя. Лакальны test-транспарт
выкарыстоўваецца толькі ў тэстах і не ўмее выдумваць поспех (не fail-open);
live-запуск (`npm start`) заўсёды падключае RevenueCat-адаптар і адмаўляецца
стартаваць без поўнага набору env.

## Уваходы і выбар

- Каталог: `kudy.spike.g00_03.story_01` → `route_id: g00-03-spike`, `tier: extended`, non-consumable; маніфест `g00-03-spike/2026-09-15.1/be/extended` з адным шляхам `transcripts/private-story-01.be.txt` і сінтэтычным `lock_url`. Сінтэтычныя значэнні спайку, не прыняты прадуктовы каталог.
- Identity: `app_user_id = device_id` (09 §5.1); кліенцкага `user_id` ў кантракце няма, спасылкі на чужыя правы немагчымыя (тэст існуе).
- Environment: sandbox/production параўноўваецца як асяроддзе правайдара супраць `GRANT_ENVIRONMENT` сервера; неадназначнасць = fail-closed (503).
- Кэш: толькі пазітыўны, ключ `(device_id, route_id, tier)`, TTL з env (0 = выкл); ніколі не абыходзіць environment і не трымае адмовы. Мяжа: адкліканне права не імгненнае — гэта дакументаваны трэйд-оф 09 §5.1.
- RC-адаптар: GET `/v1/subscribers/{device_id}` з Secret API key (форма 09 §5.1), `REVENUECAT_BASE_URL` override. **Не выклікаўся** (няма сеткі); sandbox/production атрыбуцыя адказу ў гэтым эндпоінце не дакументаваная — да ўзяснення G00.03.c недаступная атрыбуцыя = fail-closed. Форма адказу не сцвярджаецца як факт.
- TTL URL: па змоўчанні 600 s; batch-мінт падоў і перамінаванне каля expiry — паводзіны поўнага download-сэрвісу, не спайку.
- Прадуктовы выбар P01/P02 не тыкаўся; агульныя правілы спайку (пакупка ≠ ready, version нязменная да End і г.д.) не парушаліся.

## Праверкі і доказы

1. `cd spikes/G00.03-sandbox-grant && npm test` (`node --test --test-reporter=spec test/*.test.mjs`)
   - Чакалася: 18 тэстаў loopback-паведзенняў сервер/кліент праходзяць.
   - Фактычна: 18/18 pass (~1.4 s). Пакрытыя сцэнарыі: UUID device_id + 32-байтны secret, выданы адзін раз; purchase→grant→download аддае дакладна фікстурны файл і `{lock_url, urls}`; `bought=true` без пакупкі → 403 `no_entitlement`, нуль байтаў; чужы Bearer secret → 403 `device_auth_failed`; недаступны правайдар без кэшу → 503 `entitlement_unavailable` з `Retry-After: 30`, без fallback, з аднаўленнем; пазітыўны кэш трымае grant пры збоі правайдара (log `entitlement_cache_hit`); не-член маніфеста, `..`, абсалютны, URL, drive-шлях, пусты → 403 `path_not_allowed` да любой праверкі каталогу; канверт памылкі толькі `{"error":{"code"}}`; unmapped route/tier → 403 `unknown_route_tier`; unmapped version/locale → 403 `manifest_not_found`; restore на новай прыладзе → grant без другога плацяжу (лічильнік payments = 1); пратэрмінаваны URL → 403 `url_expired`, новы grant без аўтарызацыі → 403, з ёй → новы працоўны URL; sandbox-права супраць production-рэсурсу → 403 `environment_mismatch`; падроблены `user_id` не дае чужога права → 403 `no_entitlement`; падпорчаны токен → 403 `url_invalid`; логі не змяшчаюць device_secret/device_id/signed URL/bearer/receipt — толькі коды, падзеі і 16-hex `device_hash` (у тым ліку route miss па `/private/…` чырвоным у логу і `file_denied`); кліент адхіляе не-HTTPS base URL па-за loopback і прымае https/loopback; `register()` адкідае няўдалую рэгістрацыю і не трымае прыладу; live RC-адаптар адмаўляе не-https `REVENUECAT_BASE_URL`.

## Not-run і блокеры

- **Рэальны sandbox purchase/restore ў iOS/Android** — `not-run`: няма store-акаунтаў, прылад і сеткі; па разьдзеленні гэта G00.03.c. Mock-тэсты не выдаюцца за store-доказ.
- **Жывы выклік RevenueCat** — `not-run`: адаптар не правяраў форму адказу па сетцы; да G00.03.c ён паводзіць сябе fail-closed (любы неадназначны адказ → 503), атрыбуцыя sandbox/production у RC адказу патрабуе жывой зверкі.
- **Showboat-дэма** — не створана: палітыка `showboat.md` абавязвае для гэтай задачы (платежы/аўтарызацыя/знешняя інтэграцыя), але `uvx showboat==0.6.1` недаступны — у асяроддзі няма `uvx`, `uv` і `pip`, пакет не закэшаваны. Зроблены звычайныя праверкі (п.1–3); гэта дакладны blocker, не weakening рэалізацыі.
- **CDN/адкліканне URL** — не ўваходзіць у .a; TTL у спайку — «не раздаць назаўсёды», не механізм адзыву (09 §5.1), праверка CDN паводле правайдара — за G00.03.c.
