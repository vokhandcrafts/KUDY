# G00.04.b result — мінімальны агульны scaffold

**Дата:** 2026-09-16
**Статус:** `blocked-external` — названы вынік існуе і ўсе магчымыя тут праверкі зялёныя (install з lockfile, `expo-doctor` 18/18, typecheck, run-model 51/51, jscpd 0 clones), але development build Android/iOS і прыладавая прыёмка — `not-run`: на хосце няма JDK/Android SDK/ADB, macOS/Xcode і прылад. **Інтэграцыйная знаходка і фікс (адзін набор замест двух мажораў).** Першае рэзалюванне выявіла несумяшчальнасць transitive: `expo-audio@1.1.1` мае peer `expo-asset: "*"` без верхняй мяжы — npm усталяваў expo-asset `57.0.17` → expo-constants `57.0.18`, тады як expo@54 нясе expo-asset `12.0.13` → expo-constants `18.0.14`: два мажоры натыўнага модуля ў адной зборцы ( expo-doctor: «Native builds may only contain one version of any given native module»). Спайк ніколі не рэзолвіў transitive (lock — `candidate-direct-versions-only`, без `npm install`), таму гэта немагчыма было ўбачыць да .b. Фікс па кананічных чаканнях SDK 54 (`node_modules/expo/bundledNativeModules.json`: expo-asset `~12.0.12`, expo-constants `~18.0.13`): `expo install expo-asset` (прамая залежнасць `~12.0.13` — peer спаганяецца на яе) + `expo install --fix` (expo `54.0.33` → `~54.0.37`, патч-выраўноўванне ўнутры верыфікаванай лініі SDK 54, не скачок мажора). Пасля: адна копія expo-asset 12.0.13 і expo-constants 18.0.14, `expo-doctor` 18/18.
