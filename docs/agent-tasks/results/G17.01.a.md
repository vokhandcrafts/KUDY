# G17.01.a — Каркас калектара: схема кампаніі, схема сховішча, цыкл запуску

Issue #155 · branch `zcode/155` · 2026-09-23 · executor: Zcode session (GLM-5.3-Flash).

`tools/collector/` існуе і запускаецца: CLI (`init` / `run --campaign <file>` /
`status`), YAML кампаніі валідуецца схемай Zod, сховішча — убудаваны
`node:sqlite` без асобнага package.json (узор `tools/validate`), цыкл запуску
ідэмпантэнтны і аднаўляльны. Новыя залежнасці: `zod@4.6.5`, `yaml@2.9.1`
(exact-піны ў devDependencies). Сеткавага збору няма; здымкі, ачыстка і фота —
за G17.01.b+.

## Acceptance criteria — walked from the card

1. ✅ **Кампанія без `city` або з дрэннымі значэннямі `fence` адхіляецца з
   дыягностыкай, што называе поле.** `parseCampaign`
   (`tools/collector/campaign.mjs`) вяртае па адной дыягностыцы на кожнае
   парушэнне ў форме `campaign.fence.depth: …` (шлях поля з Zod-issues).
   Негатыўныя тэсты: missing city, depth ≤ 0 / не-лік, arity і парадак
   `delay_s`, не-масіў `extra_domains`, чужыя ключы (strictObject), сапсаваны
   YAML, пусты/не-мэпінгавы ўвод — `tools/collector/campaign.test.mjs`
   (7 тэстаў, ніводны не мок); і менавіта гэтыя правілы адхіляюцца праз
   `campaign.city:` на stderr у CLI-тэсце.
2. ✅ **Першы `run` стварае поўную схему; паўторны запуск не дублюе радкі.**
   `openStore` стварае `campaigns`, `raw_records`, `links`, `media`, `run_log`
   (`CREATE TABLE IF NOT EXISTS`, тэст «first open creates the full schema»);
   ідэмпатэнтнасць — `UNIQUE(campaign_id, url)` на `raw_records` з
   `ON CONFLICT DO NOTHING`, `UNIQUE(campaign_id, kind, ref)` на `run_log`,
   ідэнтычнасць кампаніі = шлях файла. Тэст «AC2: first run registers …
   second run inserts nothing new» параўноўвае лічбы і ідэнтыфікатары радкоў
   да/паўтору; end-to-end праз два рэальныя выклікі CLI — «run is idempotent
   end-to-end».
3. ✅ **Перапынены ранаў завяршаецца наступным выклікам без дубляў
   (resume, not restart).** Крок, пакінуты ў стане `running` (імітацыя
   забітага працэсу), перазабіраецца і завяршаецца аднойчы (`attempts` = 2),
   завершаныя крокі не перавыконваюцца — тэст «AC3: a step left running …».
   Ранаў, перарваны пасля enqueue (усе крокі `pending`), даганяецца наступным
   выклікам — тэст «AC3: a run interrupted after enqueue …». Стан `failed`
   захоўвае памылку і не перазапускаецца — тэст «a handler failure …».
4. ✅ **Усе палі пашпарту са спецыфікацыі ёсць у `raw_records` з дакладнымі
   імёнамі.** Тэст «AC4» параўноўвае `PRAGMA table_info(raw_records)` са
   спісом з табліцы «Пашпарт запісу (RawRecord)» у `docs/24_web_collection.md`
   даслоўна і ў парадку табліцы; мапінг `topics[]` → JSON-тэкст у калонцы
   `topics` аб'яўлены аднойчы (каментар у `store.mjs` + каментар тэста) і
   зафікаваны ў README. Слоўнікі `source_type`/`rights`/`status` — CHECK-ы
   па спецыфікацыі з негатыўным тэстам.
5. ✅ **Наборы тэстаў пералічаныя дэфолтным `npm test` і праходзяць лакальна;
   jscpd чысты.** Глоб `"tools/collector/*.test.mjs"` у `npm test`;
   праводка ахаваная двума камітнутымі праверкамі: `tools/build-bundle/
   test-wiring.test.mjs` (глоб-радок + пералік набораў) і
   `tools/ci/check-required-checks.mjs` (G17.01.a revert guard). Негатыўны
   эксперымент для праводкі не ганяўся — клас і знак змены ідэнтычныя
   arch-surface guard'у (даданне радка), таму рызыка рэверту пакрытая
   існым тэстам на тое ж поле `pkg.scripts.test`.
