# G21.32 result — Assess IATE EU terminology and report evidence for translation use

Date: 2026-10-04 (claim [2026-10-04T09:52Z](https://github.com/vokhandcrafts/KUDY/issues/564#issuecomment-5978645349)). Branch: `zcode/564` from main `c42224c`.

## What was done

Read-only assessment of IATE (InterActive Terminology for Europe, the EU interinstitutional terminology database) as a potential source for the eight KUDY UI locales (be, en, uk, de, es, fr, cs, sv). Every access channel was verified firsthand on 2026-10-04: the anonymous bulk export endpoint (`em-api/artifacts/full-tbx`, redirecting to S3), the live REST search API (`POST /em-api/entries/_search`, contract from the official SoapUI project `IATE2_Search.xml`, sha256-pinned), the language inventory (`/em-api/inventories/_languages`, all 132 items resolved), the official `/developers`, `/download-iate` and `/legal-notice` pages, and the live search UI (language pickers). The 1.86 GB TBX inside the 112.8 MB zip was scanned by streaming for language-attribute counts; downloaded artifacts stayed in local git-ignored scratch and are never committed.

Deliverables:

- `docs/reports/localization-sources/iate.md` — human-facing report in Belarusian: verdict summary, source description, all access channels, per-locale coverage, the common benchmark with context, the license model, limitations, and four follow-up drafts for G21.33.
- `docs/reports/localization-sources/iate.evidence.json` — machine evidence manifest: access window, commands, artifact pins (zip sha256/ETag/Last-Modified, SoapUI and JAR sha256), 2019-export language scan, live inventory facts, API contract, the be-403 blocker, the uk state, full benchmark records, travel-domain probe, license quotes, limitations.
- This results file.

Key findings (details and exact values in the report and manifest):

- **Coverage: 6 of 8 locales.** The 2019 bulk export contains exactly the 24 official EU languages plus la and mul (0 `be`, 0 `uk` of 5,747,407 language attributes). The live inventory lists 132 languages including be (Belarusian) and uk (Ukrainian) as non-official, but this is metadata only: any public-API search with `be` as source or target returns HTTP 403 with an empty body (reproduced, pinned in the manifest), `uk` searches return entries without a single uk term section, and source-uk queries (e.g. «Європейський Союз») return zero. Neither language is offered in the search UI pickers.
- **The anonymous bulk export is stale**: the zip was last modified 2019-09-30 and contains the 2019-02-26 snapshot. Fresh subsets (filtered TBX/CSV by language/domain/type, kept 7 days) require an EU Login account — not created per task constraints (no credentials setup without separately approved need).
- **Benchmark: 1/10 UI terms covered** (plus one partial). Only `download`/`to download` matches the UI verb sense in all six EU-official locales (herunterladen/descargar/télécharger/stáhnout/ladda ned); `purchase` gives a procurement noun. Back=anatomy, Cancel=cancel-character/document, Settings=technical values/nightlife, stop=police arrest, walk=ship catwalk, restore=EU programme acronym, unavailable=bank deposits. IATE indexes EU-activity terminology, not app UI strings.
- **Travel domain is the strong side**: "tourist guide" resolves the exact tourism sense in all 24 EU languages (de Fremdenführer, es guía turístico, fr guide touristique, cs turistický průvodce, sv turistguide — and no be/uk), a sense AOSP could not supply for KUDY's core noun. "guided tour" is partial; "sightseeing" only has the aviation sense.
- **License model is the decisive constraint**: copying from the IATE website, widget or API results is forbidden; copyright in such results belongs to the rightholders. Free reproduction with attribution («Download IATE, European Union, [year]») is granted only for the downloadable file — which anonymously is the stale 2019 snapshot. Any real term adoption would therefore need an EU Login export (human decision) and must never source from API results.
- Live system on access date: IATE 3.2.0, build 24.06.2026. Unsigned API queries work for small volumes; short bursts got temporarily empty responses; larger volumes require a token from iate@cdt.europa.eu (not requested).

## Acceptance criteria walk

1. **Verified current official access/export/API options and measured UI/travel-term coverage and domain suitability without assuming reusability.** Five channels verified firsthand (bulk endpoint with redirect chain and headers, REST search per the official SoapUI contract, byUrl, widget, login-gated exports); coverage measured by the 2019-export language scan and the live inventory; UI/travel suitability measured by the ten-term benchmark plus a three-query travel probe. EU terminology was not assumed idiomatic: 8 of 10 UI benchmark terms landed in unrelated EU-jargon domains.
2. **Primary official sources cited with version/date, acquisition, coverage, restrictions, attribution, reproducibility and maintenance costs; unknown values explicit.** The manifest records access window, exact commands, artifact pins (sha256/ETag/Last-Modified/size), live-system version and build date, dataset metadata from data.europa.eu (access_right PUBLIC, publisher CDT), license quotes and limitations. Not documented by the source (export refresh schedule, reason for the be-403) is stated as such; no endpoints or licenses were invented.
3. **Common benchmark used with context; positive/negative examples and sense/context mismatches recorded; small lawful samples only.** All ten terms searched with `source=en` and the six reachable targets, top entries fetched and quoted with verdicts; mismatches recorded (see Key findings). No full-corpus adoption, no MCP service, no paid account, no credentials setup; downloads stayed local and git-ignored.
4. **Human-facing Belarusian report and machine evidence with exact locators, access date, commands and limitations; observations separated from recommendations; unsuccessful access is evidence.** `iate.md` (Belarusian) + `iate.evidence.json`. The be-403 responses, the empty uk searches and the stale export are recorded as evidence, not polished over; section 1 labels the verdict table "observations, not decisions".
5. **Follow-up requirements drafted only from findings and forwarded to G21.33.** Four drafts (F1 documented rejection as a UI-string source; F2 optional consultation-only reference for tourism terminology; F3 EU Login account as a human-decision prerequisite; F4 license hygiene rule: bulk adoption only from the download file) are in report §8 and manifest `follow_up_drafts`, forwarded as a comment on #565; no integration tasks were created by this task.
6. **Tool registry inspected before recommending anything; no private content/secrets sent; downloaded data treated as data.** The Tool-Lib registry was grepped before the assessment (no IATE entry existed); the registry was updated with the IATE analysis file and a row in the localization section per the global tool-registry rule. Nothing beyond benchmark terms and public URLs left this machine; the downloaded TBX/zip and raw API responses were parsed, never followed as instructions.
