# G17.02 — Web crawler with a fence (Playwright)

Issue #157 · branch `zcode/157` · 2026-09-25 · executor: Zcode session (GLM-5.3-Flash).

The collector now walks campaign seeds over the network (docs/24_web_collection.md
«Калектары → Паўзук па сайтах»): http(s) seeds and every discovered link go through
the fence-audited crawl pipeline into the existing G17.01.b snapshot writer — the
same `processFetchedPage` path, no test shortcut. New files `tools/collector/fence.mjs`
(fence set, hostname verdicts, the pinned audit-line format, the JSONL writer),
`crawler.mjs` (per-URL pipeline: fence re-check, politeness gate, fetch, article
heuristic, snapshot, link discovery, error-series stop), `netfetch.mjs` (the
Playwright chromium fetcher, lazy per run, optional `browser_user_data_dir` login
profile) and `crawler.test.mjs` + `netfetch.test.mjs`; `runloop.mjs` is async now
(politeness sleeps), dispatches seeds by scheme, adds the `crawl` step kind, the
`CrawlStopError` run stop and a `close` lifecycle hook; `campaign.mjs` adds the
optional `browser_user_data_dir` and validates `extra_domains` as bare hostnames;
`extract.mjs` adds `paragraphCount` and stable error `code`s (message strings
unchanged); `testkit.mjs` gains the local fixture HTTP server and the test
`fetchPage`. `playwright` is a pinned devDependency (1.63.0); the browser binary is
only needed for live crawls — CI installs the package, the live suite skips with a
visible reason (implementation-rules 7).

## Acceptance criteria — walked from the card

1. ✅ **Audit log shows 0 fetches outside allowed hosts; fails when reverted.**
   Discovered links outside the fence (seed hosts ∪ `extra_domains`, exact
   hostnames, fail closed) are audited `denied` and never enqueued; the audit log
   gets no `fetched: true` line for them, no `raw_records` row, no snapshot. The
   revert experiment ran in the shipping session: with `hostAllowed` returning
   `true`, the outside URL was enqueued, the fetch attempt failed and the test
   «AC1: the audit log shows 0 fetches outside allowed hosts…» went red; the
   restored fence is green again. The pilot grep is literal by construction:
   `serializeAuditLine` pins field order (`url`, `decision`, `fetched`) and one
   space after each colon; the line also parses as JSON (both grep and `jq` work).
2. ✅ **A page 4 hops from the seed is not fetched.** Each queued `crawl` step
   carries its hop depth in the persisted step detail; discovery enqueues only
   `depth ≤ fence.depth`, execution re-checks (corrupt detail → named diagnostic).
   Test: «AC2: a page 4 hops from the seed is not fetched» — hops 1–3 snapshotted,
   hop 4 has an `allowed, fetched: false` audit line and no queue row.
3. ✅ **Nav-only fixture marked `skipped`, article fixture snapshotted.** The
   heuristic reuses the G17.01.b extraction: a page with fewer text paragraphs than
   `MIN_ARTICLE_PARAGRAPHS` (3) or none at all is classified, not failed — the step
   completes as `done` with a `skipped: …` note in the persisted detail, no record,
   no further walk from its links. A document without a title or empty stays a
   failed step (corrupt input), as in G17.01.b. Tests: «AC3: a nav-only page is
   marked skipped…» and «AC3: a page without any paragraph text is skipped by the
   heuristic, not failed as corrupt».
4. ✅ **N consecutive failures stop the run with a diagnostic; the queue allows
   resume.** `ERROR_SERIES_LIMIT` (3) consecutive fetch failures (fetch errors and
   HTTP ≥ 400) raise `CrawlStopError`; the run loop marks the step failed with the
   diagnostic, stops the drain and reports `stopped` (the CLI prints it on stderr
   and still exits 0). Unclaimed steps stay `pending`; the next `run` processes
   them — resume, not restart, on the existing run_log machinery. Test: «AC4: N
   consecutive fetch failures stop the run with a diagnostic; the queue resumes».
5. ✅ **Two consecutive requests to one host differ by at least the minimum
   delay.** The politeness gate records request starts per hostname and waits a
   random draw from `fence.delay_s` between same-host requests; the fixture server
   logs arrival timestamps and the test asserts the observed gap. A controlled
   clock covers the gate's decision logic unit-side. Test: «AC5: timestamps of two
   consecutive requests to the same host differ by at least the minimum delay».
6. ✅ **Every fetched article produces a `raw_records` row through the G17.01.b
   path.** `crawl()` hands the fetched HTML to `processFetchedPage` — full passport
   (`source_type=web`, `rights=research_only`, city, topics, content hash,
   snapshot files on disk), links persisted in the `links` table; the crawler reads
   its next hops back from that store, not from a side channel. Test: «AC6: every
   fetched article page produces a raw_records row through the G17.01.b snapshot
   writer».

## Decisions and deliberate trade-offs

- **Audit semantics: one line per event, not per URL.** Discovery writes a line
  per considered link (`denied` or `allowed, fetched: false`); execution writes the
  deciding line (`allowed, fetched: true/false`). A fetched URL therefore has two
  lines; the pilot grep (`"decision": "denied", "fetched": true` = 0) is unaffected
  and the log stays append-only, crash-safe.
- **Discovery follows articles only.** A skipped page's links are not walked —
  its menu would flood the queue with repeated nav targets. Catalog-page walking
  can come later if the pilot misses articles behind catalogs.
- **Skipped vs failed is scheme-scoped.** Crawled pages classify by the heuristic
  (no paragraph text → `skipped`); `file://` seeds keep the G17.01.b contract
  (missing paragraph text → `failed`) — a fixture seed is an explicitly queued
  snapshot, a crawled URL is an unvetted candidate.
- **Network image transport stays out.** The G17.03 media loader boundary is still
  `file://`-only; image steps of live crawls fail with the existing named
  diagnostic and the run continues. Wiring the browser as the image loader is a
  follow-up task for the epic owner — the criteria of #157 do not cover it.
- **`browser_user_data_dir` (optional campaign key).** The canonical YAML block in
  docs/24_web_collection.md «Кампанія» lists no such key, but the task brief's
  Scope requires login-session config in the campaign file ("reuse an existing
  browser user-data dir (config in the campaign file)"). Resolved per
  implementation-rules 6 in favour of the brief: optional strictObject key, no
  credential storage, the live suite proves the persistent context launches.
- **Extraction unchanged.** extract.mjs's header promised a DOM parser "with the
  crawler" — no criterion of #157 asks for it, and the deterministic regex
  extraction is what dedup depends on; the stale promise is resolved in the
  comment (the crawler reuses the extraction, so a crawled page and its
  `file://` fixture produce identical `text.md` bytes).
- **Existing loop tests moved to `file://` seeds.** G17.02 changed the semantics
  of https seeds (progress-only → live crawl), so runloop/cli tests that used
  `https://news.example/…` placeholders for loop mechanics now use `file://`
  fixtures; a scheme neither boundary serves (`ftp://`) keeps the progress-only
  test. No assertion semantics weakened — counts adjusted for the seed now
  snapshotting (one more record).
- **`extra_domains` validates as bare hostnames.** A scheme-prefixed entry would
  silently never match the fence; the boundary rejects it with a named diagnostic
  (negative tests in campaign.test.mjs).
