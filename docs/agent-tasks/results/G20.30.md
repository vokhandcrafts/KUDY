# G20.30 — пераключэнне GPS пасля дазволу на фонавую лакацыю

Issue: [#792](https://github.com/vokhandcrafts/KUDY/issues/792) (эпік #470); галіна `chatgpt/792`; [draft PR #841](https://github.com/vokhandcrafts/KUDY/pull/841). Дата: 2026-10-22. Залежнасці #663 і #664 закрытыя перад пачаткам працы.

## Прычына

Пры пераходзе з гарадской паверхні або халоднага запуску прагулкі існая падпіска `watchPositionAsync` магла быць спыненая адразу пасля адказу «фонавая лакацыя дазволена», хоць `startLocationUpdatesAsync` яшчэ не завяршыўся. Так узнікаў прагал без GPS-фіксаў; пры адмове натыўнага старту стваралася яшчэ адна падпіска, а позні callback старой мог прайсці праз той самы нумар сэрвіснай падпіскі.

## Змена і адпаведнасць крытэрыям

| Крытэрый | Рэалізацыя / праверка |
|---|---|
| 1. Позні дазвол пасля Start і пераходу city → Run | `applyAnswer` запускае перадачу ў `startFixes` без чакання watchdog; новы G20.30 тэст правярае позні дазвол з `city-surface`; асобныя тэсты правяраюць халодную прагулку. |
| 2. Адна падпіска, адкіданне позніх callbacks | `ExpoLocationOsPort` трымае існы foreground watch да **паспяховага** старту фонавай задачы; `releaseForegroundWatch()` і `watchEpoch` адключаюць старыя callbacks нават пры тым самым service `sub`. Тэст правярае безперапынную перадачу, адно выдаленне watch і адсутнасць другога background start пры паўторным дазволе. |
| 3. Адмова, няўдалы старт, pause/end, новы дазвол | Адмова ў дазволе пакідае foreground без зменаў; пры натыўнай памылцы `startForegroundWatch` не дублюе ўжо наяўны або яшчэ не атрыманы watch. Новыя сцэнарыі: няўдалы background start з гатовым і з чакаючым watch, stop да адказу, новы city-запыт, stop падчас натыўнага старту. |
| 4. Production-тэсты і ўключэнне ў раннер | Новыя тэсты працуюць праз сапраўдныя `LocationService` і `ExpoLocationOsPort`, з заменай толькі мяжы Expo; яны ўключаныя існым `services/**/*.test.ts` у `npm test`. Фізічная прылада Android у гэтай сесіі **не правяралася**. |

## Ахова ад адкату

Існая `tools/ci/adapter-revert-guard.test.mjs` працягвае выдаляць радок ачышчэння позняга foreground-watch у скопіраваным production-адаптары і патрабуе, каб стандартны тэст `delayed_foreground_after_stop` падаў. Ахова перанакіраваная на актуальны каментар радка; сам guard не адключаны.

Канкрэтныя дадатковыя рэгрэсійныя тэсты ў `services/location/expo/expo-location-port.test.ts` фіксуюць перадачу без прагалу, памылку native start, запознены callback і спыненне падчас перадачы. Праверку ручнога адкату новага `releaseForegroundWatch` лакальна правесці не ўдалося, бо аддалены shell недаступны.

## Праверкі і межы доказу

GitHub Actions правярае галіны PR #841. Папярэдні прагон выявіў адзін устарэлы revert-target у `adapter-revert-guard.test.mjs`, пасля чаго гэты target быў выпраўлены. Папярэдні jscpd знайшоў дубляваны фрагмент у новым тэсце; пасля прыбрання дублікатаў jscpd прайшоў на каміце `5994a5f`. Актуальны стан праверак трэба браць з [PR #841](https://github.com/vokhandcrafts/KUDY/pull/841/checks); не варта лічыць старыя чырвоныя прагоны вынікам фінальнага дрэва.

Каманда для факуснай праверкі:

```sh
node --test --experimental-strip-types --experimental-test-module-mocks --test-reporter=spec services/location/expo/expo-location-port.test.ts
```

Каманды агульных праверак — `npm test`, `npm run typecheck`, `npm run arch:check`, `npx --yes jscpd@5.1.2 --config .jscpd.json --no-tips .`.

На аддаленым хосце ў гэтай сесіі shell быў недаступны; аўтар асабіста не запускаў гэтыя каманды. Па той самай прычыне `uvx showboat==0.6.1 verify` не запускаўся і Showboat-дэма не заяўлена як правераная. Натыўны Android GPS і паводзіны фонавай службы застаюцца асобнай прыладнай прыёмкай: CI з Expo-заглушкамі яе не замяняе.

## Аўтарскі self-review

Змены абмежаваныя GPS Expo-адаптарам, яго рэгрэсійнымі тэстамі і прывязанай ужо існай аховай ад адкату. Працяглы foreground watch падчас pending background start — свядомае захаванне працаздольнасці да паспяховага пераключэння. Старыя callbacks павінны губляцца пры паузе, замене owner або паспяховым background start. Прагрэс прагулкі, runtime permission UX, Expo modules, pipeline, кантракты і аўтарызацыя не змененыя.

Незалежнага рэв'ю і judge verdict на момант запісу няма; PR застаецца draft і не павінен быць змержаны толькі паводле аўтарскага self-review.
