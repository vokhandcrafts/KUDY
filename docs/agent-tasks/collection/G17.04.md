# G17.04 — Wiki collector (MediaWiki API / export)

## Context

- Specification: [`docs/24_web_collection.md`](../../24_web_collection.md) — section «Калектары → Энцыклапедыі і вікі».
- Encyclopedias with official doors are not crawled like a human: MediaWiki API and exports are faster, more complete, and allowed. Wikipedia content is CC BY-SA — `rights=licensed`, quotations permitted with attribution (unlike `research_only` news sites).

## Goal

Given a campaign's list of articles and categories for a city, fetch them through the MediaWiki API, expand wiki links within the configured topic and depth limits, and store `raw_records` (`source_type=wiki`) with license and attribution metadata. Tests use recorded fixtures — no network in tests; live runs are manual.

## Scope

- Article list + category expansion per campaign; topic filter and depth limit from the campaign config.
- Fetch via MediaWiki API (article HTML/wikitext + revision metadata).
- `raw_records` with `rights=licensed` and attribution fields (source site, revision id, contributors URL, license name) so `07`'s bibliography and the citation rule can use them.
- Missing article (bad title) → diagnostic in the run log, run continues.

## Out of scope

- Non-MediaWiki encyclopedias (a later family — the pilot decides), cleaning, photos beyond the G17.01.b empty media dir.

## Acceptance criteria

1. Fixture API responses for a requested article list produce `raw_records` with `source_type=wiki` and complete attribution metadata (assert each field).
2. Category expansion respects the topic filter and depth: out-of-topic categories are not expanded — negative test names the filter.
3. `rights` is `licensed` automatically for wiki sources — assertion; reverting the mapping fails the test.
4. A missing-title fixture yields a logged diagnostic and the run completes; all suites wired into `npm test`; jscpd clean.

## Proof

Revert the wiki→licensed rights mapping → criterion 3's test fails.
