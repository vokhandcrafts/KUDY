# G17.03 — Media: photos paired with text

## Context

- Specification: [`docs/24_web_collection.md`](../../24_web_collection.md) — section «Фота». Photos are raw material of their own: one good place photo is worth a paragraph to a guide.
- Rules from the spec: content images only (≥ ~150 px longest side), per-article `media/` folder, human filenames `<article-slug>-img-NN.<ext>`, three-level pairing (filename ↔ position in markdown ↔ `media` table), hash-identified duplicates, per-image `rights` (a photograph is a protected work even when the fact in the text is free).

## Goal

From raw snapshots (fixtures in tests), extract content images, store them under the article's media folder with spec filenames, register them in the `media` table, and place each image at its original position in `text.md` as a markdown image with `alt` and caption.

## Scope

- Content-image filter: minimum ~150 px longest side; icons, logos, banners, buttons, counters excluded.
- Download images to the article's `media/` dir; slug filenames with stable per-article numbering (`gdansk-stocznia-img-01.jpg` style).
- `media` table rows: article, paragraph index, `alt`, caption, source URL, file, sha256, pixel dimensions, `rights`, `collected_at`.
- Markdown placement at the original position; caption preserved.
- Duplicate detection: same hash on two articles → both keep their copies, rows cross-referenced by hash.

## Out of scope

- Cleaning-stage photo normalization (G17.06), YouTube thumbnails (G17.05), any image processing beyond download+hash.

## Acceptance criteria

1. Fixture with mixed-size images: only ≥150 px images are saved; sub-150 px icons are excluded — negative test names the size rule.
2. Every saved image has a complete `media` row (all fields above) and a filename starting with the article slug; re-running keeps numbering stable (no `-img-1-1` duplicates).
3. Position test: the markdown image sits at the paragraph index where it appeared in the source page.
4. Same image on two fixture articles → equal hashes on both rows.
5. A broken image URL produces a diagnostic row (failed status) and no crash; all suites wired into `npm test`; jscpd clean.

## Proof

Revert the size filter → criterion 1's negative test fails.
