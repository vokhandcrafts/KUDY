# G17.07 — Search, basket, draft export

## Context

- Specification: [`docs/24_web_collection.md`](../../24_web_collection.md) — section «Зборка гайдаў — рукамі». Guides are assembled by the author: the tool offers search, a basket of fragments, and a markdown draft export with citations. Search lives in the same SQLite as `07` — full-text plus sqlite-vec vector search, as the spec's technical minimum names.

## Goal

The author can find library records (city, topic, source type, full text), collect them into a basket, and export a draft markdown with citation links (URL + verification date); exported records move `status: cleaned → used`.

## Scope

- CLI search command with filters and full-text over cleaned documents.
- Basket add/list/clear commands (per campaign or global — follow the spec's single-library model).
- Draft export: markdown file with fragment texts and a citation line per fragment (source URL, `collected_at`).
- Status transition on export; handoff record keeps `raw_record_id` so `07` receives `Source` with provenance.

## Out of scope

- Any guide auto-composition (explicitly rejected by the spec), changes to `07`, app code.

## Acceptance criteria

1. Search fixtures: query hits the expected records under city/topic/type filters; full-text finds a record by a phrase from its cleaned text.
2. Export produces a markdown draft where each fragment carries its citation line (URL + date) — assertion checks format; reverting the citation writer fails the test.
3. Exported records have `status=used`; a repeat export does not duplicate fragments (idempotent).
4. Empty basket export answers with a diagnostic, no empty file; suites wired into `npm test`; jscpd clean.

## Proof

Revert the citation-line writer → criterion 2's test fails.
