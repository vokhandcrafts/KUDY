# G17.06 — Cleaning rules engine v1

## Context

- Specification: [`docs/24_web_collection.md`](../../24_web_collection.md) — section «Ачыстка»; the LLM boundary from `07` applies: LLM only in production authoring, never in the app runtime — and in v1 there is no LLM here at all (structural rules and regexes first).
- Raw is never rewritten: cleaning writes a new version; bad rules are rolled back by re-running on raw.

## Goal

A data-driven cleaning engine with versioned rule packages per source type (`news-v1`, `wiki-v1`, `youtube-v1`) that turns raw records into cleaned documents and produces an author-review export bundle. The pilot's acceptance sample comes from this task.

## Scope

- Main-content extraction (Readability-class library; `@mozilla/readability` checked 2026-09-21 via GitHub API: Apache-2.0, maintained by Mozilla — safe for an internal tool) plus rule packages: strip headers/menus/ads/"read also" blocks, anchor normalization (anchor + URL), photo normalization (image stays at its position with caption), publication date and language.
- Cleaned output written as a new version linked to the raw record; `status` moves `raw → cleaned`.
- Package version recorded in the run log for every cleaning run.
- Review export: a browseable markdown bundle of a sample of cleaned documents for the author's acceptance pass.

## Out of scope

- LLM normalization passes (later, as an auxiliary stage), search/basket (G17.07), changing `07`'s pipeline stages.

## Acceptance criteria

1. Per type, a raw fixture cleans to a document with no nav/ad/"read also" markers (negative assertions) and with every content paragraph of the fixture present (no content loss).
2. Raw bytes on disk are identical before and after cleaning (non-destructive assertion).
3. Changing a rule and re-running produces version 2 of the cleaned output; both versions retained; the run log names the package version — reverting the versioning fails this test.
4. Anchors keep anchor+URL form and photos stay at their positions with captions in the cleaned output.
5. The review export bundle is generated and its markdown opens with visible citations; suites wired into `npm test`; jscpd clean.

## Proof

Revert the "cleaned output is a new version" write path (overwrite raw instead) → criterion 2's byte-identity test fails.
