# G17.01.a — Collector scaffold: campaign schema, storage schema, run loop

## Context

- Specification: [`docs/24_web_collection.md`](../../24_web_collection.md) — sections «Кампанія», «Пашпарт запісу (RawRecord)», «Тэхнічны мінімум».
- Feeds the content pipeline [`docs/07_content_pipeline.md`](../../07_content_pipeline.md); this tool never publishes anything.
- Local one-person CLI tool, no server, no queue, no scheduler. Runtime: Node/TypeScript under `tools/collector/` (same pattern as `tools/validate`).
- Parent epic: G17 (see `README.md` in this folder).

## Goal

`tools/collector/` exists with a runnable CLI skeleton (`init`, `run --campaign <file>`, `status`): a campaign YAML is validated by Zod, the SQLite schema is created on first run, and the run loop is idempotent and resumable — a repeated or interrupted run never duplicates rows.

## Scope

- New package `tools/collector/` (package.json, tsconfig, source, tests).
- Campaign YAML schema (city, seeds, topics, fence with depth/extra_domains/delay_s, youtube ids) validated with Zod.
- SQLite schema: `campaigns`, `raw_records` (all passport fields from the spec: `id`, `campaign_id`, `source_type`, `url`, `canonical_url`, `collected_at`, `city`, `topics[]`, `rights`, `content_hash`, `status`, `snapshot_path`, `media_dir`), `links`, `media`, `run_log`.
- Run-loop skeleton that records progress so `run` can resume after interruption.

## Out of scope

- Any network fetching (no crawler, no yt-dlp calls here).
- Snapshot writing, cleaning, photo logic (G17.01.b and later).
- Any change to `docs/07` or product code.

## Acceptance criteria

1. A campaign YAML missing `city` or with invalid `fence` values is rejected with a diagnostic naming the offending field — negative test fails if the validation is reverted.
2. First `run` creates the full schema; running the same campaign twice inserts no duplicate `raw_records`/`campaigns` rows (idempotency test).
3. An interrupted run (second invocation in a test) resumes without duplicating records (rule: resume, not restart).
4. Every passport field from the spec table exists in `raw_records` with the exact spec name — schema test compares against the documented list.
5. The package's test suites are enumerated by the default `npm test` command and pass locally; `npx --yes jscpd@5.1.2 --config .jscpd.json --no-tips .` is clean.

## Proof

Revert the Zod fence validation → criterion 1's negative test fails.
