# G18.04 — Size guideline in the review rules

**Source:** [adoption plan](../../plans/2026-09-21-zcode-lessons-adoption.md), task 4 ·
audit 2026-09-21 (`tools/build-bundle/build-bundle.mjs` — 680 lines)

## Goal

Encode the source's size orientation as a review-time requirement, not dogma and
not a CI gate: a file over ~400 lines, or a contract with more than ~12 public
methods, obliges the reviewer to write one phrase assessing it (is there a second
owner or a contract asking to be extracted?). The plan explicitly forbids a
standalone refactor of `build-bundle.mjs` just for the count: the assessment
happens on the next real touch.

## Acceptance criteria

1. `code-review.md` gains the one-phrase requirement with the ≤400-lines /
   ≤12-public-methods orientation, worded as orientation, not dogma.
2. The guideline lives in `code-review.md` only — no second copy in
   implementation-rules or elsewhere (duplication rule).
3. A guard test (under `tools/validate/`, already in the `npm test` glob) fails if
   the guideline requirement is removed from `code-review.md`.
4. `tools/build-bundle/build-bundle.mjs` is not touched.

## Out of scope

- any refactor motivated only by the line count;
- hard limits or CI gates on file size;
- touching other agent-rules files.

## Proof

`node --test tools/validate/size-guideline-guard.test.mjs` — fails if the
guideline is removed from `code-review.md`.
