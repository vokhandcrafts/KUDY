## Goal

The module boundaries that today only review catches (the AR-finding class in
[22](../../architecture/22_code_architecture_review.md), audit 2026-09-21) become a
machine check. `dependency-cruiser`, pinned as a devDependency, forbids cycles,
checks layer direction and forbids platform imports in `core/`. The check exits
nonzero on **new** violations; legacy violations live in a dated baseline and are
updated only consciously, in review.

## Layer matrix

Canonical sources are 09 §6 and 19 §2 — the `.dependency-cruiser.cjs` config is only
the machine projection of that matrix; drift between config and canon is a review
defect (implementation-rules §2).

| Zone | May import | Must not import |
|---|---|---|
| `core/` (production files) | relative files inside `core/` | anything outside `core/`, plus `node:*`, `react-native`, `expo`, npm packages (tests inside `core/` are exempt: `node:test`, `node:assert`, fixture file access) |
| `services/` | `node:*`, `core/`, `contracts/`, relative | `web/`, `tools/`, `spikes/`, `app/`, `controllers/` |
| `contracts/` | relative | every app zone (`core/`, `services/`, `web/`, `tools/`, `spikes/`) |
| `web/` | its own packages, `contracts/` | `core/`, `services/`, `tools/`, `spikes/` |
| `tools/` | `node:*`, `contracts/` | `core/`, `services/`, `web/`, `spikes/` (19 §2.4: separate process, no shared code with the app) |
| `spikes/`, `docs/` | outside the machine check (isolation by construction, 22 §4.3; `docs/` holds the executable run-model) | — |
| `app/`, `controllers/` | do not exist yet — the PR that creates the first screen introduces their rules | — |

Cycles are forbidden within and across all checked zones.

## Acceptance criteria

1. `npm run arch:check` exits 0 on the repository at the final HEAD of the task PR.
2. A committed test (`tools/arch/arch-check.test.mjs`, wired into the `npm test`
   glob) builds a sandbox with a copy of the repo config and planted violations —
   (a) a two-file cycle, (b) a `core/` production file importing `node:fs`, (c) one
   layer-direction violation — and asserts the checker exits nonzero naming the
   violated rule.
3. The baseline exists, is dated, and carries an explanation for every entry
   (expected on 2026-09-22: zero entries); `npm run arch:baseline` regenerates it;
   updates happen only in review.
4. CI coverage and wiring are guarded: removing the `tools/arch` glob entry from
   `npm test`, or the `arch:check` script from `package.json`, turns a committed
   check red (extend `tools/ci/check-required-checks.mjs`; CI already runs
   `npm test` via required-checks — no `.github/` edits, which executors may not
   make).
5. `implementation-rules.md` gains a new § naming `npm run arch:check` with the
   «configuration is code» requirement (extension of §1, stated explicitly), and
   the root `AGENTS.md` local pre-push line lists `npm run arch:check` next to
   jscpd.

## Out of scope

- rules for `app/`/`controllers/` (they do not exist yet);
- deep-import limits (not in the canonical sources);
- fixing or refactoring existing violations (baseline only);
- editing `.github/` (hard boundary for executors);
- scanning `spikes/` and `docs/run-model`.

## Proof

`node --test tools/arch/arch-check.test.mjs` — fails if the config, the script or
the glob wiring is reverted; its sandbox cases fail the checker on planted
violations.

## Notes for the executor

- Pin `dependency-cruiser` to an exact version in `devDependencies`.
- Config at repo root (`.dependency-cruiser.cjs`); baseline file under
  `tools/arch/` with the explanation table in `tools/arch/README.md` (Belarusian —
  human-facing).
- Scope the scan to `core services contracts tools web`; exclude `node_modules`,
  build outputs and gitignored mirrors (implementation-rules §5).
- The repo currently has zero violations of this matrix (surveyed 2026-09-22:
  nothing outside `core/` imports `core/`; production `core/` files import no
  `node:*`), so the baseline should start empty — a non-empty first baseline is a
  finding to reconcile, not to commit blindly.
