# G26.11 — Bring app components to the approved component spec with a state specimen

## Epic

Epic: #764

## Goal

Every approved component exists in code with all its states, so screens are assembled from it rather than styled locally.

## Shared design source

Required: `docs/design/brand/atlas-brief.md`, `docs/design/brand/decisions.md`, `docs/design/visual-language.md` and the requirements synthesis `docs/design/brand/2026-10-17-requirements-synthesis.md`. See `docs/agent-tasks/brand-skeleton/README.md` for the wave order. Product/Run/ADR contracts remain authoritative for behavior. Record the git commit the sources were read at.

## Acceptance criteria

1. [ ] Map each component approved in G26.06 to its code component; list missing or divergent ones in the result.
2. [ ] Implement the missing states (loading, empty, error/retry, offline, disabled, locked, paused, completed where applicable) using tokens only.
3. [ ] Add a dev-only specimen screen that renders every component in every state at normal and largest font scale; it is not reachable in production builds.
4. [ ] Behavioral tests cover the state switching; screenshots of the specimen on a device or emulator are attached, or the result states "not verified on device".

## Out of scope

New components or states that G26.06 did not approve; illustration content.
