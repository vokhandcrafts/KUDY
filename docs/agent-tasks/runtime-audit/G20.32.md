# G20.32 — Restore the validated catalog and downloaded-guide preview after offline restart

Issue: https://github.com/vokhandcrafts/KUDY/issues/794

## Epic

Epic: #470

## Goal

A non-demo installation that previously loaded a valid catalog can reopen the guide list and the preview of a downloaded free guide after a process restart without network access.

## Evidence

Audit task ID: G20.32. Severity: HIGH. Finding key: `catalog-cache-is-process-local`.

Production createCatalogController/createCatalogService with the committed discovery-contract fixture: online boot=ready; same-process offline refresh=offline; fresh controller offline=error. previous is process-local and catalog_cache has no production reader/writer on main 85c020c2cb99453f291e68479a9708372843669a. The embedded demo origin added in PR #760 is not persistence of a previously fetched remote catalog.

## Scope

services/catalog/*; existing derived catalog persistence in services/db; controllers/catalog/*; minimal composition wiring after #663/#664. Preserve demo-source behavior.

## Acceptance criteria

1. [ ] Persist validated catalog and the preview inputs needed for a downloaded free guide in rebuildable storage, using the existing derived/durable separation. Do not persist signed media URLs.
2. [ ] After online load, construct fresh services/controllers over the same persistent store with network disabled: the list and downloaded guide preview remain usable with an offline indication; the existing download/Start readiness contract is preserved.
3. [ ] Failed refreshes and malformed responses cannot replace the last valid snapshot. A corrupt persisted snapshot yields a named safe state; a later valid refresh recovers.
4. [ ] An explicit derived-cache purge leaves session history/progress untouched. Cover restart, corrupt cache, corrupt refresh, missing cache, and demo-source compatibility through the production path in npm test.

## Out of scope

Discovery/feedback implementation owned by #664, purchase/restore, caching private media grants, changing product or package contracts.

## Dependencies

Blocked-by: #663, #664

Serialization: #663 and #664 both edit controllers/createServices.ts, deviceServices.ts and integration tests; #664 also introduces a persistent Discovery snapshot. Reuse the resulting seams after merge, without conflating catalog and Discovery ownership.

## Proof

Record and verify a Showboat proof under `docs/demos/` per the repository policy. Future tests are deliverables, not claims of existing coverage.
