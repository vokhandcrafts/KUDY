# G20.31 — Replace existing layer directories correctly during Expo download activation

Issue: https://github.com/vokhandcrafts/KUDY/issues/793

## Epic

Epic: #470

## Goal

Reactivating a damaged downloaded layer replaces it at its final path and never reports complete with a new layer nested inside the damaged directory.

## Evidence

Audit task ID: G20.31. Severity: HIGH. Finding key: `directory-existence-misclassified`.

Expo FileSystem 19.0.24 Android File.exists uses isFile; Directory.move to an existing directory moves inside it. Production createExpoDownloadStore + activate, with a filesystem stand-in matching those installed native semantics: activate a two-file layer; overwrite final stops.json with x; activate again. Observed: exists(final directory)=false; result=complete; final stops.json=x; nested base/base/stops.json exists. Adapter and activation code are unchanged on main 85c020c2cb99453f291e68479a9708372843669a. This is a deterministic adapter reproduction, not device E2E.

## Scope

services/download/expo/expo-download-store.ts; focused adapter/activation tests. Reuse the existing activation lane and deletion gate.

## Acceptance criteria

1. [ ] exists returns true for existing files and directories, false for absent/unsafe paths, with the same containment boundary.
2. [ ] A complete first activation followed by corruption and reactivation restores the expected bytes at the original final path, creates no nested layer and returns complete only for a valid final layer.
3. [ ] The regression stand-in preserves Expo File.exists and Directory.move semantics rather than Node rename semantics. Exercise the production adapter and activate together.
4. [ ] Existing first-download, idempotent repeat, staging recovery, hash failure and same-package concurrency tests pass. Wire the new regression into npm test without changing shared E2E runners.

## Out of scope

Package format, new backup policy, download UI, #663 recovery suite or #664 integration files.

## Dependencies

None.

No open prerequisite. Scope is confined to the adapter and focused tests; #663 and #664 currently do not edit these files. Coordinate before expanding scope.
