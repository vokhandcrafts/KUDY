# G20.33 — Keep the public bundle deadline active until the response body finishes

Issue: https://github.com/vokhandcrafts/KUDY/issues/795

## Epic

Epic: #470

## Goal

The public bundle timeout bounds the complete transfer, including body consumption, and aborts a stalled body so activation can report a retryable failure.

## Evidence

Audit task ID: G20.33. Severity: HIGH. Finding key: `bundle-body-outside-deadline`.

Production createOriginByteSource with a fetch stand-in that immediately returns status 200 but whose arrayBuffer never resolves: configured deadline=20ms; at 100ms the promise is still pending and signal.aborted=false. withWaitLimit currently wraps only fetch, while arrayBuffer runs after cleanup. Both files are unchanged on main 85c020c2cb99453f291e68479a9708372843669a.

## Scope

services/download/origin-bytes.ts and origin-bytes.test.ts; reuse services/network-wait.ts unchanged unless a verified shared-helper defect is found.

## Acceptance criteria

1. [ ] The same withWaitLimit scope includes headers, status handling and full body consumption; retain the canonical bundleBytesMs policy and redacted errors.
2. [ ] A stalled response body rejects with WaitTimeoutError rule wait-bundle-bytes at the configured test deadline and its signal is aborted.
3. [ ] Cover delayed headers, delayed/stalled body, successful bytes, non-200 status and body failure. A late body resolution cannot turn a timeout into success.
4. [ ] Through activate, a timed-out byte transfer yields the existing partial/fetch-failed result and a subsequent successful retry completes. Wire regressions into npm test; preserve the grant transport contract.

## Out of scope

Grant/signing behavior, network policy values, new retries/backoff, catalog loader, shared E2E runner changes.

## Dependencies

None.

No open prerequisite. #481 is closed; the existing timeout helper is published on main. No currently claimed task edits the scoped byte-source files.

## Proof
