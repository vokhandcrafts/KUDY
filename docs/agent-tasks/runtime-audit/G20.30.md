# G20.30 — Promote the active GPS subscription after background permission is granted

Issue: https://github.com/vokhandcrafts/KUDY/issues/792

## Epic

Epic: #470

## Goal

A newly granted background location capability promotes an active guide from its foreground watch to exactly one background update stream without waiting for watchdog recovery.

## Evidence

Audit task ID: G20.30. Severity: HIGH. Finding key: `background-grant-does-not-promote-watch`.

Production LocationService + ExpoLocationOsPort, mocked Expo boundary: foreground permission granted → Start → foreground watch starts while background ask is pending → background grant. Recorded calls contain only foreground-watch, no startLocationUpdatesAsync. applyAnswer returns when the foreground state is unchanged. The affected adapter is unchanged between audit c5e3e66 and main 85c020c2cb99453f291e68479a9708372843669a.

## Scope

services/location/expo/expo-location-port.ts and its behavioral tests; services/location/service.ts only if the port contract requires a minimal change.

## Acceptance criteria

1. [ ] Cover foreground-granted → active-guide → delayed background-granted and city-surface → active-guide. Background updates start promptly after grant without a watchdog tick.
2. [ ] Transfer ownership to one stream: release the foreground watch, reject late callbacks, and avoid duplicate background starts on repeated replies.
3. [ ] A background denial or start failure preserves usable foreground tracking. A pause/end or newer permission decision while the ask is pending cannot resurrect tracking.
4. [ ] Add deterministic tests using the real service and adapter with deferred Expo replies; include them in npm test. Check promotion, denial, stale replies and stop-during-promotion, and state separately whether Android background behavior was run.

## Out of scope

Changing permission UX, adding native modules, weakening generation guards, field calibration or editing active #663/#664 work.
