# G20.29 — Initialize speech audio mode before device playback

Issue: https://github.com/vokhandcrafts/KUDY/issues/791

## Epic

Epic: #470

## Goal

Every device guide and Moment playback awaits the shared speech-mode initialization. Background playback and interruption policy are configured before a player starts; a failed initialization produces the existing named playback failure and can be retried.

## Evidence

Audit task ID: G20.29. Severity: HIGH. Finding key: `speech-mode-not-initialized`.

The audit at c5e3e66 recorded 0 setAudioModeAsync calls while the production orchestrator, audio service and Expo adapter played a story with only the Expo boundary mocked. Rechecked on main 85c020c2cb99453f291e68479a9708372843669a: configureSpeechAudioMode is exported but has no production caller. Expo Audio 1.1.1 defaults shouldPlayInBackground to false. File-URI resolution is already fixed by #749 / PR #750 and must remain intact.

## Scope

controllers/deviceRoot.ts; services/audio/service.ts and services/audio/expo/ where initialization belongs; focused production-wiring and adapter tests. Avoid deviceServices.ts/createServices.ts unless required after #664 lands.

## Acceptance criteria

1. [ ] Before the first physical play, await configureSpeechAudioMode with the existing SPEECH_AUDIO_MODE values; concurrent requests share one successful initialization.
2. [ ] Initialization rejection causes no physical play, reaches the existing playback-error state, and a subsequent explicit retry can initialize successfully.
3. [ ] A superseded or stopped launch cannot start after its pending initialization resolves; token and one-player ownership tests remain green.
4. [ ] Add regression tests through production composition with only the Expo boundary mocked. Assert order (mode completion before play), one-time success, rejection/retry, and cancellation. Include them in npm test; document native background behavior as unverified unless actually run.

## Out of scope

Audio path redesign, new player ownership rules, lock-screen features, physical-device interruption acceptance (#297), changing #664 while claimed.
