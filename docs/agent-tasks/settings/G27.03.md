## Epic

Epic: #346

## Goal

Make community angles explicit author-reviewed catalog facts, and derive guide depth from the existing `audience_level` contract without a second depth field.

## Acceptance criteria

1. [ ] Define bounded community-angle tags from the two reviewed pilot briefs in #788, with an editorial reason for each. Use G27.01’s approved aggregation of story `audience_level` for guide depth; keep community angle, theme and locale distinct.
2. [ ] Extend authoring, validation and versioned discovery/catalog output for community-angle tags. For guide offers, the builder also derives `audience_level` from story `audience_level` using G27.01’s approved aggregation and exports that same name and `tourist` / `traveller` / `maniac` values in the versioned index. Amend the owning definition in `docs/01_product_structure.md` to distinguish authored story depth from derived guide depth; then check the `audience_level` row in `docs/architecture/25_domain_vocabulary.md` against that definition and amend 21 §3.2 to reference it. Document compatibility for old data and clients; an old offer without these optional facts remains eligible. Do not add a second depth field.
3. [ ] Add contract and export guards for unknown tags, missing translations, duplicates and payload bounds; update the canonical architecture document once rather than copying contracts into task results.

## Out of scope
