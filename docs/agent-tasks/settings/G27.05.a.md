# G27.05.a — Define durable collection provenance

## Epic

Epic: #346

## Goal

Give saved souvenirs and verified achievements a durable, distinguishable local record before the collection screen reads them.

## Acceptance criteria

1. [ ] Define the canonical identity, provenance and condition-evidence contract for a saved souvenir versus an approved achievement; do not treat a card open, GPS proximity or sound start as a visit or completed story.
2. [ ] Implement bounded local persistence and an additive migration with deduplication, offline restart and interrupted-write behavior. A cache purge cannot erase the record.
3. [ ] Add a revert-sensitive contract/persistence test and document recovery for old or unknown records. Do not emit achievements until an owner-approved condition exists.

## Out of scope

Collection UI, accessory unlocks, cloud sync, and defining a new achievement condition in this task.

## Dependencies

Blocked-by: #781, #769.

## Proof

Schema/migration and persistence tests fail when provenance or deduplication is removed; Showboat if persisted data changes.
