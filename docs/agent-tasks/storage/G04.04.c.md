# G04.04.c — Presence check after restart and app update

**Status:** not-started. **Model class:** medium. **Dependencies:** [G04.02.a](G04.02.a.md) and [G04.04.a](G04.04.a.md) complete. Parent task: G04.04.

## Scope

After a restart the app re-checks that ready layers still have their files (09 §7: iOS may orphan files while SQLite survives), with the cheap check by default and the full re-hash only when the contract asks for it.

Read: [09 §4](../../architecture/09_technical_architecture.md) (three-level sha256 policy), §7 («Пасля абнаўлення дадатку»), [ADR G01.03 §3.7](../../architecture/decisions/G01.03-session-access.md), result [G04.03](../results/G04.03.md) (needs-recovery card).

## Allowed outputs

- `services/contentRepo/` and `services/download/` — presence check and re-download request, tests
- `docs/demos/<YYYY-MM-DD>-g0404c-presence-check.md`
- `docs/agent-tasks/results/G04.04.c.md`

## Acceptance

1. [ ] After a restart, every ready layer gets the level-2 check of 09 §4 (JSON files, plus media presence and size from `lock.json`); a missing or short file moves the layer to needs-recovery, never to Play.
2. [ ] A full re-hash runs only on the three conditions of 09 §4 (app version changed, decode error reported, user-requested check); a test shows an ordinary restart does not trigger it.
3. [ ] Missing files lead to a re-download request through `services/download` for exactly those paths.
4. [ ] A pinned version with missing files is never filled with files of another version.

## Out of scope

Background scheduling on the device, UI, the grant server.
