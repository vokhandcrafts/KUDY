# G04.02.b — Grant client, retries, URL expiry

**Status:** not-started. **Model class:** strong. **Dependencies:** [G04.02.a](G04.02.a.md) complete. Parent task: G04.02.

## Scope

The download side of `/v1/grant`: request shape, the closed error list and retry behaviour, over an injected HTTP port. The server grant is not built here.

Read: [09 §5](../../architecture/09_technical_architecture.md) (`/v1/grant`, «Мяжа /grant»), §5.1, §12 cases 2–3, [19 §3.6](../../architecture/19_class_and_module_map.md) (closed `GrantError` list), [ADR G01.03 §3.6](../../architecture/decisions/G01.03-session-access.md) («Купленае без файлаў — не ready»). `spikes/G00.03-sandbox-grant/server/` is a read-only contract reference and is never imported from `services/`.

## Acceptance

1. [ ] The request is exactly `{route_id, version, locale, tier, paths[]}` with a Bearer credential from an injected port; `paths` come only from the verified `lock.json` of that layer, never from the caller.
2. [ ] Each code of the closed list has its own outcome: `403 no_entitlement` → purchase path; `503 entitlement_unavailable` → retry honouring `Retry-After`; `400 invalid_request` → executor error; `url_expired` → re-grant. An unknown status or code is a named failure — never ready, never free access (fail closed).
3. [ ] When a URL expires mid-download the client re-grants and continues; verified files are not fetched again.
4. [ ] Offline has a defined outcome: the partial state is kept, a retry is available, and no exception reaches the caller.
5. [ ] No secret, token or signed URL is logged or persisted (the test captures diagnostics).
6. [ ] The fake's negative-case list is copied verbatim from 19 §3.6; live parity is recorded in the results file as G08.04's duty ([implementation-rules §15](../../agent-rules/implementation-rules.md)).
