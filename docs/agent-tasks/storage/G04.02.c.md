# G04.02.c — `AccessReady` capability channel and crash recovery

**Status:** not-started. **Model class:** strong. **Dependencies:** [G04.02.b](G04.02.b.md) complete (same module; sequential to avoid parallel edits). Parent task: G04.02.

## Scope

`services/download` becomes the only issuer of `AccessReady`, and the crash rows of ADR G01.03 §3.7 hold after restart.

Read: [ADR G01.03](../../architecture/decisions/G01.03-session-access.md) §3.5, §3.7; [09 §6.1](../../architecture/09_technical_architecture.md) (the `AccessReady` paragraph); [19](../../architecture/19_class_and_module_map.md) §3.2 (`DownloadAccessPort`), §6.4–§6.5.

## Allowed outputs

- `services/download/` — capability port, emission after commit, recovery on open, tests
- `docs/demos/<YYYY-MM-DD>-g0402c-access-ready.md`
- `docs/agent-tasks/results/G04.02.c.md`

## Acceptance

1. [ ] `AccessReady(route_id, version, locale, tier, stop_ids[], issuer='services/download')` is emitted exactly once per activation commit, only through the typed `DownloadAccessPort`; an event object built outside the module is never delivered (runtime test).
2. [ ] `stop_ids` come from the activated layer's package, not from the caller.
3. [ ] Repeating the same identity produces no second emission.
4. [ ] After a restart between rename and emission, readiness is derived from disk; zone B has no ready column or flag (the test inspects zone B).
5. [ ] A download finishing after End mutates no session row; the files stay under their package key.

## Out of scope

Engine acceptance of `AccessReady` (G05.01.a), controller wiring (G05.05), UI.

## Proof

Emit before the rename commit → the crash-injection test fails. Showboat: required (persisted data, authorization boundary).
