# G20.06 — Reject unsafe credential transport before network calls

## Goal

Registration and secret-bearing requests use the configured HTTPS endpoint and never follow a credential-bearing redirect.

## Sources

- Specification: [network-privacy.md](../../specifications/architecture-hardening/network-privacy.md), section N3.
- [Publication index](README.md) contains the real issue IDs and dependencies.
- [Original audit](../../audits/2026-10-02-architecture-review.md) and [reproduction script](../../audits/2026-10-02-proof.mjs.txt).

## Evidence boundary

Audit A26-06: http://example.invalid receives Authorization: Bearer SYNTHETIC-AUDIT-SECRET.

## Scope

services/device.ts; services/analytics.ts; shared existing URL-validation owner; authenticated production transports identified by search.

## Acceptance criteria

1. [ ] HTTP, malformed URLs and URL credentials are rejected before fetch; assert zero network calls using synthetic secrets.
2. [ ] A HTTPS redirect cannot start a second authorized request; valid configured HTTPS retains existing API/status behavior.
3. [ ] Search other authenticated client/server transports and apply/reuse the same boundary where present; record reviewed paths and avoid duplicate validators.
4. [ ] Unsafe-URL and redirect tests fail on reverting validation; logs and demos contain no real secret.

## Out of scope

No new features, engine rules, access bypasses, unrelated refactoring or production data.
