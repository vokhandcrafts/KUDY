# G20.11 — Reject oversized or invalid signed-media URL lifetimes

## Goal

Grant signing never receives a TTL outside the canonical short-lived policy.

## Sources

- Specification: [network-privacy.md](../../specifications/architecture-hardening/network-privacy.md), section N5.
- [Publication index](README.md) contains the real issue IDs and dependencies.
- [Original audit](../../audits/2026-10-02-architecture-review.md) and [reproduction script](../../audits/2026-10-02-proof.mjs.txt).

## Evidence boundary

grant/index.ts:270 accepts any finite nonnegative parsed value; core forwards TTL without an upper bound.

## Scope

supabase/functions/grant/index.ts; _shared/grant-core.ts; configuration/handler tests.

## Acceptance criteria

1. [ ] Absent configuration uses the existing 600-second default; zero, negative, fractional, nonfinite, malformed and above-bound values prevent minting.
2. [ ] Validate at configuration and core boundaries; direct core callers cannot bypass the bound and signer call count is zero on invalid input.
3. [ ] Valid TTL keeps entitlement verification and sandbox/production isolation; entitlement-cache TTL remains a distinct policy.
4. [ ] Use synthetic signer/provider tests under npm test; an oversized-TTL test fails on reverting the guard. Do not claim a live Storage maximum from this test.

No new features, engine rules, access bypasses, unrelated refactoring or production data.
