# G20.08 — Prove and enforce GPS start-stop and screen ownership

## Goal

Stopped location owners leave no background task; Nearby releases only its own foreground watch when the app backgrounds.

## Sources

- Specification: [runtime.md](../../specifications/architecture-hardening/runtime.md), section R4.
- [Publication index](README.md) contains the real issue IDs and dependencies.
- [Original audit](../../audits/2026-10-02-architecture-review.md) and [reproduction script](../../audits/2026-10-02-proof.mjs.txt).

## Evidence boundary

Static risk in asynchronous startLocationUpdatesAsync/hasStartedLocationUpdatesAsync; no deterministic native-race or battery measurement yet.

## Scope

services/location/expo/expo-location-port.ts; controllers/nearby/nearbySurfaceController.ts; lifecycle/controller tests.

## Acceptance criteria

1. [ ] Control unresolved native promises and reproduce Start -> Stop before start resolves, plus old-stop/new-start and start rejection. Record actual outcomes before changing code.
2. [ ] After all promises settle, stopped owners have zero tasks/watchers; old callbacks and cleanup cannot stop the new owner.
3. [ ] Drive Nearby foreground/background/foreground transitions through the production hook/controller: release its own watch, preserve an active walk and avoid duplicate watchers.
4. [ ] Commit behavioral regressions under npm test. If a proposed race cannot be reproduced, record its guarantee and retain the tested behavior rather than adding a speculative lock.

## Out of scope

No new features, engine rules, access bypasses, unrelated refactoring or production data.
