# G20.16 — Check JavaScript tools for async and error-handling defects

## Goal

Production tools have an enforced focused check that rejects forgotten asynchronous work and empty error handlers.

## Sources

- Specification: [verification-integration.md](../../specifications/architecture-hardening/verification-integration.md), section V3.
- [Publication index](README.md) contains the real issue IDs and dependencies.
- [Original audit](../../audits/2026-10-02-architecture-review.md) and [reproduction script](../../audits/2026-10-02-proof.mjs.txt).

## Evidence boundary

No lint script currently exists; tools JavaScript has no explicit checked-JS type gate.

## Scope

tools/**/*.mjs; minimal pinned lint/JS typing configuration; test-command and authorized workflow wiring.

## Acceptance criteria

1. [ ] Inventory production tool files and existing conventions; choose the smallest JS type/lint configuration with explicit coverage and documented intentional exclusions.
2. [ ] Synthetic missing-await/unhandled-promise and empty-catch fixtures make the check fail; valid async/error code passes. A generic linter that cannot catch these cases is insufficient.
3. [ ] Pin introduced tooling and enforce the check in the standard command/authorized CI after G20.22; no broad formatting or blanket disable list.
4. [ ] If separating tool/docs suites, retain required execution and the actual docs ledger check; demonstrate a dropped canonical fact still fails.

## Out of scope

No new features, engine rules, access bypasses, unrelated refactoring or production data.
