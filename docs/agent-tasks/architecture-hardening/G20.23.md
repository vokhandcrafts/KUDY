# G20.23 — Release preview busy state after package-fact failures

## Goal

A completed activation followed by a failed inventory/readiness refresh gives a terminal error and a usable retry, without authorizing Start from the activation result.

## Sources

- Specification: [runtime.md](../../specifications/architecture-hardening/runtime.md), section R6.
- [Task index](README.md) and [review boundary proof](../../audits/2026-10-02-review-boundaries-proof.mjs.txt).

## Evidence boundary

Reproduced through createPreviewController: activate completes, second layerState throws synthetic-inventory-fault; download rejects and busy remains true.

## Scope

controllers/catalog/previewController.ts; preview/controller operation tests.

## Acceptance criteria

1. [ ] Invoke the production controller with successful activation then inventory or evaluate rejection: busy becomes false, failure is visible and retry can run.
2. [ ] Start remains blocked until readiness is actually verified; no activation-result shortcut or silent success clears a failed verification.
3. [ ] An initial refresh failure yields a terminal surface state, and a stale failure cannot overwrite a newer refresh result.
4. [ ] Tests execute in npm test and fail when operation cleanup/error handling is reverted; record errors using synthetic data only.

## Out of scope

New product features, weakening authorization, live secrets, unrelated cleanup, dispatcher/branch-protection changes and implementation before publication.
