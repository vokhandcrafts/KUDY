# G20.05 — Recheck analytics consent before every batch

## Goal

Revoking persisted consent prevents any subsequent batch from starting and leaves unsent rows queued.

## Sources

- Specification: [network-privacy.md](../../specifications/architecture-hardening/network-privacy.md), section N2.
- [Publication index](README.md) contains the real issue IDs and dependencies.
- [Original audit](../../audits/2026-10-02-architecture-review.md) and [reproduction script](../../audits/2026-10-02-proof.mjs.txt).

## Evidence boundary

Audit A26-05 reproduced sending256+1 after revocation.

## Scope

services/analytics.ts; services/eventLog.ts; consent/batch tests.

## Acceptance criteria

1. [ ] Queue 257 events; revoke stored consent after the first 256: exactly one network batch is sent and the final event remains unsent.
2. [ ] Revoked consent before flush produces no network request; restoring consent resumes queued events without duplicates.
3. [ ] A completed in-flight request may be acknowledged, but skipped batches cannot be marked delivered by a successful no-op sender.
4. [ ] The between-batches test fails on reverting the consent check and runs in npm test.

## Out of scope

No new features, engine rules, access bypasses, unrelated refactoring or production data.
