# G20.27 — Pin workflow actions and verify the secret-scanner download

## Goal

All workflow action references are immutable and gitleaks executes only after a pinned checksum verifies its downloaded archive.

## Sources

- Specification: [verification-integration.md](../../specifications/architecture-hardening/verification-integration.md), section V6.
- [Task index](README.md) and [review boundary proof](../../audits/2026-10-02-review-boundaries-proof.mjs.txt).

## Evidence boundary

Current workflows use checkout/setup-node tags; required-checks downloads gitleaks 8.24.3 without checksum validation.

## Scope

.github/workflows/*.yml after G20.22 approval; pinned action/checksum ownership and behavior tests.

## Acceptance criteria

1. [ ] After G20.22 authorization, replace action tags with verified upstream full 40-hex commit SHAs and retain readable version annotations; no guessed SHA or permissions expansion.
2. [ ] Pin the gitleaks archive digest from verified release provenance; require HTTPS/HTTP success, validate before extraction/execution, and redact scanner output.
3. [ ] In an isolated workflow-equivalent fixture, altered archive, missing checksum and HTTP failure each produce nonzero exit and zero scanner executions; the genuine pinned fixture passes.
4. [ ] Removing a pin/checksum gate fails the required wiring/behavior check. Document how version/provenance updates are reviewed; preserve all current required jobs and avoid printing real secrets.

## Out of scope

New product features, weakening authorization, live secrets, unrelated cleanup, dispatcher/branch-protection changes and implementation before publication.
