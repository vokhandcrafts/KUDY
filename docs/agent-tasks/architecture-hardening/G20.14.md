# G20.14 — Run real Expo adapter behavior in the standard test command

## Goal

The default suite executes production audio/location adapters at the OS boundary and catches reverted resource fixes.

## Sources

- Specification: [verification-integration.md](../../specifications/architecture-hardening/verification-integration.md), section V1.
- [Publication index](README.md) contains the real issue IDs and dependencies.
- [Original audit](../../audits/2026-10-02-architecture-review.md) and [reproduction script](../../audits/2026-10-02-proof.mjs.txt).

## Evidence boundary

Existing Node globs and Jest app/components match do not exercise these Expo adapter behaviors.

## Scope

jest.config.js or a focused compatible test configuration; test wiring guards; Expo adapter suites.

## Acceptance criteria

1. [ ] npm test discovers real audio and GPS adapter suites, mocking only Expo/OS modules; do not replace production adapter logic with fake service ports.
2. [ ] Cover native startup, delayed completion, errors, replacement and cleanup using the scenarios from G20.02/G20.07/G20.08.
3. [ ] In temporary copies, remove the play call and pending-start cleanup: the standard check fails. Removing suite wiring is also detected.
4. [ ] Keep Node and Jest runner boundaries explicit and report platform tests as adapter evidence rather than physical-device proof.

## Out of scope

No new features, engine rules, access bypasses, unrelated refactoring or production data.
