# G20.19 — Generate schema-owned wire types while preserving catalog compatibility

## Goal

Catalog/bundle wire definitions and repeated supported-locale lists have a single declared owner and deterministic consumers.

## Sources

- Specification: [verification-integration.md](../../specifications/architecture-hardening/verification-integration.md), section V4.
- [Publication index](README.md) contains the real issue IDs and dependencies.
- [Original audit](../../audits/2026-10-02-architecture-review.md) and [reproduction script](../../audits/2026-10-02-proof.mjs.txt).

## Evidence boundary

services/catalog/envelope.ts:24 explicitly supports legacy-v0/unknown-major; sizes optional there is not automatically a bug.

## Scope

contracts schemas; services/catalog/types.ts and envelope.ts; web catalog wire types; bundle wire consumers; focused generation/check scripts.

## Acceptance criteria

1. [ ] Map each manual catalog/bundle wire type and locale list to its canonical source; do not treat intentionally looser legacy projections as schema defects.
2. [ ] Generate only schema-owned wire types and compatible derived locale lists deterministically; generated output has a check that fails when stale.
3. [ ] Legacy-v0, unknown-major and optional sizes projection tests retain current compatibility; malformed external input still requires runtime validation.
4. [ ] Repeated generation has no diff; schema/locale fixture changes make the stale-output check fail until regeneration; keep current accepted locale scope.

## Out of scope

No new features, engine rules, access bypasses, unrelated refactoring or production data.
