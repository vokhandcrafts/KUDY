# G20.09 — Prove same-package download activation remains atomic

## Goal

Two overlapping activations of one package cannot expose mixed or incomplete content as ready.

## Sources

- Specification: [runtime.md](../../specifications/architecture-hardening/runtime.md), section R5.
- [Publication index](README.md) contains the real issue IDs and dependencies.
- [Original audit](../../audits/2026-10-02-architecture-review.md) and [reproduction script](../../audits/2026-10-02-proof.mjs.txt).

## Evidence boundary

Concurrent staging uses shared package paths; incomplete-ready outcome has not been reproduced.

## Scope

services/download/download.ts; nodeDownloadStore.ts; repair/delete coordination; concurrency tests.

## Acceptance criteria

1. [ ] Run two real activate paths for the same key with controlled fetch/write/rename barriers; check ready inventory against actual files and hashes at each publish point.
2. [ ] Cover cancellation, deletion, fetch/write failure and restart during overlap; progress and protected walk content remain intact.
3. [ ] If a failing interleaving exists, reuse the existing ownership gate or minimal per-key serialization; two unrelated package keys remain independent.
4. [ ] The regression runs in npm test and fails on reverting a proven fix. If no failing schedule exists, publish the tested guarantee and no speculative runtime change.

## Out of scope

No new features, engine rules, access bypasses, unrelated refactoring or production data.
