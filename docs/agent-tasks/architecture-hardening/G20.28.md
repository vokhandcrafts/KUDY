# G20.28 — Discover every accepted test and enforce engine mutations in CI

## Goal

Adding an accepted test file cannot silently bypass the default suite; engine:regressions runs in the required workflow.

## Sources

- Specification: [verification-integration.md](../../specifications/architecture-hardening/verification-integration.md), section V7.
- [Task index](README.md) and [review boundary proof](../../audits/2026-10-02-review-boundaries-proof.mjs.txt).

## Scope

package.json test entrypoint; explicit Node/Jest ownership/discovery; tools/engine-regressions; authorized required workflow wiring.

## Acceptance criteria

1. [ ] Inventory committed test files and declare Node/Jest ownership plus justified exclusions; new accepted test paths are discovered or fail an explicit unowned-test check.
2. [ ] Add a named synthetic failing test in a temporary checkout for each supported runner: the standard command executes that named sentinel and fails, rather than merely finding its source text.
3. [ ] After G20.22 authorization, run npm run engine:regressions in a required job; a planted missed mutation fails with its guard name, and removing the invocation is detected.
4. [ ] Existing suites, security scenarios and docs ledger stay enforced. Record runner commands/platform limits; no broad skip list or green result caused by a pre-existing unrelated failure.
