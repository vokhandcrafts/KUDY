# G06.10.c — Lucide icon layer

**Status:** not-started. **Model class:** medium. **Dependencies:** G06.10.a closed (the icon sizes/colors come from the canon tokens). Parent task: G06.10 ([16 design block](../../16_delivery_backlog.md)).

## Scope

One shared icon component over Lucide, the founder-chosen set (one rounded outline style, ISC). Icons take color and size only from the canon tokens; glyphs are imported per-glyph (deep imports — Metro does not tree-shake barrel exports); every icon-only usage carries a screen-reader label (canon §9). First real application on one surface, so the slice is complete end-to-end.

Read: [visual-language.md](../../design/visual-language.md) §5, §9, the parent [G06.10.md](G06.10.md), [implementation-rules](../../agent-rules/implementation-rules.md). Registry note: `lucide-react-native` 1.48 ISC, peer `react-native-svg` (SDK 54 pin 15.12.1).

## Allowed outputs

- `package.json` + `package-lock.json` — `react-native-svg` and `lucide-react-native` pinned exactly as `npx expo install --check` accepts
- one icon component in `components/` (never `app/` — expo-router route rule): props color/size from tokens by default, a required accessibility label for icon-only rendering, passthrough for pressable composition
- the first application: the metadata row of the guide preview surface (time, stops) and/or the screen header action — one surface is enough, named in the results
- a component test (render + accessibility label + token color); `docs/demos/<YYYY-MM-DD>-g0610c-icons.md`, `docs/agent-tasks/results/G06.10.c.md`

## Acceptance

1. [ ] The icon component renders a Lucide glyph with color/size resolved from the canon tokens; a test overrides a token and sees the change — values never hardcoded in the component.
2. [ ] Rendering without an accessibility label on an icon-only usage fails the component test (the label contract is enforced, not advisory); a labelled usage passes with the label visible to accessibility tooling.
3. [ ] Glyphs are imported per-glyph (deep imports); a source check in the demo shows no barrel import of the icon package anywhere.
4. [ ] The named surface shows the icons on the guide preview in BY and EN (demo screenshots); the pressed/flat states of surrounding elements are unchanged.
5. [ ] `npm test`, `npm run typecheck`, `npm run arch:check` and the copy-paste gate are green.

## Out of scope

Duotone or any other icon set; icons inside buttons' shelf styling (d); map markers (they stay letter-per-state per canon §5); web/ icon usage; animating icons.

## Proof

Change the icon component to read color from a hardcoded literal → the token-override test fails; restore the token read → green. Showboat: required (user-visible runtime behaviour — preview screenshots BY/EN).
