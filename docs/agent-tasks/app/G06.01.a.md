# G06.01.a — City and Guides surfaces on the published catalog

**Status:** not-started. **Model class:** medium. **Dependencies:** G06.06–G06.08 approved (design canon), G06.09.a+b complete, G01.04 contract accepted. Parent task: G06.01 (issue #62). ## Scope

The first two surfaces of the canonical chain — Explore (city) and the «Гіды» rubric — reading the published catalog through a ports-injected catalog service. After this part the app shows real published guides (one or many) with no invented cards; the third link of the chain (guide preview) is [G06.01.b](G06.01.b.md).

Read: [09 §4](../../architecture/09_technical_architecture.md) (`catalog.json` — the public list of what exists; refresh at every start, failure fatal only with no cache), [11 §16.1–§16.2](../../11_run_interaction.md) (canonical chain, one card per guide D02, rubric as a surface not a tab, empty rubrics never render NAV2, back), [21 §3.2–§3.3, §4](../../architecture/21_discovery_feedback_architecture.md) (DiscoveryIndexV1 offer fields, catalog envelope and reader policy, ordering `editorial_order` then `offer_id`), [screens-and-transitions](../../design/screens-and-transitions.md) (Explore and Guides sections, state coverage table), [visual-language](../../design/visual-language.md) (card kinds, badges, focus, big text), results [G06.06](../results/G06.06.md) and [G06.07](../results/G06.07.md) (approved canon), [G06.09.b](../results/G06.09.b.md) (composition root, controller store, layer rules).

## Allowed outputs

- `services/catalog/` — the catalog service: the G01.06 envelope reading and
  the last-valid-cache semantics per 09 §4 and 21 §3.3 (unknown major version →
  route list only; corrupted or missing index → previous valid cache; no cache
  → normal city page without discovery), and its tests. `contracts/reader.mjs`
  stays the single interpretation source, but it is Node-stdlib only and cannot
  join the RN bundle — the device path ships a narrow envelope projection whose
  verdicts a committed parity test pins to `readCatalogDoc` on the published
  fixtures, with no deep validation (publication owns the schema verdict). The
  service takes an injected text-loader port (device build: the configured
  HTTPS public origin; Node tests: fixture text).
- `controllers/catalog/` — the city catalog controller as a vanilla store (G06.09.b helper): the city's published guides and their card state (title/summary, languages, tariff badge, order), the rubric rendering flag, and the surface state (ready / empty city / offline / error); Node tests with fake ports.
- `controllers/createServices.ts`, `app/_layout.tsx` — wire the new service behind its port.
- `app/(tabs)/explore.tsx`, `app/city/[id]/guides.tsx` — the two surfaces per the approved scheme, sharing one guide-card component; cards link to the preview route, which stays a placeholder until G06.01.b.
- `npm test` globs for the new suites; `docs/demos/<YYYY-MM-DD>-g0601a-city-guides.md`; `docs/agent-tasks/results/G06.01.a.md`.
