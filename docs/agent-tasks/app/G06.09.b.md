# G06.09.b — Composition root, controller store and layer rules

**Status:** not-started. **Model class:** medium. **Dependencies:** [G06.09.a](G06.09.a.md) complete. Parent task: G06.09.

## Scope

The one place where services are constructed and handed to controllers, and the store library for controllers. After this part a controller can be written once and run both in the app and in a Node test with fake ports. No product controller is implemented here: `useRunController` is G05.05, the others belong to G06/G07/G15/G16.

Read: [09 §6, §6.4](../../architecture/09_technical_architecture.md), [19 §2.2–§2.3, §2.6, §4.2, §5.2](../../architecture/19_class_and_module_map.md) (hooks as controllers, plain classes as services, no DI framework, no event bus), results [G04.01](../results/G04.01.md) and [G04.03](../results/G04.03.md) (how `services/db` and `services/contentRepo` take injected ports), `tools/arch/README.md`.

## Allowed outputs

- `controllers/` — the composition root (`createServices(ports)` or equivalent), a store helper over the pinned store library, one sample controller used only by tests, and tests
- `app/_layout.tsx` — provides the composition root to screens
- `package.json` + `package-lock.json` — the store library named in 19 §2.2 (Zustand), exact pin
- `.dependency-cruiser.cjs` and `tools/arch/` — rules: `app/` imports `controllers/` only (plus React/Expo), `controllers/` may import `core/` and `services/`, `core/` imports neither; no new baseline entries
- `npm test` glob for `controllers/**/*.test.ts`
- ADR G00.04 §6 (the new pin), `docs/demos/<YYYY-MM-DD>-g0609b-composition-root.md`, `docs/agent-tasks/results/G06.09.b.md`

## Acceptance

1. [ ] The composition root is the only module that constructs services: outside the root and tests, every import of `services/` is type-only (dependency-cruiser `dependencyTypes: ["type-only"]`), and a deliberate value import from a controller fails `npm run arch:check`.
2. [ ] Ports are explicit parameters: the same root builds the app with device ports and a Node test with fake ports; the test drives the sample controller end to end without React Native.
3. [ ] Each rule of Allowed outputs has a fixture violation that `arch:check` rejects, recorded in the demo.
4. [ ] Screens stay placeholders; no screen imports `services/` or `core/` directly.
5. [ ] `npm run typecheck`, `npm test`, `npm run arch:check`, `npx expo-doctor` are green; the store pin is exact and recorded in ADR G00.04 §6.

## Out of scope

Any product controller or its state (G05.05, G06.01, G06.04, G07.05, G15.03, G16.03); device adapters for location/audio/filesystem (G05.02.c, G05.03.b, TR-10); visuals.

## Proof
