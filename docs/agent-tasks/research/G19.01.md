# G19.01 — Validated corpus contracts and synthetic fixtures

## Context

Read [the canonical specification](../../25_content_research.md), especially sections 3–6, 8–9, and [the implementation plan](../../superpowers/plans/2026-10-01-content-research.md). The source library/parser are external; repository collector files are implementation references, not a description of that live system.

## Goal

Pinned version-1 schemas for input, article/fragment, both model levels, Case, review, private run configuration and exports. A runnable local schema validator and source-free fixtures.

## Scope and files

- `tools/corpus/schemas/*.schema.json`
- `tools/corpus/contracts.mjs`
- `tools/corpus/contracts.test.mjs`
- `tools/corpus/cli.mjs`
- `tools/corpus/cli.test.mjs`
- `tools/corpus/fixtures/*`
- `tools/corpus/vocabularies/gdansk-v1.json`
- `package.json`

## Interfaces

validateInput(manifest), validateRunConfig(config), validateModelResult(level, result, fragments), validateCase(record); each returns { ok, errors } without coercing invalid values.

## Acceptance criteria

1. [ ] CLI validate-input accepts a synthetic valid manifest and rejects null, wrong types, unknown rights, duplicate source keys and limit violations with stable diagnostics and nonzero exit; no filesystem or model call is made.
2. [ ] Result schemas forbid unknown topics/IDs, inverted dates, invalid mention types and more than three hooks; quote validation uses Unicode code-point offsets and exact equality.
3. [ ] Synthetic HTML fixtures cover navigation within the content container, a single p with br, captions, unlinked names, family/person ambiguity, differing image dates and script/network traps; no real source URL, title, text or media is committed.
4. [ ] Runtime dictionaries have stable IDs and version gdansk-v1; unknown classifications remain unknown, proposed themes are separate; node:test glob tools/corpus/*.test.mjs is added to npm test and its runner wiring is tested.

## Implementation steps

- [ ] Read dependencies, schemas and relevant existing helpers before writing a new helper.
- [ ] Add the behavioral checks listed below and run them to show the missing behavior. G19.08 instead validates the actual owner-supplied inputs.
- [ ] Implement only this task's files/interfaces; reuse earlier tasks' boundary checks and persistence paths.
- [ ] Run the task proof and repository checks from the plan; inspect the resulting diff for contract/privacy drift.
- [ ] Record actual outcomes, gaps and evidence in `docs/agent-tasks/results/G19.01.md`; commit the implementation with its behavioral checks.

## Checks

contracts.test.mjs: invalid_null_manifest, duplicate_source_key, invalid_rights, hook_limit, quote_unicode_offsets, unknown_fragment_id; cli.test.mjs: validation_exit_codes, corpus_suite_is_wired.

## Proof

node --test tools/corpus/contracts.test.mjs tools/corpus/cli.test.mjs

Reverting the owned behavior must break the named behavior test. G19.08 is a human-input tracking task: its proof is actual validation and decisions, not a code-revert test.
