# G19.05 — Search and explicit research-case selection

## Context

Read [the canonical specification](../../25_content_research.md), especially sections 5, 7, and [the implementation plan](../../superpowers/plans/2026-10-01-content-research.md). The source library/parser are external; repository collector files are implementation references, not a description of that live system.

## Goal

Word search plus entity/topic/district/year filters and saved, revision-pinned author selection for a topic.

## Scope and files

- `tools/corpus/search.mjs`
- `tools/corpus/cases.mjs`
- `tools/corpus/search.test.mjs`
- `tools/corpus/cases.test.mjs`
- `tools/corpus/cli.mjs`

## Interfaces

searchCorpus(store, filters) -> Candidate[]; createCase(store, { question, filters }) -> Case; selectFragments(store, caseId, fragmentRefs) -> Case; suggestThreads(store, caseId) -> ThreadSuggestion[].

## Acceptance criteria

1. [ ] Search uses real SQLite FTS5 and alias/filter joins; returns evidence fragments and distinguishes body from captions; unlinked/unresolved mentions remain discoverable.
2. [ ] Year queries select overlapping factual ranges rather than a whole article's minimum-to-maximum span; unknown dates/places remain visibly unknown.
3. [ ] Case pins article/extraction revisions and explicit fragment IDs; an updated source marks the selection stale rather than substituting a newer fragment.
4. [ ] Thread suggestions list episodes, reasons for inclusion and missing context; links/co-occurrence never become confirmed causal relations.
5. [ ] Selection triggers no second-level request; outputs label the 90–120 minute duration as a target and contain no fabricated coordinates or walking-time guarantee.
