# G19.03 — Durable corpus storage and recoverable backups

## Context

Read [the canonical specification](../../25_content_research.md), especially sections 5, 9, and [the implementation plan](../../superpowers/plans/2026-10-01-content-research.md). The source library/parser are external; repository collector files are implementation references, not a description of that live system.

## Goal

An independent local SQLite corpus database, transaction-safe registration, author-owned annotation storage and verified backup/restore.

## Scope and files

- `tools/corpus/store.mjs`
- `tools/corpus/store.test.mjs`
- `tools/corpus/backup.mjs`
- `tools/corpus/backup.test.mjs`
- `tools/corpus/cli.mjs`

## Interfaces

openCorpus(dbPath) -> CorpusStore; registerPackage(store, packageRecord); backupCorpus(store, { libraryRoot, outDir }); restoreCorpus({ backupDir, newLibraryRoot }); closeCorpus(store).

## Acceptance criteria

1. [ ] Registering the same package twice creates no duplicate article/revision/media associations; foreign-key validation rejects orphan fragments and links.
2. [ ] Entities and mentions are distinct; unresolved mentions and family/person separation are stored; confirmed identity decisions survive machine-result replacement.
3. [ ] Rebuilding FTS/cache or deleting machine results preserves Cases and author decisions; transactions close before external model requests.
4. [ ] Second write session reports busy; failed migration retains a recoverable pre-migration snapshot.
5. [ ] Backup captures a consistent DB plus required files and checksums; restore into a fresh directory reproduces annotations and image associations; corrupted/incomplete backup cannot overwrite a live library.

## Implementation steps

## Checks

store.test.mjs: duplicate_registration, orphan_fragment, unresolved_mention, decisions_survive_reindex, writer_lock; backup.test.mjs: restore_roundtrip, corrupt_checksum, failed_migration_keeps_backup.

## Proof

node --test tools/corpus/store.test.mjs tools/corpus/backup.test.mjs

Reverting the owned behavior must break the named behavior test. G19.08 is a human-input tracking task: its proof is actual validation and decisions, not a code-revert test.
