# G19.08 — Private pilot inputs and approved model policy

## Context

Read [the canonical specification](../../25_content_research.md), especially sections 1, 6, 9–10, and [the implementation plan](../../superpowers/plans/2026-10-01-content-research.md). The source library/parser are external; repository collector files are implementation references, not a description of that live system.

## Goal

A reproducible private pilot selection and an explicit provider/model/budget/data-transfer decision before any live LLM request.

## Scope and files

- `docs/agent-tasks/results/G19.08.md (source-free decision record)`
- `Private corpus-input/v1 and run-config/v1 files outside Git`

## Interfaces

Produces owner-approved run-config/v1 and private corpus-input/v1. G19.01's CLI validators consume these files; no secret value is copied into the issue or results.

## Acceptance criteria

1. [ ] Author supplies one sample, a varied 30-article selection and one research question through a private filesystem handoff; records/media have source rights metadata.
2. [ ] Author chooses execution host, provider/model, whether clean text may leave the host, budget currency/cap, per-request token/cost ceilings, tariff snapshot, timeout and retry limit; no API secret enters Git or issue comments.
3. [ ] validate-input and validate-run succeed on the actual private files; public results record policy identifiers and validation outcome without source content/paths.
4. [ ] If remote transfer is declined, a usable local provider is selected or the live pilot stays blocked; no cloud fallback is automatic.
5. [ ] Outputs state that model annotation is not historical verification and that pilot acceptance is required before a bulk level-1 run.

## Implementation steps

- [ ] Read dependencies, schemas and relevant existing helpers before writing a new helper.
- [ ] Add the behavioral checks listed below and run them to show the missing behavior. G19.08 instead validates the actual owner-supplied inputs.
- [ ] Implement only this task's files/interfaces; reuse earlier tasks' boundary checks and persistence paths.
- [ ] Run the task proof and repository checks from the plan; inspect the resulting diff for contract/privacy drift.
- [ ] Record actual outcomes, gaps and evidence in `docs/agent-tasks/results/G19.08.md`; commit the implementation with its behavioral checks.

## Checks

Human decision/input tracking task: actual validator output and source-free decision record; a synthetic transport is not proof that these resources exist.

## Proof

node tools/corpus/cli.mjs validate-input --manifest <private-manifest>; node tools/corpus/cli.mjs validate-run --config <private-run-config> (actual private paths supplied at execution).

Reverting the owned behavior must break the named behavior test. G19.08 is a human-input tracking task: its proof is actual validation and decisions, not a code-revert test.

## Dependencies

G19.01. GitHub issue links are in [the task index](README.md). G19.00 must be closed and the specification present in the runner's default-branch checkout before execution.

## Out of scope

Buying services, account setup or consent on the author's behalf, scraping, uploading actual articles to Git, claiming a simulated pilot is complete.
