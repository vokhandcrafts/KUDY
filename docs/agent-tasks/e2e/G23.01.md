# G23.01 — Deterministic synthetic catalog origin for E2E

Issue: [#659](https://github.com/vokhandcrafts/KUDY/issues/659).

## Epic

Epic: #658

## Goal

One command builds and serves a synthetic catalog that the app (through `EXPO_PUBLIC_CATALOG_ORIGIN`) and the E2E suites use, so every run sees the same city, guides, stops, Moments and collection. No real content and no external host.

## Scope

Fixture content under `fixtures/e2e/`; a build-and-serve script that reuses `tools/publish-catalog/publish-catalog.mjs` and `tools/serve-static.mjs`; an npm script (planned `e2e:origin`); `docs/development_setup.md`.

## Acceptance criteria

1. [ ] The fixture has at least: one city; one free guide with 3+ stops, one of them with a Moment; one guide with a free layer and a locked paid extension; one collection; be and en texts; short synthetic audio (reuse the playable test signal from #537, no real narration).
2. [ ] The catalog is produced by the production publishing path and validates against the bundle schema; no field is invented for the tests.
3. [ ] `npm run e2e:origin` builds and serves it on a configurable localhost port and prints the value for `EXPO_PUBLIC_CATALOG_ORIGIN`; reaching it from the emulator through `10.0.2.2` is documented.
4. [ ] Two builds produce byte-identical files (SHA-256 recorded), so suites can assert exact content.
5. [ ] A fault switch makes the origin return 404/500 or stall for named files; G23.05 and G23.06 need it.
6. [ ] A test fails when the fixture stops validating against the schema.

## Out of scope

Real guide content, public deployment, changes to the bundle contract.
