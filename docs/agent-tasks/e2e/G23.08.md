# G23.08 — Run the E2E suites in CI

Issue: [#666](https://github.com/vokhandcrafts/KUDY/issues/666).

## Epic

Epic: #658

## Goal

The web E2E suite runs on every PR to main, and the Android suites have a repeatable CI run, so regressions are caught without a manual retest.

## Acceptance criteria

1. [ ] A web E2E job builds `web` and runs `e2e:web` with a pinned Chromium on ubuntu; a failing case fails the job. Making it a required check needs explicit operator authorization recorded in an issue (the #493 pattern); without it the job stays optional and the result says so.
2. [ ] If the job becomes required, `tools/ci/check-required-checks.mjs` pins the new step.
3. [ ] An Android emulator workflow (`workflow_dispatch` plus nightly) builds the debug APK, starts the fixture origin and runs the smoke and walk suites; screenshots, dumps and logs are uploaded on failure.
4. [ ] All actions are pinned to full commit SHAs (V6 policy); no secrets are needed.
5. [ ] A deliberately broken case on a throwaway branch makes the job fail (run link recorded).

## Out of scope

Store builds, iOS CI, paid device farms.

## Dependencies

Blocked-by: #660, #662

## Proof

Links to one failing and one passing CI run in the result file.

## Execution boundaries

Current checkout only. Backlog only: creating this issue is not execution permission; `agent:ready`/`prio:*` are set by the operator. Follow AGENTS.md, `docs/agent-rules/implementation-rules.md`, `issue-workflow.md`, `code-review.md` and `showboat.md`. No secrets, production data or personal data in fixtures, logs or screenshots. No new npm dependency or third-party automation tool without a separate operator decision: the repo deliberately drives browsers through its own CDP driver (`web/test-browser/cdp-browser.mjs`, G21.03), and the Android driver follows the same zero-dependency principle. A suite that cannot run (no Chromium, no adb, no emulator) skips visibly with the reason; it never passes silently. Named test files and commands are planned deliverables, not existing tests. Result: `docs/agent-tasks/results/<ID>.md`.
