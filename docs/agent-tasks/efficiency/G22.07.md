# G22.07 — Project run markers without repeated full-stop scans

Reviewed implementation contract; LOW priority. Issue: [#612](https://github.com/vokhandcrafts/KUDY/issues/612). Epic: #604. Blocked-by: #605. Execution requires published prerequisites and an explicit assignment; see [README](README.md).

## Goal and scope

One map projection does work proportional to the valid route size and still shows canonical engine status.

- [Specification E7](../../specifications/efficiency/2026-10-04-bounded-work.md#e7-лінейны-пералік-карты--g2207-нізкі-прыярытэт).
- Modify `controllers/run/runMap.ts` and narrowly scoped derived lookup code in `core/engine/state.ts` only if sharing the canonical rules requires it; keep existing status consumers compatible.
- Test existing `controllers/run/runSurfaceController.test.ts`; add `controllers/run/runMap.test.ts` for direct production projection behavior. Touch the screen binding only if required by actual cache lifecycle.

## Interfaces and acceptance criteria

Preserve `runMapView` inputs and output marker meanings. A package geometry index or per-projection derived lookup is read-only and invalidated with its owning package/run facts. It never becomes an independently writable source of heard/access status.

1. [ ] Measure 10, 30, 100 and 200 stops; never use 1,000 stops as a valid product route.
2. [ ] Eliminate per-marker full geometry/state scans. An input-array access counter around the real function verifies linear growth, without asserting private source text or replacing status logic.
3. [ ] Marker statuses agree with real `stopStatus` for `locked`, `playing`, `played`, `available`, and `pending`; include both story tiers and inaccessible stories.
4. [ ] Missing geometry, changed package/version, progress updates and `Paused`/`Ended` states do not retain stale coordinates or status. Inputs are not mutated.
5. [ ] Projection-only progress/index data is ephemeral or bound to immutable package identity; no duplicate persistent state, map SDK or dependency is added.
