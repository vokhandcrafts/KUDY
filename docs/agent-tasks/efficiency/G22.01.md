# G22.01 — Close owned PGlite databases on success and failure

Reviewed implementation contract. Issue: [#606](https://github.com/vokhandcrafts/KUDY/issues/606). Epic: #604. Blocked-by: #605. Execution requires published prerequisites and an explicit assignment; see [README](README.md).

> For agentic workers: use `superpowers:executing-plans` after the prerequisites close and execution is authorized. Current checkout only.

## Goal

Every database created by the shared test factory has a defined lifetime, and the standard runner executes the heavy PostgreSQL suites without resource exhaustion.

## Sources and scope

- [Specification E1](../../specifications/efficiency/2026-10-04-bounded-work.md#e1-жыццёвы-цыкл-тэставых-баз--g2201).
- Modify `supabase/functions/_shared/test-db.ts`, its actual test/demo callers, and `supabase/tests/feedback/test-support.ts`.
- Test: existing grant, webhook, retention, RLS and feedback suites; add `supabase/functions/_shared/test-db-lifecycle.test.ts`.
- Runner configuration only if cleanup alone does not resolve the measured concurrent failure; preserve every existing suite and its discovery guard.

## Interfaces and acceptance criteria

The existing `freshMigratedDatabase(): Promise<PGlite>` remains the source of real migrated databases. Callers own successful returns; the factory owns cleanup before a failed return. Reuse Node test teardown and scoped `try/finally` rather than a global database registry.

1. [ ] Inventory every factory caller at current HEAD and register cleanup immediately after acquisition, including multiple databases in one test and demos.
2. [ ] A real database is closed after a successful test, a thrown assertion/body error and a forced migration error; the original error remains observable.
3. [ ] `test-db-lifecycle.test.ts` reaches the actual factory and real PGlite. The fault may be injected at the migration boundary; successful SQL/RLS behavior is not replaced with mocks.
4. [ ] Run the standard command after cleanup. If resource exhaustion remains, bound only the heavy execution as far as the runner allows, prove complete discovery, and report the before/after result.
5. [ ] Retention, webhook and feedback suites retain their real SQL, concurrency, authorization and transaction assertions. No added skips, ignored close failures or memory-limit-only workaround.
6. [ ] Distinguish unrelated Windows export failures in #591 from this result; never claim the whole suite passed when it did not.
