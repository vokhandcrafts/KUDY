# G22.05 — Read teaser media only for the selected place

Draft implementation plan. Publication and execution require the review described in [README](README.md).

> For agentic workers: use `superpowers:executing-plans` for the approved plan. Current checkout only.

## Goal and scope

Place-card media work depends on matching local stories instead of every story in the downloaded library; identical text files are parsed once per call.

- [Specification E5](../../specifications/efficiency/2026-10-04-bounded-work.md#e5-медыя-толькі-выбранага-месца--g2205).
- Modify `services/contentRepo/momentFacts.ts`, `controllers/place/placeDetailController.ts`, their tests and the reader binding in `controllers/createServices.ts`.
- Preserve manifest validation, local-library discovery, locale behavior and the G22.02 metadata probe.

## Interfaces and acceptance criteria

Extend `readMomentFacts(store, options)` with optional `options.placeId: string`; keep `Promise<MomentFacts>` and all fact fields. `PlaceDetailDeps.moments` becomes `(placeId: string) => Promise<MomentFacts>`, and the composition root passes the place before media resolution. Missing place scope retains the existing general-reader mode.

1. [ ] Validate a supplied place identifier at the boundary; invalid input has a named diagnostic and never becomes a storage path.
2. [ ] For five packages with twenty stories each and one match per package, return the five matching facts and perform no media/text work for the other places. Manifest reading needed to find matches remains allowed.
3. [ ] Read/parse each relevant `stops.json` at most once per package and locale per invocation, preserving locale preference and removing duplicate locale work without reordering preferences.
4. [ ] Cache only within the invocation: a changed package or UI language is visible at the next open. Different versions remain distinct.
5. [ ] Corrupt/missing packages preserve diagnostics and usable siblings. A late request cannot replace a newer place or update a closed binding.
6. [ ] General-reader callers and all actual root/controller consumers remain type-correct; no second content-read policy is created.
