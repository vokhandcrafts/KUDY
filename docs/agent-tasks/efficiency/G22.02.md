# G22.02 — Resolve teaser audio without loading the full media file

Draft implementation plan. Publication and execution require the review described in [README](README.md).

> For agentic workers: use `superpowers:executing-plans` for the approved plan. Current checkout only.

## Goal and scope

Opening a place card selects available teaser audio without reading its entire body, preserving safe path handling and locale fallback.

- [Specification E2](../../specifications/efficiency/2026-10-04-bounded-work.md#e2-наяўнасць-аўдыя-без-загрузкі-яго-цела--g2202).
- Modify `services/contentRepo/momentFacts.ts` and, when required to provide the documented metadata semantics, `services/contentRepo/nodeBundlesStore.ts`.
- Update relevant BundlesStore fixtures in tests and demos, preserving their parity with the real adapter.
- Test `services/contentRepo/momentFacts.test.ts`; add `services/contentRepo/nodeBundlesStore.test.ts` for actual filesystem behavior if no equivalent suite exists at execution time.

## Interfaces and acceptance criteria

Consume the existing `BundlesStore.statSize(rel: string): Promise<number | null>`. Do not call `PackageStore.exists` on a BundlesStore or invent authorization from presence. `readMomentFacts` keeps its current result shape and locale preference input.

1. [ ] Normal discovery does not load the complete `.m4a` body; instrument the real adapter to measure bytes/reads, rather than source-grep the implementation.
2. [ ] A missing file, directory, empty media, inaccessible file and metadata failure do not become a playable path. Preserve the next-locale fallback and existing safe-segment rejection.
3. [ ] Use native file/permission metadata where reliable. If checking readability needs an open handle, perform only a bounded probe and close it on every path; do not silently replace unreadable with present.
4. [ ] Cover real filesystem success, missing/empty/directory cases and platform-supported permission denial. Windows limitations are named, and supported Linux negatives remain required.
5. [ ] A file disappearing after discovery still follows the existing playback error path. No access grant, hash bypass or dependency on the device-composition task is introduced.
