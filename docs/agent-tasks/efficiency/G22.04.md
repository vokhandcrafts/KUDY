## Interfaces and acceptance criteria

GET `/records` gains validated `limit` and `cursor` parameters alongside existing filters. Default limit is 50, accepted range 1–100. The cursor carries the last ordering key `collected_at` (including null), `url`, and `id`, plus the normalized city/status filter values. Reject a cursor whose filter values differ from the request; changing a filter starts a new traversal. The cursor does not authorize access.

1. [ ] Schema opening idempotently creates `links(raw_record_id)` for new and existing stores. Do not duplicate the media uniqueness index.
2. [ ] A real HTTP request over 1,000 records returns only the requested/default page and a next-page link; count actual rendered rows and selected SQL rows.
3. [ ] Cursor pages preserve `collected_at DESC, url, id`, filters, null dates, tied dates and cross-campaign repeated URLs. New insertion between requests does not repeat or skip older traversal rows.
4. [ ] Zero, negative, fractional, oversized and nonnumeric limits, malformed cursors and mismatched filter cursors return 400 with a reason before unsafe SQL execution.
5. [ ] All external values are validated and parameter-bound; rendered strings remain escaped. Existing listening/confinement settings do not widen.
6. [ ] SQLite query-plan evidence shows indexed link lookup; record cards preserve every link/photo/source detail.
