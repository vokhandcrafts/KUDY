## Acceptance

1. [ ] The ADR fixes, each with a number, unit and reason: proximity threshold, accepted accuracy, freshness, dwell near the guide, foreground cooldown between app openings; it states that the audio trigger radius is **not** reused as the hint radius (15 R07).
2. [ ] Lifecycle by context: idle (foreground city/Guides/Nearby surface only, subscription dropped on close or background), Active (shared accepted-fix stream, no geofence change), Paused (hints off, no location resume); no hint during audio, a call, a commercial dialog or manual automation block; after audio a fresh-fix re-check, no queue.
3. [ ] Repeat protection: one real display per `guide_id` per walk session; one per foreground city session without a session; grouping several guides into one card with per-`guide_id` shown/dismissed; carry-over of shown/dismissed IDs into the session at Start; survival across restart of that session — each mapped to `guide_hint_state` / `guide_hint_last` fields of ADR G01.03 §3.9 by their existing names.
4. [ ] Events `guide_nearby_shown/opened/dismissed` use the names and payload limits of the accepted G01.05 table verbatim, with `suggestion_id`, the displayed public `guide_id` list, `context` and `session_id` only when a session exists; no coordinates, distances, tracks or URLs.
5. [ ] The values schema rejects each invalid example with a named diagnostic (negative values, cooldown missing, accuracy above the threshold it gates, unknown key); the test fails if any rule is removed.
6. [ ] Open points are listed as founder decisions, not decided silently.
