# G25.06 — Specify branded components and their states

## Epic

Epic: #346

## Goal

Provide reusable component designs that keep brand expression consistent in real application states.

## Shared design source

Required: `docs/design/brand/atlas-brief.md` (accepted v1, 2026-10-08), `docs/design/brand/decisions.md`, and `docs/design/visual-language.md`. These new files become available in the default runner checkout only after #699 merges; do not start from unavailable links.

Record the brief revision/git commit and a requirement → decision → evidence → open-question table in the result. Propose new values/names in the task result; follow the decision-register process before treating them as approved. Product/Run/ADR contracts remain authoritative for behavior. See `docs/agent-tasks/brand-design/README.md` for the shared order and source-of-truth policy.

## Acceptance criteria

1. [ ] Map the existing canon/components to a specimen sheet: buttons/chips, guide/story cards, Moment and R07 cards, map markers, notices, dialogs, download/progress rows and Run panel. Preserve the distinct behavioral roles; do not invent a fourth card type as a local styling shortcut.
2. [ ] Show loading, empty, error/retry, offline, disabled, locked, paused and completed states where applicable, with exact copy references, token references and accessibility semantics.
3. [ ] Specify phone/web layouts, large-text wrapping, focus/keyboard, screen-reader names, contrast and reduced-motion equivalents. Dragon/texture decoration must not obscure reading, controls or map states.
4. [ ] Deliver HTML/CSS specimens plus SVG/PNG exports, state matrix and a mapping to current component names. Record implementation gaps as handoff items, not fixes in this design task.

## Out of scope

Production component changes, new audio/access contracts, implementation of deferred Nearby or collection functionality.
