# G25.02 — Define menu names and the interface glossary

## Epic

Epic: #346

## Goal

Give every existing user-facing destination and recurring action a consistent name that fits KUDY and is understandable without the dragon.

## Shared design source

Required: `docs/design/brand/atlas-brief.md` (accepted v1, 2026-10-08), `docs/design/brand/decisions.md`, and `docs/design/visual-language.md`. These new files become available in the default runner checkout only after #699 merges; do not start from unavailable links.

See `docs/agent-tasks/brand-design/README.md` for the shared order and source-of-truth policy.

## Acceptance criteria

1. [ ] Inventory existing Explore, My KUDY, Guides, Nearby/Walk, guide preview, downloads, settings and feedback strings against R01 and screens-and-transitions. Map current label, proposed Belarusian label, purpose, existing route/key and decision; preserve the two-tab navigation contract.
2. [ ] Compare 2–3 naming sets in small navigation mockups and recommend one. Cover menu items, buttons, empty/error/locked states, collection wording and a translatable tagline; separate functional UI copy from dragon speech.
3. [ ] Provide a glossary and draft equivalents for all R11 interface locales (be/en/uk/de/es/fr/cs/sv), with lengths, ambiguity notes and explicit native-review status. Keep content/audio availability wording separate from UI language.
4. [ ] Check long labels and large text on phone/web samples. New destinations or routing changes require a separate decision; proposals are not new runtime routes.

## Out of scope

Editing generated message catalogs, route IDs, adding tabs, narrowing locale support or claiming native-language review without evidence.
