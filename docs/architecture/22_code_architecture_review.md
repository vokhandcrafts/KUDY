## 2. Знаходкі

### AR-1 [HIGH] — няма `.gitattributes`: CRLF-checkout ламае праверку цэласнасці G00.02 — #78

`spikes/G00.02-offline-map` — праверка хэшаў падае на свежым Windows-checkout.

**Чым небяспечна:** `source/lock.json` захоўвае sha256 па LF-байтах, а git з `core.autocrlf=true` аддае файлы CRLF → любая зборка/праверка пакета на асноўнай хост-машыне падае з `integrity mismatch: index.html` (`lib/package.mjs:16`). Спайк не праходзіць уласную цэласнасць, а праз яго ідзе прэ-праверка прыладавых клетак G00.02.b; той самы клас рызыкі тычыцца будучага bundler'а з праверанымі хэшамі (G02.03).

**Доказ (2026-09-15):** worktree sha256 `d6d21bf7…` (CRLF) ≠ blob `7952b440…` (LF) = значэнне ў `lock.json`; `node scripts/prepare-data.mjs` → `Error: integrity mismatch: index.html`. Блокер ужо быў апісаны ў [`evidence/G00.02.b-device-evidence.md`](../../spikes/G00.02-offline-map/evidence/G00.02.b-device-evidence.md) і [`results/G00.02.b.md`](../agent-tasks/results/G00.02.b.md) — і дагэтуль не вырашаны.

**Выпраўленне:** `.gitattributes` без канверсіі EOL для хэшаваных фікстур (мінімум `spikes/G00.02-offline-map/source/** -text` або `eol=lf`) + рэнармалізацыя дрэва. Рашэнне агульнай палітыкі для production-бандлаў — за G02.03.

### AR-2 [HIGH] — `serve.mjs:15`: праверка шляху з жорсткай `/` аддае 404 на ўсё ў Windows — #79

`spikes/G00.02-offline-map/scripts/serve.mjs:15` — `file.startsWith(`${root}/`)`.

**Чым небяспечна:** адзіны выканаўчы транспарт спайку (loopback-сервер, задакументаваны ў пратаколе .b як «спайк .a — браўзерны дыягностык: Node-сервер на loopback аддае гатовы `runtime/active/`») мёртвы на Windows: `path.join`/`normalize` даюць `\`, таму праверка дае 404 на кожны запыт — у тым ліку легітымныя.

**Доказ (2026-09-15, LF-нармалізаваная часовая копія, бо без гэтага AR-1 блакуе падрыхтоўку):** сервер стартуе, `GET /` → 404, `GET /style.json` → 404; traversal таксама 404, але выпадкова — 404-іць усё.

**Выпраўленне:** `root + sep` — карэктны ідыём ужо ёсць у рэпазітары: `spikes/G00.03-sandbox-grant/server/grant-server.mjs:246` (`filePath.startsWith(root + sep)`). Пасля фіксу пераверыць: легітымныя файлы → 200, traversal (`/../`, `%2e%2e`) → 404. Выконваецца пасля AR-1.

### AR-3 [MEDIUM] — канфлікт кантрактаў: разрыў злучэння пры перавышэнні цела супраць закрытага спісу кодаў — #80

`spikes/G00.03-sandbox-grant/server/grant-server.mjs:69–76` — `readJsonBody` выклікае `req.destroy()` на першым чанку па-над `MAX_BODY_BYTES`.

**Чым небяспечна:** загалоўак таго ж файла (радкі 15–22) і `09` §5.1 задаюць **закрыты спіс HTTP-кодаў**, дзе памер/форма — `400 invalid_request`; адпаведны шлях у кодзе ёсць, але недасяжны — сокет зачыняецца да адказу. Кліент не адрознівае «адхілена» ад «сервер недаступны». Пасля PR #53 гэтыя паводзіны наўмысна замацаваныя тэстам (`tests/negative-grant.test.mjs:87–93`, `dropped.status === 0`), таму гэта ўжо не прапушчаны выпадак, а нявырашанае процірэчча двух кананічных сцвярджэнняў.

**Доказ (2026-09-15):** `POST /v1/grant` з целам ~80 КіБ → `CONNECTION ERROR: UND_ERR_SOCKET`, адказу няма.

**Выпраўленне (рэкамендаванае):** аддаць `400 invalid_request`, потым зачыніць злучэнне, і абнавіць тэст `.b`; альбо альтэрнатыўна — дапоўніць задакументаваны кантракт (загаловак `grant-server.mjs`, пры патрэбе `09` §5.1) паводзінамі «разрыў без адказу». Рашэнне напрамку — за ўладальнікам G00.03.

### AR-4 [LOW] — `run-model.mjs:1–13`: падвоены загаловачны каментар — #81

Радкі 1–6 паўтараюцца даслоўна як 8–13 (другая копія працягваецца нататкай пра ідэнтычнасць сесіі). jscpd каментары не лічыць, таму gate зялёны. Зліць у адзін загаловак; узоры мутацый, якія правярае `check-regressions.mjs`, павінны працягваць супадаць роўна адзін раз.

### AR-5 [MEDIUM, архітэктура] — правілы прыёму пазіцыі і вытрымкі дублікуюцца з рознымі канстантамі і без адзінага ўладальніка — #82

`docs/run-model/run-model.mjs:92–101` (`located()`: свежасць 30 000 мс, accuracy ≤ radius, чарга ≤ 2×radius) супраць `spikes/G00.01-location-audio/src/session.mjs:1–3, 79–103` (`MAX_ACCURACY_M = 40`, `MAX_FIX_AGE_MS = 15_000`, `DWELL_MS = 6_000`, адлегласць ≤ radius).

**Чым небяспечна:** гэта адно і тое ж пытанне («якая пазіцыя дае права на аўтазапуск»), прычым частковае разыходжанне апраўданае слаямі (мадэль мадэлюе `DwellCompleted` як ужо пацверджаны ўвод), а частковае — проста розныя лікі без заяўленага ўладальніка. [`README.md` мадэлі](../run-model/README.md) сам папярэджвае: «Не падтрымліваць дзве незалежныя рэалізацыі правілаў бясконца». Трэцяя копія ў будучым engine — найдаражэйшы варыянт, якраз тое, што [`17_development_readiness.md`](../17_development_readiness.md) называе галоўнай рызыкай паралельнай працы агентаў.

**Кансалідацыя:** назваць уладальніка ў мапе класаў — па [18 §2](18_component_blueprint.md) гэта `core/pipeline` (адкід дрэннай пазіцыі, dwell) + канфіг engine; канстанты жывуць у адным месцы, а мадэль і спайкі пазначаюць свае значэнні як лакальныя для свайго ўзроўню, не як правілы дадатку. Гэта ўваходзіць у заданне AR-5 (#82): стварыць `19_class_and_module_map.md` па гатовым brief-у [`docs/agent-tasks/architecture-class-map.md`](../agent-tasks/architecture-class-map.md).

### AR-6 [MEDIUM] — `npm test` спайку G00.03 не запускае наборы `tests/` ад G00.03.b — #83

`spikes/G00.03-sandbox-grant/package.json` — `"test": "node --test --test-reporter=spec test/*.test.mjs"`: негатыўны і мутацыйны наборы `tests/` (`negative-grant`, `guard-mutations`, `live-remote`) ідуць толькі праз асобна дакументаваную каманду ([`results/G00.03.b.md:47`](../agent-tasks/results/G00.03.b.md)). `npm test` зялёны, пакуль палова пакрыцця не выконвалася. Live-файл самаскіпаецца без `G00_03_B_LIVE_URL` (`tests/harness.mjs:31`), таму падключыць каталог да скрыпта бяспечна.

## 3. Што праверана і чыста

- **jscpd:** 0 клонаў на ўсім дрэве (24 файлы, 3 075 радкоў). Задубленні існуюць на ўзроўні каментароў (AR-4) і сэмантыкі канстант (AR-5) — па-за магчымасцямі gate, адсюль іх фіксацыя тут.
- **Слаі спайкаў адпавядаюць [18](18_component_blueprint.md):** чыстыя часткі без сеткі/OS (`run-model` — рэдьюсар без I/O; `session.mjs` — без `fetch`); усе OS/сеткавыя выклікі — на краях (`App.tsx`, `serve.mjs` — толькі loopback, `grant-server.mjs` — серверная зона). Парушэнняў забарон [09 §17](09_technical_architecture.md) не знойдзена: няма LLM у рантайме, DRM, anti-cheat, уласных натыўных модуляў; каардынаты ў G00.01 толькі ў памяці (`App.tsx:99`), серверныя payload'ы — за згодай (`session.mjs:131–136`).
- **Бяспечны бок G00.03 падмацаваны тэстамі:** fail-closed пры недаступнасці провайдэра (503 + Retry-After), `environment_mismatch` sandbox→production, `timingSafeEqual` (`signed-url.mjs:24`, `device-auth.mjs:37`), членства ў маніфесте як defense-in-depth (`grant-server.mjs:239–248`), рэдакцыя `/private/` маршрутаў з логаў (`grant-server.mjs:124–126`) — усе пацверджаныя `test/grant.test.mjs` і `tests/`.
- **Мадэль Run:** мутацыйны гарнізм `check-regressions.mjs` адхіляе 16 рэгрэсій; перабор усіх паслядоўнасцяў глыбінёй 4 — 7 380 пераходаў (`run-model.test.mjs:495–521`); кантракты ADR G01.01/G01.03 выкананы ў кодзе мадэлі.

## 4. Архітэктурныя рэкамендацыі: слаі і кансалідацыя

Пытанне «стварыць некалькі слаёў класаў для мацнейшай архітэктуры» ужо мае адказ у [18 §1–2](18_component_blueprint.md): UI (`app/`) → кантролеры → чыстыя `core/engine` + `core/pipeline` → services (`audio`, `location`, `download`, `contentRepo`, `entitlement`, `db`, `eventLog`) → SQLite/файлы, з давернымі зонамі між імі. Новая лесвіца не патрэбна; трэба перавесці яе ў мапу класаў і модуляў `19_class_and_module_map.md` (AR-5, #82 — brief ужо напісаны). Канрэтныя правілы:

1. **Класы — толькі для рэсурсаў з уласным станам і жыццёвым цыклам** (адзіны фізічны плэер, адзіная GPS-падпіска, download staging/activation, SQLite-транзакцыі). Чыстыя пераходы стану застаюцца функцыямі — узор ужо ёсць: `run-model.mjs` `step(previous, event, now) → state + commands`.
2. **Без base-service іерархій, generic event bus і DI-фрэймворкаў** без дэманстрацыйнай патрэбы — прамое патрабаванне brief-у 19; тоесна духу забарон `09` §17 («дадатковыя станы без патрэбы»).
3. **Спайкі не зліваць і не «павышаць» да архітэктуры.** Яны наўмысна ізаляваныя, аднаразовыя доказы платформавых паводзін з уласнымі тэстамі; зліццё стварыла б злучнасць там, дзе задуме яе няма. Кансалідацыя дублікатаў адбываецца ў момант напісання engine: адна мапа (19), адзін уладальнік канстант (AR-5), адзін набор кантрактных імёнаў з ADR G01.01/G01.03.
4. **Адзін уладальнік кожнага бізнес-факту** ([18 §3](18_component_blueprint.md)): прагрэс, версія сесіі, згода, entitlement, shown/dismissed — без незалежна зменных копій. Гэта праверана ў мадэлі і павінна захавацца ў engine: `heard`/`autoFired` мутуюцца толькі ў рэдьюсары.
5. **Не трымаць дзве рэалізацыі правілаў назаўсёды:** пасля пераносу сцэнараў у сапраўдны engine мадэль замарожваецца як гістарычны прыклад (README мадэлі, «Як перанесці ў дадатак»).
