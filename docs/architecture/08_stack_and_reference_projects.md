## Частка 1. Ці ёсць гатовы праект, які можна ўзяць за аснову

### 1.1 `tourforge/baseline` — **не браць за аснову. Юрыдычны блакер**

Праверана:

| Параметр | Значэнне |
|---|---|
| Мова | Dart / Flutter |
| Зоркі / форкі | 7 / 7 |
| Апошні коміт | 2026-02-11 |
| **LICENSE** | **адсутнічае (`license: null`, файла LICENSE у root няма)** |

README запрашае «fork this repository», але **запрашэнне ў README — не ліцэнзія**. Без файла ліцэнзіі код па змоўчанні пад поўным аўтарскім правам: юрыдычна яго нельга ні распаўсюджваць, ні выкарыстоўваць у камерцыйным закрытым прадукце. Для прадукту, які будзе прадавацца ў App Store, гэта дыскваліфікуе праект як аснову — незалежна ад тэхнічнай якасці.

Дадатковыя мінусы: залежнасць ад TomTom API key для satellite-фічы; свой уласны фармат кантэнту, зроблены пад TourForge CMS (не пад нашу мадэль Place/Story/Route/Recommendation); маштаб праекта (7 зорак, 3 адкрытыя issue) не дае ні супольнасці, ні гарантыі падтрымкі.

**Дзеянне:** можна вывучаць па GitHub як прыклад структуры Flutter-праекта. Калі Flutter усё ж будзе выбраны — варта напісаць аўтарам і папрасіць дадаць ліцэнзію (MIT/Apache-2.0); гэта бясплатны запрос, які або адкрывае варыянт, або канчаткова яго зачыняе. **Да атрымання ліцэнзіі — ні радка кода адтуль.**

### 1.2 `zipos/tramio` — **лепшы архітэктурны рэферэнс, але не форк**

Праверана:

| Параметр | Значэнне |
|---|---|
| Мова | TypeScript (Expo bare / React Native, монарэпа) |
| Зоркі | 1 |
| Апошні коміт | 2026-08-03 (актыўны) |
| **LICENSE** | **AGPL-3.0-or-later**, у README прама: «Proprietary / closed-source products cannot incorporate this codebase» |
| Самаапісанне | «Spec-driven portfolio MVP», частка функцый — заглушкі |

Гэта GPS-аўдыёгід на гарадскім транспарце. Структура монарэпы амаль адзін-у-адзін адпавядае таму, што патрэбна KUDY:

`packages/engine` (чысты reducer тур-логікі: geofence pipeline, priority, dwell, focus loss/regain, audio commands), `packages/storage` (загрузка пакетаў, цэласнасць, SQLite, LRU-бюджэт), `packages/clients` (catalog + entitlement, pin публічнага ключа), `packages/crypto-service` (Ed25519-падпіс кантэнт-пакетаў), `packages/map` (offline MapLibre), `packages/authoring` (схема кантэнт-бандла + CLI-валідатар), `packages/simulator` (дэтэрмінаваны прайгравальнік GPS-трэкаў), `packages/capability` (матрыца магчымасцей OS).

Тры з гэтых рашэнняў незалежна супадаюць з заўвагамі ў `05_architecture_review.md`: чысты тэставальны engine без RN, падпісаныя кантэнт-бандлы замест публічных URL (п. 5), сімулятар GPS замест фізічных прагулак (п. 13). Гэта добры сігнал: архітэктура правільная, а не проста прыгожая.

Абмежаванні: AGPL (вірусная — форк закрытага прадукту немагчымы); адзін аўтар, 1 зорка, няма супольнасці; сам аўтар пералічвае, што не дароблена (dead reckoning, deviation, standby scheduling — заглушкі; overlays карты не дарэндараны; уласныя turbo-модулі не падключаны).

**Дзеянне:** выкарыстоўваць як **архітэктурны рэферэнс** — ідэі і структура не абараняюцца аўтарскім правам, канкрэтны код абараняецца. Дадатковая опцыя, вартая аднаго ліста: аўтар прама прапануе камерцыйнае ліцэнзаванне («For commercial closed-source licensing, contact the copyright holder»). Гэта **адзіны рэальны шлях зэканоміць месяцы**: адзін фізічны аўтар, партфоліо-праект — цана перамоваў, хутчэй за ўсё, невялікая. Рызыка — залежнасць ад аднаго чалавека і кода, які сам аўтар назваў незакончаным; таму гэта опцыя «паспрабаваць і паглядзець умовы», а не план.

### 1.3 `Terrastories/terrastories` — рэферэнс мадэлі кантэнту, не стэку

Праверана: Ruby (Rails + React web), **MIT**, 375 зорак, актыўны (2025-11-25), 187 МБ.

Гэта не мабільны дадатак, а вэб-платформа geostorytelling з CMS, разлічаная на офлайн-разгортванне ў полі. Каштоўнасць для нас — **як мадэляваць «гісторыя ў месцы»** (story ↔ place ↔ media ↔ speaker), што прама пацвярджае наш выбар Place/Story/Route/Recommendation замест плоскага `Tour → Stop`. Ліцэнзія MIT дазваляе браць і код, але браць з Rails-вэб-праекта ў мабільны дадатак няма чаго.

**Дзеянне:** прачытаць іх схему БД перад фіналізацыяй нашай. Больш нічога.

### 1.4 Kuratour — не адкрыты код, але найкарысны blueprint

Праверана: тэхнічны разбор на блогу Expo (guest post, 2026-01-06), сам прадукт закрыты, kuratour.com, пераможца Innovation Award 2025 (Adventure Tourism Awards, Аўстралія).

Стэк: Expo (new architecture), `expo-location`, `expo-file-system` + `expo-sqlite`, `expo-audio`, `expo-video`, `expo-apple-authentication`, `expo-application`, `@rnmapbox/maps`.

Дзве канкрэтныя рэчы, якія варта скапіяваць як практыку (не код):

1. **Версіяванне схемы SQLite з міграцыямі** з першага дня — інакш першае ж абнаўленне ламае офлайн-дадзеныя існуючых карыстальнікаў.
2. **Content Validation Bridge**: пасля абнаўлення дадатку на iOS файлы ў `Documents` могуць «асіратэць» пры зруху ўнутраных шляхоў, хоць SQLite выжывае. Kuratour пры змене версіі дадатку праганяе праверку «ці ўсе файлы на месцы» і пры недахопе перазапампоўвае. Без гэтага карыстальнік адкрывае «загружаны» маршрут і не чуе аўдыё — рэйтынг 1 зорка ў платным дадатку.

Бізнес-заўвага на бок: Kuratour жыве не з продажу турыстам, а з **white-label для тур-аператараў**. Гэта і канкурэнт, і доказ, што мадэль працуе.

### 1.5 Што ёсць яшчэ (пошук па GitHub)

Ніша практычна пустая. Пошук па `audio tour`, `geofence audio guide`, `audio guide react-native` дае: `CMP-Studio/TheWarholOutLoud` (MIT, 89 зорак, **мёртвы з 2018**, музейны аўдыёгід без GPS-маршрутаў) і `jtschoonhoven/tour` (MIT, 2 зоркі, эксперымент). Ніводнага пермісіўнага, падтрымліванага, прадакшн-якасці GPS-аўдыёгіда.

### Выснова часткі 1

**Форкаць няма чаго.** Пермісіўнага і жывога праекта ў гэтай нішы не існуе: адзін кандыдат без ліцэнзіі, другі пад AGPL, трэці — вэб на Rails. Правільны план — **свой тонкі дадатак на managed-платформе + запазычаныя архітэктурныя ідэі**, а не пошук базы для перафарбоўкі. Гэта не дрэнная навіна: 70% працы тут — не код, а кантэнт (сцэнары, галасы, права на фота), і форк яго не зэканоміў бы.

## Частка 2. Flutter ці Expo / React Native

Крытэрый выбару — не «якая мова прыгажэйшая», а тры рэчы: хто будзе пісаць, наколькі платформа закрывае складаныя часткі (GPS у фоне, аўдыё ў фоне, offline), і як хутка можна выправіць памылку без чакання рэвю ў сторы.

| Крытэрый | Expo / React Native | Flutter |
|---|---|---|
| Пул распрацоўшчыкаў / кошт найму | значна большы (TS/JS) | меншы, асабліва пад мабільны GPS/аўдыё |
| Пакрыццё складаных частак «з каробкі» | `expo-location` (фонавая лакацыя **і** geofencing), `expo-audio`, `expo-video`, `expo-sqlite`, `expo-file-system`, `expo-notifications` — усё first-party | ёсць пакеты, але часцей community, з рознай якасцю |
| Зборка iOS без Mac | **EAS Build** — так | звычайна патрэбны Mac/CI-настройка |
| Выпраўленне багу без рэвю ў сторы | **EAS Update** (OTA для JS-часткі) — гадзіны | толькі новы рэліз, 1–3 дні рэвю |
| Прадакшн-доказ у нашай нішы | Kuratour (той самы сцэнар, шматмоўны, offline) | TourForge (7 зорак, без ліцэнзіі) |
| Сыравы UI-перформанс | трохі слабейшы | трохі лепшы |

Апошні радок — адзіная перавага Flutter, і яна для нас нязначная: наш вузкі бок не спіскі і анімацыі, а GPS, фонавае аўдыё і загрузкі. Затое **EAS Update** мае прамы сэнс для сола-праекта: памылка ў платным маршруце, якую відаць у турыста ў Гданьску сёння, выпраўляецца за гадзіны замест 1–3 дзён рэвю. Дат рэлізу ў нас няма (`04`), але хуткасць рэакцыі на баг — усё роўна грошы і рэйтынг.

**Рэкамендацыя: Expo / React Native** (managed workflow з config plugins; `prebuild` толькі калі спатрэбіцца нешта нативнае).

## Частка 3. Рэкамендаваны стэк

| Слой | Выбар | Прычына / альтэрнатыва |
|---|---|---|
| Кліент | Expo SDK (new architecture) + Expo Router | гл. частку 2 |
| Карта + offline-тайлы | **MapLibre RN — кандыдат**; спосаб офлайн-дастаўкі выбіраецца ў M0b (`09`, разд. 6.3.1) | Код MapLibre — MIT. **Але:** дадзеныя OSM — **ODbL з абавязковай атрыбуцыяй**, а публічныя тайл-серверы OSM забараняюць масавае офлайн-спампоўванне, таму тайлы генеруем і хостім самі (Protomaps/OpenMapTiles з экстракта). Правільна: **няма платы за карыстальніка**, але ёсць ліцэнзійныя абавязкі і кошт хостынгу. Mapbox — платны фолбэк з гатовым offline. Google Maps SDK — выключаны: забараняе трымаць тайлы офлайн |
| GPS | `expo-location`: `startGeofencingAsync` для кропак + `watchPositionAsync` толькі ў актыўным рэжыме | акно геафенсаў з-за ліміту iOS у 20 рэгіёнаў (`05`, п. 7) |
| Аўдыё / відэа | `expo-audio`, `expo-video` + `UIBackgroundModes: audio` | фонавае прайграванне — абавязковае (`05`, п. 9) |
| Лакальныя дадзеныя | `expo-sqlite` **з версіяванай схемай і міграцыямі** | практыка Kuratour |
| Файлы / загрузкі | `expo-file-system` + праверка цэласнасці пры змене версіі дадатку | Content Validation Bridge (п. 1.4) |
| Пакупкі / entitlement | **RevenueCat** | не пісаць receipt-валідацыю самому; сервер правярае entitlement прамым REST-запросам пры выдачы гранта. Webhook апцыянальны і не стаіць на крытычным шляху |
| Бэкенд | **Supabase** (Postgres + Storage + Edge Functions) | адзін сэрвіс замест трох. Postgres трымае **не кантэнт**, а `devices` / `entitlements` / `event_log`; Storage — медыя і бандлы; Edge Function — выдача падпісаных URL |
| Дастаўка кантэнту | версіяваныя бандлы `route × version × locale × tier` у Storage/CDN | натуральны offline: бандл = тое, што качаецца (`05`, п. 1); той самы бандл чытае і вэб-версія (`04`) |
| Абарона платнага медыя | Edge Function правярае entitlement праз RevenueCat → выдае **падпісаны URL з кароткім TTL** | інакш платнае аўдыё — публічны mp3 (`05`, п. 5) |
| Аўтарынг кантэнту | **уласны пайплайн `07_content_pipeline.md`** (SQLite + CLI на ноўтбуку), не CMS | Кантэнт вырабляецца праз «крыніцы → claims → сцэнар → рэвю», а не набіраецца ў адмінцы. CMS (Directus/Sanity) тут не дадае нічога, а дадае сэрвіс, які трэба трымаць жывым. Разгледжана і адхілена |
| Remote config | табліца параметраў у Postgres, кэш на кліенце | `trigger_radius`, `moment_cooldown` мяняюцца без рэлізу (`05`, п. 12) |
| Аналітыка | адзін інструмент + фіксаваная схема падзей, без сырых каардынат | (`05`, п. 10, 11) |
| Crash reporting | з першага білда | (`05`, п. 17) |
| Тэст GPS | прайгравальнік GPX-трэкаў + dev-панэль «перайсці да кропкі N» | ідэя з `packages/simulator` Tramio (`05`, п. 13) |

Пастаянныя выдаткі, якія трэба ўлічыць адразу: Apple Developer $99/год, Google Play $25 адзін раз, Expo EAS (ад бясплатнага да платнага пры актыўнай зборцы), Supabase (бясплатны тыр → ~$25/мес), RevenueCat (бясплатна да пэўнага абароту). Карта пры MapLibre — толькі хостынг тайлаў, без per-user платы.

## Частка 4. Што я б адкінуў з першаснага рэсёрчу

- **«Форкнуць TourForge»** — юрыдычна небяспечна (няма ліцэнзіі), і гэта не дэталь, а стоп-фактар.
- **«Форкнуць Tramio»** — AGPL, аўтар прама забараняе для закрытых прадуктаў.
- **«Mapbox бо так у Kuratour»** — для аднаго горада свае тайлы дзешавей па плаце за карыстальніка. Папраўка да першай версіі гэтага файла: «без ліцэнзійных лімітаў» было **няправільна** — ODbL-атрыбуцыя абавязковая, а тайлы нельга цягнуць з публічных серверов OSM. Mapbox застаецца легітымным фолбэкам да замеру ў M0b.
- **Мадэль `City → Route → RoutePoint → Audio → Image` для MVP** (як прапаноўвалася) — амаль правільна, але **прапушчана мова**. У KUDY мовы — множнік усяго кантэнту, і `locale` мусіць быць у схеме з першага дня (`05`, п. 3).

## Частка 5. Статус рашэнняў

1. **Expo / React Native** — прынята **да M0**: фонавыя GPS і аўдыё мусяць прайсці матрыцу адмоў на рэальных прыладах (`09_technical_architecture.md`, разд. 0, 9.1, 13).
2. **Ці пісаць ліст аўтару Tramio** пра камерцыйную ліцэнзію (і аўтарам TourForge — пра дадаванне ліцэнзіі) — **адкрыта**. Кошт — два лісты; патэнцыял — месяцы. Пры адмове нічога не мяняецца: архітэктура ў `09` не залежыць ад іх коду.
3. **Мовы на старце** — **вырашана: `be` + `en`** (`04`, `09` разд. 8).

Поўная архітэктура, што выйшла з гэтага параўнання: **`09_technical_architecture.md`**. Дэтальныя разборы рэферэнсаў: `refs/`.
