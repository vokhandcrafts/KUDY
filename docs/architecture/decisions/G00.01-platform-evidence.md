## 1. Пытанне

Якіх платформавых абяцанняў MVP (GPS-аўтагук, фон, lock, перапыненні, спыненне OS) тычыцца G00.01, што з іх праверана фактычна, а што — толькі задекларавана кантрактам, і што G00.04/G05 маюць права лічыць уваходам.

## 2. Дзе жыве аўтатрыгер — па кантракце

Абагульненне прынятых правілаў (не новае правіла): аўтатрыгер існуе **толькі ў адным месцы** — актыўная сесія абранага гіда пасля яўнага Start, і ўсе наступныя ўмовы трымаюцца адначасова ([ADR G01.01 §4.8](G01.01-narration-progress.md), R02, R04, R07):

1. сесія `Active`, запушчаная яўным Start поўнага праверанага пакету; пакупка сама не значыць ready (бацькоўскі [brief G00.01](../../agent-tasks/G00.01.md), [ADR §4.4](G01.01-narration-progress.md));
2. аўтаматыка не прыпыненая (`autoplay_suspended = false`) і нічога не гучыць (`playing = null`);
3. кропка яшчэ не адпрацавала: `stop_id ∉ auto_fired` і асноўны наратыў `∉ heard`;
4. фікс свежы: узрост ≤ 30 с, `accuracy ≤ radius` (кананічнае значэнне — ADR §4.8 умова 5);
5. dwell 6 с у радыусе кропкі;
6. гісторыя даступная: `story_accessible(primary_story_id)`.

І таксама — **дзе аўтатрыгера няма ніколі**: да Start; ад Moment (R04); ад падказкі R07 (R07 не запускае аўдыё і не аднаўляе геалакацыю); са састарэлага або недакладнага фіксу (GPS-gap); з locked кропкі да AccessReady (paid-only, ADR §4.4); ад чужога або спозненага `AudioFinished` (ADR §4.11); паўторна на тую ж кропку ў тую ж сесію (`auto_fired` манатонны); дадатковы extended-наратыў ніколі не гучыць сам (толькі ручны «Яшчэ пра гэтае месца»). Аўтазапускаецца роўна адзін файл — асноўны наратыў кропкі; плэер і GPS-уласнік адныя ([18 §2](../18_component_blueprint.md)).

## 3. Дзе жыве ручны шлях — па кантракце

Ручны fallback — другая абавязковая палова кожнага сцэнара матрыцы (R02, R03, бацькоўская матрыца праверак):

- для `story_accessible` кантэнту — ручны Play незалежна ад адлегласці і радыуса, у тым ліку без дазволу на пазіцыю (тады выбар — карта/спіс); paid-only locked да AccessReady — ні ручны, ні аўта Play ([ADR §4.4](G01.01-narration-progress.md));
- адмова або адкліканне дазволаў → чэсны стан дазволаў у дыягностыцы, ручнае прайграванне застаецца, аўтагук і R07-падказкі знікаюць;
- GPS-gap / састарэлы фікс → няма аўтагуку са старой каардынаты; ручны шлях не залежыць ад пазіцыі;
- званок/іншы аўдыё-фокус → перапыненае не залічваецца як `AudioFinished`; пасля вяртання фокусу гук не вяртаецца і новае аўдыё не пачынаецца без чалавека; паўторны запуск — з пачатку файла (R03);
- Pause → GPS-падпіска знятая чэсна, чарга і wakelock вызваленыя; аднаўленне толькі яўным Resume (R07 у Paused няма);
- recent-apps removal, force-stop, перазагрузка, battery saver → гэта спыненні, не адмовы: яны не маскіруюцца retry-цыклам; пасля ручнога запуску прыклад аднаўляецца, аўтагук — не;
- хуткія Play/Stop і паўтор файла → гучыць роўна адзін гук; спознены callback не залічваецца і не ўплывае на новы запуск.

## 4. Што праверана фактычна (стан 2026-09-15)

| Уровень | Што праверана | Статус і доказ |
|---|---|---|
| Лагічная мадэль (Node) | кантрактныя паводзіны run-model і спайка | зялёна: `node --test docs/run-model/run-model.test.mjs` → 51 pass / 0 fail; `node docs/run-model/check-regressions.mjs` → 16/16 rejected; `npm test` у спайку → 8 pass / 0 fail; `npm run generate-audio` → файлы байт-у-байт ідэнтычныя зафіксаваным |
| Канфігурацыя зборкі | `app.json`/`eas.json` спайка заяўляюць background modes, дазволы, background playback | задэкларавана, **не** праверана: канфігурацыя сама не доказ таго, што OS так сябе вядзе (README спайка прама забараняе выводзіць паводзіны з канфігурацыі) |
| OS-узровень | уся матрыца G00.01.b | **37 з 37 радкоў `not-run`** (3 класы прылад × 12 сцэнараў + эмулятар); development build спайка не існуе (G00.01.a `blocked-external`); ніводнае платформавае абяцанне з §2–§3 не пацверджанае на iPhone, чыстым Android, Samsung/Xiaomi або эмулятары |
| Store/сервер | па-за межамі G00.01 | кароткая адсылка: G00.03 |

Гэта значыць: на сёння абяцанні §2–§3 маюць сілу **кантракту**, а не вымеранага факту. Зялёны Node-тэст пацвярджае логіку мадэлі, не паводзіны OS, store або сервера.

Ніводнага вымеранага ліку не існуе: затрымка трыгера, інтэрвал фіксаў, паводзіны ў фоне/lock і спажыванне батарэі — усе `not-run`. ## 6. Зверка сцэнараў і імёнаў палёў з прынятым ADR

- Назвы падзей: матрыца [G00.01.b](../../../spikes/G00.01-location-audio/evidence/G00.01.b-device-matrix.md) выкарыстоўвае `AudioFinished` у значэнні ADR §4.11 і [18 §2](../18_component_blueprint.md) — імёна супадае; забароненыя [ADR §4.2](G01.01-narration-progress.md) назвы (`consumed`, захоўваны `played`) у дакументах пакета не сустракаюцца. Уровень ідэнтычнасці прагрэсу ў мадэлі спайка — асобна ў наступным пункце.
- Расхожданне з гісторыі: мадэль спайка `src/session.mjs` трымае `heard`/`autoFired` **па кропках** (`point.id`) — яна напісаная да прыняцця ADR G01.01 (2026-09-14), які задаў `heard: Set<story_id>`. Спайк — выкідны прыклад, не нарматыў; правіла межаў задачы не дазваляе ціха мяняць чужыя файлы папярэдняй часткі. Выконваная рэпрадукцыя для ўладальніка G00.01.a (спайк не змяняецца; каманда з кораня рэпазіторыя):

  ```sh
  cd spikes/G00.01-location-audio && node -e "import('./src/session.mjs').then(({createSession}) => { const s = createSession([{id:'stop-crane', x:0, y:0, radiusM:40}]); s.manualPlay('stop-crane'); s.audioFinished(); console.log('heard =', JSON.stringify(s.snapshot().heard)); })"
  ```

  Факт: `heard = ["stop-crane"]` — ключ прагрэсу ёсць `stop_id`, паняцця `story_id` у спайку няма ўвогуле; чаканае паводле ADR §4.2 — манатонны `Set<story_id>`, `heard` як `Set<stop_id>` забаронены. Узгадніць узровень ідэнтычнасці з ADR §4.2 пры дапрацоўцы спайка да прыладавай прыёмкі, інакш прыладавыя лікі будуць адносіцца да састарэлай мадэлі.
- Гэты файл не ўводзіць альтэрнатыўных парогаў, імёнаў або правіл; агульны `09` не мяняўся; усё, што тут пералічана як «па кантракце», цытуе прынятыя крыніцы з пазнакай раздзела.

## 7. Абяцанні па сцэнарах і класах прылад

Поўныя клеткі — у матрыцы [G00.01.b](../../../spikes/G00.01-location-audio/evidence/G00.01.b-device-matrix.md). Зводка па 12 сцэнарах: у кожным классе (iPhone, чысты Android, Samsung/Xiaomi) і на Android-эмулятары **усе клеткі `not-run`**. (У табліце радкі аб'яднаныя: «Заблакаваны экран / фон» — гэта два сцэнары; «Recent-apps / force-stop / reboot» — тры. Поўны пералік 12 × 3 класы + эмулятар — у матрыцы.)

| Сцэнар | Па кантракце | Статус усіх класаў |
|---|---|---|
| Foreground + падыход, dwell 6 с | адзін аўтазапуск асноўнага; ручны Play незалежна ад радыуса | `not-run` |
| Заблакаваны экран / фон | гук і фіксы працягваюцца; затрымкі — толькі вымераныя | `not-run` |
| Званок / іншае аўдыё | няма накладання; перапыненае ≠ `AudioFinished`; аўтапрацягнення няма | `not-run` |
| Pause / End / яўны Resume | GPS зняты чэсна; трыгера няма; Resume толькі яўны | `not-run` |
| Адмова/адкліканне дазволаў | чэсны стан; ручны шлях працуе | `not-run` |
| GPS-gap / састарэлы фікс | няма аўтагуку са старой каардынаты | `not-run` |
| Recent-apps / force-stop / reboot | спыненне ёсць спыненне; ручны запуск аднаўляе прыклад, не аўтагук | `not-run` |
| Battery saver (асабліва Samsung/Xiaomi, M0) | факты фіксаў/затрымак у рэжыме, не здагадка | `not-run` |
| Хуткія Play/Stop, паўтор файла | адзін гук; спознены callback не ўплывае | `not-run` |

## 8. Што пераводзіць гэты файл у `complete`

1. Хвост [G00.01.a](../../agent-tasks/results/G00.01.a.md): афіцыйная верыфікацыя версій §5.1, `package-lock.json`, `npm install`, `npx expo-doctor`, сабраны development build.
