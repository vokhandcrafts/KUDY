## 1. Праблема

`09` разд. 7 называе табліцу `session` (зона B) і палі, але не задае: моманты запісу і аднаўлення кожнага поля; транзакцыйныя межы Start/Pause/Resume/switch/End; ідэнтычнасць даверанага `AccessReady`; размяшчэнне shown/dismissed R07; міграцыю `heard` пры змене тыпу элемента; паводзіны пры crash каля verify/activate/persist. Без гэтага G04 (SQLite), G05 (download), G08 (entitlement) і run-model (G01.03.b) атрымліваюць розныя здагадкі пра адно і тое ж.

Ключавая небяспека: `session` — **незаменныя дадзеныя** (зона B). Памылковая праўка тут губляе платную прагулку на паўдарозе, і адбудаваць яе няма адкуль: сервер прагрэсу не трымае да `/link`.

## 3. Прапанованы кантракт (набывае сілу пасля прыняцця)

Пакуль статус гэтага файла не «прынята», не змяняць `09` / `11` / `run-model` паводле §3. Гэтая праца — G01.03.c (сінхранізацыя) і G01.03.b (мадэль).

### 3.1 Durable-полі сесіі (зона B, табліца `session`)

Ключ — `session_id`. Адна прагулка = адзін радок; паўторны праход — новы радок; старая гісторыя ніколі не выдаляецца і не перазапісваецца. Усе запісы ў радок — толькі ўнутры транзакцый §3.3; адзін пісьменнік — контролер сесіі (`useRunController`), які адзіны стыкуе engine са светам (`09` §6.4).

| Поле | Тып (SQLite) | Nullable | Default | Уладальнік | Момент запісу | Момант аднаўлення |
|---|---|---|---|---|---|---|
| `session_id` | TEXT (UUIDv4) | NOT NULL | — | `core/engine` пры Start | у транзакцыі Start; ніколі не перавыкарыстоўваецца | чытаецца як ключ радка |
| `route_id` | TEXT | NOT NULL | — | engine, з абранага гіда | у транзакцыі Start; пасля — не мяняецца | як крыніца `session.route_id` для праверкі `AccessReady` і гісторыі My KUDY |
| `version` | TEXT | NOT NULL | — | engine, з ключа праверанага пакета | у транзакцыі Start; **нязменны да End** (§3.4) | абавязковы ўвод у праверку замацаванага пакета пры Resume |
| `locale` | TEXT (BCP-47 з allowlist) | NOT NULL | — | engine, з выбару мовы да Start | у транзакцыі Start; пасля — не мяняецца | мова аднаўленай сесіі; змена UI-мовы яе не чапае |
| `tier` | TEXT (JSON-масіў, напр. `["base"]`) | NOT NULL | `["base"]` | engine | у транзакцыі Start: пласты, поўнасць якіх правераная перад стартам. **Інфармацыйны запіс старта**, не runtime-стан: runtime `tier_available` выводзіцца з дыска (§3.2) і расце толькі праз `AccessReady` | не ўвод; паказ у гісторыі |
| `state` | TEXT CHECK `active`/`paused`/`finished` | NOT NULL | `active` | контролер | толькі ў транзакцыях Start/Pause/Resume/End/switch; `Idle` у сховішча не пішацца (адсутнасць радка і ёсць Idle) | вызначае, ці прапануецца «Працягнуць захаваную прагулку?» |
| `started_at` | INTEGER (unix ms) | NOT NULL | — | engine (`now` ін'ектаваны) | у транзакцыі Start; не мяняецца | паказ «пачатая ўчора» (11 разд. 4.3: адно пытанне пры сесіі старэйшай за 24 г) |
| `finished_at` | INTEGER (unix ms) | NULL | NULL | контролер | толькі ў транзакцыі End/switch | тэрмін жыцця радка ў My KUDY |
| `auto_fired` | TEXT (JSON-масіў `stop_id`) | NOT NULL | `[]` | толькі рэдуктар `core/engine` | checkpoint-запіс пасля кожнай прынятай мутацыі; **манатонны**, ніколі не сціраецца ў сесіі | поўнае аднаўленне набору ў engine |
| `heard` | TEXT (JSON-масіў; тып элемента — §3.8) | NOT NULL | `[]` | толькі рэдуктар | checkpoint-запіс пасля кожнага прынятага `AudioFinished`; **манатонны** | поўнае аднаўленне набору; адсутны файл не выдаляе факт |
| `last_stop_id` | TEXT | NULL | NULL | контролер | checkpoint-запіс | толькі паказ; **не** увод трыгера або геафенсаў |
| `play_seq` | INTEGER | NOT NULL | `0` | engine | **write-through на кожным `PlayStory`** да высоўкі каманды аўдыё; расце на +1; нуль не аднаўляецца ў сесіі | counter `play_id` працягваецца пасля restart — спознены callback старага запуску не супадае з новым |

Забаронена: захоўваць `heard`/`auto_fired` як пасіўныя копіі па-за адным радком; трымаць «куплена»/«ready» сцяг у `session` (§3.6); пісаць у радок сесіі pipeline, сэрвісам або UI мінулы контролер.

**Унікальнасць жывой сесіі.** Частковы ўнікальны індэкс на канстантным выразу:

```sql
CREATE UNIQUE INDEX one_live_session ON session(
  (CASE WHEN state IN ('active','paused') THEN 1 END)
);
```

Жывыя радкі даюць ключ `1`, скончаныя — `NULL` (NULL-ы не канфліктуюць). Спроба ўставіць/вярнуць другі жывы радок падае з абмежавання — «Дзве спробы Start або switch адначасова» вырашаюцца базай, не ўзаемным блокаваннем кода.

### 3.2 Вытворныя палі — не захоўваюцца

| Поле | Крыніца аднаўлення | Чаму не калонка |
|---|---|---|
| `accessible_stop_ids` | выводзіцца з праверанага замацаванага пакета + `tier_available` (прэдыкат `story_accessible` ADR G01.01 §4.2) | захаваны набор адразу расце з фактамі дыска; дубль = два ўладальнікі адной праўды |
| `tier_available` | пласты замацаванага пакета, поўнасць якіх пацверджаная на дыску (lock.json + факт файлаў) | «не дублюй гатоўнасць файлаў як незалежны некантраляваны сцяг»; дыск — крыніца праўды лакальнай гатоўнасці |
| `playing` | заўсёды `null` пасля аднаўлення; аднаўленне **не запускае гук сама** (`09` §18 аднаўленне, R03) | прайграванне належыць жывому плэеру, не диску |
| `queued` | заўсёды `null` пасля аднаўлення | чарга адна ячэйка жывога трыгера; пасля crash рашэнне прымае толькі новая свежая пазіцыя |
| `autoplay_suspended` | заўсёды `true` пасля аднаўлення; здымае толькі яўнае дзеянне чалавека (`11` разд. 5.2) | гарантуе «аднаўленне не запускае аўдыё» нават пры актыўным стане на диску |
| `story_accessible(story_id)` | вылічваецца | вылічальны прэдыкат ADR G01.01 §4.2 |

### 3.3 Транзакцыйныя межы

Умовы (readiness, адсутнасць іншай жывой сесіі) правяраюцца **да** транзакцыі; каманды эфектаў (геафенсы, гук, wakelock, рэжым GPS) высоўваюцца **толькі пасля commit** — пры збоі запісу эфекты не запускаюцца (`18` §4, дыяграма Start). Уладальнік транзакцый — `services/db`; яны не робяць сеткавых/OS-выклікаў.

| Мяжа | Унутры адной транзакцыі | Пасля commit (эфекты) | Збой |
|---|---|---|---|
| **Start** | INSERT новага радка (`state='active'`, пустыя наборы, `play_seq=0`) + перанос R07-стану (§3.9) | узбраенне акна геафенсаў, рэжым GPS, wakelock, адзінае абяцанне аўтазапуску | адкат: сесіі няма, эфектаў няма; паўторны Start чысты |
| **Pause** | UPDATE `state='paused'` + checkpoint набораў | стоп аўдыё, ачыстка чаргі, `ClearGeofences`, адпусканне GPS і wakelock (`11` разд. 4.2) | адкат: сесія застаецца `active` |
| **Resume** | UPDATE `state='active'` | перазбройванне акна геафенсаў, рэжым GPS; **аўдыё не стартуе**, `autoplay_suspended=true` да яўнага дзеяння | адкат: сесія застаецца `paused` |
| **switch-guide** (пацверджаны дыялог, `11` разд. 4.1) | UPDATE старога радка `state='finished'`, `finished_at` + INSERT новага радка | эфекты Start новай сесіі | адкат **абодвух**: старая сесія ў папярэднім стане, новай няма; цыхага перамыкання няма |
| **End (Finish)** | UPDATE `state='finished'`, `finished_at` + фінальны checkpoint | стоп аўдыё/геафенсаў/wakelock; «Яшчэ можна адкрыць» лічыцца з захаванага стану пасля commit | адкат: сесія ў папярэднім стане |
| **checkpoint** (`PersistProgress`) | UPDATE набораў/`last_stop_id` (і `play_seq`, калі ён не запісаны write-through) | няма | адкат бяспечны: наступны checkpoint запіша навейшы стан |

Правілы checkpoint-у: контролер выдае `PersistProgress` пасля кожнай прынятай падзеі, якая мутуе `heard`/`auto_fired`, у парадку падзей; адзін пісьменнік; паўторны запіс таго ж або навейшага стану ідэмпатэнтны. Crash паміж падзеяй і checkpoint губляе апошні факт чэсна: пасля аднаўлення стан адназначны, «partial не выдаецца за ready», гісторыя праходаў не пашкоджаная.

### 3.4 Версія нязменная

`session.version` пішацца адзін раз у Start і не мяняецца да End, у тым ліку пры паўзе, restart, наступным дні, абнаўленні каталога і серверным адкате (`09` §4; сцэнар «Паўза ўчора → новая версія каталога сёння → Resume»). Настствы:

- `AccessReady` іншай версіі адхіляецца цалкам (§3.5); пашырэнне мусіць супадаць з версіяй сесіі (`11` C35).
- Новая версія каталога патрабуе новай сесіі; адсутнасць патрэбнай версіі паказваецца як недаступная загрузка, без падмены кантэнту.
- Замацаваная версія абароненая ад лакальнага выдалення: ачыстка пакета ў My KUDY адмаўляе выдаленне, пакуль існуе не-`finished` сесія з гэтай версіяй.

### 3.5 Межа даверу `AccessReady`

Выдавец — **толькі** `services/download` пасля сервернага гранта, поўнай пер-файлавай праверкі `sha256` і атамарнай актывацыі (`09` §6.1, §6.3; `18` §2). UI, `entitlement`, факт store-пакупкі і client-сцягі не з'яўляюцца выдаўцамі і не ўводам даверу.

Поўная ідэнтычнасць падзеі (удакладненне `09` `AccessReady(version, stop_ids[])` — дададзены route/locale/tier і ўладальнік загрузкі; сінхранізацыю рабіць у G01.03.c):

```
AccessReady(route_id, version, locale, tier, stop_ids[], issuer='services/download')
```

Engine прымае падзею толькі калі **усё адначасова**:

1. `route_id == session.route_id`;
2. `version == session.version` (дакладна; іншая версія не падмешваецца ў сесію);
3. `locale == session.locale`;
4. `tier ∈ {base, extended}` і адпавядае пласту, які сапраўды загружаны;
5. `stop_ids` — падмноства кропак замацаванага пакета (невядомыя `stop_id` не адкрываюць кантэнт);
6. выдаўцей — download-сэрвіс аднаго запуску дадатку; падзея ад іншай крыніцы адхіляецца цалкам.

Пры адмове — падзея ігнаруецца **цалкам**, ніводнае поле не мутуецца. Пры прыняцці: `tier_available` пашыраецца, `accessible_stop_ids` пералічваецца, акно геафенсаў пералічваецца; **Play няма**, `heard`/`auto_fired` не чапаюцца (same-version unlock без скіду прагрэсу, `11` C34).

**Позняя загрузка не муціруе новую сесію:** grant/загрузка, завершаныя для версіі ўжо скончанай або пераключанай сесіі, не праходзяць праверку 2 і адхіляюцца; файлы застаюцца на диску пад сваім ключам пакета і яшчэ будуць даступныя сесіі, якая зноў замацуе гэтую версію. **Ідэмпатэнтнасць:** паўторны `AccessReady` той самай ідэнтычнасці — no-op (наборы манатонныя, Play няма); паўторная падзея не стварае другога заліку і другіх эфектаў.

### 3.6 Разведзеныя паняцці

| Паняцце | Крыніца праўды | Дзе жыве |
|---|---|---|
| Права (entitlement) | сервер праз RevenueCat у момант grant; кліенцкае «куплена» — не крыніца (`09` §5.2, `02`) | сервер; серверны пазітыўны кэш `(device_id, route_id, tier)` TTL 24 г |
| Загружаныя і правераныя файлы | дыск + `lock.json` (пер-файлавы `sha256`), стан `bundle_asset` (зона A) адбудоўваецца перахэшаваннем | лакальныя файлы; **ніякай калонкі «ready» у зоне B няма** |
| Прыдатны наратыў | `story_accessible(story_id)` — вылічаны прэдыкат (§3.2) | engine |
| Стан праслухоўвання | `heard`, `auto_fired`, `playing` — рэдуктар + durable checkpoint (§3.1) | `session` радок |

**Купленае без файлаў — не ready.** Пасля паспяховай аплаты і збою файлаў: права не губляецца, файл не ready, паўтор загрузкі не патрабуе паўторнай аплаты (пазітыўны кэш гранта, паўторны запыт `RevenueCat` серверам, `11` разд. 8 «Куплена · трэба загрузіць»). **Start патрабуе поўнага выбранага пласта:** для `free_base` — поўны `base` абранага пакета, закрыты `extended` не патрабуецца (`11` разд. 7); для платнага маршрута — поўны яго пласт. Partial або hash mismatch → Start не адбываецца, паказаны стан загрузкі.

### 3.7 Crash каля verify/activate/persist і зашытая загрузка

Ланцуг download: `staging/` (сусед фінальнай дырэкторыі) → пер-файлавы хэш на ляту → атамарны rename → толькі потым `AccessReady` (`09` §6.3). Паводзіны:

| Crash | Стан пасля аднаўлення | Правіла |
|---|---|---|
| падчас staging | `.part`-файлы; рэзюмаванне па хэшы, не па афсеце; двухзначнасць → выдаліць staging і перакачаць | partial ніколі не лічыцца ready |
| пасля rename да `AccessReady` | пласт поўны на диску; гатоўнасць **выводзіцца** з дыска (§3.2), таму стан самалякуецца | ніякага асобнага сцягу, які мог бы «адстаюць» |
| падчас verify | праверка перазапускаецца; стары працаздольны пласт не чапаецца | няўдалы upgrade не выдаляе стары пласт |
| паміж падзеяй і `PersistProgress` | апошні зацверджаны checkpoint; факт да checkpoint-у чэсна адсутнічае; адзін адназначны стан | partial выданні за ready няма |

**Адсутны файл пасля restart** (у т. л. «асіратэлыя» файлы iOS, `09` §7): сесія аднаўляецца як стан, кантэнт — чэсна недаступны: паказ загрузкі/праверкі, не Play, не `heard`, не падмена файлаў іншай версіяй. **Стары працаздольны пласт не выдаляецца пры няўдалым upgrade**; staging аднаго тома з фінальнай дырэкторыяй, бо rename атамарны толькі ў межах тома.

### 3.8 Міграцыі зоны B

- `PRAGMA user_version` — нумар схемы; адзін крок = адна міграцыя = адна транзакцыя; крокі дадаюць табліцы/калёнкі, не перапісваюць гісторыю.
- **Памылка міграцыі не дазваляе сцерці базу**: адкрыццё падае з дыягностыкай, дроп-і-перастварыць фізічна недасяжны для зоны B (асобная функцыя зоны A не бачыць яе табліц, `09` §7; G04.01).
- **Міграцыя тыпу элемента `heard`** (толькі калі заснавальнік прыме варыянт A з ADR G01.01): для кожнага незавершенага радка `heard`-элемент `stop_id` пераўтвараецца ў `primary_story_id` гэтай кропкі па замацаванай версіі пакета; пераўтварэнне дэтэрмінаванае, у межах транзакцыі міграцыі; `stop_id`, не вырашаныя па пакеце, захоўваюцца ў запісе міграцыі (`migration_log`: `version`, `applied_at`, нязмененыя ідэнтычнасці) — не выдаляюцца цыха і не выдумваюцца story. Пры варыянце B міграцыі няма.
- Новыя durable-табліцы гэтага кантракта (`guide_hint_state`, `guide_hint_last`, §3.9) ствараюцца дадаваннем; існуючыя радкі не перазапісваюцца.

### 3.9 R07 shown/dismissed: размяшчэнне і перанос

Носьбіт — **durable зона B**, побач з прагрэсам (`09` §20). Дзве табліцы:

| Табліца | Палі | Сэнс |
|---|---|---|
| `guide_hint_state` | `scope` (`session`/`foreground`), `guide_id`, `session_id` (NOT NULL для `session`), `shown_at`, `dismissed_at NULL` | факт паказу/адхілення па кожным фактычна прадстаўленым `guide_id`; унікальнасць `(scope, session_id, guide_id)` для сесійнага scope = **адзін паказ гіда за сесію** |
| `guide_hint_last` | `guide_id` PK, `last_shown_at`, `last_dismissed_at NULL` | падтрымка foreground-cooldown паміж адкрываннямі дадатку |

Уладальнік запісу — nearby controller; падзея лічыцца паказанай па факце бачнасці, **не** па адпраўцы на сервер. Перанос пры Start: у транзакцыі Start shown/dismissed `guide_id` бягучага foreground-вокна пераносяцца ў сесійны scope, каб не паўтарыць іх адразу; яны перажываюць restart гэтай сесіі (R07). Пры End сесійныя радкі застаюцца як гісторыя; foreground-лиміты працягваюць трымаць `guide_hint_last`.

**Лічбы — не гэтага кантракта:** парог блізкасці, accuracy, dwell і cooldown фіксуе G07.04 з палявой каліброўкай G11.02; тут толькі сховішча і ўнікальнасць. Аналітычная згода не кіруе лакальнымі лімітамі: радкі пішуцца заўсёды, адпраўка `guide_nearby_*` — толькі са згодай (G09.02).

### 3.10 Жыццё сесіі супраць сервернага retention

Радок `session` жыве на прыладзе даўжа; сервер яго не бачыць да `/link` (Phase 2, `02`). Серверны retention старых версій бандлаў — асобнае эксплуатацыйнае рашэнне G11.03; гэты кантракт не вызначае тэрмін. Калі замацаваная версія больш не загружальная з сервера: сесія працягваецца з наяўных файлаў; іх страта дае чэсны недаступны стан (§3.7), без падмены кантэнтам іншай версіі.

### 3.11 Межы ад discovery/feedback

`feedback_local` / `feedback_outbox` — асобныя durable-табліцы, `discovery_cache` — зона A ([21, §5.4](21_discovery_feedback_architecture.md); `09` §21). Яны не ўваходзяць у радок сесіі і не мутуюцца яго транзакцыямі; гэтая задача іх не рэалізуе і не мяняе іх allowed-file scope.

## 4. Сцэнары прыёмкі кантракта

| Сцэнар (з `G01.03.md`) | Адказ кантракта |
|---|---|
| Start пры partial або hash mismatch | readiness да транзакцыі падае; INSERT няма; эфектаў няма; паказаны стан загрузкі (§3.6) |
| Купіў, сетка знікла | права ў сторы/RevenueCat; файл не ready; паўтор загрузкі без паўторнай аплаты (§3.6, §3.5 issuer) |
| Base праслуханы → same-version upgrade | `AccessReady` той самай версіі пашырае `tier_available`; `heard`/`auto_fired` цэлыя; Play няма (§3.5) |
| Чужы route/version/locale або стары completion | праверкі 1–5 §3.5 адхіляюць падзею цалкам; спознены callback не супадае з `(session_id, play_seq)` (§3.1, ADR G01.01 §4.11) |
| Crash каля activate/persist | табліца §3.7: адзін адназначны стан; partial не ready |
| Дзве спробы Start або switch адначасова | частковы ўнікальны індэкс §3.1: другі жывы радок немагчымы; старая гісторыя не выдаляецца |
| Паўза ўчора → новая версія каталога сёння → Resume | `version` нязменны (§3.4); аднаўленне па замацаваным пакеце; новы каталог не падмяняе файлы |
| Выдаленне выкарыстоўванага пакета | ачыстка адмаўляецца, пакуль ёсць не-`finished` сесія гэтай версіі (§3.4) |
| Restart без згоды на аналітыку | наборы і R07-стан з зоны B аднаўляюцца; `event_queue` пішацца лакальна, адпраўкі няма (§3.9, `09` §10) |

Гэта лагічны кантракт дакументацыйнай мадэлі: **не** доказ OS, сервера, store або crash recovery — іх правяраюць G04/G05/G08 і спайкі.
