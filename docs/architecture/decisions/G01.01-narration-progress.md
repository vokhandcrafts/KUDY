## 1. Праблема

Цяперашні `heard: Set<stop_id>` і выканальная мадэль апісваюць **адзін наратыў на кропку**. Дзве гісторыі аднаго месца (base і extended) зліваюцца ў адзін факт праслухоўвання.

Прыклад, які трэба закрыць: чалавек даслухаў base → same-version unlock extended → extended **не** heard, сесія тая ж, **новага Play няма**.

Асобны аўдыёфайл на гісторыю (R02) сам гэтага не вырашае: ідэнтычнасць прагрэсу застаецца stop-level.

---

## 2. Варыянты

### A. Асноўны story для аўтаматыкі, дадатковы — толькі ручны Play (P01)

Кожны наратыў мае ўласны `story_id`. Base і extended не перазапісваюць адзін аднаго. Праслухоўванне — па `story_id` у замацаванай версіі сесіі. Аўтатрыгер — па `stop_id`, заўсёды асноўны наратыў гэтай кропкі. Дадатковы — кнопка «Яшчэ пра гэтае месца». Paid-only кропка мае свой асноўны наратыў без фіктыўнага free story; ён становіцца прыдатным пасля AccessReady. Пакупка і AccessReady самі не граюць.

### B. Замена асноўнага аўдыё пашыраным

Пасля адкрыцця extended асноўны файл кропкі становіцца пашыраным. Адзін «цяперашні» наратыў на stop. Прагрэс застаецца прывязаным да кропкі (або скідаецца, каб новая гісторыя магла граць).

---

## 3. Кошт і наступствы

| | A — асобныя story | B — замена асноўнага аўдыё |
|---|---|---|
| Base heard пасля unlock | base застаецца heard; extended асобна не heard | калі `heard` па stop_id — extended памылкова heard; калі скінуць heard — знікае факт base і рызыка паўторнага аўтагуку |
| Нябачная змена файла | няма: асноўны шлях не змяняецца пасярод сесіі | ёсць: картка і плэер пачынаюць іншы файл без новага выбару чалавека |
| Маркер і картка | маркер `played` = асноўны heard; картка можа сказаць «асноўная праслуханая · дадатковая яшчэ не» | адзін маркер не адрознівае дзве гісторыі; дадатковую нельга паказаць як непраслуханую, не ператварыўшы кропку зноў у pending |
| «Яшчэ можна адкрыць» | адзінка = story; extended трапляе ў спіс | адзінка = stop; кропка ўжо «праслуханая» і extended не з'яўляецца, або спіс мяшае stop- і story-прагрэс |
| Аўтазапуск | адзін раз на stop (асноўны); extended ніколі сам | каб extended граў сам, трэба скінуць `auto_fired` або зрабіць яго story-level — паўторны аўтагук таго ж месца |
| Durable | `heard` мяняе элемент з `stop_id` на `story_id` (міграцыя ў G01.03) | можна пакінуць `heard: Set<stop_id>`, але тады прадуктовы сцэнар P01 невыканальны |
| UI | кнопка дадатковага story; два радкі стану на картцы | прасцейшы UI, горшы сэнс пасля пакупкі |
| Сумяшчальнасць з R03 | паўтор не сцірае heard канкрэтнага story | перарваны паўтор «новага» файла лёгка зблытаць са скідам старога факту |

**Рэкамендацыя:** варыянт A. Ён адзіны закрывае прыклад base→extended без скіду прагрэсу, без паўторнага аўтагуку і без нябачнай падмены файла. Варыянт B таннейшы толькі пакуль у кропцы адзін наратыў; пры двух гісторыях ён альбо хлусіць пра heard, альбо ламае манатоннасць набораў.

Гэта **не** прыняты выбар.

## 4. Прапанаваны кантракт (набывае сілу толькі калі прыняты варыянт A)

Ніжэй — канкрэтныя правілы для ўзгаднення. Пакуль статус не «прынята», не змяняць нарматыўныя `09` / `11` / `15` / `run-model` паводле гэтых правоў.

### 4.1 Ідэнтычнасці

| Імя | Што ідэнтыфікуе | Не з'яўляецца |
|---|---|---|
| `stop_id` | `RouteStop.id` — месца на гіде; стабільны паміж версіямі бандла | гісторыя, файл, запуск |
| `story_id` | `Story.id` — адзін наратыў (асобны тэкст, транскрыпт, аўдыё) | кропка, media hash, play |
| media | цэласнасць файла: `Media.sha256` (+ `bytes`, `mime`, `locale`) | ключ прагрэсу; перакадзіроўка не стварае новы факт heard |
| `play_id` | лічыльнік запускаў унутры `session_id`; разам з `session_id` — токен запуску | ідэнтычнасць гісторыі |
| `session_id` | адна прагулка; `version` і `locale` замацаваныя да End | маршрут |

Шлях файла: `<locale>/<tier>/audio/<story_id>.m4a`. Прайграванне бярэ `story_id` + замацаваныя locale/version, не hash.

На `RouteStop`:

- `story_base_id?`, `story_extended_id?` — палі пакета; хоць адно абавязковае.
- **Асноўны** `primary_story_id` — **вытворны**, не асобнае захоўванае поле:
  - ёсць `story_base_id` → асноўны = base, **у тым ліку пасля unlock extended**;
  - няма base, ёсць толькі extended → асноўны = extended (paid-only, без фіктыўнага free story).
- **Дадатковы** `additional_story_id` — `story_extended_id`, калі ёсць і base, і extended; інакш няма.
- Unlock **не** мяняе `primary_story_id`. Гэта адрозненне ад варыянту B.

### 4.2 Палі стану

| Поле | Тып | Уладальнік | Правіла змены |
|---|---|---|---|
| `session_id` | ID | `core/engine` пры Start; SQLite зона B | новы радок на кожную прагулку; не перавыкарыстоўваецца |
| `version` | ID бандла | engine, з гатовага пакета | замацаваны да End; AccessReady іншай версіі адхіляецца |
| `locale` | BCP-47 з allowlist | engine, з выбару да Start | замацаваны да End; UI-мова не мяняе аўдыё сесіі |
| `auto_fired` | манатонны `Set<stop_id>` | толькі рэдуктар `core/engine`; pipeline не піша | дадаецца, калі аўтаматычная спроба **скончана**: фактычны аўтазапуск асноўнага **або** перавод у ручны доступ (`11` §5.1.1). Чарга і ігнараванне трыгера **не** дадаюць. Ніколі не сціраецца ў сесіі. Не ключуецца `story_id` |
| `heard` | манатонны `Set<story_id>` | толькі рэдуктар; durable сесія | дадаецца **толькі** на прынятым `AudioFinished` гэтага story. Паўтор, перапыненне, Pause, FocusLoss, пакупка, AccessReady, End **не** выдаляюць. Новая сесія — пусты набор. **Не** `Set<stop_id>` |
| `playing` | `{ stop_id, story_id, play_id } \| null` | рэдуктар | ставіцца на кожны `PlayStory` (`play_id` +1); здымаецца на любым спыненні. Не замяняе `heard` |
| `queued` | `{ stop_id, radius, at } \| null` | рэдуктар | адна ячэйка, найноўшы **stop**-трыгер; без `story_id` (аўтазаўсёды асноўны). Пастаноўка не чапае `auto_fired` |
| `accessible_stop_ids` | `Set<stop_id>` | уваход engine ад даверанай даступнасці (grant + поўная праверка файлаў) | дадаецца праз `AccessReady` той самай версіі; engine не вырашае пакупку. Сэнс: асноўны наратыў кропкі гатовы |
| `tier_available` | набор пластоў `base` / `extended` | той жа давераны ўваход | same-version unlock дадае `extended` без скіду heard/auto_fired і без Play. Не client-сцяг пакупкі |
| `autoplay_suspended` | bool | рэдуктар | як у `11` §5.2; не звязаны з heard |
| `story_accessible(story_id)` | вытворны прэдыкат, не захоўваны набор | лічыцца з пакета + `accessible_stop_ids` + `tier_available` | так, калі story — асноўны або дадатковы кропкі з `accessible_stop_ids` і `story.tier ∈ tier_available`. Дадатковы extended той жа ўжо адкрытай кропкі становіцца так пасля дадавання `extended` у `tier_available` |
| вылічаны статус **кропкі** | не захоўваецца | UI ад engine | гл. §4.5 |
| вылічаны стан **story** | не захоўваецца | UI | `locked` / `unheard` / `heard` па `story_accessible` і `heard` |

Забароненыя сінонімы пасля прыняцця A: `consumed`; захоўваны статус `played`; `heard` як набор `stop_id`. Старыя радкі `09`/`11` з `heard: Set<stop_id>` становяцца гісторыяй у G01.01.c.

### 4.3 Асноўны і дадатковы наратыў

- Аўтазапуск, чарга, lock-screen prev/next па спісе кропак — **толькі** `primary_story_id`.
- Дадатковы — толькі яўны ручны Play («Яшчэ пра гэтае месца»). Ні Dwell, ні чарга, ні AccessReady, ні prev/next яго не запускаюць.
- `UserSelectedStop(stop_id)` грае асноўны, калі `story_accessible(primary_story_id)`.
- `UserSelectedStory(stop_id, story_id)` грае названы story, калі ён належыць гэтай кропцы і `story_accessible(story_id)` (асноўны або дадатковы).
- Адзін фізічны плэер: новы Play спыняе папярэдні. Уладальнік гуку — G01.02, не гэты файл.
- Ручны Play не патрабуе блізкасці. Аўтагук — толькі абраны гід пасля Start, пры свежай пазіцыі і dwell (`11` §5.1), ніколі ад Moment або R07.

### 4.4 Paid-only stop

- Кропка без `story_base_id` дазволеная. `primary_story_id = story_extended_id`. Фіктыўны free story забаронены.
- Да same-version AccessReady: `locked`; ні ручны, ні аўта Play; `auto_fired` не ставіцца (ігнараванне як у `11` §5.1.1 умова 6).
- Пасля AccessReady: звычайная прыдатная кропка. Геафенсы пералічваюцца; наступная свежая пазіцыя і dwell **могуць** запусціць асноўны па агульных правілах, без патрабавання выйсці з зоны (`11` §8).
- Пакупка, факт store, client-сцяг і няпоўная загрузка **не** робяць ready і **не** эміцяць Play.

### 4.5 Маркеры карты (адзінка = stop, ад асноўнага story)

Парадак як у `11` §3.1, з уточненнем крыніцы `played`:

| Маркер | Умова | Аўтазапуск |
|---|---|---|
| `locked` | не `story_accessible(primary_story_id)` | не |
| `playing` | `playing.stop_id == stop_id` (асноўны **або** дадатковы гучыць) | — |
| `played` | `primary_story_id ∈ heard` | не |
| `available` | `stop_id ∈ auto_fired` і асноўны не heard | не |
| `pending` | інакш | так, калі астатнія ўмовы §5.1 |

`played` **не** азначае «усе гісторыі кропкі праслуханыя». Дадатковы непраслуханы **не** вяртае маркер у `pending`.

На картцы кропкі, калі дадатковы існуе і даступны:

- асноўны ∈ heard і дадатковы ∉ heard → «асноўная праслуханая · дадатковая яшчэ не праслуханая»;
- абодва ∈ heard → абедзве праслуханыя;
- дадатковы locked → публічны анонс + замок, без поўнага тэксту/медыя.

Тап па маркеры не запускае аўдыё.

### 4.6 «Яшчэ можна адкрыць» (адзінка = story)

На `Finish` спіс = усе `story_id` з `story_accessible`, што належаць кропкам маршруту і **не** ў `heard`. Locked (не `story_accessible`) выключаныя. Гэта магчымасці, не пропускі.

Спіс **не** з'яўляецца stop-прагрэсам. Нельга ў адным спісе змешваць `stop_id` і `story_id` як раўназначныя радкі. Паказ можа ўключаць назву кропкі і ролю (асноўная / дадатковая), але ключ радка — `story_id`.

Наследства: калі ў кропкі толькі асноўны, спіс супадае са старым «даступныя кропкі не ў heard». Калі ёсць дадатковы — ён з'яўляецца асобным радком, нават калі маркер кропкі ўжо `played`.

### 4.7 Выбар наратыву да і пасля пакупкі

| Момант | Аўта / чарга | Ручны асноўны | Ручны дадатковы |
|---|---|---|---|
| Да unlock, ёсць base | base | base | няма (locked) |
| Пасля same-version unlock, ёсць base | усё яшчэ толькі base; auto_fired/heard не скідаюцца; Play няма | base | extended, калі `story_accessible` |
| Paid-only да unlock | няма | няма | — (гэта і ёсць асноўны, locked) |
| Paid-only пасля unlock | асноўны = extended, па правілах аўтазапуску | extended | няма дадатковага |

Пакупка сама не грае. AccessReady сам не грае і не мяняе `heard` / `auto_fired`.

### 4.8 Аўтазапуск: умовы (усе адначасова)

Як `11` §5.1, з заменай праверкі heard:

1. сесія `Active`;
2. `autoplay_suspended = false`;
3. `playing = null`;
4. `stop_id ∉ auto_fired` **і** `primary_story_id ∉ heard`;
5. свежы фікс (узрост ≤ 30 с, `accuracy ≤ radius`);
6. `story_accessible(primary_story_id)`; dwell у радыусе.

Праверка `primary ∈ heard` абавязковая: ручны асноўны да падыходу не павінен даць паўторны аўтагук. Дадатковы ∈ heard **не** забараняе аўтазапуск асноўнага, і наадварот.

### 4.9 Ручны паўтор, перапыненне, чарга

- Ручны паўтор з пачатку дапушчальны (R03). Не сцірае `heard` і не сцірае `auto_fired`.
- Перапыненне (ручны стоп, іншы Play, FocusLoss, Pause) **не** ёсць `AudioFinished`. Story становіцца heard толькі на ўласным прынятым завяршэнні.
- Званок / паўза аўдыё не аўтапрацягваюць і не аўтазапускаюць наступнае.
- Чарга трымае `stop_id`. Пасля `AudioFinished` адкладзены stop грае **толькі** калі ўмовы §4.8 трымаюцца для яго **асноўнага**. Калі чалавек паспеў праслухаць асноўны рукамі, пакуль stop у чарзе — чарга **не** грае, stop сыходзіць у `auto_fired`.
- Выцясненне з чаргі — як `11` §5.3: выцеснены → `auto_fired`, ручны доступ да асноўнага.

### 4.10 Адсутнае аўдыё і мова

- Няма праверанага файла сесіі (locale/version/tier) → не `story_accessible`; не Play, не heard. Паказаць недаступнасць або працяг загрузкі.
- Збой прайгравання → `story_play_failed`, не `AudioFinished`.
- `heard` не ключоўцца media hash і не ключоўцца locale асобна: locale ўжо на сесіі. Іншая мова — іншая сесія з чыстым `heard`.
- Ланцужок fallback моў — у `contentRepo` да Start, не падмена файла пасярод прагулкі.
- Аўдыё без транскрыпту не публікуецца (`09` інварыянт 1).

### 4.11 Спознены callback

`AudioFinished(session_id, play_id)` прымаецца, толькі калі пара супадае з бягучым `playing` і сесія не `Ended`. Калі ў падзеі ёсць `story_id`, ён мусіць супадаць з `playing.story_id`. Інакш ігнараваць: ніякага заліку бягучага наратыву, ніякага старту чаргі ад чужога completion.

Адной `story_id` недастаткова (два ручныя запускі). Аднаго `play_id` недастаткова (новая сесія пачынае лічыльнік з нуля). Стары stop_id не залічвае новы story.

### 4.12 Свабодны парадак і End

Нумар кропкі і кірунак не ўмовы запуску. End дапушчальны пасля любой колькасці гісторый, у тым ліку адной. Няма прымусовага завяршэння і няма статусу `deviated`.

## 5. Сцэнары прыёмкі кантракту

Сінтэтычныя ID: stop `stop-crane`, stories `story-crane-base` / `story-crane-ext`, сесія `session-1`, version `v3`.

| Сцэнар | Чаканы вынік |
|---|---|
| Base даслуханы (`AudioFinished` play 1, `story-crane-base`) → same-version AccessReady extended | `heard = {story-crane-base}`; `story-crane-ext` не heard; `session-1` і `v3` тыя ж; каманды Play няма; маркер `played`; у «Яшчэ можна адкрыць» ёсць `story-crane-ext` |
| Extended выбраны рукамі (`UserSelectedStory`), перапынены, запушчаны зноў | не heard да ўласнага `AudioFinished` новага `play_id`; `story-crane-base` застаецца heard |
| Paid-only `stop-gate` заблакаваны, затым same-version AccessReady | да адкрыцця не грае, `auto_fired` не ставіцца; пасля — звычайная прыдатная кропка; Play ад самой пакупкі/AccessReady няма |
| Асноўны праслуханы рукамі да падыходу | Dwell не дае паўторнага асноўнага аўтагуку (`primary ∈ heard`) |
| Stop у чарзе, чалавек даслухаў яго асноўны рукамі | пасля бягучага `AudioFinished` чарга не грае гэты асноўны; stop → `auto_fired` |
| Спознены callback старога story / play / session | бягучы наратыў не залічваецца; `heard` бягучага story не мяняецца |
| Падыход у іншым парадку; End пасля адной гісторыі | няма ўмовы `position`; сесія завяршаецца; спіс адкрыццяў — непраслуханыя даступныя **stories**, без locked |

Гэта лагічны кантракт, не доказ OS, store або сервера.

---

## 6. Што не ўваходзіць

- Рэалізацыя `run-model` і тэстаў — G01.01.b пасля **прынятага** ADR.
- Сінхранізацыя `09` / `11` / `13` / `14` / `15` / `16` — G01.01.c.
- Уладальнік гуку, Moments, tagged callbacks OS — G01.02.
- Durable SQLite-схема і міграцыя `heard[]` — G01.03 (гэтае ADR задае сэнс поля, не SQL).
- P02 і P03 не вырашаюцца тут.
