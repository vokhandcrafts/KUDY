## 1. Праблема

G08 (entitlement) і G00.04 (сумяшчальны стэк) атрымліваюць пра плацежную вертыкаль тры розныя сігналы: кананічны кантракт `09` §5 (рашэнне), спайк з mock/live-тэстамі (.a/.b), і не выкананы live-прагон (.c). Без адной высновы кожны з іх будзе лічыць розныя рэчы «даказанымі»: хтосьці прыме mock-паводзіны сервера за store-праверку, хтосьці адкладзе ўсё з-за незробленага sandbox-прагону. Адзіны вынік гэтай задачы — выснова, якая аддзяляць live ад mock і фіксуе response/errors/restore/environment mapping/SDK settings у межах, дазволеных задачай.

## 2. Узроўні доказа: што даказана, а што не

### 2.1 Mock-узровень — даказаны (спайк .a/.b, 2026-09-15)

| Факт | Доказ |
|---|---|
| Кананічны API `.a`: `POST /v1/device` → `device_id` (UUID) + `device_secret` (32 байты, **адзін раз**; захоўваецца толькі SHA-256 хэш); `POST /v1/grant` `{route_id, version, locale, tier, paths[]}` → `{lock_url, urls:[{path,url,expires_at}]}` | result .a, 20/20 тэстаў |
| Усе крывыя формы `Authorization` (адсутнічае, ніжні рэгістр схемы, Basic, пусты сакрэт, без схемы) → `403 device_auth_failed` | .b, negative-grant |
| Зламаны JSON з правільным bearer → `400 invalid_request`; > MAX_PATHS → `400`; `GET /v1/grant` → `404 not_found` | .b |
| **Адзін крывы шлях у batch адхіляе ўвесь запыт** — ніводзін URL не выдаецца, новага `grant_issued` няма (няма частковага выканання) | .b |
| Перавышэнне цела — fail-closed: злучэнне скінута, нуль грантаў, сервер выжывае (не чысты `400` — назіранне для ўладальніка .a, не дэфект бяспекі) | .b |
| **Адмова не кэшуецца**: чужая прылада без пакупкі атрымлівае `403 no_entitlement` пры кожнай спробе; падчас збою правайдара — `503 entitlement_unavailable` (не грант, не кэшаваная адмова); пасля аднаўлення — зноў `403`; кожная спроба сапраўды пытае правайдара | .b |
| Пазітыўны кэш падзелены па device; `cacheTtl=0` → столькі ж зваротаў да правайдара, колькі грантаў | .b |
| **Кэшаванае права не абыходзіць manifest guard** — нячленскі шлях адхілены і з цёплым кэшам (`403 path_not_allowed`) | .b |
| **Падпісаны токен — недастаткова** (чужы ключ, нячленскі шлях, traversal, backslash, абсалютны шлях, невядомы manifestBase) → `403 url_invalid` без байтаў файла | .b |
| Production-права супраць sandbox-сервера → `403 environment_mismatch`; кантроль: аднолькавыя асяроддзі працуюць | .b |
| Пратэрмінаваны URL не ажывае пасля regrant (`403 url_expired`); новы URL працуе | .b |
| Гігіена логаў: ні сакрэтаў, ні device_id, ні `Bearer `/`receipt`; `device_hash` толькі 16-hex | .b |
| **Мутат-довад у два бакі**: выдаленне device auth / manifest guard / download-аховы `/private/` дае breach на мутата-копіі і адмову на рэальным серверы — набор падае пры выдаленні аховы | .b, guard-mutations (3/3) |
| Strict env-gate: `npm start` без env → exit 1 са спісам назваў (`GRANT_ENVIRONMENT`, `GRANT_URL_SIGNING_KEY`, `REVENUECAT_SECRET_API_KEY`, `GRANT_STORAGE_ROOT`, `DEVICES_FILE`) | .b, праверка 3 |

Мяжа гэтага ўзроўню: даказвае **логіку сервера спайку супраць кананічнага кантракта** на mock-транспарце (фальш-правайдар, лакальныя файлы). Не даказвае RevenueCat REST, крамы, store-receipts, iOS/Android-прылады і production-разгортванне.

### 2.2 Live-узровень — не правераны, блокеры (з .c, пратакол гатовы)

| Клетка | Статус |
|---|---|

## 3. Зафіксаваныя факты для G08 (entitlement)

Усё ніжэй — кананічныя рашэнні `09`/G01.03, пераказаныя даслоўна для аднаго адрасата; нічога не мяняецца.

1. **Выдаўца права — сервер, не кліент.** Кліент ніколі не сцвярджае, што ён нешта купіў; лакальны сцяг «купілі» — не крыніца праўды (`09` §5.1). `AccessReady` выдае толькі `services/download` пасля сервернага гранта, пер-файлавага `sha256` і атамарнай актывацыі ([ADR G01.03](G01.03-session-access.md) §3.5).
2. **Коды памылак — закрыты спіс, без шляхоў файлаў** (`09` §5). Сэнсавая мяжа, правераная .b: `403 no_entitlement` — «права няма»; `503 entitlement_unavailable` (з `Retry-After`) — «не змаглі праверыць». **Адрозніваць іх абавязкова** — інакш плацельнік бачыць «у вас няма права» (`09` §5.1). Адмова ў кэш ніколі не трапляе (§2.1).
3. **Пазітыўны кэш** `(device_id, route_id, tier)` TTL 24 г (`GRANT_ENTITLEMENT_CACHE_TTL_SECONDS`, па змоўчанні 86400): рэзюмаванне загрузкі і паўторныя спробы працуюць без паўторнай аплаты; кэш не абыходзіць manifest guard і environment-праверку (§2.1).
4. **Пакупка ≠ ready.** Права не губляецца пры збоі файлаў; паўтор grant/загрузка — без паўторнай аплаты (`09` §5.1, [ADR G01.03](G01.03-session-access.md) §3.6). Start патрабуе поўнага праверанага пласта незалежна ад факту аплаты.
5. **Уже загружаны бандл грае незалежна** ад даступнасці RevenueCat і гранта (`09` §5.1); рэфанд-трэйд-оф «файлы на дыску = купленае» прыняты заснавальнікам (`09` §2), умова перагляду — вымяральныя злоўжыванні.
6. **`tier: base` для `access: free_base` гранта не патрабуе** — публічныя URL; грант — для `extended` і ўсяго платнага маршрута (`09` §5.2). Манifest бясплатнага пласта не змяшчае шляхоў extended-ассетаў (`09` §4) — інакш падпісаныя URL губляюць сэнс.
7. **Заглушка верыфікацыі** — толькі пры яўнай env-змене і з крыклівым папярэджаннем у лог (`09` §5.1); strict env-gate спайку падае без абавязковых зменных (§2.1).

## 4. Environment mapping (sandbox ↔ production)

| Складнік | Sandbox (тэставае асяроддзе) | Production | Заўвага |
|---|---|---|---|
| `GRANT_ENVIRONMENT` (сервер) | `sandbox` | `production` | entitlement правяраецца **патрэбнага асяроддзя**: sandbox-права не адкрывае production-файл (`09` §5 «Мяжа /grant»; праверана .b як `403 environment_mismatch`) |
| Крамы | ASC sandbox-тэстэры; Google Play internal testing | жывыя прадукты | крокі канфігурацыі 1–5 — пратакол .c |
| RevenueCat | тэставы праект, дзве аплікацыі (iOS + Android), entitlement з прывязаным прадуктам | тая ж структура, асобны сакрэт | Secret API key — **толькі env сервера**, ніколі не кліент і не логі (`.env.example`); RC разбірае аліасы/трансферы сам (`09` §5.1) |
| Прадукт | `kudy.spike.g00_03.story_01` — адна назва на дзве крамы, `server/catalog.json` не мяняецца | `ROUTE` / `ROUTE_EXTENSION` як **non-consumable one-time purchases** (`09` §5.2) — consumable можа не аднавіцца пасля пераўстаноўкі | mapping без per-store змяненняў |
| Кліент | `REVENUECAT_PUBLIC_SDK_KEY` (адзіны ключ у кліенце) + `GRANT_SERVER_BASE_URL`; з прылады — толькі **https** | тое самае; база — https-хост | мяжа кліента .a; сакрэты сервера кліент не атрымлівае ніводнай (`.env.example`) |

|---|---|---|

| Restore API | `restorePurchases()` праз store-акаўнт, без рэгістрацыі; перанос entitlement бачны ў RC як `TRANSFER` | `10` (афіцыйная дакументацыя RC, рэсёрч 2026-09-03); жывы прагон — `not-run` |
| Cross-platform | `/v1/link` — Phase 2; эндпоінт не існуе да рэалізацыі праверкі identity-токена | `09` §5, §5.2 |
| Server verification | на **кожны** grant: `GET /v1/subscribers/{device_id}` (RevenueCat REST, Secret API key) | `09` §5.1 |

| Версіі RC SDK/REST | **не правераны** — забарона сеткавага доступу; пін робіць G00.04.c па актуальных афіцыйных крыніцах (`18` §5) | гэты ADR §2.2 |

## 6. Сцэнары і адзіныя імёны палёў

Імёны перанесеныя даслоўна без перафразавання: `device_id`, `device_secret`, `route_id`, `version`, `locale`, `tier` (`base`/`extended`), `lock_url`, `urls:[{path,url,expires_at}]`, `AccessReady(route_id, version, locale, tier, stop_ids[], issuer='services/download')` ([ADR G01.03](G01.03-session-access.md) §3.5), коды памылак `09` §5. Уласных нарматыўных імёнаў гэты файл не ўводзіць.

| Сцэнар | Адказ | Роўень доказа |
|---|---|---|
| Пакупка → grant → байты (iOS/Android) | ланцуг `09` §5.1: SDK-чэк → `POST /v1/grant` → RC REST → падпісаныя URL | кананічнае; live — `not-run` (Прагон 1–2) |
| Restore на чыстай ўстаноўцы | новы `device_id`/`device_secret`; grant **без другога плацежу**; у RC — `TRANSFER` | пратакол гатовы; live — `not-run` (Прагон 3) |
| Правайдар недаступны | `503 entitlement_unavailable` + `Retry-After`; адмова не кэшуецца | **mock proven** (.b) |
| Чужая прылада без пакупкі | `403 no_entitlement` пры кожнай спробе, нуль байтаў | mock proven; на прыладзе — `not-run` |
| Sandbox-права супраць production | `403 environment_mismatch` | mock proven (.b) |
| Падпісаны чужым ключом / traversal | `403 url_invalid`, нуль байтаў; мутат-довад аховы `/private/` | mock proven (.b, мутат 3) |
| Куплены, файлы не ready | права захавана; паўтор grant/загрузкі без паўторнай аплаты; Start без поўнага пласта не адбываецца | кананічнае (`09` §5.1, G01.03 §3.6) |
| Ужо загружаны бандл | грае незалежна ад RC/гранта; рэфанд-трэйд-оф зафіксаваны | кананічнае (`09` §5.1, §2) |

Гэта лагічная фіксацыя: **не** доказ store, RevenueCat production, OS або прылад — іх правярае пратакол .c на жывым прагоне.

## 7. Блокеры (усё, што не праверана)

1. Live-клеткі §2.2 — purchase/restore на абедзвюх крамах, on-device негатывы, RC REST форма, webhook-off факт.
2. Версіі RevenueCat SDK/REST і Supabase — пін G00.04.c; тут **не праверана** і не «бясплатна».
3. Production-ключы: не існуюць і не ствараліся; ніводны сакрэт не трапіў у рэпазітар, evidence або гэты ADR.
4. Паўторны live-прагон патрабуе .b-набор з `G00_03_B_LIVE_URL` супраць таго ж сервера (ранер адрознівае рэжымы).

## 8. Што не ўваходзіць

- Не змяняе `09`/`10`/`11`/`15`/`18` і не сінхранізуе агульныя дакументы — G00.04.
- Не стварае і не дапаўняе бацькоўскі result `G00.03.md` — толькі пасля апошняй часткі.
- Не пераносіць спайк у production, не стварае RC-праект/акаўнты, не выдае production-ключоў.
- P01/P02 не датычацца плацяжоў; версіі SDK — G00.04.c.

## 9. Дзеянне заснавальніка

1. Пасля жывога прагону .c паводле `evidence/README.md` (Прагон 1–3 + негатывы) і фіксацыі формы RC REST — зацвердзіць гэту выснову або вярнуць з прычынай; тады статус ADR і result .c пераглядаюцца, а бацькоўскі result `G00.03.md` дапаўняецца пасля апошняй часткі пакета.
2. Выбар плана/абароту RevenueCat (Pros/Limits) і рашэнне пра ўключэнне webhook — эксплуатацыйныя, па-за гэтай задачы; фіксуюцца G08/G00.04 пры разгортванні.
