## 1. Праблема

`09` §6.3.1 фіксуе кірунак («MapLibre + свае тайлы») і тры варыянты фізічнай дастаўкі тайлаў (A — `OfflineManager` па нашым style URL; B — гатовы файл тайлаў у бандле; C — тайлы ў бандле маршрута), але выбар мае рабіць замер M0b, а не абмеркаванне. [18 §5](../18_component_blueprint.md) дадае, што «пастаўшчык тайлаў, offline-manager/pack і версіі SDK патрабуюць вынікаў G00.02.c/G00.04.c». Адзіны вынік гэтай задачы — рашэнне пра карту і тайлы — пакуль не мае фактаў для прыняцця; без яго G00.04 і G04/G06 атрымліваюць розныя здагадкі пра тое, што фізічна кладзецца на прыладу і дзе жыве крыніца гатоўнасці карты.

## 3. Рэкамендацыя (не прынята; чакае доказа з §4)

### 3.1 Адзіны кандыдат для першага замеру — варыянт A

Рэкамендаваны парадак выпрабавання: **першым замеряць варыянт A — штатны `OfflineManager` па нашым style URL на MapLibre RN, з уласнымі тайламі (генерацыя з OSM-экстракта, кандыдат Protomaps) на ўласным/ліцэнзаваным хостынгу.** Калі замер A не дае прымальнага выніку — тады B (гатовы файл тайлаў у бандле); C як стратэгія тайлаў не рэкамендуецца.

Абгрунтаванне — толькі ўжо запісанымі фактамі:

1. A — «штатны шлях бібліятэкі» (`09` §6.3.1) → найменш уласнага кода; «колькі кода патрабуе» — адзін з чатырох крытэраў выбару M0b.
2. B патрабуе адаптар: «MapLibre Native не чытае PMTiles без пласта-адаптара» (`09` §6.3.1) → болей кода; падтрымка MBTiles у MapLibre Native на гэты дрэвазапіс не спраўджаная — **не праверана**.
3. C «дублюе тайлы між маршрутамі» (`09` §6.3.1) → самы дарагі па трафіку/сховішчы пры колькасці гідаў > 1. Спайк .a праверыў C як **package-механіку** (completeness, атамарная актывацыя) на браўзерным узроўні — гэта дыягностык жыццёвага цыклу пакета, не выбар стратэгіі тайлаў; сам result .a гэтага не сцвярджае.
4. A абнаўляе рэгіён з сервера без рэлізу, што адпавядае крытэру «ці абнаўляецца без рэлізу»; але менавіта паводзіны абнаўлення/квот `09` загадвае замерыць — яны **не замераны**.

**Кантрактнае следства A, якое замер павінен адказаць (за G01.03):** тайлы, дастаўленыя `OfflineManager`, жывуць па-за ланцугом `staging` → пер-файлавы `sha256` → атамарная актывацыя → `AccessReady`, якім кантракт сесіі доказвае «поўны правераны пакет перад Start». Пры A з'яўляецца **другая крыніца гатоўнасці** (унутранае офлайн-сховішча рэндэрара), і readiness мусіць уключаць яе праверку — альбо гэта становіцца аргументам супраць A. B/C укладаюць тайлы ў існуючы ланцуг пакета без другой крыніцы праўды; гэтая акаўнтычная цана павінна быць у табліцы выбару нароўні з чатырма крытэрамі `09` §6.3.1 (памер; авіярэжым з назвамі вуліц/гліфамі; абнаўляльнасць без рэлізу; колькасць кода).

| Атрыбуцыя | бачная на экране карты і клікабельная, **у тым ліку офлайн**, паводле OSMF Attribution Guidelines (тэкст канчаткова фіксуе рэалізацыя, не гэты ADR); спайк дэманструе механізм (`ODbL-1.0-compatible`), не канчатковы тэкст | `09` §6.2, §6.3.1 |

Лічбы хостынгу — **не праверана**; «бясплатна» не пішацца. Mapbox-фолбэк — платны, MAU-залежны, лічбы **не правераны** | `09` §6.3.1; `08` частка 3 |

### 3.3 Сцэнары і адзіныя імёны палёў (супраць прынятага ADR)

Правераны адносна [ADR G01.03](G01.03-session-access.md) і `09`: імёны `version`, `tier` (`base`/`extended`), `AccessReady(route_id, version, locale, tier, stop_ids[], issuer='services/download')`, `lock.json`, `staging`, `ready` (вывад з дыска, не калонка), `stop_id`/`story_id` — перанесеныя без перафразавання; уласных нарматыўных імёнаў гэты файл не ўводзіць. Сцэнары:

| Сцэнар | Адказ гэтай рэкамендацыі |
|---|---|
| Авіярэжым з назвамі вуліц | патрабуе гліфаў на дыску (§3.2) незалежна ад A/B/C; даказываецца клеткамі 2–3/6–7 пратакола .b — `not-run` |
| Пакупка ≠ ready | выключэння для карты няма: гатоўнасць тайлаў уваходзіць у тую самую readiness (у A — праверка офлайн-рэгіёна, у B/C — `lock.json`); Start без поўнага пласта не адбываецца |
| `version` нязменная да End | офлайн-рэгіён/тайлы замацоўваюцца за версіяй пакета; абнаўленне каталога не падмяняе рэгіён жывой сесіі (G01.03 §3.4) |
| Панарама па-за bbox | чэсны стан «па-за загружаным рэгіёнам», без спробы сеткі; на браўзерным узроўні паказана спайкам .a, на прыладзе — клеткі 4/8, `not-run` |
| Атрыбуцыя офлайн | бачная і клікабельная без сеткі (§3.2); браўзерны ўзровень спайку — так, прылады — `not-run` |

Гэта лагічная дакументацыйная мадэль: **не** доказ OS, сервера, store або прадукцыйнасці — іх правярае прыладавая матрыца .b і G00.04.

## 4. Канкрэтны наступны эксперымент для G00.02.a

Уладальнік .a (выканаўца з прыладай і дазволеным build-шляхам):

1. **Перадумова — ліквідаваць CRLF-checkout-блокер** (`core.autocrlf=true` без `.gitattributes` ламае `integrity mismatch: index.html` у `prepare-data` і 3 з 4 тэстаў): `.gitattributes` з `eol=lf` для `source/**` спайку ці нармалізацыя пры падліку хэшаў. Рэпрадукцыя і корань — result .b, праверкі 2–4; гэта рашэнне ўладальніка .a або мэйнтэйнера, спайкавы код тут не правіўся.
2. **Выканаць падготованы пратакол** [G00.02.b-device-evidence](../../../spikes/G00.02-offline-map/evidence/G00.02.b-device-evidence.md): прэ-праверкі шляху загрузкі 0i/0a, клеткі 1–8 (чысты download → авіярэжым → restart → па-за bbox, iOS/Android асобна), метрыкі памераў/часу, клеткі збояў 9–12, натыўны ўзровень 13–14 (той самы пакет у development build MapLibre RN).
3. **Дадаць руку замеру A** на тых жа фіксаваных уводах (bbox/zoom/версія/крыніца): `OfflineManager` па ўласным style URL на той самы bbox і zoom 14–16 — памер офлайн-рэгіёна, час, паводзіны квот/абнаўлення, авіярэжым + restart, гліфы; дэталі руки — у файлавым scope .a (`spikes/G00.02-offline-map/`).
4. **Запоўніць табліцу выбару** A/B/C па чатырох крытэрах `09` §6.3.1 + кантрактны крытэр «адна крыніца гатоўнасці» (§3.1) і вярнуцца да гэтага ADR: пазначыць прыняты варыянт. Толькі затым сінхранізацыю `09` робіць G00.04; бацькоўскі result G00.02 дапаўняецца пасля апошняй часткі пакета.

Пакуль клеткі `not-run`, статус гэтай задачы — `decision-required`, а залежная праца (G00.04) застаецца незаблакаванай ад гэтага факту ніколькі.

## 5. Што не ўваходзіць

- Не змяняе `09`/`08`/`10`/`15`/`18` і не сінхранізуе агульныя дакументы — гэта G00.04.
- Не стварае і не дапаўняе бацькоўскі result `G00.02.md` — толькі пасля апошняй часткі.
- Не фіксуе версій SDK/інструментаў і хостынгу канчаткова (G00.04.c па актуальных афіцыйных крыніцах).
- Не чапае код спайку; CRLF-блокер перадаецца ўладальніку .a з рэпрадукцыяй result .b.
- Не датычыцца P01/P02; не дае дазволу на рэальныя грошы або production; API-ключы ў ассетах і два рэндэрары на экране забароненыя §17.

## 6. Дзеянне заснавальніка

1. Пасля запоўненай прыладавай матрыцы .b і замеру A (§4) — зацвердзіць варыянт у гэтым ADR або вярнуць з прычынай.
2. Калі замер пакажэ перавагу платнага правайдара (Mapbox-фолбэк) — даць або не даць дазвол на выдатак; без яго платны шлях не выбіраецца.
