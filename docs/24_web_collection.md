# KUDY — збор з сеткі (сайты і YouTube → сыравая бібліятэка)

Асобны **унутраны інструмент**, не частка дадатку. Задача: з крыніц, якія вызначае аўтар (навінныя парталы, энцыклапедыі і вікі, YouTube), сабраць сыравую бібліятэку з «пашпартамі» і правамі — і давесці яе да стану, з якога пачынаецца пайплайн [`07`](07_content_pipeline.md). Гэта слой збору: ён не піша гісторый і нічога не публікуе.

## Ключавыя рашэнні (вынік абмеркаванняў 2026-09-16 і 2026-09-21)

- **Збор разавы, кампаніямі.** Кампанія = горад + стартавыя адрасы + межы. Ніякага сталага маніторынгу і перыядычнага перазбору.
- **Сырая копія — гэта архіў.** Сайт змяніцца або знікне — пераздабыць будзе нягде. Захоўваем шчодра: поўную копію старонкі, тэкст, спасылкі, дату. Ачыстку можна перарабляць над сыравом бясконца, здабычу — толькі раз.
- **Лакальны інструмент, без адмін-панэлі.** Панэль — работа над інтэрфейсам, які не паляпшае якасць дадзеных. Калі з'явяцца прычыны (рэгулярныя кампаніі, другі аператар), той жа код загортваецца ў панэль без перапісвання.
- **Гайды збіраюцца рукамі.** Бібліятэка — працоўнае месца рэдактара; аўтазборка гайда з парсінгу не прадугледжана.

## Мяжа паміж `24` і `07`

`07` пачынаецца з крыніц: «PDF / сканы / кнігі / архіўныя выпіскі / нататкі аўтара». Гэты дакумент дадае чацвёрты ўваход — сетку — і завяршае сваю работу на этапе `Source`:

```
Кампанія (горад + стартавыя адрасы + межы + тыпы крыніц)
   ↓ collect: паўзук з парканам / MediaWiki-экспарт / субтытры YouTube
RawRecord (копія старонкі + тэкст + спасылкі + пашпарт)      ← сыравая бібліятэка
   ↓ clean: правілы па тыпу крыніцы; сыро не перазапісваецца
Source (чысты тэкст + бібліяграфія + rights)   → Fragment → Claim → … далей па `07`
```

Этапы `Fragment`, `Claim`, `Draft` і review у `07` не мяняюцца.

## Кампанія

Кампанія — YAML-файл; запуск уручную, лакальна. Праца аднаўляемая: перапынак нічога не губляе, паўторны запуск не стварае дублікатаў (URL + хэш тэксту). Шмат гарадоў пазней — проста новыя файлы кампаній; горад з першага дня ў пашпарце кожнага запісу.

```yaml
# campaigns/gdansk-2026-09.yaml
city: gdansk
seeds:
  - https://…            # навінны партал, старонка пра горад
topics: [architecture, history]
fence: { depth: 3, extra_domains: [], delay_s: [2, 5] }
youtube: [<ідэнтыфікатары відэа>]
```

## Пашпарт запісу (RawRecord)

| Поле | Змест |
|---|---|
| `id`, `campaign_id` | сувязь з кампаніяй |
| `source_type` | `news` / `wiki` / `web` / `youtube` |
| `url`, `canonical_url` | адкуль узята; кананічны адрас — для дэдуплікацыі |
| `collected_at` | дата збору; для бібліяграфіі — дата зверкі |
| `city`, `topics[]` | горад/рэгіён і тэгі тэм |
| `rights` | значэнні — ніжэй |
| `content_hash` | дэдуплікацыя зместу |
| `status` | `raw → cleaned → used` |
| `snapshot_path` | шлях да сырой копіі на дыску |
| `media_dir` | шлях да папкі фота гэтага артыкула |

Сырая копія на дыску: HTML, прачытаны тэкст у markdown, спіс спасылак (тэкст-анкер + адрас + кантэкстны абзац), метаданыя старонкі (загаловак, дата публікацыі, аўтар, мова) і фота — асобнай папкай на артыкул (раздзел «Фота»). Індэкс — у тым самым SQLite, што і `07`; `Source` атрымлівае `raw_record_id`.

**Правы** — слоўнік з `07` (`public_domain` / `licensed` / `research_only` / `author_own`); для сеткі:

- Вікіпедыя і MediaWiki-сайты — `licensed` (CC BY-SA): цытата дазволена з атрыбуцыяй;
- навінныя парталы і іншыя сайты — `research_only`: факты так, фармулёўкі — сваімі словамі;
- транскрыпты YouTube — `research_only`;
- уласныя тэксты аўтара — `author_own`.

## Калектары

### Паўзук па сайтах

Рэальны браўзер (Playwright) — з-за старонак на JavaScript і лагінаў.

- **Лагін**: аўтар адзін раз уваходзіць у сваё акно браўзера; інструмент далей карыстаецца гэтай сесіяй. Паролі інструмент не захоўвае.
- **Паркан** — без яго паўзук пойдзе «чытаць» увесь інтэрнэт:
  - толькі свой домен, плюс яўна дазволеныя дадатковыя;
  - глыбіня ад стартавага адраса, па змаўчанні 3 крокі;
  - бяром старонкі, якія выглядаюць як артыкул: загаловак + дастаткова абзацаў тэксту; меню, каталогі і службовыя — прапускаем;
  - ветлівасць: затрымка 2–5 с паміж запытамі да аднаго хоста, спыненне па серыі памылак;
  - дэдуплікацыя: па URL і па хэшы тэксту (той самы тэкст пад новым адрасам звязваем, а не дублюем).

### Энцыклапедыі і вікі

Калі ёсць афіцыйныя дзверы — не паўзім «як чалавек»: MediaWiki API і экспарт даюць хутчэй, поўней і дазволена. Задаём спіс артыкулаў і катэгорый па горадзе; пераход па вікі-спасылках — у межах зададзеных тэм і глыбіні.

### YouTube

`yt-dlp` спампоўвае субтытры; ручныя субтытры маюць прыярытэт над аўтаматычнымі (якасць). Захоўваем транскрыпт і метаданыя: назва, канал, дата, працягласць, мова. Аўтасубтытры без пунктуацыі — работа этапу ачысткі. Відэа зусім без субтытраў трапляюць у адкладзены спіс `asr-backlog`; распазнанне голасу — не ў першай версіі.

## Фота

Фота — не прыдатак да тэксту, а асобны кавалак сыравіны: для гайда адно добрае фота месца каштуе як цэлы абзац. Правілы:

- **Што бярэм.** Змястоўныя выявы з тэксту артыкула: фатаграфіі будынкаў, карты, партрэты, дакументы. Іконкі, логатыпы, банеры, кнопкі, счётчыкі і ўсё дробнае (менш за ~150 px па большай старане) — не бяром.
- **Дзе жывуць.** Асобна ад тэксту: свая папка медыя на кожны артыкул, побач з яго сыравой копіяй. Так фота нельга губляць пры пераапрацоўцы тэксту — яны не ўшыты ў HTML-копію.
- **Імёны файлаў — чалавечыя.** `слаг-артыкула-img-01.jpg`, `…-img-02.jpg` — слаг — гэта кароткі лацінскі запіс назвы артыкула (`gdansk-stocznia-img-01.jpg`). Назва артыкула ў кожным імені файла: у файлавым менеджэры адразу відаць, адкуль фота. Сапраўдны адрас выявы захоўваецца ў табліцы, а не ў імені.
- **Суаднясенне фота і тэксту — тры ўзроўні:**
  1. імя файла змяшчае слаг артыкула;
  2. у прачытаным тэксце кожнае фота стаіць на сваёй пазіцыі як звычайная markdown-выява з `alt` і подпісам;
  3. табліца `media` у SQLite: артыкул, нумар абзаца, `alt`, подпіс, сапраўдны URL, файл, хэш, памер у пікселях, `rights`, дата збору.
- **Дублікаты.** Адно фота на розных старонках — свая копія ў кожным артыкуле (сховішча танное), хэш у табліцы паказвае, што гэта адна выява.
- **Правы — асобныя на кожнае фота.** Фатаграфія — ахаваны твор нават тады, калі факт у тэксце вольны. У бандл прадукту трапляюць толькі выявы з `licensed` / `public_domain` / `author_own` і з атрыбуцыяй; астатнія (`research_only`) — унутраная праца і прыкладкі для рэдактара.
- **YouTube.** Захоўваем мініяцюру відэа як вокладку запісу — тым жа правілам імёнаў.

## Ачыстка

- Правілы збіраюцца ў **пакеты па тыпу крыніцы** (`news-v1`, `wiki-v1`…) з версіямі; кожны запуск фіксуе версію пакета ў логу.
- Парадак: вылучэнне асноўнага зместу → зняцце шапак, меню, рэкламы, блокаў «прачытайце таксама» → нармалізацыя спасылак (анкер + адрас) і фота (выява на сваёй пазіцыі ў тэксце, подпіс захоўваецца) → дата і мова.
- Спачатку структурныя правілы і рэгулярныя выразы; LLM-нармалізацыя (склейванне абзацаў, пунктуацыя аўтасубтытраў) — пазней, як дапаможны праход. Мяжа `07` дзейнічае: LLM — толькі ў вытворчасці, ніколі ў рантайме.
- **Сыро не перазапісваецца**: ачыстка піша новую версію; дрэнныя правілы адкатваюцца паўторным запускам на сыраве.
- Прыёмка пакета — прагляд аўтарам выбаркі ачышчаных дакументаў, экспартаванай у зручны для прагляду выгляд. Крытэр: у выбарцы няма рэкламы і меню і не згубіўся ніводзін абзац зместу.

## Зборка гайдаў — рукамі

- Пошук па бібліятэцы: горад, тэма, тып крыніцы, паўнатэкставы пошук (тыя ж SQLite + sqlite-vec, што ў `07`).
- «Кошык»: аўтар пазначае фрагменты, экспартуецца чарнавік у markdown са спасылкамі-цытатамі (адрас + дата зверкі).
- Далей — `07` без зменаў: фрагменты кормяць claims, claims — чарнавік, чарнавік — рэвю аўтара.

## Тэхнічны мінімум

Той жа прынцып, што ў `07`: інструмент аднаго чалавека, які запускаецца ўручную.

- лакальны CLI (Node/TypeScript), SQLite + sqlite-vec, файлы сырых копій на дыску з рэзервовай копіяй;
- Playwright, `yt-dlp`, YAML-канфігі кампаній са схемай-праверкай (Zod);
- ніякага сервера, чаргі, планавальніка.

**Майстэрня ≠ крама.** Сыравая бібліятэка жыве па-за базай прадукту; публікацыя зацверджаных гісторый у бандлы — этап publish з `07`. Бясплатнасць/платнасць — уласцівасць бандла, не бібліятэкі.

## Юрыдычная мяжа

Збор — для ўнутранай даследчай працы; сырыя копіі публічна не перавыкладваюцца. Паводле `rights`: дакладныя цытаты — толькі з `licensed`/`public_domain` і з атрыбуцыяй; з `research_only` — факты сваёй мовай (`07`, рызыка 1). Платны доступ мы не «ламаем»: збор ідзе толькі там, куды аўтар і так мае доступ па сваёй падпісцы.

## Пілот

Гданьск, адна кампанія: адзін навінны партал (выбірае аўтар), падборка артыкулаў Вікіпедыі пра горад, 5–10 відэа YouTube з ручнымі субтытрамі.

Крытэрыі прыёмкі:

1. паўзук не выйшаў за паркан: 0 старонак з недазволеных хостоў;
2. кожны запіс мае поўны пашпарт: горад, тып, rights, дата;
3. у выбарцы старонак захаваны ўсе спасылкі-анкеры з тэкстам;
4. кожнае змястоўнае фота захавана з імем па слагу артыкула, стаіць на сваёй пазіцыі ў тэксце і занесена ў табліцу `media` (alt, подпіс, крыніца, rights); іконкі і банеры не трапілі;
5. ачышчаная выбарка праходзіць прагляд аўтара: без меню і рэкламы, змест і фота поўныя;
6. транскрыпты з ручнымі субтытрамі разбіты на абзацы па таймкодах;
7. перапынак і перазапуск кампаніі не ствараюць дублікатаў.

Па пілёце вырашаем: ці хапае правіл для другога «сямейства» навінных сайтаў, патрэбу ў распазнанні голасу (`asr-backlog`) і фінальны фармат перадачы ў `07`.
