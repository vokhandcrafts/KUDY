*2026-09-23 by Showboat 0.6.1*

Issue #155 acceptance criteria 1 and 2, driven through the real CLI
(`tools/collector/collector.mjs`, no test harness). The first block runs the
same campaign twice against a fresh database: the first run registers the
campaign, enqueues 3 steps (1 seed + 2 youtube) and registers the two youtube
record shells; the second run finds everything done and inserts nothing new.
`status` then shows the stored counts. The second block feeds a campaign with
`fence.depth: 0` — rejected with a diagnostic naming the offending field,
exit code 1.

```sh
rm -rf /tmp/kudy-collector-demo && mkdir -p /tmp/kudy-collector-demo && printf '%s\n' 'city: gdansk' 'seeds:' '  - https://news.example/gdansk' 'topics: [history]' 'fence:' '  depth: 3' '  extra_domains: []' '  delay_s: [2, 5]' 'youtube:' '  - dQw4w9WgXcQ' '  - aQw4w9WgXcQ' > /tmp/kudy-collector-demo/gdansk.yaml && node tools/collector/collector.mjs run --campaign /tmp/kudy-collector-demo/gdansk.yaml --db /tmp/kudy-collector-demo/db.sqlite && node tools/collector/collector.mjs run --campaign /tmp/kudy-collector-demo/gdansk.yaml --db /tmp/kudy-collector-demo/db.sqlite && node tools/collector/collector.mjs status --db /tmp/kudy-collector-demo/db.sqlite
```
