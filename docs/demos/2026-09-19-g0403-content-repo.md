# G04.03 — картка гатоўнасці пакета (services/contentRepo)

Дэма правярае ўсе пяць крытэрыяў issue #60 на сінтэтычным пакеце `route-x@1`:
гатовасць без сеткі, тыр-размежаванне, аднаўленне пасля памылкі медыя,
блакаванне няпоўнага пакета і асобнасць discovery-кэшу ад AccessReady.
Сцэнар піша пакет у часовую тэчку і друкуе толькі вердыкты — без шляхоў
і таймінгаў, таму вывад дэтэрмінаваны.

```sh
node --no-warnings --experimental-strip-types services/contentRepo/demo-g0403.ts
```

```output
1. free start on a complete package: {"status":"ready","routeId":"route-x","version":"1","tier":"base","tierAvailable":["base"]}
2. paid start without grant:          {"status":"access-locked","tier":"extended"}
3. media error:                       {"status":"needs-recovery","media":["be/base/audio/story-b.m4a"]}
4. missing layer file:                {"status":"incomplete","missing":["be/base/stops.json#missing-file"]}
5. missing discovery index:           {"revision":null,"index":null,"fromCache":false} (start: ready)
5. discovery cached reads:            revision=r-1 fromCache=false -> fromCache=true
```

Дадатковая праверка крытэрыя 3: ядро гатоўнасці не імпартуе ніякіх сеткавых
API — гэта мацуе тэст-гард `wiring: the readiness core stays network-free`
у `services/contentRepo/wiring.test.ts` (ён ідзе ў агульным `npm test`).
