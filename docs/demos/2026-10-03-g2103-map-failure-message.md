# G21.03: бачнае лакалізаванае паведамленне пры адмове карты горада

*Showboat-дэма задачи #536: калі тайл-правайдар недаступны, `CityMap` больш не
пакідае маўклівы пусты квадрат. Збой ініцыялізацыі пазначаецца на кантэйнеры
`data-map-error`, а побач з'яўляецца тыпаванае даступнае паведамленне
`<p role="status">` з рэальнага слоўніка лакалі (be/en/uk) — без сыравага
выключэння і без URL правайдара. Паспяховае `load` здымае паведамленне і
маркер; пост-лод недахопы тайлаў застаюцца ў кансолі, бо карта працуе.
Размантаванне зачышчае рэсурсы MapLibre. Створана 2026-10-03.*

<!-- showboat-id: g2103-map-failure-message -->

Паводзінная праверка ў рэальным headless Chromium (сістэмны двайнік праз
`KUDY_CHROMIUM` або агульнадаступныя шляхі; голы CDP без новых залежнасцяў):
запыты правайдара адкідваюцца з CDP-прычынай `InternetDisconnected`
(пратакольны варыянт «internetdisconnected» з задачы), далей mount рэальнай
`MapPage` з рэальнымі радкамі be/en, потым аднаўленне на лакальным
дытэрмінісцкім стылі:

```sh
node --test --experimental-strip-types web/city-map.browser.test.ts 2>&1 | grep -E 'ℹ (tests|pass|fail)'
```

```output
ℹ tests 1
ℹ pass 1
ℹ fail 0
```

Што сцвярджае тэст: пустая карта толькі з `data-map-error`, бачнае
неўтоенае паведамленне роўнае `be.mapError` (і `en.mapError` на en-мантажы),
ніводзін сыравы тэкст (`openfreemap`/`http`/`Failed to fetch`/`TypeError`) не
трапляе ў DOM адмовы, спасылкі на гіды бачныя і не перакрытыя ўва ўсіх
сцэнарыях, паводзіны аднаўлення здымае маркер, і размантаванне жывой карты
не пакідае ніякіх старонкавых памылак.

Экспэрымент па зняцці фіксу (implementation-rules 1) выкананы ў гэтай сесіі:
стары `web/components/city-map.tsx` (без рэндэру паведамлення) вернуты
часова — той самы тэст чырванеў на сцвярджэнні бачнага паведамлення
(`messageText` → падзенне), тады як маркер `data-map-error` ад старога коду
яшчэ ставіўся; аднаўленне фіксу вяртае зелёны (вывад блока вышэй).
