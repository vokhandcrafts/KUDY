# G05.06.b — the committed trace set and its per-trace expectations

*Showboat demo for issue #219 (`tools/simulate` trace set), created 2026-09-26.*

<!-- showboat-id: g0506b-trace-set -->

The committed set under `tools/simulate/traces/` carries the four generators of
09 §11 (clean walk, standing at every stop, fast walk, mid-route start) plus
the scenario fixtures of the 16 G05.06 row (replay of a heard stop, reverse
order, GPS gap, focus loss during guide audio, locked stop unlocked mid-walk
by `AccessReady`). The runner `tools/simulate/verify.mjs` replays every trace
through the production stack and compares it with its OWN expectation — the
`mustFire`/`mustNotFire` lists, then the byte-stable report line by line.

Setup: the proof below swaps the engine's `FocusLoss` case for an
`AudioFinished` call at module-load time — the classic bug the focus-loss
fixture exists to catch. The loader lives in a fixed temp dir; a stale one is
removed first:

```sh
rm -rf /tmp/kudy-g0506b-demo && mkdir -p /tmp/kudy-g0506b-demo && node -e '
const fs = require("node:fs");
fs.writeFileSync("/tmp/kudy-g0506b-demo/hooks.mjs", [
  "export async function load(url, context, next) {",
  "  const result = await next(url, context);",
  "  if (url.endsWith(\"/core/engine/reducer.ts\")) {",
  "    const source = String(result.source).replaceAll(",
  "      \"if (s.playing) s.playing.paused = true;\\n      s.focusLostAt = now;\\n      s.autoplaySuspended = true;\",",
  "      \"if (s.playing) audioFinished(s, { type: \\x27AudioFinished\\x27, sessionId: s.sessionId, playId: s.playing.playId }, now, config, commands);\"",
  "    );",
  "    return { format: \"module-typescript\", shortCircuit: true, source };",
  "  }",
  "  return result;",
  "}",
  "",
].join("\n"));
fs.writeFileSync("/tmp/kudy-g0506b-demo/register.mjs", "import { register } from \"node:module\";\nregister(\"./hooks.mjs\", import.meta.url);\n");
console.log("mutation loader ready: FocusLoss case is swapped for the AudioFinished call");
'
```

```output
mutation loader ready: FocusLoss case is swapped for the AudioFinished call
```

The committed set verifies against its expectations — every trace matches its
own `mustFire`/`mustNotFire` lists and its pinned report:

```sh
node --no-warnings -e "
import('./tools/simulate/verify.mjs').then((v) => {
  const { failures } = v.verifyTraceSet({ tracesDir: 'tools/simulate/traces', expectationsDir: 'tools/simulate/expectations' });
  console.log('failures:', failures.length);
  for (const f of failures) console.log(f.message);
})"
```

```output
failures: 0
```

The proof: the simulator imports the production reducer, so treating
`FocusLoss` as `AudioFinished` must break the focus-loss fixture. The loader
swaps `core/engine/reducer.ts` for a copy whose interruption is credited as a
finish — the story is "heard" at the call, the explicit `ResumeAudio` turns
into a no-op, and the runner fails naming the trace and the first differing
report line (the `ResumeAudio` outcome). No repository file is touched — the
mutation happens at module load in memory:

```sh
node --no-warnings --import /tmp/kudy-g0506b-demo/register.mjs -e "
import('./tools/simulate/verify.mjs').then((v) => {
  const { failures } = v.verifyTraceSet({ tracesDir: 'tools/simulate/traces', expectationsDir: 'tools/simulate/expectations' });
  console.log('failures:', failures.length);
  for (const f of failures) console.log(f.message);
})" && [ -z "$(git status --porcelain core/engine/reducer.ts)" ] && echo "repository files unchanged by the mutation"
```

```output
failures: 1
trace traces/focus-loss.json: the report diverges from the expectation at line 57 — expected: "      \"outcome\": \"applied\"" actual: "      \"outcome\": \"no-op\""
repository files unchanged by the mutation
```
