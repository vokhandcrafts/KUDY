# G16.01 — прыватнае сховішча водгукаў і API ацэнак

*Showboat demo for issue #72 (G16.01 — `POST /v1/feedback/read`, `PUT /v1/feedback`, `POST /v1/feedback/delete`), created 2026-10-04.*

Сцэнар на рэальным прадакшн-кодзе (wire → core → SQL) над in-process Postgres
(PGlite з закамічанымі міграцыямі + міграцыя гэтай задачы). CAS-кантракт
`21` §5: стварэнне з expected_revision 0, страчаны ACK паўтарае той самы
рэзультат без другога голасу, рэдагаванне зрушвае рэвізію, старая рэвізія
атрымлівае 409 і нічога не перазапісвае, tombstone не мае ні score, ні
прычын, чытанне аддае толькі ўласны радок прылады, імпартаваны/невядомы
target — 422. (`export LD_LIBRARY_PATH` — хоставае патрабаванне node, не
частка змены; сакрэты і UUID — сінтэтычныя фікстуры.)

```sh
export LD_LIBRARY_PATH=$HOME/.local/lib
node --experimental-strip-types --input-type=module -e '
import { pathToFileURL } from "node:url";
const { readFileSync } = await import("node:fs");
const support = await import(pathToFileURL("supabase/tests/feedback/test-support.ts"));
const wire = await import(pathToFileURL("supabase/functions/feedback/feedback-wire.ts"));
const fixture = JSON.parse(readFileSync("fixtures/discovery-contract/feedback-cases.json", "utf8"));

const db = await support.freshFeedbackDatabase();
const client = support.pgliteFeedbackClient(db);
const config = support.testFeedbackConfig();
const deviceA = await support.registerFeedbackDevice(db);
const deviceB = await support.registerFeedbackDevice(db);
await support.publishFixtureTargets(db, fixture.targets);

const call = (device, method, path, body) =>
  wire.handleFeedbackEdgeRequest(
    support.feedbackRequest({ method, url: "https://feedback.test" + path, body, secret: device.secret }),
    client,
    config,
  ).then(async (r) => JSON.stringify({ path, status: r.status, body: r.status === 204 ? null : await r.json() }));
const put = (device, mutation, revision, score, reasons) => call(device, "PUT", "/v1/feedback", {
  mutation_id: mutation, target: fixture.targets[0], expected_revision: revision,
  score, reason_codes: reasons, disclosure_version: fixture.disclosure_version,
});

console.log("create:", await put(deviceA, "00000000-0000-4000-8000-000000000001", 0, 2, ["audio_problem"]));
console.log("lost-ack-retry:", await put(deviceA, "00000000-0000-4000-8000-000000000001", 0, 2, ["audio_problem"]));
console.log("edit:", await put(deviceA, "00000000-0000-4000-8000-000000000002", 1, 4, ["interesting_stories", "audio_problem"]));
console.log("stale-revision:", await put(deviceA, "00000000-0000-4000-8000-000000000003", 1, 5, ["interesting_stories"]));
console.log("delete:", await call(deviceA, "POST", "/v1/feedback/delete", { mutation_id: "00000000-0000-4000-8000-000000000004", target: fixture.targets[0], expected_revision: 2 }));
console.log("read-own:", await call(deviceA, "POST", "/v1/feedback/read", { target: fixture.targets[0] }));
console.log("read-other:", await call(deviceB, "POST", "/v1/feedback/read", { target: fixture.targets[0] }));
console.log("imported-target:", await call(deviceB, "PUT", "/v1/feedback", { mutation_id: "00000000-0000-4000-8000-000000000008", target: fixture.unknown_targets[0], expected_revision: 0, score: 5, reason_codes: ["worth_visiting"], disclosure_version: fixture.disclosure_version }));
' 2>/dev/null
```

Другі сцэнар — жыццёвы цыкл рэестра мэт (`21` §5.2) і інтэграцыя з
`DELETE /v1/device`: імпарт даверанага экспарту рыхтуе мэтy ў стане
`prepared` (збор fail-closed, 503), публікацыя адкрывае прыём, паўторны
імпарт не прыніжае апублікаванае, а выдаленне прылады каскадам забірае ацэнкі
і робіць наступны выклік 401 без магчымасці ўваскрэсіць радок.

```sh
export LD_LIBRARY_PATH=$HOME/.local/lib
node --experimental-strip-types --input-type=module -e '
import { pathToFileURL } from "node:url";
const support = await import(pathToFileURL("supabase/tests/feedback/test-support.ts"));
const wire = await import(pathToFileURL("supabase/functions/feedback/feedback-wire.ts"));
const deviceWire = await import(pathToFileURL("supabase/functions/_shared/device-wire.ts"));
const registry = await import(pathToFileURL("supabase/functions/feedback/registry-import.ts"));

const db = await support.freshFeedbackDatabase();
const client = support.pgliteFeedbackClient(db);
const config = support.testFeedbackConfig();
const device = await support.registerFeedbackDevice(db);
const runner = { query: (sql, params) => db.query(sql, params) };
const exportDoc = { schema_version: 1, status: "prepared", targets: [{ kind: "guide", route_id: "guide-route-a1", version: "1", locale: "be", status: "prepared" }] };

const call = (method, path, body) =>
  wire.handleFeedbackEdgeRequest(
    support.feedbackRequest({ method, url: "https://feedback.test" + path, body, secret: device.secret }),
    client,
    config,
  ).then(async (r) => JSON.stringify({ path, status: r.status, body: r.status === 204 ? null : await r.json() }));
const putBody = { mutation_id: "00000000-0000-4000-8000-0000000000a1", target: { kind: "guide", route_id: "guide-route-a1", version: "1", locale: "be" }, expected_revision: 0, score: 3, reason_codes: [], disclosure_version: "feedback-disclosure-1" };

await registry.importFeedbackRegistry(runner, exportDoc);
console.log("prepared:", await call("PUT", "/v1/feedback", putBody));
console.log("published:", await registry.publishFeedbackTargets(runner, exportDoc));
console.log("after-publish:", await call("PUT", "/v1/feedback", putBody));
console.log("re-import:", JSON.stringify(await registry.importFeedbackRegistry(runner, exportDoc)));
const deleteResponse = await deviceWire.handleDeviceRequest(
  { method: "DELETE", headers: { get: (n) => (n === "authorization" ? "Bearer " + device.secret : null) } },
  client,
);
console.log("device-delete:", deleteResponse.status);
console.log("after-device-delete:", await call("POST", "/v1/feedback/read", { target: putBody.target }));
' 2>/dev/null
```

```output
prepared: {"path":"/v1/feedback","status":503,"body":{"error":"target_not_published"}}
published: 1
after-publish: {"path":"/v1/feedback","status":200,"body":{"revision":1,"saved":true}}
re-import: {"imported":0,"alreadyPresent":1}
device-delete: 204
after-device-delete: {"path":"/v1/feedback/read","status":401,"body":{"error":"unknown_device"}}
```

Абодва сцэнары выкарыстоўваюць толькі сінтэтычныя фікстуры
(`guide-route-a1`, `place-a1`, выдуманыя mutation-UUID і сакрэты з
`fixtures/discovery-contract/feedback-cases.json`); ніякіх рэальных
даменаў, сакрэтаў або кантэнту. Гарачыя даныя жывуць толькі ў памяці
PGlite.
